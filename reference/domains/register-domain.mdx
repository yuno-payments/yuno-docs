---
title: "Register Domain"
openapi: "/openapi/domains/register-domain.json POST /v1/payment-methods/domains"
description: "Register the domains that display the Apple Pay or Google Pay button on a wallet connection"
---

Registers one or more domains against a wallet connection. Yuno sends each domain to the wallet provider and stores the result on that connection

Registration is synchronous. The response carries the final status of every domain you sent, so there is no callback to wait for: `REGISTERED` means the domain can display the wallet button, and `ERROR` means the provider rejected it. Yuno does not send a webhook for domain events, so use [Get domain](/reference/domains/get-domain) when you need to read a status again

<Note>
  `X-Idempotency-Key` is required, and Yuno stores it for audit without enforcing it. A second call with the same key creates a new registration attempt and a new call to the wallet provider, so every retry adds another row to your domain list. Fix the cause of the failure, such as an association file that Apple could not reach, before you send the request again
</Note>

Apple allows 99 domain names per merchant identifier, and Yuno registers one identifier per Apple Pay connection, so a connection holds at most 99 domains. Read [Apple Pay prerequisites](/docs/wallets/apple-pay/prerequisites-apple-pay) for what to do when you reach that limit
