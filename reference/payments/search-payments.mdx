---
title: "Search Payments"
openapi: "/openapi/payments/search-payments.json GET /payments/search"
description: "Lists the account's payments created in a window of at most 1 day, with filters and cursor pagination."
---

This request lists the payments of the account sent in the `X-Account-Code` header. Use it to sync payments to a data warehouse or to build an admin panel. To look up a single payment, use [Retrieve Payment by ID](/reference/payments/retrieve-payment-by-id-v2) or [Retrieve Payment by Merchant Order ID](/reference/payments/retrieve-payment-by-merchant-order-id) instead.

## Creation window

`created_at_from` and `created_at_to` are required date-times in RFC 3339 format with a timezone offset, for example `2026-11-03T00:00:00Z` or `2026-11-03T00:00:00-03:00`. `created_at_from` is inclusive and `created_at_to` is exclusive, so consecutive windows that share a boundary do not overlap. `created_at_to` must be after `created_at_from`, and the window between them is at most 1 day (24 hours). A wider window answers `400 DATE_RANGE_TOO_WIDE`. To cover a longer period, send one request per 24-hour window, for example consecutive UTC days.

## Filters

All filters are optional and combine with AND:

| Parameter | Matches |
| --- | --- |
| `updated_at_from`, `updated_at_to` | Payments last updated inside this range (`updated_at_from` inclusive, `updated_at_to` exclusive) |
| `status` | Any of the statuses sent, comma-separated (`status=SUCCEEDED,DECLINED`) or repeated (`status=SUCCEEDED&status=DECLINED`) |
| `customer_id` | Payments of this customer (UUID) |
| `country` | Payments of this country (ISO 3166-1 alpha-2, for example `US`) |
| `currency` | Payments in this currency (ISO 4217, for example `USD`) |
| `merchant_order_id` | Payments with this merchant order ID |

Send each parameter once, except `status`. A parameter that is not listed on this page, or a filter with an invalid value, answers `400 INVALID_PARAMETERS`.

## Pagination

Rows are ordered by `created_at` ascending and then by `id`. `limit` sets the page size, from 1 to 100, and defaults to 50.

The response is an object with three fields:

| Field | Description |
| --- | --- |
| `payments` | The rows of the page |
| `next_cursor` | Cursor for the next page, or `null` on the last page |
| `has_more` | `true` when another page exists, `false` on the last page |

To read the next page, send `cursor` with the `next_cursor` value unchanged, and the same `X-Account-Code` and filters as the request that returned it. Keep paging until `has_more` is `false`. A modified cursor, or one sent with a different account or different filters, answers `400 INVALID_CURSOR`. Pagination moves forward only.

## Rows

Each row is a summary of the payment: `id`, `account_id`, `merchant_order_id`, `description`, `country`, `status`, `sub_status`, `amount.value`, `amount.currency`, `payment_method.type`, `customer_payer.id`, `created_at` and `updated_at`.

<Info>
  Rows carry no `transactions` array. Retrieve a payment by its `id` to get the full payment object.
</Info>

## Errors

Errors use the `code` and `messages` envelope.

| Status | Code | Cause |
| --- | --- | --- |
| 400 | `INVALID_PARAMETERS` | A required parameter is missing, a parameter is not supported or is sent more than once, or a value is invalid: a date that is not RFC 3339 with a timezone offset, `created_at_to` not after `created_at_from`, an unknown `status`, a `customer_id` or `X-Account-Code` that is not a UUID, or a `limit` outside 1 to 100 |
| 400 | `DATE_RANGE_TOO_WIDE` | The window between `created_at_from` and `created_at_to` is longer than 1 day (24 hours) |
| 400 | `INVALID_CURSOR` | The cursor was modified, or was sent with an account or filters different from the request that returned it |
| 400 | `INVALID_ACCOUNT_ID` | `X-Account-Code` is not an account of your organization |
