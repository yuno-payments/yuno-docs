This request creates a payment after you created a checkout session.

<Danger>
**Important**

Although certain objects are not mandatory when creating a **Payment**, the user’s payment experience can be enhanced if you provide this information.
</Danger>

<Note>
**3DS Payments**

Check the [3D Secure](/docs/security-and-compliance/3d-secure) page to learn how to create payments using 3DS on Yuno.

</Note>

<Note>
**Promotions**

To charge a promotion's price, send the original `amount` and a discount line in `additional_data.order.discounts` with `type: YUNO_PROMOTION` and the `quote_id` of a promotion quote. Yuno charges the discounted price, keeps `amount` as you sent it, and returns `discount_amount`. To redeem a promotion code instead of a quote, send `{ "code": "<code>" }` on the discount line. See [Promotion codes](#promotion-codes) and [Promotions](/docs/payment-features/promotions).
</Note>

To authorize a payment without capturing it immediately (the client is not charged), send `capture: false` inside the payment method detail, under the object that matches the payment method type: `payment_method.detail.card.capture` for cards and `payment_method.detail.wallet.capture` for wallets that support authorization (for example PayPal with a vaulted billing agreement). Yuno only reads the flag under the object that matches the payment method type, so `capture: false` under `card` is ignored on a wallet payment and the payment is captured right away.

If you want to process payments in a Single Step (Authorization and Capture simultaneously), send `capture` as `true` under that same object.

To test all possible transaction outcomes within Yuno in **Sandbox**, refer to the [test data documentation](/docs/direct-integration-use-cases/yuno-testing-gateway#4-provide-the-payment-method-information).

<Danger>
**Metadata and routing logic**

If you use metadata to drive routing logic, it must also be set in the **[Checkout Session](/reference/checkout-sessions/create-checkout-session)**. Filling it only in the Payment object will not activate route logic.
</Danger>

<Warning>
**`vaulted_token` overrides device fingerprint**

If `payment_method.vaulted_token` is provided alongside `payment_method.token`, the `vaulted_token` replaces all payment data, including the device fingerprint (`third_party_session_id`). If you need fraud screening with a device fingerprint, do not send both fields together.
</Warning>

For Two-Step payments (Authorization then Capture), send `capture` as `false` as described above, then use the [Capture Authorization](/reference/payments/capture-authorization) endpoint.

This request requires an `X-Idempotency-Key`. See [Authentication](/reference/authentication#idempotency) for details.


## Promotion codes

<Note>
**Promotions is enabled per organization**

A payment that carries a code works only after Yuno enables Promotions for your organization. Until then it is refused with `422 PROMOTION_NOT_APPLICABLE` and the reason `PROMOTIONS_NOT_ENABLED`, and no payment is created. See [Promotions](/docs/payment-features/promotions#enable-promotions-for-your-organization).
</Note>

To charge the price of a promotion code, put the code on a discount line of `additional_data.order.discounts` instead of a `quote_id`. Send the original `amount`, never the discounted one.

```json Request
{
    "account_id": "00000000-0000-4000-8000-0000000000a1",
    "country": "US",
    "amount": { "currency": "USD", "value": 250.00 },
    "additional_data": {
        "order": {
            "discounts": [{ "code": "SUMMER10" }]
        }
    }
}
```

This is the part of the request that matters here; the rest is the body you already send. Yuno exchanges the code for a quote before it creates the payment, and the payment goes on as a payment with a quote. The answer is the one in [What the payment carries](/docs/payment-features/promotions#what-the-payment-carries). Create the promotion with [Create Promotion](/reference/promotions/create-promotion). [Promotion codes](/docs/payment-features/promotion-codes) describes the whole flow.

The discount line follows these rules. A line that breaks one is refused with `400 INVALID_PARAMETERS` before anything else happens, and no payment is created.

| Rule | Message when broken |
| --- | --- |
| `code` has 3 to 32 characters: letters, digits, `-` and `_`. Yuno trims the spaces around it. | `The field 'additional_data.order.discounts[0].code' must have 3 to 32 characters, letters, digits, hyphens and underscores only.` |
| `code` is not blank. | `The field 'additional_data.order.discounts[0].code' must not be blank.` |
| The line has no `quote_id`. A line carries a code or a quote id, never both. | `The fields 'additional_data.order.discounts[0].code' and 'additional_data.order.discounts[0].quote_id' must not be sent together.` |
| `type` is left out or is `YUNO_PROMOTION`. A line with a `code` and no `type` is read as `YUNO_PROMOTION`. | On a `MERCHANT` line: `The field 'additional_data.order.discounts[0].code' must not be sent on a MERCHANT discount line.` |
| The line has no `id`, `name` or `unit_amount`. Yuno fills them after it applies the promotion. | `The field 'additional_data.order.discounts[0].id' must not be sent on a YUNO_PROMOTION discount line.` (the same for `name` and `unit_amount`) |
| The payment has one promotion line in all: one code, or one quote id. | `Only one YUNO_PROMOTION discount line is permitted per payment.` |

No answer repeats your code. Where the promotions service quotes it back in a message, Yuno replaces it with `***`.

`payment_method.type` is not required for a code. A code applies to the whole payment, whatever the payment method. Yuno sends the type to the promotions service only when your payment has one.

### Idempotency key and uses

* **The `X-Idempotency-Key` is required.** A payment with a code and without that header is refused with `400 INVALID_PARAMETERS`: `The header 'x-idempotency-key' is required to apply a promotion code.` A dry run is the exception.
* **A use is counted when Yuno accepts the code for a payment.** The count happens at the payment attempt, before the payment reaches a provider, and it is keyed by the `X-Idempotency-Key` of the payment.
* **The same key again counts no second use.** A retry of a payment with the same key and the same code is priced from the first use.
* **A key belongs to one code.** The same key with another code is refused with `422 PROMOTION_NOT_APPLICABLE` and the reason `IDEMPOTENCY_KEY_REUSED`.
* **A declined payment keeps its use.** Yuno gives no use back. A new attempt after a decline needs a new `X-Idempotency-Key`, and it counts a new use.

### Dry run

A payment with the header `X-Dry-Run: true` is quoted with the code, and the quote counts no use. Only the value `true`, in any case, makes a dry run. A dry run does not need an `X-Idempotency-Key` for the code. A code with no use left is still refused in a dry run, with `USAGE_LIMIT_REACHED`. A dry run sends no key, so it is not refused with `ZERO_CHARGE`: a code that leaves a charge of zero is refused in a dry run with `ENGINE_UNAVAILABLE`.

### Answers to a payment with a code

When a code does not become a quote, no payment is created and the answer says why.

| HTTP | Code | Reason | When |
| --- | --- | --- | --- |
| `404` | `PROMOTION_NOT_FOUND` | | No promotion of the account holds the code, or the promotion holding it has not started. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `EXPIRED` | The promotion ended. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `DISABLED` | You disabled the promotion. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `USAGE_LIMIT_REACHED` | The code has no use left. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `IDEMPOTENCY_KEY_REUSED` | The payment key already counted a use of another code. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `CONDITIONS_NOT_MET` | The country or the amount does not meet the conditions of the promotion. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `CURRENCY_MISMATCH` | The promotion lists no amount rule for the currency of the payment, or it is a fixed discount with no amount in that currency. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `ZERO_DISCOUNT` | The promotion gives no discount on this amount. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `ZERO_CHARGE` | The code applies and the payment would be charged zero or less. Yuno counts no use. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `PROMOTIONS_NOT_ENABLED` | Promotions is not enabled for your organization. |
| `422` | `PROMOTION_NOT_APPLICABLE` | `ENGINE_UNAVAILABLE` | Promotions is temporarily disabled by Yuno, the promotions service did not answer in time or answered with an error, or the winning promotion would leave a charge of zero in a dry run or when an automatic promotion wins. |

```json Code that leaves a charge of zero (422)
{
    "code": "PROMOTION_NOT_APPLICABLE",
    "messages": ["The promotion leaves a charge of zero on this amount."],
    "reason": "ZERO_CHARGE"
}
```

`ZERO_CHARGE` belongs to a code that wins and to a payment that carries a key. When an automatic promotion wins the selection and its quote would charge zero, the payment is not refused with `ZERO_CHARGE`: Yuno refuses it with `422 PROMOTION_NOT_APPLICABLE` and the reason `ENGINE_UNAVAILABLE`, and no payment is created.

A code is refused for these payments too, and no payment is created:

| Payment | Answer |
| --- | --- |
| A payment that carries a `subscription` | `422 PROMOTION_SUBSCRIPTION_UNSUPPORTED`: `YUNO_PROMOTION discount lines are not supported on subscriptions.` |
| A payment that carries an `external_subscription` or an `external_invoice` | `422 PROMOTION_SUBSCRIPTION_UNSUPPORTED`: `Subscription payments cannot carry a promotion quote.` |
| A payment whose `amount` carries a `currency_conversion` or a `merchant_currency_conversion` | `422 PROMOTION_CONTEXT_MISMATCH`: `The payment context does not match the promotion quote.` |

[Promotion Error Codes](/reference/promotions/promotion-error-codes) lists every answer, with the text of each message.
