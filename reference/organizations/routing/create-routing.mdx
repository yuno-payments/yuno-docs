---
title: "Create a Routing"
description: "Creates a routing for one (account_id, payment_method) pair. Always live on success."
openapi: "/openapi/organizations/routing/create-routing.json POST /routing"
---

Creates a routing for one `(account_id, payment_method)` pair. Each routing references **connections** by their `connection_id`. Make sure your connections are created and `ACTIVE` for the requested `payment_method` *before* you call routing. Outputs that reference a decline, Merchant Advice Code or succeeded group by `group_id` need that group to exist on the account too — see [Outcome groups](/reference/organizations/routing/routing-resource-shape#outcome-groups).

### Body

<ParamField body="account_id" type="string (UUID)" required>
  The merchant account ID this routing rule applies to.
</ParamField>

<ParamField body="payment_method" type="enum" required>
  E.g., `CARD`, `PIX`, `WALLET`. Immutable per routing — to route a different method, create a new routing.
</ParamField>

<ParamField body="name" type="string" required>
  Free-form label.
</ParamField>

<ParamField body="default_route" type="object" required>
  The route used when no `condition_sets[]` matches.
  <Expandable title="properties">
    <ParamField body="start_split" type="object[]">
      Optional. Splits the entry of the route across several steps by percentage, as `[{ "index": 1, "percentage": 45 }, { "index": 2, "percentage": 55 }]`. Percentages are integers that must sum to `100`. Omit to start every payment on step 1. See [Percentage splits](/reference/organizations/routing/routing-resource-shape#percentage-splits).
    </ParamField>
    <ParamField body="steps" type="object[]" required>
      Each step is either one provider attempt or an [action step](/reference/organizations/routing/routing-resource-shape#action-steps). `index` values are contiguous starting at 1.
      <Expandable title="item">
        <ParamField body="index" type="integer" required>
            Step ordinal.
        </ParamField>
        <ParamField body="provider_id" type="string">
            Required on provider steps (a payment, fraud, 3DS or authentication provider) and `SMART_ROUTING` on a smart routing step; omit on an action step. Must match the provider of the connection.
        </ParamField>
        <ParamField body="connection_id" type="UUID">
            Required on provider steps; omit on action and smart routing steps. Must be `ACTIVE` and support the `payment_method`.
        </ParamField>
        <ParamField body="fraud" type="object">
            Configuration of a fraud provider step: `rules`, `blocklists`, `allowlists`, `reviewlists`, `preset` (codes copied from the dashboard, kept as given) and `report_only`. Only on `FRAUD` providers. See [Provider step kinds](/reference/organizations/routing/routing-resource-shape#provider-step-kinds).
        </ParamField>
        <ParamField body="smart_routing" type="object">
            Makes the step a smart routing step: `type` (`COSTS` or `LATENCY`), `providers` (two to four `{ provider_id, connection_id, network_token_on }` payment providers), `no_retry_decline_types` and `no_retry_failure_causes`. Card routings only, one per route. See [Smart routing steps](/reference/organizations/routing/routing-resource-shape#smart-routing-steps).
        </ParamField>
        <ParamField body="action" type="enum">
            Makes the step an action step: `CANCEL` rejects the payment, `CAPTURE` captures the authorization, `HOLD_FOR_REVIEW` leaves it pending manual review, `REVERT` reverts it after a fraud screening that ran after the payment. `CAPTURE` and `HOLD_FOR_REVIEW` are reached only from `APPROVED` or `SUCCEEDED_GROUP` outputs of a payment or smart routing step, `REVERT` only from the outputs of a fraud step that runs after the payment, and `CANCEL` never from an approval. An action step has no `provider_id`, `connection_id` or `output`. See [Action steps](/reference/organizations/routing/routing-resource-shape#action-steps).
        </ParamField>
        <ParamField body="action_delay" type="string">
            Only with `action = CAPTURE`. ISO-8601 duration between the approval and the capture, greater than zero and at most `P7D` (e.g. `PT5M`, `PT3H`, `P2D`). Omit to capture as soon as the approval is processed.
        </ParamField>
        <ParamField body="output" type="object[]">
          Defines how to handle each possible outcome of this step. Not allowed on an action step.
          <Expandable title="item">
            <ParamField body="status" type="string" required>
              The outcome status that triggers this rule: `APPROVED`, `DECLINED`, `DECLINE_GROUP`, `MAC_CODE_GROUP`, `SUCCEEDED_GROUP`, `PENDING` (fraud, 3DS and authentication steps only) or `INTERNAL_ERROR`.
            </ParamField>
            <ParamField body="group_id" type="integer">
              Id of a group of the account, from [List Decline Groups](/reference/organizations/routing/list-decline-groups) or [List Succeeded Groups](/reference/organizations/routing/list-succeeded-groups). Required when `status` is `MAC_CODE_GROUP` or `SUCCEEDED_GROUP`; optional on `DECLINE_GROUP`; not allowed otherwise. The group must be of the kind the status expects.
            </ParamField>
            <ParamField body="decline_types" type="string[]">
              Decline sub-statuses (e.g., `INSUFFICIENT_FUNDS`, `DECLINED_BY_BANK`). On `DECLINE_GROUP`, required unless `group_id` is sent; with `group_id`, it must equal the group's members. Not allowed on `SUCCEEDED_GROUP`.
            </ParamField>
            <ParamField body="retry" type="boolean">
              `true` attempts the same provider once more when this outcome happens, before following `next`. Only on `DECLINED`, `INTERNAL_ERROR` and `DECLINE_GROUP`. Defaults to `false`.
            </ParamField>
            <ParamField body="next" type="integer">
              The `index` of the next step to execute. Omit if no fallback is needed. Optional next to `next_split`; if both are sent it must be the first `next_split` entry.
            </ParamField>
            <ParamField body="next_split" type="object[]">
              Splits the fallback across several steps by percentage, as `[{ "index": 2, "percentage": 70 }, { "index": 3, "percentage": 30 }]`. At least two entries, integer percentages that sum to `100`. `next` is not required with it.
            </ParamField>
          </Expandable>
        </ParamField>
      </Expandable>
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="condition_sets" type="object[]">
  Optional. Ordered by `sort_number` — first matching set wins.
  <Expandable title="item">
    <ParamField body="sort_number" type="integer" required>
        Priority of the condition set.
    </ParamField>
    <ParamField body="name" type="string" required>
        Label for the set.
    </ParamField>
    <ParamField body="conditions" type="object[]" required>
        List of [Conditions](/reference/organizations/routing/routing-conditions) that must match. Besides `condition_type`, `conditional`, `values`, `key` and `currency`, a `TIME_PERIOD` condition carries its schedule fields and a `VOLUME_PAYMENTS_LIMIT` condition its `limit_by`, `payments_count` and period fields.
    </ParamField>
    <ParamField body="route" type="object" required>
        The steps to execute if this set matches. Same shape as `default_route`, including `start_split`, `output[].next_split` and action steps; a route made of a single `CANCEL` step rejects the matching payments.
    </ParamField>
  </Expandable>
</ParamField>

### Response

<ResponseField name="id" type="string">
  Unique identifier for the routing.
</ResponseField>
<ResponseField name="account_id" type="string">
  Unique identifier for the account.
</ResponseField>
<ResponseField name="payment_method" type="enum">
  The payment method this routing applies to (e.g., `CARD`).
</ResponseField>
<ResponseField name="name" type="string">
  Label for the routing.
</ResponseField>
<ResponseField name="default_route" type="object">
  The default routing logic, in the shape described in [Retrieve a Routing](/reference/organizations/routing/retrieve-routing).
</ResponseField>
<ResponseField name="condition_sets" type="object[]">
  Optional conditional logic.
</ResponseField>
<ResponseField name="created_at" type="string">
  ISO 8601 timestamp.
</ResponseField>
<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp.
</ResponseField>

### Errors

<div className="code-nowrap-table dense-table">

| HTTP | `code` |
| --- | --- |
| `400` | `INVALID_PARAMETERS`<br />A field is missing or has an invalid value: a step with neither `provider_id` nor `action`, a `status` or `action` outside their enums, an `action_delay` on a step that is not `CAPTURE`, a malformed `group_id`. `messages` names the offending field. |
| `400` | `INVALID_ROUTE_CONFIGURATION`<br />Route rule violation: non-contiguous step indexes, a `next` or split branch to a missing step, a split that does not sum to 100 or leaves a step unreachable, a `CAPTURE` or `HOLD_FOR_REVIEW` step not reached only from `APPROVED`, an `action_delay` of zero or above 7 days, `retry` on a status that does not support it, a `group_id` that is unknown, of another account or of the wrong kind, `decline_types` that do not match the group, a condition that breaks a rule of its `condition_type`, or a `connection_id` not found for the account and provider. `messages` explains which rule. |
| `400` | `INVALID_VOLUME_LIMIT_CURRENCY`, `INVALID_VOLUME_LIMIT_PERIOD`, `UNSUPPORTED_VOLUME_LIMIT_TIMEZONE`<br />A `VOLUME_PAYMENTS_LIMIT` condition with an invalid currency, period or timezone. See [Volume and count limits](/reference/organizations/routing/routing-conditions#volume-and-count-limits-volume_payments_limit). |
| `400` | `INVALID_PROVIDER_ID`<br />`provider_id` has an invalid format. |
| `409` | `ROUTING_ALREADY_EXISTS`<br />A routing already exists for this `(account, payment_method)`. Use `PATCH` to update it. |
| `401` | `NOT_AUTHENTICATED`<br />Missing `public-api-key` or `private-secret-key` header. |
| `401` | `INVALID_CREDENTIALS`<br />Wrong key pair, or a Dashboard **Customized API key** was used. Use an account key or organization key instead. |
