---
title: "Create a Routing"
description: "Creates a routing for one (account_id, payment_method) pair. Always live on success."
openapi: "/openapi/organizations/routing/create-routing.json POST /routing"
---

Creates a routing for one `(account_id, payment_method)` pair. Each routing references **connections** by their `connection_id`. Make sure your connections are created and `ACTIVE` for the requested `payment_method` *before* you call routing.

### Body

<ParamField body="account_id" type="string (UUID)" required>
  The merchant account ID this routing rule applies to.
</ParamField>

<ParamField body="payment_method" type="enum" required>
  E.g., `CARD`, `PIX`, `WALLET`. Immutable per routing — to route a different method, create a new routing.
</ParamField>

<ParamField body="name" type="string" required>
  Free-form label.
</ParamField>

<ParamField body="default_route" type="object" required>
  The route used when no `condition_sets[]` matches.
  <Expandable title="properties">
    <ParamField body="steps" type="object[]" required>
      Each step is either one provider attempt or a [Cancel step](/reference/organizations/routing/routing-resource-shape#cancel-steps). `index` values are contiguous starting at 1.
      <Expandable title="item">
        <ParamField body="index" type="integer" required>
            Step ordinal.
        </ParamField>
        <ParamField body="provider_id" type="string">
            Required on provider steps; omit on a Cancel step. Must match the provider of the connection.
        </ParamField>
        <ParamField body="connection_id" type="UUID">
            Required on provider steps; omit on a Cancel step. Must be `ACTIVE` and support the `payment_method`.
        </ParamField>
        <ParamField body="action" type="enum">
            `CANCEL` rejects the payment without sending it to any provider. A Cancel step must be the only step of its route and has no `provider_id`, `connection_id` or `output`.
        </ParamField>
        <ParamField body="output" type="object[]">
          Defines how to handle each possible outcome of this step. Not allowed on a Cancel step.
          <Expandable title="item">
            <ParamField body="status" type="string" required>
              The outcome status that triggers this rule: `APPROVED`, `DECLINED`, `DECLINE_GROUP` or `INTERNAL_ERROR`.
            </ParamField>
            <ParamField body="decline_types" type="string[]">
              Required when `status` is `DECLINE_GROUP`. Specifies which decline subtypes trigger this rule (e.g., `INSUFFICIENT_FUNDS`, `DECLINED_BY_BANK`).
            </ParamField>
            <ParamField body="next" type="integer">
              The `index` of the next step to execute. Omit if no fallback is needed.
            </ParamField>
          </Expandable>
        </ParamField>
      </Expandable>
    </ParamField>
  </Expandable>
</ParamField>

<ParamField body="condition_sets" type="object[]">
  Optional. Ordered by `sort_number` — first matching set wins.
  <Expandable title="item">
    <ParamField body="sort_number" type="integer" required>
        Priority of the condition set.
    </ParamField>
    <ParamField body="name" type="string">
        Label for the set.
    </ParamField>
    <ParamField body="conditions" type="object[]" required>
        List of [Conditions](/reference/organizations/routing/routing-conditions) that must match.
    </ParamField>
    <ParamField body="route" type="object" required>
        The steps to execute if this set matches. Same shape as `default_route`; a route made of a single Cancel step rejects the matching payments.
    </ParamField>
  </Expandable>
</ParamField>

### Response

<ResponseField name="id" type="string">
  Unique identifier for the routing.
</ResponseField>
<ResponseField name="account_id" type="string">
  Unique identifier for the account.
</ResponseField>
<ResponseField name="payment_method" type="enum">
  The payment method this routing applies to (e.g., `CARD`).
</ResponseField>
<ResponseField name="name" type="string">
  Label for the routing.
</ResponseField>
<ResponseField name="default_route" type="object">
  The default routing logic.
</ResponseField>
<ResponseField name="condition_sets" type="object[]">
  Optional conditional logic.
</ResponseField>
<ResponseField name="created_at" type="string">
  ISO 8601 timestamp.
</ResponseField>
<ResponseField name="updated_at" type="string">
  ISO 8601 timestamp.
</ResponseField>

### Errors

<div className="code-nowrap-table dense-table">

| HTTP | `code` |
| --- | --- |
| `400` | `INVALID_PARAMETERS`<br />A field is missing or has an invalid value, for example a step with neither `provider_id` nor `action`, or an `action` other than `CANCEL`. `messages` names the offending field. |
| `400` | `INVALID_ROUTE_CONFIGURATION`<br />The routing breaks a route rule: step indexes not contiguous from 1, an `output[].next` that doesn't point to a later step, a Cancel step that isn't the only step of its route or that has `provider_id`, `connection_id` or `output`, an unknown `condition_type` or `conditional`, or a `connection_id` not found for the account and provider. `messages` explains which rule. |
| `400` | `INVALID_PROVIDER_ID`<br />`provider_id` has an invalid format (letters, digits, `_` and `-`, up to 64 characters). |
| `409` | `ROUTING_ALREADY_EXISTS`<br />A routing already exists for this `(account, payment_method)`. Use `PATCH` to update it. |
| `403` | `INSUFFICIENT_SCOPE`<br />API key missing `routing:write`. |

</div>
