<Note>
**Enabled per organization**

Usage-based billing must be enabled for your organization before these endpoints accept requests. Contact your Yuno account manager to enable it. Requests from an organization where it is not enabled return `403 PRODUCT_NOT_ENABLED`.
</Note>

Lookup failures referenced by a path parameter (`meter_id`, `plan_id`, or a plan/meter relation) return HTTP `404` with a specific `code`. Lookup failures referenced only inside the request body (e.g. an unknown `meter_id` in Attach Meter to Plan, or an unknown meter/subscription in Report Usage Event) return HTTP `400` instead. Every error follows the standard shape used across the Subscriptions API:

```json
{
  "code": "INVALID_PARAMETERS",
  "messages": ["The field 'account_id' is required."]
}
```

For general HTTP status semantics see [HTTP Response Codes](/reference/getting-started/response-codes).

## Codes

| HTTP | `code` | Returned by | When |
| --- | --- | --- | --- |
| 403 | `PRODUCT_NOT_ENABLED` | All endpoints | Usage-based billing is not enabled for your organization. Contact your Yuno account manager. |
| 400 | `INVALID_PARAMETERS` | All endpoints | A field failed validation. `messages` carries one human-readable reason per failure — see the list below. |
| 404 | `METER_NOT_FOUND` | Create Plan (`meters[]`) | The `meter_id` does not exist or is not linked to your account, or the meter is `INACTIVE` (archived meters cannot be attached). Retrieve Meter and Update Meter do **not** 404 on an `INACTIVE` meter — they return it normally (`200`), same as any other status. |
| 400 | `METER_NOT_FOUND` | Attach Meter to Plan, Update Plan Meters, Report Usage Event | The `meter_id` does not exist or is not linked to your account, or the meter is `INACTIVE` (archived meters cannot be attached and reject usage events) — on usage events, no `ACTIVE` meter with that `event_name` exists. |
| 404 | `PLAN_NOT_FOUND` | Attach Meter to Plan, List Plan Meters, Update Plan Meter | The `plan_id` does not exist or is not linked to your account. |
| 404 | `PLAN_METER_NOT_FOUND` | Update Plan Meter | The meter is not attached to this plan, or the meter is `INACTIVE` (its metered prices are frozen until it is reactivated). |
| 400 | `SUBSCRIPTION_NOT_FOUND` | Report Usage Event | The `subscription_id` does not exist in your account. |
| 400 | `SUBSCRIPTION_NOT_ACTIVE` | Report Usage Event | **Not currently enforced on staging** — confirmed 2026-09-02/03: a usage event sent to a `PAUSED` or `CANCELED` subscription (status checked with `GET` immediately beforehand) is accepted (`201`) and recorded, not rejected. Documented behavior, pending confirmation from the API owner, would be: the subscription is `PAUSED`, `CANCELED` or `COMPLETED` (only `ACTIVE`, `TRIALING` and `PAST_DUE` accept usage) → event rejected, nothing counted, message "The subscription is not active." |
| 409 | `METER_EVENT_NAME_CONFLICT` | Create Meter | A meter with the same `event_name` already exists in the account — active or archived. Choose another name (uniqueness is status-blind, so archiving does not free the name). Message: "An active meter with this event_name already exists for this account." |
| 409 | `PLAN_METER_ALREADY_ASSIGNED` | Attach Meter to Plan, `PATCH /subscriptions/plans/{plan_id}` | The meter is already attached to the plan — including when the same `meter_id` appears twice in one `meters[]` list on `PATCH /subscriptions/plans/{plan_id}`. Use Update Plan Meter to change it. Create Plan's own `meters[]` returns a different error for an in-list duplicate — see `400 BAD_REQUEST` "Duplicated meters meter_id" below. |
| 400 | `PLAN_METER_PRICING_CONFIG_UNSUPPORTED` | Attach Meter to Plan, Create Plan (`meters[]`), Update Plan Meter | `package_size`/`package_price`/`package_country_prices`/`tiers` sent for a metered price whose `pricing_strategy` isn't the matching one, or sent to Update Plan Meter at all (that config is attach-time only). Message: "Package and tier pricing configuration is not supported for this meter's pricing strategy." |
| 400 | `PLAN_METER_MISSING_CURRENCY` | Attach Meter to Plan, Create Plan (`meters[]`), Update Plan Meter | A `PACKAGE`/`TIERED` metered price doesn't price every currency the plan supports — `messages` lists the missing ones. Message: "The meter must be priced in every currency the plan supports. Missing: %s." |
| 400 | `PLAN_METER_BASE_CURRENCY_MISMATCH` | Attach Meter to Plan, Create Plan (`meters[]`), Update Plan Meter | A `PACKAGE`/`TIERED` metered price's base price currency doesn't match the plan's base currency. Message: "The meter base price currency must match the plan base currency." |

## Validation and business-rule messages

Most of these are `400 INVALID_PARAMETERS`, but several field-level and cross-field business rules return `400 BAD_REQUEST` instead — check the `Code` column, don't assume from context.

| Code | Message | Endpoint | Fix |
| --- | --- | --- | --- |
| INVALID_PARAMETERS | The field 'event_name' has an invalid value, it must contain only lowercase letters, numbers, underscores and dots. | Create Meter | Use lowercase letters, digits, `_` and `.` only (MAX 100). |
| INVALID_PARAMETERS | The field 'account_id' is required. | Create Meter | Send the `account_id` of the account the meter belongs to. |
| BAD_REQUEST | The default_price currency must be USD. | Create / Update Meter | Only `USD` is accepted for `default_price`. Price non-USD plans explicitly with `price_per_credit`. |
| BAD_REQUEST | Duplicated meters meter_id '&lt;meter_id&gt;'. | Create Plan | The same `meter_id` appears twice in `meters[]` — unlike Attach Meter to Plan and `PATCH /subscriptions/plans/{plan_id}`, Create Plan returns `400 BAD_REQUEST` for this, not `409 PLAN_METER_ALREADY_ASSIGNED`, since the plan doesn't exist yet to be "already assigned" to. |
| BAD_REQUEST | The price_per_credit currency must match the plan base currency. | Attach Meter to Plan, Update Plan Meter, Create Plan | Send `price_per_credit` in the plan's `base_amount` currency. |
| BAD_REQUEST | A price_per_credit is required when the plan base currency is not USD. | Attach Meter to Plan | Inheritance from `default_price` only works for USD plans — send the price. |
| BAD_REQUEST | A price_per_credit is required for meter `<meter_id>` when the plan base currency is not USD. | Create Plan (`meters[]`) | Same rule as Attach Meter to Plan; Create Plan's message additionally names the offending `meter_id` since `meters[]` can hold several. |
| BAD_REQUEST | A price_per_credit is required when the meter has no default_price. | Attach Meter to Plan, Create Plan | Send the price, or set a `default_price` on the meter first. |
| INVALID_PARAMETERS | The field 'credits' must be greater than or equal to the minimum allowed value. | Attach Meter to Plan, Update Plan Meter | `credits` cannot be negative. Use `0` to bill every unit. |
| INVALID_PARAMETERS | The field 'meters[0].credits' must be greater than or equal to the minimum allowed value. | Create Plan | Same rule; Create Plan's `meters[]` array indexes the field name. |
| INVALID_PARAMETERS | The field 'pricing_strategy' has an invalid value. | Attach Meter to Plan, Update Plan Meter | Send one of the three supported strategies: `PER_UNIT`, `PACKAGE`, `TIERED`. |
| INVALID_PARAMETERS | The field 'meters[0].pricing_strategy' has an invalid value. | Create Plan | Same rule; Create Plan's `meters[]` array indexes the field name. |
| BAD_REQUEST | Duplicated country_prices for `<COUNTRY>`. | Attach Meter to Plan, Update Plan Meter, Create Plan | One entry per country; the message names the duplicated country. |
| INVALID_PARAMETERS | The field 'event_id' is required. | Report Usage Event | Always send your idempotency key. |
| BAD_REQUEST | The value is required for a SUM meter. / The value is required for a LAST meter. | Report Usage Event | `value` is mandatory for `SUM` and `LAST` meters (the message names the meter's aggregation); only `COUNT` defaults to 1. |
| INVALID_PARAMETERS | The field 'occurred_at' has an invalid value, it must not be more than 35 days in the past. | Report Usage Event | Report closer to real time, or drop events older than the 35-day window. |
| BAD_REQUEST | The meter_id does not match the meter resolved for event_name `<event_name>`. | Report Usage Event | Either omit `meter_id` or make sure it belongs to the meter whose `event_name` you send. |
| BAD_REQUEST | At least one field must be provided to update the meter. | Update Meter | Send at least one updatable field in the PATCH body. |
| BAD_REQUEST | At least one field must be provided. | Update Plan Meter | Send at least one of `credits`, `pricing_strategy`, `price_per_credit`, `country_prices`. |
| INVALID_PARAMETERS | A package_size is required for PACKAGE pricing. / The package_size must be greater than 0. | Attach Meter to Plan, Create Plan | `package_size` is required and must be positive for `pricing_strategy: PACKAGE`. |
| INVALID_PARAMETERS | A package_price is required for PACKAGE pricing. | Attach Meter to Plan, Create Plan | Send `package_price` for `pricing_strategy: PACKAGE`. |
| — | ~~A TIERED meter must define at least one tier~~ | Attach Meter to Plan, Create Plan | **Not currently enforced on staging** — confirmed 2026-09-02/03: `pricing_strategy: TIERED` with `tiers` omitted, or `tiers: []`, is accepted (`201`) with `tiers: []` stored on both endpoints. Pending confirmation from the API owner; do not rely on this validation firing. |
| INVALID_PARAMETERS | The last tier up_to must be null (unbounded). / Only the last tier may have a null up_to. | Attach Meter to Plan, Create Plan | Exactly the last entry in `tiers[]` has `up_to: null`; every other tier needs a bound. |
| INVALID_PARAMETERS | Each tier up_to must be greater than 0. / Tier up_to bounds must strictly ascend. | Attach Meter to Plan, Create Plan | Each non-last tier's `up_to` must be positive and strictly greater than the previous tier's. |
| INVALID_PARAMETERS | Each tier must define a rate. | Attach Meter to Plan, Create Plan | Every entry in `tiers[]` needs a `rate`. |
| INVALID_PARAMETERS | Every tier must be priced in the same set of currencies. | Attach Meter to Plan, Create Plan | Use the same currency (and the same `country_rates` countries, if any) across every tier in `tiers[]`. |
| INVALID_PARAMETERS | The field 'limit' must be an integer between 1 and 100 | List Meters | `limit` accepts 1-100, defaults to 20. |
| INVALID_PARAMETERS | The field 'offset' must be a multiple of 'limit' | List Meters | `offset` must be a non-negative multiple of the effective limit. |
| INVALID_PARAMETERS | The field 'offset' must be a non-negative integer | List Meters | `offset` cannot be negative — checked before the multiple-of-`limit` rule above. |

<Note>
Treat both the code list and the message texts as open-ended: new codes and messages can be added. Match on `code` for control flow and log `messages` for diagnostics.
</Note>
