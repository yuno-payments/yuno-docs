---
title: "Retrieve Recipient by Merchant Recipient ID"
openapi: "/openapi/recipients-for-marketplace/retrieve-recipient-by-merchant-recipient-id.json GET /recipients"
description: "Retrieves a single recipient using the merchant_recipient_id your system assigned when the recipient was created."
---

This request enables you to retrieve a recipient based on its `merchant_recipient_id`, which needs to be provided as a query parameter. The response is a single [recipient object](/reference/recipients-for-marketplace/the-recipient-object), the same one returned by [Get Recipient](/reference/recipients-for-marketplace/get-recipient) — not a paginated list.

- `merchant_recipient_id` is an optional query parameter on this path, and sending it selects this operation. Omit it and the request is served by [List Recipients](/reference/recipients-for-marketplace/list-recipients) instead. Sending it with an empty value returns `400` with `INVALID_PARAMETERS`.
- The lookup covers every account in your organization.
- If no recipient in your organization has that `merchant_recipient_id`, or the recipient was deleted, the request returns `400` with `RECIPIENT_NOT_FOUND`.

<Info>
  This is the read-after-write path. A recipient can be retrieved here as soon as [Create Recipient](/reference/recipients-for-marketplace/create-recipient-1) returns, because the lookup reads the primary store. [List Recipients](/reference/recipients-for-marketplace/list-recipients) is eventually consistent and may not include a recipient you just created.
</Info>

<Note>
  To browse or filter recipients, use [List Recipients](/reference/recipients-for-marketplace/list-recipients). That endpoint shares this path and is selected when `merchant_recipient_id` is omitted; it accepts `limit`, `offset`, `country` and `national_entity`, and returns a paginated envelope instead of a single object.
</Note>
