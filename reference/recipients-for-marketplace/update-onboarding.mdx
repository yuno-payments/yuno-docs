Updates an existing onboarding for a recipient. Only specified fields will be updated.

This endpoint updates an existing onboarding for a recipient, allowing you to modify onboarding details after initial creation. Use this when you need to update provider information, documentation, banking details, or other onboarding parameters for existing recipients in the [split payments marketplace](/docs/split-payments-marketplace#/).

## Prerequisites

This endpoint requires an existing onboarding created via [Create Onboarding](/reference/create-onboarding)

## Updating a bank account

For Zoop and Pagar.me onboardings with a provider recipient ID, an explicit `withdrawal_methods.bank` update waits for the provider result. It updates only the selected onboarding; the recipient default and other onboardings remain unchanged.

Only a confirmed account is saved for the onboarding. Bank-update results do not change its lifecycle status. Send a complete account when the onboarding shows no bank account. See [bank errors and retries](/reference/recipients-for-marketplace/update-recipient-1#bank-errors-and-retries) for partial outcomes, `400` responses and `409` reconciliation guidance.

For these supported provider-bound onboardings, non-bank fields on this endpoint are saved in Yuno without a separate provider profile update. Sending a description or metadata does not resend the saved bank account. In a mixed request, the bank is processed first; other fields are saved only after it succeeds. Previously onboarded recipients retain the existing status notification for non-bank updates.

For example, changing only a store's description leaves its confirmed payout account and onboarding status unchanged. To change the payout account, include `withdrawal_methods.bank` explicitly.
