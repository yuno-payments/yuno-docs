---
title: "Set External Subscription Payment Method"
openapi: "/openapi/subscriptions/change-external-subscription-payment-method.json POST /external-subscriptions/{external_subscription_id}/payment-method"
description: "Links a Stripe Billing subscription to a card the customer already verified in Yuno, or moves a linked subscription to another enrolled payment method, without a payment."
---

Use this endpoint with [Stripe Billing subscriptions](/docs/payment-features/subscriptions/stripe-billing) in two cases:

- **The subscription is not linked to Yuno yet.** For example, a subscription created in Stripe before you integrated Yuno, whose customer already enrolled and verified a card in Yuno. Yuno links the subscription to that card, and Yuno charges the next renewals.
- **The subscription is already linked.** Yuno moves it to another vaulted payment method of the same customer.

<Note>
**No payment is made**

Yuno does not charge the customer and does not run a $0 verification or 3DS. Yuno sets the payment method as the subscription's default in Stripe, and the next renewals charge it.
</Note>

## Request

| Field | Description |
|---|---|
| `external_subscription_id` (path) | The Stripe subscription ID (`sub_...`), between 3 and 255 characters. |
| `account_id` | The Yuno account onboarded to the billing bridge (UUID). |
| `customer_payer.id` | The **Yuno customer ID** (UUID) that owns the subscription. It is not the Stripe customer ID (`cus_...`). |
| `vaulted_token` | The vaulted token (UUID) of one of that customer's enrolled payment methods. |
| `external_customer_id` | The **Stripe customer ID** (`cus_...`) of the subscription, between 3 and 255 characters. Required to link a subscription that is not linked yet. Optional to move a linked one: when you send it, Yuno checks that it is the subscription's Stripe customer. An empty value counts as not sent. |

The `X-Idempotency-Key` header is required. Replaying the same key with the same request returns the first result.

The response returns the request fields. When the request sends `external_customer_id`, it also returns `external_customer_id` and `result`:

| `result` | Meaning |
|---|---|
| `LINKED` | The subscription was not linked to Yuno. Yuno linked it to the payment method. |
| `PAYMENT_METHOD_CHANGED` | The subscription was linked. Yuno moved it to the payment method. |
| `NO_CHANGE` | The subscription already charges the payment method. Nothing changed. |

To link a subscription that is not linked yet:

- The request must send `external_customer_id`. Without it, a subscription that is not linked returns `EXTERNAL_SUBSCRIPTION_NOT_FOUND`.
- The Stripe subscription must be `active` or `trialing` and charged automatically (`collection_method: charge_automatically`), and its customer must be `external_customer_id`.
- The card must have been verified in Yuno before, for example with a $0 verification when it was enrolled. Yuno uses that verification to charge the renewals as merchant-initiated.

This API is enabled per account. Contact your Key Account Manager to request access.

## Errors

| Status | Code | Meaning | What to do |
|---|---|---|---|
| `400` | `INVALID_PARAMETERS` | A field or the `X-Idempotency-Key` header is missing or malformed, or the key was already used for another subscription or payment method. | Fix the request. Use a new key for a different change. |
| `400` | `CUSTOMER_NOT_FOUND` | The customer does not exist in the account. | Check that `customer_payer.id` is the Yuno customer ID, not the Stripe `cus_` ID. |
| `400` | `VAULTED_TOKEN_NOT_FOUND` | The `vaulted_token` is not one of the customer's payment methods. | Use a token from the customer's [enrolled payment methods](/reference/payment-methods-direct-workflow/retrieve-enrolled-payment-methods-api). |
| `400` | `VAULTED_TOKEN_NOT_ENROLLED` | The payment method is not enrolled. Only when the request sends `external_customer_id`. | Use a payment method with status `ENROLLED`. |
| `400` | `VAULTED_TOKEN_WITHOUT_COUNTRY` | The payment method has no country, and linking a subscription needs it. | Use another payment method of the customer, or enroll the card again. |
| `400` | `VAULTED_TOKEN_WITHOUT_NETWORK_TRANSACTION_ID` | The card was never verified, so Yuno cannot charge the renewals as merchant-initiated. | Verify the card first: run a $0 verification with the `external_subscription` object, as for a [free trial](/docs/payment-features/subscriptions/stripe-billing#free-trials). |
| `400` | `EXTERNAL_SUBSCRIPTION_NOT_FOUND` | Stripe has no subscription with this ID for the account, or the request did not send `external_customer_id` and the subscription is not linked to Yuno. | Check the Stripe subscription ID and the account. To link the subscription, send `external_customer_id`. |
| `400` | `EXTERNAL_SUBSCRIPTION_NOT_ACTIVE` | The Stripe subscription is neither `active` nor `trialing`. | Only active or trialing subscriptions can be linked. |
| `400` | `EXTERNAL_SUBSCRIPTION_NOT_CHARGED_AUTOMATICALLY` | The Stripe subscription sends invoices instead of charging automatically. | Set `collection_method` to `charge_automatically` in Stripe. |
| `400` | `CUSTOMER_MISMATCH` | The subscription belongs to another customer, or `external_customer_id` is not the subscription's Stripe customer. | Send the customers that own the subscription. |
| `403` | `PRODUCT_NOT_ENABLED` | The account is not enabled for the billing bridge. | Contact your Key Account Manager. |
| `409` | `CONCURRENT_CHANGE` | Another payment method change for this subscription completed first. | Check the subscription in Stripe before sending another change. |
| `409` | `EXTERNAL_SUBSCRIPTION_PENDING_ACTIVATION` | The subscription is being migrated to Yuno. Only when the request sends `external_customer_id`; without it, the answer is `EXTERNAL_SUBSCRIPTION_NOT_FOUND`. | Retry once the migration finishes. |
| `502` | `BILLING_PLATFORM_ERROR` | The billing platform could not confirm the change. The previous payment method stays, or the subscription stays unlinked. | Retry with a new `X-Idempotency-Key`. |
