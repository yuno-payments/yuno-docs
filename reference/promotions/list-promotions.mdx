title: "List Promotions"
openapi: "/openapi/promotions/list-promotions.json GET /promotions"
description: "Returns the promotions of one account, newest first, one page at a time, with an optional status filter."
noindex: true
---

<Warning>
**Promotions is enabled per organization**

This endpoint works only after Yuno enables Promotions for your organization. Until then it answers `404 PROMOTION_NOT_FOUND`. Ask your Technical Account Manager or Key Account Manager. See [Promotions](/docs/payment-features/promotions#enable-promotions-for-your-organization).
</Warning>

The list belongs to the account in the `X-Account-Code` header. To see the promotions of several accounts, call once per account.

The list holds every promotion of the account: the `CODE` promotions you create with the API and the `AUTOMATIC` ones. Check `redemption.mode` to tell them apart.

## Pages

Results come newest first, by `created_at`. A page holds up to `limit` promotions: 20 by default, 1 to 100 allowed. When more promotions exist, `next_cursor` is a string: pass it as `cursor` to read the next page. On the last page `next_cursor` is `null`. The cursor is opaque. A cursor that Yuno did not issue answers `400 INVALID_REQUEST` with the message `cursor: FORMAT`.

Use `status` to keep one status: `SCHEDULED`, `ACTIVE`, `EXPIRED` or `DISABLED`. It accepts any case of the ASCII letters. Any other value, including one with a non-ASCII look-alike letter, answers `400 INVALID_REQUEST` with `status: UNKNOWN`. Any other query parameter is ignored.
