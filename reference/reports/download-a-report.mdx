---
title: "Download a Report"
openapi: "/openapi/reports/download-a-report.json GET /reports/{report_id}/download
"
description: "Retrieves the download link for a generated report using its report ID."
---

<Warning>
**This endpoint lives under `/v2`**

Report download is served at `GET /v2/reports/{report_id}/download`. The `/v1` download path has been retired and always answers `404 NOT_FOUND`, whatever report ID you send. The other Reports endpoints ([Create a Report](/reference/reports/create-a-report), [Retrieve a Report](/reference/reports/retrieve-a-report) and [List All Reports](/reference/reports/list-all-reports)) stay under `/v1`, so a complete flow mixes both prefixes:

```text
POST https://api.y.uno/v1/reports
GET  https://api.y.uno/v1/reports/{report_id}
GET  https://api.y.uno/v2/reports/{report_id}/download
```
</Warning>

Call this endpoint with your `public-api-key` and `private-secret-key` once the report status is `SUCCEEDED` (check it with [Retrieve a Report](/reference/reports/retrieve-a-report)). You do not need to send an `X-Organization-Code` header: Yuno identifies your organization from the keys.

<Note>
**Downloading the file**

The response is a JSON object with a `download_link`. Download the report file from that link (from your browser or with a plain HTTP GET, no Yuno headers needed). Most report types are delivered as a .zip file containing a .csv; settlement reports are delivered as a .csv. The link is valid for 7 days after the report is generated. The first successful call moves the report status from `SUCCEEDED` to `DOWNLOADED`; you can call the endpoint again while the link is valid.
</Note>
