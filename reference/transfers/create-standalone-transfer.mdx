---
title: "Create Standalone Transfer"
openapi: "/openapi/transfers/create-standalone-transfer.json POST /split-marketplace/transfers"
description: "Creates a standalone transfer with an immutable direction"
---

Create a transfer independently of a payment. The `direction` field determines which account sends the funds.

<Warning>
Recipient-to-platform transfers are not generally available. Use this direction only after Yuno confirms account enablement and provider support.
</Warning>

| Direction | Movement |
| --- | --- |
| `PLATFORM_TO_RECIPIENT` | Platform balance to the recipient. This is the default when `direction` is omitted or `null`. |
| `RECIPIENT_TO_PLATFORM` | Recipient balance to the platform, for example a separate dispute fee. Requires an enabled account and `STRIPE` provider support. The recipient onboarding connection identifies the provider account. |

Direction is saved at creation and returned in the response, [GET](/reference/transfers/get-standalone-transfer), and transfer notifications. It cannot be changed after creation. Reusing the same account and idempotency key with a different direction is rejected; omitted and explicit `PLATFORM_TO_RECIPIENT` represent the same direction.

Invalid strings (including empty or incorrectly cased values), objects, arrays, numbers, and booleans return `400 INVALID_PARAMETERS`. A recipient-to-platform request with a provider other than `STRIPE` returns `400 INVALID_PARAMETERS` before the enablement check. A valid recipient-to-platform request for an account without access returns `400 DIRECTION_NOT_ENABLED`, before the idempotency direction check.

A recipient-to-platform transfer cannot be [reversed](/reference/transfers/reverse-standalone-transfer). To return a separately collected fee, create a new platform-to-recipient transfer.
