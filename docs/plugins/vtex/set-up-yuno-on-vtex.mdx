---
title: "Set up Yuno on VTEX"
description: "Start accepting payments with Yuno on your VTEX store by following this end-to-end configuration guide."
---

This page walks you through every step needed to start accepting payments with Yuno on your VTEX store. The setup happens in two places. Your **VTEX dashboard** is where you register Yuno as a payment provider, install the Payment App, and activate payment methods. Your **Yuno dashboard** is where you configure the webhook that keeps order status in sync.

### Before you start

Have the following ready:
*   A user with administrator access to your VTEX dashboard.
*   Your Yuno credentials, which you can find in your Yuno dashboard under **Developers → API Credentials**: **Account ID**, **Public API Key**, and **Private Secret Key**.

---

<Steps>
  <Step title="Configure Yuno as a payment provider">
    1.  In the **VTEX dashboard**, open the left-hand menu and go to **Store Settings → Payment → Providers**, then click **New Provider** at the top right.

    <Frame>
      <img src="/images/plugins/vtex/image-065c1400.png" alt="New Provider in VTEX" />
    </Frame>

    2.  In the **Select a provider** dialog, type `Yuno` in the search box and select **Yuno** from the results.

    <Frame>
      <img src="/images/plugins/vtex/image-d4b7cb65.png" alt="Search for Yuno provider" />
    </Frame>

    3.  Fill in the provider configuration form and save. Once saved, the provider is registered, but no payment methods are active yet.

    <Accordion title="Field reference">
      | Field | Required | What it does |
      | :--- | :--- | :--- |
      | **Application Key / Application Token** | Yes | VTEX admin credentials the plugin uses to interact with VTEX on your behalf. See VTEX's guide on [generating Application Keys](https://help.vtex.com/docs/tutorials/api-keys#generating-internal-application-keys). |
      | **Automatic Settlement** | Yes | Defines when the payment is captured automatically after authorization. Applies to card and wallet payments only. |
      | **Affiliation Name** | Yes | A human-readable name for this Yuno integration. |
      | **Account ID** | Yes | Your Yuno **Account ID**, available in your Yuno dashboard. |
      | **Public API Key** | Yes | Your Yuno **Public API Key**. The prefix determines the environment. |
      | **Private Secret Key** | Yes | Your Yuno **Private Secret Key**. |
      | **Main Account Name** | Optional | For multi-account setups. |
      | **Main Account App key** | Optional | Application Key of the main VTEX account. |
      | **Main Account App token** | Optional | Application Token of the main VTEX account. |
      | **Soft Descriptor** | Optional | Custom text that appears on the shopper's card statement. Example: `MYSTORE*ORDER`. |
      | **Create Customer** | Optional | When set to **Yes**, the plugin creates a corresponding customer record in Yuno. |
      | **VTEX IO orderPlaced page URL** | Optional | A custom URL where shoppers should be redirected after payment. Example: `https://www.example.com/checkout/orderPlaced`. |
      | **Payment Mode** | Optional | **Payment App** (modern) or **Legacy** (redirect). |
      | **Transaction Identification From** | Optional | **Yuno TID** or **Provider TID**. |
      | **Antifraud Providers for Split Orders** | Optional | Comma-separated antifraud providers (`RISKIFIED`, `CYBERSOURCE`, `SIGNIFYD`, `CIELO_CYBERSOURCE_FRAUD`) that receive the shared session for split orders. On plugin **4.2.362 or later**, all four providers receive it when left empty; on earlier versions, it defaults to `RISKIFIED` + `CYBERSOURCE`. If you fill it in, only the providers you list receive it. Example: `RISKIFIED,CYBERSOURCE`. |
      | **Vault Card for Order Modification** | Optional | When set to **Yes** (and **Create Customer** is also **Yes**), the plugin securely stores the card used on each order and allows the additional amount to be charged automatically if the order total later increases. This is the only field that authorizes additional charges: when it is **No**, an order-total increase is declined even if the card was stored for network tokens. See [Order modifications](/docs/plugins/vtex/advanced-features#order-modifications-changed-order-totals). |
      | **Enable Network Tokens** | Optional | When set to **Yes** (and **Create Customer** is also **Yes**), the plugin securely stores each card on its first purchase and recognizes it on later purchases by the same customer, so Yuno can process repeat purchases with a network token instead of the card number. **The toggle has no effect until Yuno activates network tokens on the routes your store uses**: until then cards are stored but no tokens are issued. Contact your Yuno KAM or support to activate it. See [Network tokens](/docs/plugins/vtex/advanced-features#network-tokens-repeat-card-purchases). |
      | **Use Corporate Buyer Data** | Optional | Brazil only. When set to **Yes**, orders placed by a shopper checking out as a company (*pessoa jurídica*) are paid under the company's legal name and **CNPJ** instead of the shopper's personal name and CPF, on every payment method. Default **No**. See [Corporate purchases](/docs/plugins/vtex/advanced-features#corporate-purchases-brazil). |
      | **Headless Payment Handoff** | Optional | Advanced setup for marketplaces that run their own headless checkout and create the Yuno payment themselves, for a cart that mixes the store's own items and VTEX marketplace sellers. Enable it only with guidance from the Yuno team. When set to **Yes**, the plugin creates nothing in Yuno: each authorization hands you a ready-to-send, authorization-only Yuno payment request for the VTEX part of the cart. You add the card token and the marketplace split, and create one payment that covers every seller order of the cart. The plugin then reports each order's status from that payment and captures or refunds each order's share separately. Cards and PIX only: any other payment method is declined. Available on plugin **4.2.356 or later** for cards and **4.2.361 or later** for PIX. Default **No**. Example: `Yes` on the store that runs the headless checkout; every other store keeps `No`. |
      | **Store Base Path** | Optional | For stores served under a URL path prefix, such as a storefront at `https://www.example.com/br` instead of the domain root. It is the path the Payment App uses when it calls your store's payment routes during checkout. Use plain path segments only (letters, numbers, `-` and `_`), for example `/br` or `/br/store`: no scheme, host, query string or dots. A value that looks like a hostname is ignored, and the store behaves as if the field were empty. A leading slash is added if missing. Leave it empty when the store is served from the domain root. Available on plugin **4.2.316 or later**. Example: `/br`. |
      | **Send Order Sequence as Merchant Reference** | Optional | When set to **Yes**, every payment sends the VTEX order sequence (the number shown in the VTEX order list, for example `1234567890123`) as the payment's merchant reference. A provider configured with a custom transaction identification, such as Mercado Pago, then shows that sequence as the external reference in its panel, as it did before you migrated to Yuno. When set to **No**, or when the sequence is not available, the reference is the VTEX order ID. Available on plugin **4.2.333 or later**, for PIX, boleto and the other methods created on the server. On plugin **4.2.355 or later** it applies to every payment method. Default **No**. Example: `Yes`. |
      | **Sales Channel Domains** | Optional | Maps each VTEX sales channel (trade policy) ID to the public domain of its storefront, so the payment reports the storefront the order came from instead of the account's default host. This improves reporting and reconciliation for stores that run several storefronts on one account. Write `id=domain` pairs separated by `;` (`,` between pairs and `:` between ID and domain are also accepted). An `https://` prefix and trailing slashes are removed, and malformed pairs are skipped. Sales channels you do not list use the order's own storefront host, and stores that leave the field empty keep the current behavior. Available on plugin **4.2.333 or later**. Example: `1=www.example.com;2=b2b.example.com;18=members.example.com`. |
      | **Delay To Cancel** | Optional | How long VTEX waits for a pending payment before it cancels the order and releases its stock, per payment method. Write `Method=seconds` pairs separated by `;` (`,` between pairs and `:` between name and seconds are also accepted). `Method` is the payment method name as it appears when you create a payment condition in VTEX (for example `Mastercard`, `MercadoPagoPro` or `Pagaleve Transparente`), not the name you give the condition. Names are matched without regard to case, but accents must match, as in `Elo Débito`. `Cards` applies to every card brand, and a brand's own pair wins over `Cards`. Seconds must be a whole number between `600` (10 minutes) and `2592000` (30 days): a pair outside that range, or a malformed one, is ignored and the method keeps its default. Cards and the methods rendered by Yuno (Apple Pay, Google Pay, Samsung Pay, Click to Pay) never wait less than one hour: a shorter value becomes one hour. For cards, the value also replaces the 3-day window of a card payment that already exists and is still pending (antifraud review or card challenge), so a short value cancels reviews that would have been approved later. PIX and Boleto Bancário cannot be configured: PIX follows the QR code expiration and boleto its due date. Available on plugin **4.2.373 or later**. Example: `Cards=259200;PicPay=1800` (cards wait 3 days, PicPay 30 minutes). See **How long VTEX waits for a pending payment** below the table for the defaults. |

      **How long VTEX waits for a pending payment**

      When a payment is still pending, VTEX waits for a set time before it cancels the order and releases its stock. Without the **Delay To Cancel** field, each payment method uses the window below. The field replaces it for every method except PIX and Boleto Bancário.

      | Payment method | Default window |
      | :--- | :--- |
      | Cards and MONNET | 24 hours. A card payment that already exists and is under review (antifraud review or card challenge) gets 3 days. |
      | Boleto Bancário | The boleto's due date, with a 24-hour minimum. |
      | PIX | The QR code expiration, between 15 minutes and 1 hour. |
      | Apple Pay, Google Pay, Samsung Pay, Click to Pay and the other methods rendered by Yuno, PicPay, MercadoPagoPro, Nubank, Pagaleve | 1 hour. |
    </Accordion>

    <Accordion title="Settlement Options">
      The **Automatic Settlement** field determines the timing of the capture for card and wallet payments. 

      | Option | Practical Behavior |
      | :--- | :--- |
      | **Use behavior recommended by payment processor** | **Immediate Capture**: The transaction is captured immediately after authorization. (Default) |
      | **Automatic capture immediately after payment authorization** | **Immediate Capture**: The transaction is captured immediately after authorization. Same as default. |
      | **Automatic capture immediately after anti-fraud analysis** | **Immediate Capture**: The transaction is captured immediately after authorization. |
      | **Disabled** | **Authorize Only**: The transaction is only authorized. Capture happens later when the order is **invoiced**. |
    </Accordion>

    <Note>
      **Environments**: The Yuno environment is determined by the prefix of your **Public API Key**: `dev_`, `staging_`, `sandbox_`, or `prod_`.
    </Note>

    <Tip>
      We suggest using **Use behavior recommended by payment processor** unless your business specifically requires capture after invoicing.
    </Tip>
  </Step>

  <Step title="Install the Yuno Payment App">
    After saving the provider configuration, install the Yuno Payment App from your VTEX dashboard.

    1.  In the **VTEX dashboard**, go to **Apps → App Management**.
    2.  Search for **Yuno** and select the **Yuno Payment App** in the list of available apps and open its **Settings**.

    <Frame>
      <img src="/images/plugins/vtex/image-c64bef9b.png" alt="Install Yuno Payment App" />
    </Frame>

    3.  Click **Install** to complete the setup.

    Once installed, the Payment App takes care of rendering the Yuno checkout experience inside your VTEX checkout.
  </Step>

  <Step title="Activate payment methods">
    Now choose which payment methods you want to offer to your shoppers and route them through Yuno.

    1.  In the **VTEX dashboard**, go to **Store Settings → Payment → Settings → Payment Conditions**. Click the **+** button to add a payment condition.

    <Frame>
      <img src="/images/plugins/vtex/image-68c9e7f2.png" alt="Add Payment Condition" />
    </Frame>

    2.  Select the payment method you want to activate (for example, Visa, Mastercard, Pix, Apple Pay, Samsung Pay, or any of the generic **Yuno** methods, such as Yuno Card or Yuno Wallet).

    <Frame>
      <img src="/images/plugins/vtex/image-309cec4b.png" alt="Select Payment Method" />
    </Frame>

    3.  In the **Process with provider** field, select the Yuno affiliation you configured in Step 1. Set the **Status** to **Active** and save.

    <Frame>
      <img src="/images/plugins/vtex/image-73d8fe62.png" alt="Configure Payment Affiliation" />
    </Frame>

    <Note>
      Repeat for every method you want to offer. You can review the full list of available methods in the [Overview](/docs/plugins/vtex) page.
    </Note>
  </Step>

  <Step title="Configure the webhook in your Yuno dashboard">
    The webhook keeps your VTEX orders in sync with Yuno's payment status updates. 

    1.  In the **Yuno dashboard**, open **Developers → Webhooks** and click **Add webhook**.
    2.  Fill in the form:
        *   **Name**: For example `VTEX webhook`.
        *   **Endpoint URL**: `https://{store_name}.myvtex.com/_v/yunopartnerbr.yuno/v4/webhook`, replacing `{store_name}` with your VTEX account name.
        *   **x-api-key** and **x-secret**: Enter any placeholder value (for example, `VTEX`).
    3.  Select all events and click **Add**.
  </Step>
</Steps>
