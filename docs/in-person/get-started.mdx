Five steps from your Yuno account to a first sale on a terminal. Most are configuration with your Yuno contact; the only code is on your side of the [integration type](/docs/in-person/ways-to-integrate) you choose.

<Steps>
  <Step title="Use your Yuno account">
    In-person payments live in the same account, API keys and dashboard as your online payments. Nothing new to create. If you are new to Yuno, [set up your account](/docs/step-1-set-up-your-account) first.
  </Step>
  <Step title="Register stores and terminals">
    Each store gets an identifier, each lane a terminal. Registration happens in the dashboard or through your Yuno contact for large fleets, from a list of serial numbers. Only registered terminals can talk to Yuno.
  </Step>
  <Step title="Install the app">
    Yuno's payment app is signed and distributed to your fleet through the vendor's or your own device management. The acquirer's keys are injected by the acquirer or the vendor. See [Terminals and fleet](/docs/in-person/terminals).
  </Step>
  <Step title="Set acquirers and routing rules">
    Which acquirers each store can use, and the rules Yuno applies per sale: store, amount, payment method, acquirer health. Enable the instalment plans and the brand for the terminal screens. The configuration reaches each terminal when it next connects.
  </Step>
  <Step title="Test in sandbox, then go live">
    Sandbox terminals run the same app against Yuno's acquirer simulator, with test cards that produce approvals, declines and timeouts on demand. Switch a store to live when its terminals report online and a test sale reconciles. See [Testing](#testing) below.
  </Step>
</Steps>

## What you build

| Integration type | On your side |
| --- | --- |
| Standalone | Nothing |
| Local | The local interface on your POS, or the configuration of the one it already has |
| Cloud | One API call and a webhook handler, which you likely have already |
| Reconciliation first | Access to your acquirers' settlement files |

## Testing

- **Sandbox terminals.** A registered terminal can be switched to sandbox: the same app, the same screens, against Yuno's acquirer simulator instead of the bank. No real money moves.
- **Test cards.** A set of test cards produces a fixed outcome each: approved, declined with a given reason, timeout, instalments offered or not. Ask your Yuno contact for the set.
- **Webhooks.** Sandbox sales send the same events as live ones, so your handler can be tested end to end before the first store goes live.
- **Reconciliation.** The simulator produces a settlement file for sandbox sales, so the reconciliation view can be checked before real files arrive.

## Go-live checklist

- Terminals report online in the fleet view, with the expected app version.
- A sale on each integration type you use reaches your webhook with `channel: IN_PERSON`.
- Routing rules for the store are in place and the acquirers' keys are on the terminals.
- A sandbox sale reconciled; the acquirer's live settlement file delivery is confirmed.
- Receipts print from the POS or the terminal with the text you configured.
