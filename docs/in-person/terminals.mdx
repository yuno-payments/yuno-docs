The Yuno Payment App runs on the POS terminals you already own. This page covers which terminals, how the app and the keys get onto them, what you can brand, and what you see about the fleet.

## Which POS terminals

The Yuno Payment App runs on Android POS terminals whose vendor allows external payment applications, such as terminals from Verifone and Ingenico. Countertop, portable and PIN-pad form factors all work.

| The terminal needs | Why |
| --- | --- |
| Android, with the vendor's payment SDK | The app runs as an Android application and reaches the card reader through the SDK |
| A PCI PTS approved PIN pad | The PIN is captured and encrypted on the terminal's secure keypad |
| A current EMV Level 1 and 2 approval | The app uses the vendor's certified kernel to read chip and contactless cards |
| The vendor's permission to install external payment applications | The app is signed and distributed through the vendor's programme |

The app talks to each vendor's certified EMV kernel through an adapter, so a new vendor is a new adapter, not a new app. Yuno never modifies the kernel. If you are choosing new hardware, send your Yuno contact the model list and they will confirm it before you buy.

## How the app reaches a POS terminal

<Steps>
  <Step title="Registration">
    Each terminal is registered to a store and a lane in Yuno, by enrolment code or from a list of serial numbers. Only registered terminals can talk to Yuno Cloud, over a secure channel with an identity per device.
  </Step>
  <Step title="Installation">
    The Yuno Payment App is signed through the vendor's signing process and distributed to the fleet through the vendor's estate manager or your own device management, with your approval. You keep ownership and maintenance of the hardware.
  </Step>
  <Step title="Keys and acquirer IDs">
    Each acquirer's PIN encryption key is injected by that acquirer or by the vendor, never by Yuno. A terminal holds one key and one terminal ID (TID) per acquirer it can route to, and reports whether each key is present. A terminal missing a key or a TID does not route to that acquirer.
  </Step>
  <Step title="Configuration">
    Store, enabled payment methods, instalment plans, brand and routing rules are published from Yuno Cloud. The terminal keeps the last configuration it received, so it works through outages.
  </Step>
  <Step title="Go live">
    The terminal reports online, appears in the fleet view, and takes its first sale. From then on it sends health, app version and last sale to the dashboard.
  </Step>
</Steps>

## What you can brand, and what never changes

The app has two layers. The certified core (reading the card, taking the PIN, building the message to each acquirer) is frozen once certified, because a change to it restarts the acquirer and card-brand certification. Everything a customer or cashier sees sits outside it and is configuration.

  <img src="/images/in-person/certified-boundary.svg" alt="Screens, brand and rules change without touching the certified core. The core changes only with a new certification." />

| Configurable per merchant, no recertification | Frozen after certification |
| --- | --- |
| Logo, colours and wordmark on every screen, including the idle screen | Reading the chip or contactless card |
| Screen texts and languages | PIN capture on the secure keypad |
| Receipt text and layout | The message to each acquirer |
| Enabled payment methods and instalment plans | Kernel configuration: verification methods, limits, terminal type |
| Routing rules per store | Adding a transaction type, such as tips or cashback |
| Telemetry and health reporting | Adding an acquirer (a new certification with that acquirer) |

White label is the default: no Yuno branding on the terminal unless you ask for it.

## Network requirements

- The POS terminal needs outbound HTTPS to `*.y.uno` for configuration, rules and sale reporting, and a link to each acquirer for authorisation; the link type is agreed with each acquirer at onboarding.
- Nothing comes in from the internet. In the Local type, your checkout system connects to the terminal on the store network (port 8443) or by cable; Yuno is not on that path.
- Ethernet, Wi-Fi or mobile data, as the terminal supports; a terminal with more than one path fails over on its own.

## Updates

Releases that touch only the configurable layer ship like any app update: staged to a group of terminals first, then to the fleet, installed only between sales and with no open batch. Releases that touch the certified core are rare, planned with the acquirers, and certified before they ship. Each acquirer's integration is versioned on its own, and every terminal shows in the dashboard which certified combination it runs. Routing rule changes are not app releases: they are configuration published from Yuno Cloud.
