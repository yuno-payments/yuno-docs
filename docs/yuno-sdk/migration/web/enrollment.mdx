title: "Enrollment"
description: "Migrate Web enrollment integrations (yuno.mountEnrollmentLite + yuno.apiClientEnroll) to the unified Transaction API."
---

Enrollment had two sub-modes that paralleled the payment modes: a UI-driven flow (`mountEnrollmentLite`) and a headless flow (`apiClientEnroll`). Both collapse into the same `Transaction` class in the unified API. What changes is the **session you pass** (`customerSession` instead of `checkoutSession`) and **whether you provide pre-collected data** in `paymentMethod.data`.

## Before you start

- Load the unified SDK bundle instead of the legacy one and initialize it as the side-by-side shows: `window.Yuno.initialize(...)` becomes `SdkPayments.initialize(...)`. Your public API key and the customer sessions your backend creates do not change ([Before you begin](/docs/yuno-sdk/get-started#before-you-begin)).
- There is no payment to create: `createPayment` is not invoked during enrollment, so overriding it has no effect.

## Side-by-side

### Enrollment Lite (UI)

<CodeGroup>

```typescript Before. Enrollment Lite
const yuno = await window.Yuno.initialize('your-public-api-key')

await yuno.mountEnrollmentLite({
    customerSession: 'session-from-backend',
    elementSelector: '#root',
    countryCode: 'CO',
    language: 'en',
    showStatusScreen: true,
    yunoEnrollmentStatus: ({ status, vaultedToken }) => {
        if (status === 'CREATED' && vaultedToken) {
            // Store against customer
            console.log('vault token:', vaultedToken)
        }
    },
})
```

```typescript After. Unified Transaction (enrollment)
const sdkPayments = await SdkPayments.initialize('your-public-api-key')

const transaction = sdkPayments.transaction({
    customerSession: 'session-from-backend',
    countryCode: 'CO',
    language: 'en',
    elementSelector: '#root',
    onStatus: (result) => {
        // Same payload shape as payment flows: status / substatus / message.
        if (result.status === 'CREATED') {
            // Enrollment succeeded. Retrieve the vaulted token from your
            // backend's list-customer-payment-methods endpoint.
        }
    },
})

await transaction.start()
```

</CodeGroup>

### Enrollment Headless

<CodeGroup>

```typescript Before. Enrollment headless
const yuno = await window.Yuno.initialize('your-public-api-key')

const apiClientEnroll = await yuno.apiClientEnroll({
    customerSession: 'session-from-backend',
})

const vaultedToken = await apiClientEnroll.generateVaultedToken({
    cardHolderName: 'John Doe',
    cardNumber: '4111111111111111',
    cvv: '123',
    expirationMonth: 12,
    expirationYear: 28,
})

console.log('vault token:', vaultedToken)
```

```typescript After. Unified Transaction (enrollment headless)
const sdkPayments = await SdkPayments.initialize('your-public-api-key')

const transaction = sdkPayments.transaction({
    customerSession: 'session-from-backend',
    countryCode: 'CO',
    onStatus: (result) => {
        if (result.status === 'CREATED') {
            // Enrollment succeeded. Retrieve the vaulted token from your
            // backend's list-customer-payment-methods endpoint.
        }
    },
})

await transaction.start({
    paymentMethod: {
        type: 'CARD',
        data: {
            type: 'CARD',
            holderName: 'John Doe',
            number: '4111111111111111',
            securityCode: '123',
            expirationMonth: 12,
            expirationYear: 28,
        },
    },
})
```

</CodeGroup>

## What changes

Grouped in the order you edit the code. **Renamed**: same role, new name. **Moved**: same value, new owner. **Removed**: nothing to call. The last column is the only thing you have to do beyond the rename.

### Initialization and config

| Enrollment | Unified | Change | What to do |
|---|---|---|---|
| `window.Yuno.initialize(publicApiKey)` | `SdkPayments.initialize(publicApiKey)` | Renamed | The global is `window.SdkPayments`. As before, `await` it: it resolves to the `SdkPayments` instance you create transactions from. |
| `customerSession` on `mountEnrollmentLite` / argument of `apiClientEnroll` | `customerSession` on the transaction config | Moved | Single factory: which session you pass decides the flow, `checkoutSession` for a payment, `customerSession` for an enrollment. `createPayment`, `showPayButton`, and the other payment-only config fields aren't part of the enrollment config, as there's no `/v1/payments` equivalent for enrollment. |
| `countryCode`, `language` on `mountEnrollmentLite` | The same fields on the transaction config | Moved | |
| `elementSelector: '#root'` (auto-mount) on `mountEnrollmentLite` | `elementSelector` on the transaction config | Moved | Optional, not required: the enrollment form renders inside that element. Used only by form-based flows (headless enrollment ignores it). Modal mode no longer exists. |
| `showPaymentStatus: true` | `showStatusScreen: true` | Renamed | Same field on `TransactionConfig`. Defaults to `true` for enrollment. |
| `cardHolderName`, `cardNumber`, `cvv`, `expirationMonth`, `expirationYear` (argument of `generateVaultedToken`) | `holderName`, `number`, `securityCode`, `expirationMonth`, `expirationYear` under `paymentMethod.data` | Moved | Pre-collected card data goes inline on `start()` (see Entry points). |

### Callbacks

| Enrollment | Unified | Change | What to do |
|---|---|---|---|
| `yunoEnrollmentStatus({ status, vaultedToken })` | `onStatus(result)` | Renamed | `result` carries `status` (literal union), `substatus`, and `message`, the same shape as payment flows. `result.status` uses the same 12-value literal union as the `Enrollment.Status` enum: `CREATED`, `EXPIRED`, `REJECTED`, `READY_TO_ENROLL`, `ENROLL_IN_PROCESS`, `UNENROLL_IN_PROCESS`, `ENROLLED`, `DECLINED`, `CANCELED`, `ERROR`, `UNENROLLED`, `PENDING`. When `status === 'CREATED'`, the enrollment succeeded. **`vaultedToken` is no longer delivered to the client**: retrieve it from your backend's list-customer-payment-methods endpoint and store it against your customer. See [`Status`](/docs/yuno-sdk/reference/objects-you-receive#status). |
| `yunoError(message, data?)` | *(removed)* | Removed | Errors flow through `onStatus` (a `TransactionStatus` with `message` set), or a rejected `start()` Promise. |

### Entry points

| Enrollment | Unified | Change | What to do |
|---|---|---|---|
| `yuno.mountEnrollmentLite({ customerSession, … })` | `sdkPayments.transaction({ customerSession, elementSelector, … }).start()` | Renamed | `start()` with no argument is the UI enrollment: with `elementSelector` on the config, the SDK presents the enrollment form inside that element for the customer to pick a method and fill in card data. |
| `yuno.apiClientEnroll({ customerSession })` + `.generateVaultedToken(cardData)` | `sdkPayments.transaction({ customerSession }).start({ paymentMethod: { type: 'CARD', data: CardData } })` | Renamed | `start({ paymentMethod: { type, data } })` is the headless enrollment: same shape as headless payment, but with `customerSession`; the config's `elementSelector` is ignored. The call no longer returns the vaulted token (see Callbacks). |
