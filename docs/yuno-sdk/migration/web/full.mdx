title: "Full mode"
description: "Migrate Web Full integrations (yuno.startCheckout with the embedded payment-method list) to the unified Transaction API."
---

Full mode rendered the SDK's payment-method drawer inside your layout. The user picked a method, the SDK rendered the corresponding form, tokenized, processed the payment, and reported the result. In the unified API the same flow uses a single `Transaction` plus `transaction.getPaymentMethodsViews({ types: ['paymentMethodList'], onPaymentSelected })`. The returned `views.paymentMethodList` exposes a `.mount({ elementSelector })` method.

## Before you start

- Load the unified SDK bundle instead of the legacy one and initialize it as the side-by-side shows: `window.Yuno.initialize(...)` becomes `SdkPayments.initialize(...)`. Your public API key and the checkout sessions your backend creates do not change ([Before you begin](/docs/yuno-sdk/get-started#before-you-begin)).
- Decide who creates the payment. The checkout session's `workflow` must match that decision:

| Who creates the payment | In Full you had | In the unified API | Session `workflow` |
|---|---|---|---|
| Your backend | `yunoCreatePayment` implemented | Override `createPayment` | Default (`SDK_CHECKOUT`) |
| The SDK | No `yunoCreatePayment` | No override | `SDK_SEAMLESS` |

<Warning>
A default-workflow session with no `createPayment` override ends in `INTERNAL_ERROR`: the backend rejects the SDK's payment creation. See [`createPayment`](/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Side-by-side

<CodeGroup>

```typescript Before. Full mode
const yuno = await window.Yuno.initialize('your-public-api-key')

await yuno.startCheckout({
    checkoutSession: 'session-from-backend',
    elementSelector: '#root',
    countryCode: 'CO',
    language: 'en',
    renderMode: { type: 'modal' },
    paymentListConfig: {
        scrollContainerSelector: '#scroll-container',
        bottomOffsetPx: 0,
    },
    yunoPaymentMethodSelected: ({ type, name }) => {
        console.log('selected:', type, name)
    },
    yunoPaymentResult: (status, subStatus) => {
        console.log('Final status:', status, subStatus)
    },
    yunoError: (error) => {
        console.log('Error', error)
    },
})
```

```typescript After. Unified Transaction
const sdkPayments = await SdkPayments.initialize('your-public-api-key')

const transaction = sdkPayments.transaction({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    language: 'en',
    elementSelector: '#root',
    paymentListConfig: {
        scrollContainerSelector: '#scroll-container',
        bottomOffsetPx: 0,
    },
    onStatus: (result) => {
        console.log('Final status:', result.status, result.substatus)
    },
})

const views = transaction.getPaymentMethodsViews({
    types: ['paymentMethodList'],
    onPaymentSelected: (paymentMethod) => {
        transaction.start({ paymentMethod })
    },
})

views.paymentMethodList?.mount({ elementSelector: '#root' })
```

</CodeGroup>

## What changes

Grouped in the order you edit the code. **Renamed**: same role, new name. **Moved**: same value, new owner. **Removed**: nothing to call. The last column is the only thing you have to do beyond the rename.

### Initialization and config

| Full | Unified | Change | What to do |
|---|---|---|---|
| `window.Yuno.initialize(publicApiKey)` | `SdkPayments.initialize(publicApiKey)` | Renamed | The global is `window.SdkPayments`. As before, `await` it: it resolves to the `SdkPayments` instance you create transactions from. |
| `checkoutSession`, `countryCode`, `language` on the `startCheckout` config | The same fields on the transaction config | Moved | Same fields, single factory: `sdkPayments.transaction({ checkoutSession, countryCode, language, … })`. |
| `paymentListConfig` | `paymentListConfig` on the transaction config | Moved | Same shape, same fields. |
| `renderMode: { type, elementSelector }` | `elementSelector` on the transaction config | Moved | Modal mode no longer exists. Set `elementSelector` on the transaction config to render a selected method's form. It's optional and used only by form-based flows; the payment-method list itself renders where you pass `elementSelector` to `views.paymentMethodList.mount({ elementSelector })` (see Views). |
| `yuno.mountStatusPayment(...)` | *(removed)* | Removed | The SDK's built-in result screen is controlled by `showStatusScreen` on the transaction config; it defaults to `false`. |

### Callbacks

| Full | Unified | Change | What to do |
|---|---|---|---|
| `yunoPaymentResult(status, subStatus?)` | `onStatus(result)` | Renamed | Still the single outcome callback, now a field on the transaction config. It receives one `TransactionStatus` object with `.status`, `.substatus` and `.message`. Naming convention across the new callbacks: overrides have no `on` prefix (`createPayment`, `showLoading`), observers do (`onStatus`, `onPaymentSelected`). See [`Status`](/docs/yuno-sdk/reference/objects-you-receive#status). |
| `yunoCreatePayment(ott, info)` | `createPayment(token)` | Renamed | Optional. Promise-based, single argument. Create the payment and resolve: resolving is what used to be `continuePayment()`. See [`createPayment`](/docs/yuno-sdk/controllers/create-payment). |
| `yunoError(message, data?)` | *(removed)* | Removed | Errors flow through `onStatus`, or a rejected `start()` Promise. |
| `onLoading({ isLoading, type })` | `showLoading(isLoading)` | Renamed | Optional. Boolean signal only. See [`showLoading`](/docs/yuno-sdk/controllers/show-loading). |
| `onRendered()` / `onCreateOneTimeToken()` | *(removed)* | Removed | Drop these. |
| `yunoPaymentMethodSelected({ type, name })` (notification at session level) | `onPaymentSelected(paymentMethod)` inside `getPaymentMethodsViews` | Renamed | Required. The legacy callback was advisory; the new one is the driver: wire it inside `getPaymentMethodsViews` and call `transaction.start({ paymentMethod })` from it. It receives a typed [`PaymentMethodSelected`](/docs/yuno-sdk/reference/objects-you-pass#payment-method-selected) you pass to `start()`. |

### Views

| Full | Unified | Change | What to do |
|---|---|---|---|
| `yuno.startCheckout({ elementSelector: '#root' })` (auto-mounts the payment list) | `transaction.getPaymentMethodsViews({ types: ['paymentMethodList'], onPaymentSelected })`, then `views.paymentMethodList?.mount({ elementSelector: '#root' })` | Moved | Explicit list mounting: `startCheckout` auto-mounted the list at `elementSelector`. The unified API hands you a view handle, and you call `.mount(...)` with the selector plus any per-view config. This makes the intent ("render the drawer here") visible at the call site. See [Payment Methods List](/docs/yuno-sdk/features/payment-methods-list). |

### Entry points

| Full | Unified | Change | What to do |
|---|---|---|---|
| `yuno.startCheckout(config)` | `sdkPayments.transaction(config)` | Renamed | Single factory: build the transaction with the config (fields and callbacks above), then mount the list (see Views) and `start` from `onPaymentSelected`. |
| `yuno.continuePayment()` | *(removed)* | Removed | Delete the call: the SDK orchestrates 3DS and status polling internally once `createPayment` resolves. |
