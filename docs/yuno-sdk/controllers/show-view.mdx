`showView` is invoked when the SDK has a view ready to be presented. Either a form to collect input from the user, or an action view such as a QR code. Override this controller to embed the view in your own layout instead of letting the SDK present it full-screen.

<Note>
WebViews: for example, 3DS challenges or redirects required by some payment methods, are always presented by the SDK full-screen. They do not come through `showView`, so overriding it does not change that behavior.
</Note>

`showView` is available on iOS and Android. On Web the SDK renders the form inside the element you pass as `elementSelector`, so there is no view to hand over. To submit that form from your own button, see [Web: submit from your own button](#web-submit-from-your-own-button).

## Behavior

If you do not override this controller, the SDK presents the view full-screen with its own header and submit button.

When you override it, the SDK delivers the view to your handler along with a `TransactionProcess` control object. You place the view wherever you want in your layout, and you call `process.onSubmit()` to tell the SDK the user has triggered submission.

You are responsible for removing the view from your layout once the transaction has moved past that step.

The controller can be invoked more than once per transaction. The `step` parameter indicates which step the view belongs to. For example, `FORM` for the data-capture form and `ACTION` for an action view such as a QR code. Use it to differentiate how you embed each view if needed.

## TransactionProcess

`TransactionProcess` is the control object the SDK passes alongside the view. It exposes a single method:

```
onSubmit()
```

Call `process.onSubmit()` when the user triggers submission from your own UI (for example, when they tap your custom submit button). The SDK validates the form and, if valid, continues the transaction.

You don't need to handle success or failure here. The result of submission flows through [`createPayment`](/docs/yuno-sdk/controllers/create-payment) (if overridden) and [`onStatus`](/docs/yuno-sdk/controllers/on-status).

## TransactionViewStep

`TransactionViewStep` indicates which step the view corresponds to.

| Value | Meaning |
|---|---|
| `FORM` | Data-capture form (card form, APM data, etc.). |
| `ACTION` | Additional action view, such as a QR code. |

## Threading

On iOS and Android, `showView` is invoked on the main thread. You can update UI directly from inside this handler.

## Web: submit from your own button

On Web, hide the SDK's Pay button with [`showPayButton: false`](/docs/yuno-sdk/reference/objects-you-pass#showpaybutton-web-only) and call `transaction.submit()` from your own button. It is the Web counterpart of `process.onSubmit()`.

```javascript
const transaction = sdkPayments.transaction({
    checkoutSession,
    countryCode: 'CO',
    elementSelector: '#payment-form',
    showPayButton: false,
    onStatus: (result) => { /* final status */ },
})

await transaction.start({ paymentMethod: { type: 'CARD' } })

document.querySelector('#my-pay-button').addEventListener('click', () => {
    transaction.submit()
})
```

`submit()` validates the form and, if valid, continues the transaction. The result flows through [`createPayment`](/docs/yuno-sdk/controllers/create-payment) (if overridden) and [`onStatus`](/docs/yuno-sdk/controllers/on-status), the same as when the user clicks the SDK's Pay button.

| When you call `submit()` | What happens |
|---|---|
| The form is valid | The form is submitted. |
| The form is invalid | The form shows its field errors and `onStatus` receives `INTERNAL_ERROR` with code `FORM_INVALID`. The user can correct the form and you can call `submit()` again. |
| A payment is already in progress | Nothing. The call is ignored, so a double click does not create a second payment. |
| The form has not finished loading | `onStatus` receives `FORM_INVALID`, the same as an invalid form. Enable your button once `start()` has resolved. |
| Before `start()` is called, or after `unmount()` | It throws. Call `start()` first. |
| The payment method is a wallet | It throws. The user pays by tapping the wallet button. |
| The SDK's [payment methods list](/docs/yuno-sdk/features/payment-methods-list) is mounted and `start()` has not mounted a form | It throws. On the list, your button calls `transaction.start({ paymentMethod })` with the selected method. |
| The transaction is an enrollment | It throws. `submit()` is available for payment transactions only. |
