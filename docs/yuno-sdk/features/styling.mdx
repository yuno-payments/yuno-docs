Match the SDK's built-in views to your brand.

<Note>
There are **two ways** to style the SDK:
- **In code (iOS and Android):** pass an `Appearance` object on the `TransactionConfig` (covered below). Web has no `appearance` option. See the Web tab for what you style in code.
- **From the Checkout Builder:** configure styles server-side in your [Yuno Dashboard](https://dashboard.y.uno/), no code needed.

If you set neither, the SDK falls back to its default styles.
</Note>

<Tabs>
  <Tab title="Web">

The Web SDK renders into your page as regular DOM, so you style it with CSS plus a few config fields. There is no `appearance` object on Web.

## What you can style

| Lever | Where | What it changes |
|---|---|---|
| Checkout Builder | Yuno Dashboard | Colors, fonts, and button shape of the built-in views. The SDK applies them on every mount, no code needed. |
| CSS classes with the `sdk-payments-` prefix | Your stylesheet | Every element the SDK renders on your page carries a class with that prefix. Target them from your own CSS. |
| `card.styles` | `TransactionConfig` | A CSS string injected inside the card number, expiry, and CVV iframes, which your page CSS cannot reach. |
| `card.fonts` | `TransactionConfig` | Fonts to load inside the card iframes. |
| `card.texts` | `TransactionConfig` | Custom labels for card form fields. |
| `inputDesignType` | `TransactionConfig` (payments only) | Label layout of the inputs: `float-label` (default), `float-label-static`, or `label-placeholder`. |
| Wallet button options | `mount()` of each wallet view, or `externalButtons` on the config | Type, color, shape, size, and locale of the Apple Pay, Google Pay, PayPal, Samsung Pay, and Revolut Pay buttons. |
| `options.styles` | `secureFields.create()` | CSS inside each secure field iframe. |

## CSS classes

Every element the SDK renders on your page carries a class with the `sdk-payments-` prefix. Target them from your stylesheet to customize colors, spacing, borders, and other visual properties. Common classes include:

| Class pattern | What it styles |
|---|---|
| `sdk-payments-payment-list__*` | Payment method list container and rows |
| `sdk-payments-fieldset__*` | Form field containers and boxes |
| `sdk-payments-input__*` | Input fields and labels |
| `sdk-payments-button__*` | Buttons |
| `sdk-payments-card__*` | Card form elements |

```css
/* Example: customize the payment method list and inputs */
.sdk-payments-payment-list__radio {
    border-radius: 8px;
    margin-bottom: 8px;
}

.sdk-payments-input__label {
    color: #333;
    font-weight: 500;
}

.sdk-payments-user-form__submit {
    background-color: #6200ee;
    border-radius: 24px;
}
```

<Note>
CSS classes may change between SDK versions. Inspect the rendered DOM in your browser's developer tools to find the current class names.
</Note>

## Styling card iframes

Card number, expiry, and CVV render inside iframes for PCI compliance. Your page CSS cannot reach them. Use `card.styles` to inject CSS and `card.fonts` to load custom fonts inside the iframes.

```typescript
const transaction = sdkPayments.transaction({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    card: {
        styles: `
            input {
                font-family: 'Inter', sans-serif;
                font-size: 16px;
                color: #111;
            }
            input::placeholder {
                color: #999;
            }
            input:focus {
                border-color: #6200ee;
            }
        `,
        fonts: [
            {
                src: 'url(https://fonts.gstatic.com/s/inter/v12/UcCO3FwrK3iLTeHuS_fvQtMwCp50KnMw2boKoduKmMEVuLyfAZ9hjp-Ek-_EeA.woff2)',
                family: 'Inter',
            },
        ],
    },
    onStatus: (result) => showResult(result),
})
```

## Input design types

The `inputDesignType` field controls how labels and placeholders appear on form inputs:

| Value | Behavior |
|---|---|
| `float-label` (default) | Label floats above the input when focused or filled. |
| `float-label-static` | Label stays above the input at all times. |
| `label-placeholder` | Label appears as placeholder text inside the input. |

```typescript
const transaction = sdkPayments.transaction({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    inputDesignType: 'float-label-static',
    onStatus: (result) => showResult(result),
})
```

## Wallet button options

Customize express wallet buttons through the `mount()` options or `externalButtons` on the config:

```typescript
const views = transaction.getPaymentMethodsViews({
    types: ['applePay', 'googlePay'],
    onPaymentSelected: (pm) => { /* ... */ },
})

views.applePay?.mount({
    elementSelector: '#apple-pay',
    buttonType: 'buy',       // 'plain', 'buy', 'book', 'donate', etc.
    buttonStyle: 'black',    // 'black', 'white', 'white-outline'
})

views.googlePay?.mount({
    elementSelector: '#google-pay',
    buttonColor: 'black',    // 'black', 'white'
    buttonType: 'pay',       // 'pay', 'buy', 'book', 'donate', etc.
})
```

## Secure fields styling

For [Secure Fields](/docs/yuno-sdk/features/secure-fields), pass `styles` when creating each field:

```typescript
const cardNumber = secureFields.create('cardNumber', {
    placeholder: 'Card number',
    styles: `
        input {
            font-family: 'Inter', sans-serif;
            font-size: 16px;
            border: 1px solid #ccc;
            border-radius: 4px;
            padding: 12px;
        }
    `,
})
```

Build a `SdkPayments.Appearance` with the fields you want to override and pass it to `TransactionConfig(appearance:)`. Every field is optional; unset fields fall back to the SDK default.

## Appearance fields

| Field | Description |
|---|---|
| `fontFamily` | Font family used across the SDK. Provide the font name as registered in your app's assets. |
| `accentColor` | Accent color used across several SDK elements. |
| `buttonBackgroundColor` | Background color of primary buttons. |
| `buttonTitleColor` | Text color of primary buttons. |
| `buttonBorderColor` | Border color of primary buttons. |
| `secondaryButtonBackgroundColor` | Background color of secondary buttons. |
| `secondaryButtonTitleColor` | Text color of secondary buttons. |
| `secondaryButtonBorderColor` | Border color of secondary buttons. |
| `disableButtonBackgroundColor` | Background color of disabled buttons. |
| `disableButtonTitleColor` | Text color of disabled buttons. |
| `checkboxColor` | Color of checkboxes shown in the SDK (e.g. save card). |

<Note>
All colors must be `UIColor` (from Xcode's asset catalog or your own assets) to stay compatible.
</Note>

## How styles are resolved

Setting **any** `Appearance` field makes it the active style source for the transaction: dashboard styles are then ignored entirely. Resolution is all-or-nothing per source, never a field-by-field merge. An empty `Appearance()` does not count as custom, so dashboard styles still apply. Any custom appearance (in code or from the dashboard) renders in light mode.

## Usage

Appearance is per-transaction: pass it on each `TransactionConfig`, not at `initialize`.

```swift
import SdkPayments

let appearance = SdkPayments.Appearance(
    fontFamily: "Climate Crisis",
    accentColor: .orange,
    buttonBackgroundColor: .yellow,
    buttonTitleColor: .black,
    buttonBorderColor: .black,
    secondaryButtonBackgroundColor: .yellow,
    secondaryButtonTitleColor: .black,
    secondaryButtonBorderColor: .black,
    disableButtonBackgroundColor: .gray,
    disableButtonTitleColor: .black,
    checkboxColor: .black
)

let config = SdkPayments.TransactionConfig(
    checkoutSession: "session-from-backend",
    countryCode: "US",
    appearance: appearance,
    controller: self
)

SdkPayments.Transaction(config: config)
    .start(paymentSelected: paymentSelected)
```

  <Tab title="Android">

Build an `Appearance` with the fields you want to override and pass it to `TransactionConfig(appearance = ...)`. Every field is optional; unset fields fall back to the SDK default.

## Appearance fields

| Field | Description |
|---|---|
| `fontFamily` | Font family used across the SDK. Resolved against the system fonts and the fonts configured in your dashboard; a name that cannot be resolved falls back to the device's default system font. |
| `accentColor` | Accent color used on focus strokes and cursors. It does not cascade into checkboxes or secondary button borders — those have their own fields. |
| `buttonBackgroundColor` | Background color of primary buttons. |
| `buttonTitleColor` | Text color of primary buttons. |
| `buttonBorderColor` | Border color of primary buttons. |
| `secondaryButtonBackgroundColor` | Background color of secondary buttons. |
| `secondaryButtonTitleColor` | Text color of secondary buttons. |
| `secondaryButtonBorderColor` | Border color of secondary buttons. |
| `disableButtonBackgroundColor` | Background color of disabled buttons. |
| `disableButtonTitleColor` | Text color of disabled buttons. |
| `checkboxColor` | Color of checkboxes shown in the SDK (e.g. save card). |

<Note>
All colors are `@ColorInt` integers — use `Color.parseColor("#FFD600")`, `ContextCompat.getColor(context, R.color.brand)`, or the `android.graphics.Color` constants.
</Note>

## How styles are resolved

Setting **any** `Appearance` field makes it the active style source for the transaction: dashboard styles are then ignored entirely — resolution is all-or-nothing per source, never a field-by-field merge. An empty `Appearance()` does not count as custom, so dashboard styles still apply. Any custom appearance (in code or from the dashboard) renders in light mode.

The SDK does not bundle a font of its own: with no `fontFamily` in code and no font configured in the dashboard, text renders with the device's default system font.

## Usage

Appearance is per-transaction: pass it on each `TransactionConfig`, not at `initialize`.

```kotlin
import android.graphics.Color
import com.yuno.payments.sdk.api.Appearance
import com.yuno.payments.sdk.api.Transaction
import com.yuno.payments.sdk.api.TransactionConfig

val appearance = Appearance(
    fontFamily = "Climate Crisis",
    accentColor = Color.parseColor("#E65100"),
    buttonBackgroundColor = Color.parseColor("#FFD600"),
    buttonTitleColor = Color.BLACK,
    buttonBorderColor = Color.BLACK,
    secondaryButtonBackgroundColor = Color.parseColor("#FFD600"),
    secondaryButtonTitleColor = Color.BLACK,
    secondaryButtonBorderColor = Color.BLACK,
    disableButtonBackgroundColor = Color.GRAY,
    disableButtonTitleColor = Color.BLACK,
    checkboxColor = Color.BLACK,
)

val transaction = Transaction(
    TransactionConfig(
        countryCode = "US",
        checkoutSession = "session-from-backend",
        appearance = appearance,
        controller = this,
    ),
)

transaction.start(activity = this, paymentSelected = paymentSelected)
```
