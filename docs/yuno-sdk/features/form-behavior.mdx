The SDK's built-in form is a single set of fields shared across platforms, not a collection of separate inputs your app assembles. This page documents how it behaves out of the box — no extra configuration required.

## Unified fields

Card and address inputs render as one form the SDK owns end to end: layout, validation, and formatting are handled internally, so your app doesn't need to build or style individual fields itself. [PLACEHOLDER: confirm which fields are included — card number, expiry, CVV, cardholder name, address?]

As the shopper fills in the card number, focus moves to the next field (expiry, then CVV) once the current field is complete, without the shopper needing to tap or click ahead.
