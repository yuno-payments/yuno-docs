The SDK's built-in form is a single set of fields shared across platforms, not a collection of separate inputs your app assembles. This page shows what the form looks like and how it behaves out of the box — no extra configuration required.

## Unified fields

The form always renders the card fields: **card number, expiration date, security code, and cardholder name**. Depending on the country and payment method configuration, it can also collect:

- **Customer details** — first and last name, email, phone number, and document type/number.
- **Billing and shipping address** — address lines, city, state, postal code, country, and neighborhood where required, with a checkbox to reuse the billing address for shipping.

## Auto-advance

Focus moves automatically along the card fields — card number → expiration date → security code → cardholder name — without the shopper needing to tap or click ahead.

<Frame caption="Focus advances on its own as each field completes — the shopper just types.">
  ![Auto-advance between card fields](/images/yuno-sdk/form-behavior/auto-advance.svg)
</Frame>

Each hop has its own trigger:

- **Card number** advances once the number reaches the expected length for the detected brand *and* passes Luhn validation. The expected length is not a fixed 16 digits: it comes from the BIN lookup when available (server-provided lengths per card), falling back to the brand's known range (for example, 15 for Amex).
- **Expiration date** advances when a valid month/year is entered.
- **Security code** advances when the code matches the brand's expected length (3 or 4 digits).

The card number is formatted with spacing as the shopper types, and the brand is detected from the first digits — instantly via client-side patterns, refined by a BIN lookup once six or more digits are entered.

## Autofill

Card fields are tagged for native autofill (on iOS, `textContentType` values such as `.creditCardNumber`, `.creditCardExpiration`, and `.creditCardSecurityCode`), so cards saved in the OS or browser can populate the form directly.

Address fields work differently: instead of relying on OS autofill, the SDK fills them for the shopper. When a valid postal code is entered, a Yuno lookup service completes the street, city, state, and neighborhood automatically — without overwriting anything the shopper already typed.

## Notes

- This behavior applies to the SDK-rendered form — Full and Lite checkouts and SDK-rendered method forms. In headless flows the SDK never renders a form: you build your own UI, so none of this page applies there.
