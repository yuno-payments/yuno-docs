The Yuno SDK stays small on purpose: every third-party native SDK ships as a separate, optional module. You add only the modules your account uses, the SDK picks them up when the app starts, and your `Transaction` code does not change.

<Note>
Native modules apply to iOS and Android only. On Web there is nothing to install. The SDK loads the scripts of the antifraud providers enabled for your account at runtime and collects the fingerprints during the transaction. To collect them before the transaction, call `sdkPayments.antifraud()`.
</Note>

<Note>
Installing a module does not make the SDK use it. A module runs only when the provider is enabled for your Yuno account and the backend requests it for the current transaction.
</Note>

## How it works

1. You add the module to your app next to the SDK, as a package product or a Gradle dependency.
2. When the app starts, the module registers itself with the SDK.
3. During a transaction, the SDK asks Yuno which providers apply and uses the matching module: it collects a device fingerprint and attaches it to the payment, runs the 3DS challenge natively instead of in a WebView, or opens the Revolut Pay checkout.

## Available modules

| Module | What it adds | iOS | Android |
|---|---|---|---|
| ClearSale antifraud | Collects the ClearSale device fingerprint and sends it as the payment's `customer.device_fingerprint` | Coming with SdkPayments 3.1.0 | `yuno-sdk-antifraud-clearsale` |
| PayPal Magnes antifraud | Collects PayPal's Magnes device data and attaches it to the payment | Coming with SdkPayments 3.1.0 | Not available |
| Koin antifraud | Collects the Koin device fingerprint and sends it as `customer.device_fingerprint` | Coming with SdkPayments 3.1.0 | `yuno-sdk-antifraud-koin` |
| Riskified antifraud | Starts the Riskified beacon with the checkout session and sends that session as `customer.device_fingerprint` | Not available | `yuno-sdk-antifraud-riskified` |
| Netcetera 3DS | Runs 3D Secure challenges natively in your app, for payments and enrollment | Coming with SdkPayments 3.1.0 | `yuno-sdk-3ds-netcetera` |
| Revolut Pay | Runs the Revolut Pay checkout natively, on top of Revolut's official SDK | Coming with SdkPayments 3.1.0 | Not available |

Minimum platform: iOS 14.0, Android 6.0 (API 23). Every module requires the same SDK version you install from [Get Started](/docs/yuno-sdk/get-started#install).

## Install

<Tabs>
  <Tab title="iOS">

<Note>
**iOS native modules are being published for the Yuno SDK.** They will be documented here when available. Until then, 3DS challenges run in the SDK's WebView and native antifraud fingerprints are not collected on iOS 3.x.

The Legacy SDK (2.x) modules documented at [iOS Overview](/docs/sdks/external-native-modules/ios-overview) are for the Legacy SDK only and cannot be used with the Yuno SDK (3.x).
</Note>

  </Tab>
  <Tab title="Android">

Add the modules you need to your app module's build file, next to the SDK. Each module brings its vendor SDK and its own dependencies.

```kotlin
repositories {
    maven { url = uri("https://yunopayments.jfrog.io/artifactory/snapshots-libs-release") }
}

dependencies {
    implementation("com.yuno.payments:android-sdk:3.0.0")
    // Add only the modules your account uses
    implementation("com.yuno.payments:yuno-sdk-antifraud-clearsale:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-antifraud-koin:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-antifraud-riskified:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-3ds-netcetera:1.0.1")
}
```

<Note>
The Netcetera module also needs Netcetera's Maven repository declared in your project, because its 3DS SDK is not on Maven Central. See [Netcetera 3DS on Android](/docs/sdks/external-native-modules/netcetera-3ds-android#step-1-declare-the-netcetera-maven-repository).
</Note>

  </Tab>
</Tabs>

## Activate

<Tabs>
  <Tab title="iOS">

<Note>
**iOS native modules are being published for the Yuno SDK.** They will be documented here when available. Until then, 3DS challenges run in the SDK's WebView and native antifraud fingerprints are not collected on iOS 3.x.

The Legacy SDK (2.x) modules documented at [iOS Overview](/docs/sdks/external-native-modules/ios-overview) are for the Legacy SDK only and cannot be used with the Yuno SDK (3.x).
</Note>

  </Tab>
  <Tab title="Android">

Every module registers itself when your app process starts, through [Jetpack App Startup](https://developer.android.com/topic/libraries/app-startup). Keep your usual initialization:

```kotlin
import com.yuno.payments.sdk.api.SdkPayments

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        SdkPayments.initialize(this, apiKey = "your-public-api-key")
    }
}
```

To confirm a module loaded, filter Logcat by its tag right after the app starts: `adb logcat -s ClearSaleAntifraud`, `adb logcat -s KoinAntifraud`.

<Accordion title="If your app disables App Startup">

Some apps remove the App Startup content provider from their manifest to control startup work themselves. In that case run the initializers yourself, before any transaction:

```kotlin
import androidx.startup.AppInitializer
import com.yuno.antifraud.clearsale.ClearSaleAntifraudInitializer
import com.yuno.antifraud.koin.KoinAntifraudInitializer
import com.yuno.threedsecure.netcetera.Netcetera3DSInitializer

val initializer = AppInitializer.getInstance(applicationContext)
initializer.initializeComponent(ClearSaleAntifraudInitializer::class.java)
initializer.initializeComponent(KoinAntifraudInitializer::class.java)
initializer.initializeComponent(Netcetera3DSInitializer::class.java)
```

</Accordion>

  </Tab>
</Tabs>

<Tip>
Once a module is registered the SDK uses it automatically. You do not change any payment, enrollment or 3DS code.
</Tip>

## What each module needs from your app

### Antifraud modules

- The fingerprint travels as the payment's `customer.device_fingerprint`. Nothing changes in the data you send.
- Collection runs when the shopper confirms the payment, and the shopper waits for it. On Android collection is bounded by the `timeout` configured for the provider in your Yuno account (5 seconds by default). Keep it short.
- None of them requests location. On Android, do not add `play-services-location` version 21 or higher next to the ClearSale module: those versions are incompatible with the bundled ClearSale SDK.

### Netcetera 3DS

<Note>
**iOS:** Native 3DS modules are coming with SdkPayments 3.1.0. Until then, 3DS challenges run in the SDK's WebView on iOS.
</Note>

**Android:**
- Runs the 3D Secure challenge inside your app, for payments and enrollment, instead of the WebView challenge. If you customize the SDK styles, they propagate to the challenge screen.
- The challenge is still presented full-screen by the SDK: it does not come through `showView`.
- Sandbox only: the Netcetera SDK needs a Visa test root certificate (`acq-root-certeq-prev-environment.crt`) in your app bundle. Ask your Yuno TAM for it, it is not distributed publicly. Production builds do not use it.

### Revolut Pay

<Note>
**iOS:** The Revolut Pay module is coming with SdkPayments 3.1.0. Integration instructions will be documented here when available.
</Note>

## Troubleshooting

<AccordionGroup>
  <Accordion title="The module is installed but nothing changes (Android)">
    Check, in this order: the provider is enabled for your Yuno account (ask your TAM); the module's line shows in Logcat at startup; and that your app is not removing the App Startup provider from the manifest.
  </Accordion>
  <Accordion title="Android: NoClassDefFoundError mentioning LocationServices on every collection">
    Expected with the ClearSale module: the location library is absent on purpose. The error is caught inside the SDK and the collection still completes.
  </Accordion>
</AccordionGroup>
