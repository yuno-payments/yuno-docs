The objects your app builds and hands to the SDK: the per-transaction configuration, the payment method the shopper picked, and the data you collected yourself when you skip the SDK's forms.

<Tabs>
<Tab title="TransactionConfig" id="transaction-config">

`TransactionConfig` is the configuration object passed to the `Transaction` constructor. It defines the session, locale, controllers, and behavior flags for a single transaction.

<Note>
On web, `TransactionConfig` is a plain object passed directly to `sdkPayments.transaction(config)`.
</Note>

## `checkoutSession`

Session ID for a payment flow. Pass the value returned by your backend after calling [`POST /v1/checkout/sessions`](https://docs.y.uno/reference/checkout-sessions/create-checkout-session).

Mutually exclusive with `customerSession`.

See [Sessions](/docs/basic-concepts/sessions) for more.

## `customerSession`

Session ID for an enrollment flow. Pass the value returned by your backend after calling [`POST /v1/customers/sessions`](https://docs.y.uno/reference/customer-sessions-enrollment/create-customer-session).

Mutually exclusive with `checkoutSession`.

See [Sessions](/docs/basic-concepts/sessions) for more.

## `countryCode`

ISO country code for the payment (for example, `US`, `CO`).

Accepts any string. The SDK does not validate the value. See [Country coverage](/docs/sdks/resources/country-coverage) for the list of supported countries.

## `language`

ISO-639 language code. Falls back to the device or browser language if omitted.

See [Supported languages](/docs/sdks/resources/languages-supported).

## `controller` (iOS, Android)

Object that implements the `TransactionController` interface. Used to receive transaction events (`onStatus`, `showLoading`, `createPayment`).

On iOS and Android, `controller` is **required**: `onStatus` is the only mechanism for receiving the transaction outcome, so a config without a controller would deliver every result nowhere. On iOS the SDK holds the reference weakly, so keep the instance alive for the duration of the transaction.

On Web, controllers are wired directly as fields on the config (`onStatus`, `showLoading`, `createPayment`). On iOS and Android, you pass a single controller object through the `controller` field.

See [Controllers](/docs/yuno-sdk/controllers/overview).

## `showStatusScreen`

Flag that controls whether the SDK presents its built-in result screen after the transaction finishes.

- `false` (default). The SDK does not show a result screen. You receive the final status through `onStatus` and render your own UI.
- `true`. The SDK presents its result screen.

`onStatus` is always invoked, regardless of this flag.

## `autoContinuePayment`

Controls whether the SDK automatically continues the payment flow after creating it. When `true` (default), the SDK handles 3DS and status polling internally. Set to `false` if you want to control the post-creation flow manually.

With `false`, the SDK stops once the payment is created: it does not poll status, does not run 3DS, and `onStatus` is not invoked for the transaction.

## `saveCardEnabled` (iOS)

Flag that controls whether the card form offers the save-card checkbox on payments. Defaults to `false`.

- `false` (default). The card form has no save-card checkbox.
- `true`. The card form shows the checkbox, unchecked. If the user ticks it, the card is stored on a successful payment.

Payment flows only. The enrollment initializer does not take it.

## `elementSelector` (Web only)

CSS selector for the DOM node the SDK renders the payment or enrollment form into. Optional and used only by form-based flows: headless flows ignore it, and wallet/list views take their own `elementSelector` on `.mount()`. When omitted, form-based flows fall back to the SDK's default container.

## `showPayButton` (Web only)

Whether the form the SDK mounts shows the SDK's own Pay button. Set it to `false` to use your own button: mount the form with `transaction.start({ paymentMethod })` and call [`transaction.submit()`](/docs/yuno-sdk/controllers/show-view#web-submit-from-your-own-button) when the user confirms.

Payment flows only. Enrollment forms always show the SDK button.

## `appearance` (iOS, Android)

Visual customization object for the SDK's built-in views (colors, fonts, corner radius, etc.). Not available on Web.

See [Styling](/docs/yuno-sdk/features/styling) for the full set of options.

## `viewController` (iOS only)

Optional reference to the `UIViewController` that the SDK should use to present its UI.

Optional when your app is fully built with SwiftUI. Required if you want the SDK to present from a specific UIKit view controller.

This field exists only on iOS.

## Validation

The config rejects both `checkoutSession` and `customerSession` being set, or neither. How each platform enforces it differs:

| Platform | Enforcement |
|---|---|
| iOS | Compile-time. `TransactionConfig` has two non-throwing initializers (`init(checkoutSession:...)` and `init(customerSession:...)`), so a config with both or neither sessions cannot be constructed. No `try` is needed. |
| Android | Compile-time. `TransactionConfig` has two constructors (`TransactionConfig(checkoutSession = …)` and `TransactionConfig(customerSession = …)`), so a config with both or neither session cannot be constructed. |
| Web | Runtime. Throws a Yuno SDK error |

On Web, the constructor also throws if `countryCode` is missing.

Beyond those checks, the SDK does not validate the *values* of `countryCode`, `language`, or other fields. Invalid values may surface later as backend errors or unexpected behavior.

## `paymentMethodType`

String identifying the type of payment method (for example, `CARD`, `GOOGLE_PAY`, `APPLE_PAY`).

The list of valid values is not fixed. Yuno may add new payment method types over time. Use the value returned by Yuno's API or by the [Payment Methods List](/docs/yuno-sdk/features/payment-methods-list) controller.

## `vaultedToken`

Token of a previously saved payment method, returned by Yuno when the customer enrolled the method or when a previous payment was made with `vault_on_success: true`.

Use this when the customer is paying with a saved method instead of entering data again.

## `transactionData`

Pre-collected payment data. When provided, the SDK skips its built-in forms and tokenizes directly.

See [TransactionData](/docs/yuno-sdk/reference/objects-you-pass#transaction-data) for the shape of this object.

</Tab>
<Tab title="TransactionData" id="transaction-data">

`TransactionData` is the object you pass inside [`PaymentMethodSelected`](/docs/yuno-sdk/reference/objects-you-pass#payment-method-selected) when you've already collected the payment data on your side. When provided, the SDK skips its built-in forms and tokenizes directly with the values you supply.

`TransactionData` is the union of several nested objects, each covering a different aspect of the payment (card data, installments, 3DS setup, customer data, etc.). You only fill the parts that apply to your scenario. Every nested object is optional unless required by the specific payment method or feature you're using.

## Shape

The full shape of `TransactionData` is the following. This JSON is illustrative, on each platform you build an object (JavaScript on Web, Swift on iOS, Kotlin on Android) that produces this structure. All field names are camelCase in the SDK. Every field is optional, fill only what applies to your scenario.

```json
{
  "card": {
    "number": "4111111111111111",
    "expirationMonth": 12,
    "expirationYear": 28,
    "securityCode": "123",
    "holderName": "John Doe",
    "brand": "VISA",
    "type": "CREDIT"
  },
  "vaultOnSuccess": true,
  "installment": {
    "id": "installment_xxx",
    "value": 3
  },
  "threeDSecure": {
    "setupId": "setup_xxx"
  },
  "customer": {
    "firstName": "John",
    "lastName": "Doe",
    "email": "john.doe@example.com",
    "document": {
      "documentNumber": "1090209924",
      "documentType": "CC"
    },
    "phone": {
      "countryCode": "57",
      "number": "3001234567"
    },
    "merchantCustomerId": "customer_xxx",
    "billingAddress": {
      "addressLine1": "Calle 34 # 56 - 78",
      "addressLine2": "Apartamento 502, Torre I",
      "city": "Bogotá",
      "country": "CO",
      "state": "Cundinamarca",
      "zipCode": "111111",
      "neighborhood": "Chapinero"
    },
    "shippingAddress": {
      "addressLine1": "Calle 34 # 56 - 78",
      "addressLine2": "Apartamento 502, Torre I",
      "city": "Bogotá",
      "country": "CO",
      "state": "Cundinamarca",
      "zipCode": "111111"
    }
  },
  "bankTransfer": {
    "bankAccount": "1234567890",
    "routingNumber": "021000021",
    "beneficiaryName": "John Doe"
  },
  "issuerId": "issuer_xxx",
  "otp": "123456",
  "ticket": {
    "benefitType": "FOOD"
  },
  "wallet": {
    "cardData": {
      "type": "CREDIT"
    }
  }
}
```

`type` and `vaultedToken` are not part of `TransactionData`; they live on [`PaymentMethodSelected`](/docs/yuno-sdk/reference/objects-you-pass#payment-method-selected).

<Warning>
`card.expirationYear` is the **two-digit** year: `28` means 2028. The SDK passes `TransactionData` through verbatim: it does not normalize a four-digit year, so `2028` reaches the backend as-is and is not a valid value.
</Warning>

## Top-level objects

| Field | Description |
|---|---|
| `issuerId` | Identifier of the issuer for the payment method, when applicable. |
| `vaultOnSuccess` | When `true`, saves the payment method for the customer if the payment succeeds. |
| `card` | Card data (number, expiration, security code, holder, brand, type). `expirationYear` is two-digit (`28` for 2028). |
| `installment` | Installment plan and value. |
| `threeDSecure` | 3DS setup identifier when 3DS is configured separately. |
| `bankTransfer` | Bank transfer details (beneficiary, account, routing). |
| `wallet` | Wallet-specific card data (e.g., card type). |
| `ticket` | Ticket-based payment data (e.g., benefit type for food/meal vouchers). |
| `otp` | One-time password, when the payment method requires it. |
| `customer` | Customer information (name, email, document, phone, billing and shipping addresses). |
