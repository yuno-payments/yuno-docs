One integration, every platform. Yuno's SDKs for iOS, Android, and Web 
share the same unified API, so what you build once works everywhere: the 
same `Transaction`, the same `start()`, the same setup.

Initialize the SDK with your API key and start a `Transaction` for each 
payment or enrollment. From there the SDK takes your shopper from picking 
a method to a finished payment: forms, tokenization, 3DS, and the final 
status, all handled for you.

## Start with the default checkout

The SDK ships a complete checkout: method list, forms, 3DS, and results. 
Yuno renders and runs everything; you only listen for the result with 
`onStatus`.

The form it renders is tuned so shoppers finish in seconds, with nothing 
to configure. See 
[how the form behaves](/docs/yuno-sdk/features/form-behavior) for more 
examples of what makes the checkout faster.

<Card title="Use our default checkout" icon="wand-magic-sparkles" href="https://sdk-playground.internal-tools.y.uno/#/playground/full">
  **Recommended.** Nothing to build and nothing to override. 
  **See it live in the playground →**
</Card>

Want more control? Override just the piece you need. Everything else 
keeps working by default:

| You want | Use |
|---|---|
| Your own loading UI | [`showLoading`](/docs/yuno-sdk/controllers/show-loading) |
| The SDK's forms placed in your own screens (mobile only) | [`showView`](/docs/yuno-sdk/controllers/show-view) |
| Your own form UI, with data you collect yourself | [`transactionData`](/docs/yuno-sdk/reference/transaction-data) |
| Your backend to create the payment | [`createPayment`](/docs/yuno-sdk/controllers/create-payment) |

Not sure which pieces you need? [Where do I start?](/docs/yuno-sdk/where-do-i-start) 
walks you through each decision, case by case.

## Choose a session type

The same `Transaction` class handles two flows:

- Pass a **`checkoutSession`** to process a payment.
- Pass a **`customerSession`** to enroll a payment method without 
  charging.

See [Sessions](/docs/basic-concepts/sessions) for details.

## Backend requirements

The SDKs are client-side only. Your backend must:

1. Create checkout or customer sessions.
   - **Checkout session**: see [`POST /v1/checkout/sessions`](https://docs.y.uno/reference/checkout-sessions/create-checkout-session).
   - **Customer session**: see [`POST /v1/customers/sessions`](https://docs.y.uno/reference/customer-sessions-enrollment/create-customer-session).

See [Get Started](/docs/yuno-sdk/get-started) for the full backend 
integration walkthrough.

## Migrating from a previous version

If you're currently using one of the legacy SDKs (Full, Lite, Seamless, 
Render, Headless, Secure Fields), the new unified API replaces all of 
them with a single `Transaction` class. Your existing integration will 
continue to work, but new features and improvements ship in the 
unified SDK.

See the [Migration guide](/docs/yuno-sdk/migration/overview) for a mapping from 
legacy modes to the new API and step-by-step instructions for each 
platform.
