title: "Stripe-compatible Checkout"
description: "Create Yuno payment links using Stripe's Checkout Sessions request shape, and receive Stripe-shaped webhooks — no changes to an existing Stripe integration."
---

<Note>
  This feature is enabled per organization. Contact your Key Account Manager (KAM) to activate it for your account.
</Note>

## Overview

The Stripe-compatible Checkout lets a merchant that already integrates Stripe's
**Checkout Sessions** API create a **Yuno payment link** by sending the exact
same request they send to Stripe. Yuno maps the Stripe request to a payment
link, answers with a Stripe-shaped `checkout.session` object, and — when the
link is paid — relays a Stripe-shaped `checkout.session.completed` webhook.

The goal is a drop-in migration: point the base URL at Yuno, keep the Stripe
request/response and webhook contract.

```
POST https://api.y.uno/v1/stripe-proxy/hosted-page
```

## Authentication

Unlike Stripe, the request is authenticated with **Yuno credentials**, not a
Stripe secret key. The merchant's Stripe credentials are resolved server-side —
you do **not** send a Stripe `Authorization` header.

<ParamField header="PUBLIC-API-KEY" type="string" required>
  Your Yuno public API key.
</ParamField>

<ParamField header="PRIVATE-SECRET-KEY" type="string" required>
  Your Yuno private secret key.
</ParamField>

<ParamField header="X-account-code" type="string" required>
  The Yuno account the payment link is created under.
</ParamField>

<ParamField header="X-Idempotency-Key" type="string" required>
  A unique key so retries create the payment link only once.
</ParamField>

<ParamField header="X-Subscription-Plan-Id" type="string">
  Optional. The Yuno plan id used for `mode=subscription`. When present it is
  propagated to the payment link; when absent, a subscription session is still
  accepted.
</ParamField>

## Creating a session

Send a Stripe Checkout Session body (form-urlencoded or JSON). Line items may
arrive as a Stripe **`price`** (resolved against Stripe) or as inline
**`price_data`** (no Stripe lookup).

<CodeGroup>

```bash One-time payment (price_data)
curl --location 'https://api.y.uno/v1/stripe-proxy/hosted-page' \
  --header 'PUBLIC-API-KEY: <your-public-key>' \
  --header 'PRIVATE-SECRET-KEY: <your-private-secret>' \
  --header 'X-account-code: <your-account-code>' \
  --header 'X-Idempotency-Key: <unique-key>' \
  --header 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'mode=payment' \
  --data-urlencode 'line_items[0][price_data][currency]=usd' \
  --data-urlencode 'line_items[0][price_data][unit_amount]=2000' \
  --data-urlencode 'line_items[0][price_data][product_data][name]=Kimi Pro' \
  --data-urlencode 'line_items[0][quantity]=1' \
  --data-urlencode 'success_url=https://merchant.com/success?session_id={CHECKOUT_SESSION_ID}' \
  --data-urlencode 'cancel_url=https://merchant.com/cancel'
```

```bash Existing Stripe price
curl --location 'https://api.y.uno/v1/stripe-proxy/hosted-page' \
  --header 'PUBLIC-API-KEY: <your-public-key>' \
  --header 'PRIVATE-SECRET-KEY: <your-private-secret>' \
  --header 'X-account-code: <your-account-code>' \
  --header 'X-Idempotency-Key: <unique-key>' \
  --header 'Content-Type: application/x-www-form-urlencoded' \
  --data-urlencode 'mode=payment' \
  --data-urlencode 'line_items[0][price]=price_123' \
  --data-urlencode 'line_items[0][quantity]=1' \
  --data-urlencode 'success_url=https://merchant.com/success?session_id={CHECKOUT_SESSION_ID}'
```

</CodeGroup>

The response is a Stripe **`checkout.session`** object. While the session is
open, `url` is the Yuno hosted-checkout page the customer pays on:

```json
{
  "id": "cs_test_8e5af02ee6174cb5a6f10abf797f96ec",
  "object": "checkout.session",
  "mode": "payment",
  "status": "open",
  "payment_status": "unpaid",
  "amount_total": 2000,
  "currency": "usd",
  "success_url": "https://merchant.com/success?session_id={CHECKOUT_SESSION_ID}",
  "url": "https://checkout.y.uno/payment?session=4582bdac-d25e-4f61-88c3-7c05a6b0f775"
}
```

<Note>
  The `cs_...` id is a reversible encoding of the Yuno payment link code — no
  extra storage is involved. `GET`/expire behave like Stripe: `url` is present
  only while the session is `open`.
</Note>

## Subscriptions

Send `mode=subscription` with a **recurring** price. Yuno creates a Stripe
subscription and stores its id on the payment link, so the paid webhook carries
the Stripe `subscription`.

<ParamField body="mode" type="string">
  Use `subscription` when a line item's price is recurring. `X-Subscription-Plan-Id`
  is optional.
</ParamField>

## Webhooks

When the payment link is paid, Yuno relays the event to your configured webhook
URL as a signed Stripe event:

- `checkout.session.completed` when the payment succeeds — including
  `subscription` for `mode=subscription`.
- `checkout.session.expired` when the link expires or is canceled.

The event is signed with the standard Stripe **`Stripe-Signature`** header
(`t=<timestamp>,v1=<HMAC-SHA256>`), so your existing Stripe signature
verification works unchanged.

```json
{
  "id": "evt_...",
  "object": "event",
  "api_version": "2024-04-10",
  "type": "checkout.session.completed",
  "data": {
    "object": {
      "id": "cs_test_8e5af02ee6174cb5a6f10abf797f96ec",
      "object": "checkout.session",
      "status": "complete",
      "payment_status": "paid",
      "subscription": "sub_1U84RZ..."
    }
  }
}
```

## Errors

Errors are returned in Stripe's shape so existing error handling keeps working:

```json
{
  "error": {
    "type": "invalid_request_error",
    "code": "parameter_missing",
    "message": "Missing required param: success_url.",
    "param": "success_url"
  }
}
```

An organization that is not enabled for this feature receives
`403` with `product_not_enabled`.
