PayPal is a global digital wallet that allows customers to pay using their PayPal balance, linked bank accounts, or stored credit and debit cards. In supported regions (such as the United States), shoppers can also complete purchases using **Venmo**.

## Key features

* **Global coverage**: Accept payments from millions of active PayPal accounts worldwide.
* **Venmo support**: When your PayPal connection's `ENABLE_FUNDING` parameter includes `venmo`, the Web SDK renders a Venmo button under the PayPal button once PayPal confirms the buyer is eligible (a US buyer paying in USD).
* **Express checkout**: Render standalone PayPal and Venmo buttons directly on product, cart, or payment pages.
* **Vaulting & Pay Later**: Support billing agreements and installments (Pay in 4 / Pay Later) where eligible.

## SDK integration

PayPal is available as an express button across Web SDK flows (Full Checkout, Lite, and Seamless) as well as the Yuno SDK.

### Express button configuration

Pass `externalButtons.paypal` in `startCheckout()` or `startSeamlessCheckout()` to customize button appearance:

```javascript
await yuno.startCheckout({
  checkoutSession,
  countryCode: 'US',
  language: 'en',
  externalButtons: {
    paypal: {
      color: 'gold',      // 'gold' | 'blue' | 'silver' | 'white' | 'black'
      shape: 'rect',      // 'rect' | 'pill' | 'sharp'
      label: 'paypal',    // 'paypal' | 'checkout' | 'buynow' | 'pay' | 'installment'
      layout: 'vertical', // 'vertical' | 'horizontal'
      height: 45,         // 25 to 55 px
      borderRadius: 4,
    },
  },
})
```

For custom Braintree integrations using PayPal, configure `externalButtons.paypalBraintree` with shipping callbacks such as `onShippingAddressChange`. See the [Web SDK reference](/docs/sdks/resources/references/web#paypal-braintree) for full options.

### Enrollment flow

For recurring payments or tokenization, mount the PayPal button in enrollment mode using `mountEnrollmentLite()`. See [PayPal enrollment with element render mode](/docs/sdks/lite-web/enrollment#paypal-enrollment-with-element-render-mode).

## Direct integration with a Braintree nonce

If you collect PayPal in your own checkout with the Braintree JS SDK and call Yuno server to server, send the single-use Braintree nonce on a `DIRECT` payment. Yuno forwards it to the Braintree connection, which charges it and, with `vault_on_success`, vaults the PayPal account.

1. Collect the PayPal approval with the Braintree JS SDK and get the nonce.
2. Create the payment with [Create Payment](/reference/payments/create-payment): `workflow` `DIRECT`, `payment_method.type` `PAYPAL_BRAINTREE`, the nonce in `payment_method.detail.wallet.provider_payment_token` and, to save the account, `payment_method.vault_on_success` `true`.
3. On success, the payment returns `payment_method.vaulted_token`. Charge later payments with that `vaulted_token`.
4. When you need the Braintree payment method id (for example, to share the PayPal account with a partner through the Braintree Grant API), read it from [Retrieve Payment Method](/reference/payment-methods-checkout/retrieve-payment-method-by-id-checkout) with the `vaulted_token`, in `provider.token`. The payment response does not include it.

```json
{
  "account_id": "<ACCOUNT_ID>",
  "merchant_order_id": "order-1234",
  "country": "US",
  "amount": { "currency": "USD", "value": 50 },
  "workflow": "DIRECT",
  "customer_payer": { "id": "<CUSTOMER_ID>" },
  "payment_method": {
    "type": "PAYPAL_BRAINTREE",
    "vault_on_success": true,
    "detail": {
      "wallet": {
        "provider_payment_token": "<BRAINTREE_NONCE>"
      }
    }
  }
}
```

Rules for `provider_payment_token`:

* Accepted only on the `DIRECT` workflow; `REDIRECT` and `SDK_CHECKOUT` return `400 INVALID_REQUEST`.
* Must not be blank and must not be combined with `wallet.payment_token`, `wallet.cryptogram`, `payment_method.token` or `payment_method.vaulted_token`.
* The nonce is single use: send a new one on every payment that uses it. Yuno does not store it.

## Mobile browser presentation

When shoppers trigger PayPal or Venmo express checkout on mobile devices:
* **iOS browsers (Safari, Chrome, Firefox, Edge on iOS), including Venmo**: By default, mobile browsers opening popups freeze background browser tabs, which can interrupt payment handshakes. The Web SDK can show PayPal and Venmo in an in-page modal iframe overlay instead, keeping the merchant page active while the order is handed off. The overlay shipped in Web SDK 1.11.40 and is off by default; Yuno enables it per account.
* **Desktop**: Desktop browsers (such as macOS Safari) always use a popup window.
* **Order generation time**: The SDK logs when generating the order takes longer than 30 seconds, without failing the session or returning an error to the shopper.
