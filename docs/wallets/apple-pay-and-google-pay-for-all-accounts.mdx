---
title: "Apple Pay and Google Pay for all accounts"
description: "Set up one Apple Pay or Google Pay connection for your whole organization and use it in every account, including accounts you create later."
---

An organization wallet connection is one Apple Pay or Google Pay connection that belongs to your organization instead of to a single account. Every account in the organization uses it, including accounts you create later, so you configure the wallet once.

Organization wallet connections are available for:

- **Apple Pay** with your own certificates.
- **Google Pay** in Yuno gateway mode or partner gateway mode.

<Note>
The wallet only covers how the customer pays. The purchase itself is still routed by each account's **card routing**. An account without a published card route is not offered the wallet until it publishes one.
</Note>

## Create the organization connection

Create the connection with [Create a Connection](/reference/organizations/connections/create-connection), with `scope` set to `"ORGANIZATION"`. An organization connection belongs to no account, so don't send the `X-account-code` header.

Two extra fields are required:

- `organization_connection_confirmation`: send `true` to confirm that the connection reaches every account in the organization, including accounts created later.
- `checkout_activation`: how the wallet appears in each account's checkout.
  - `"AVAILABLE"`: the wallet is available to every account, and each account turns it on in its own checkout.
  - `"ENABLED"`: the wallet is switched on in every account's checkout at once.

```bash
curl -X POST 'https://api.y.uno/v1/connections' \
  -H 'public-api-key: <YOUR_PUBLIC_KEY>' \
  -H 'private-secret-key: <YOUR_SECRET_KEY>' \
  -H 'Content-Type: application/json' \
  -H 'X-Idempotency-Key: <UUID>' \
  -d '{
    "scope": "ORGANIZATION",
    "organization_connection_confirmation": true,
    "checkout_activation": "ENABLED",
    "merchant_connection_id": "apple-pay-org-001",
    "provider_id": "<APPLE_PAY_PROVIDER_ID_FROM_CATALOG>",
    "payment_methods": ["APPLE_PAY"],
    "params": [
      { "param_id": "<PARAM_ID_FROM_CATALOG>", "value": "<VALUE>" }
    ]
  }'
```

Get the `provider_id` and the params from the [provider catalog](/reference/organizations/connections/get-provider-catalog). For Apple Pay, the connection must use your own certificates; see [Apple Pay prerequisites](/docs/wallets/apple-pay/prerequisites-apple-pay).

When an account reads the organization connection, every param value is masked as `***`.

If the request is rejected, check the error code:

| Code | What to do |
| --- | --- |
| `ORGANIZATION_CONNECTION_CONFIRMATION_REQUIRED` | Send `organization_connection_confirmation: true`. |
| `ORGANIZATION_SCOPE_NOT_SUPPORTED_FOR_PROVIDER` | Only Apple Pay and Google Pay can be organization connections. |
| `ORGANIZATION_APPLE_PAY_REQUIRES_OWN_CERTIFICATES` | Configure the Apple Pay connection with your own certificates. |
| `ORGANIZATION_CHECKOUT_ACTIVATION_REQUIRED` | Send `checkout_activation` as `AVAILABLE` or `ENABLED`. |
| `ORGANIZATION_ACCOUNTS_UNAVAILABLE` (`503`) | The organization's accounts could not be listed. Nothing changed; retry the request. |

## How accounts use it

You don't need to change anything in each account. An account that has no wallet route of its own for Apple Pay or Google Pay uses the organization connection automatically, as long as the account has a published card route.

An account that already has its own wallet route keeps using it.

## Move an account to the organization connection

To move an account that has its own wallet route to the organization connection, publish a route for that account whose `APPLE_PAY` or `GOOGLE_PAY` step uses the organization connection's `connection_id`. You can do this from the Dashboard or with [Create a Routing](/reference/organizations/routing/create-routing) or [Update a Routing](/reference/organizations/routing/update-routing).

## Stop one account from using it

How an account stops depends on how it uses the organization connection.

- **It uses it automatically** (it has no wallet route of its own): the automatic use stops once the account has its own wallet route, published or archived. To keep offering the wallet with the account's own connection, create an account connection for Apple Pay or Google Pay and publish a wallet route whose step uses it. To stop offering the wallet, archive the account's wallet route.
- **Its wallet route names the organization connection:** change the route's step to an account connection of its own and publish it, or archive the route to stop offering the wallet.

The other accounts keep using the organization connection.

## Stop it reaching accounts created later

An organization connection reaches every account, including new ones. To stop that while keeping the wallet in your current accounts:

1. Create an account connection for Apple Pay or Google Pay in each current account, and publish a wallet route in each account that uses it.
2. Delete the organization connection with [Delete a Connection](/reference/organizations/connections/delete-connection).

If a route still references the organization connection, the delete fails with `409 CONNECTION_IN_USE` and `details.accounts` lists the accounts whose routes still reference it. Repoint or archive those routes, then retry.

## Edit, pause and delete

Edit the organization connection with [Update a Connection](/reference/organizations/connections/update-connection) and delete it with [Delete a Connection](/reference/organizations/connections/delete-connection). Send these requests without `X-account-code` and without `account_id`: an organization connection belongs to no account. A change applies to every account that uses it.

On an update you can also change `checkout_activation`. The new value applies only to accounts where the wallet is added to the checkout after the change; accounts that already show the wallet keep their current setting.

Pause and unpause the organization connection from the Dashboard. A pause always goes through, so you can stop the wallet in every account at once.

If an update or delete is rejected, check the error code:

| Code | What to do |
| --- | --- |
| `ORGANIZATION_SCOPE_NOT_SUPPORTED` | The request was sent with an account (`X-account-code` or `account_id`). Send it again without the account. |
| `ORGANIZATION_ACCOUNTS_UNAVAILABLE` (`503`) | The organization's accounts could not be listed. Nothing changed; retry the request. |
