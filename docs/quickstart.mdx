## Before you start

You need these facts for every call on this page.

| Fact | Value |
|---|---|
| Account code | `account_id` in the dashboard, under **Developers** |
| Keys | `public-api-key` and `private-secret-key`, both starting with `sandbox_` |
| Base URL | `https://api-sandbox.y.uno/v1` (keep the `/v1`) |
| Amounts | `amount.value` is a number next to a `currency`. This page sends `25` with `USD` |
| Tools | Node 18 or later, or `curl` |

<Step titleSize="h3" title="Get your sandbox credentials">

Log in to the [Yuno dashboard](https://dashboard.y.uno/) and open **Developers** to find three values:

* **Account code**, shown as `account_id` in the dashboard
* **`public-api-key`**
* **`private-secret-key`**

Sandbox keys start with `sandbox_`. Production keys are different and start with `prod_`.

If you do not have an account yet, ask your Yuno contact or write to [sales@y.uno](mailto:sales@y.uno). There is no self-serve signup today.

Set your credentials as environment variables:

```bash Shell
export YUNO_PUBLIC_API_KEY="sandbox_..."
export YUNO_PRIVATE_SECRET_KEY="sandbox_..."
export YUNO_ACCOUNT_ID="your-account-code"
```

Prove the keys by creating a customer. The base URL is `https://api-sandbox.y.uno/v1`.

<CodeGroup>

```bash cURL
curl --request POST \
  --url https://api-sandbox.y.uno/v1/customers \
  --header "public-api-key: $YUNO_PUBLIC_API_KEY" \
  --header "private-secret-key: $YUNO_PRIVATE_SECRET_KEY" \
  --header "content-type: application/json" \
  --data '{
    "merchant_customer_id": "customer-0001",
    "first_name": "John",
    "last_name": "Doe",
    "email": "john.doe@example.com"
  }'
```


5. Open [Checkout builder](https://dashboard.y.uno/checkout-builder), turn on **Card**, and publish the settings.

<Step titleSize="h3" title="Choose how the payment is created">

The `workflow` field tells Yuno who creates the payment. Pick one, then use the matching tab in step 4.

| Workflow | Who creates the payment | Use it when |
|---|---|---|
| `SDK_SEAMLESS` | The SDK creates the payment | You want the fewest moving parts. Recommended |
| `SDK_CHECKOUT` plus a `createPayment` callback | Your backend creates it, from the one-time token the SDK hands you | You add order data, fraud checks or idempotency on your server |
| `DIRECT` | Your backend sends the raw card data | You have PCI DSS scope. Otherwise use it for sandbox tests only |

A session and an integration that disagree end in `INTERNAL_ERROR`. See [Get started with the Yuno SDK](/docs/yuno-sdk/get-started) and [Direct flow](/docs/direct-integration-use-cases/direct-flow) for each path in full.

<Check>
**Gate passed when** you can name the workflow you will send: `SDK_SEAMLESS`, `SDK_CHECKOUT` or `DIRECT`. The checkout session (SDK paths) or the payment (`DIRECT`) carries it in the `workflow` field.
</Check>

</Step>

The `DIRECT` workflow is a back-to-back payment where your server sends the card data. Use the customer `id` you saved as `YUNO_CUSTOMER_ID` in step 1.

Create the payment with a test card. Send a new `X-Idempotency-Key` with each payment.

<CodeGroup>

```bash cURL

  --url https://api-sandbox.y.uno/v1/payments \

  --header "private-secret-key: $YUNO_PRIVATE_SECRET_KEY" \
  --header "X-Idempotency-Key: $(uuidgen)" \
  --header "content-type: application/json" \

    "account_id": "'"$YUNO_ACCOUNT_ID"'",
    "merchant_order_id": "order-0001",

    "payment_method": {
      "type": "CARD",
      "detail": { "card": { "card_data": {
        "number": "4507990000000002",
        "expiration_month": 11,
        "expiration_year": 28,
        "security_code": "123",
        "holder_name": "John Doe"
      } } }
    }
  }'
```

<Tab title="SDK_CHECKOUT">

Your server creates the checkout session with `workflow: "SDK_CHECKOUT"`. The browser starts the transaction and passes a `createPayment` callback. The SDK hands the callback a one-time token, and your backend creates the payment from it.

**On your server**, create the checkout session with the customer from step 1:

```bash cURL
curl --request POST \
  --url https://api-sandbox.y.uno/v1/checkout/sessions \
  --header "public-api-key: $YUNO_PUBLIC_API_KEY" \
  --header "private-secret-key: $YUNO_PRIVATE_SECRET_KEY" \
  --header "content-type: application/json" \
  --data '{
    "account_id": "'"$YUNO_ACCOUNT_ID"'",
    "merchant_order_id": "order-0001",
    "payment_description": "First test payment",
    "country": "US",
    "customer_id": "'"$YUNO_CUSTOMER_ID"'",
    "amount": { "currency": "USD", "value": 25 },
    "workflow": "SDK_CHECKOUT"
  }'
```

**In the browser**, start the transaction and override `createPayment`. Send `token.token` and `token.checkout_session` to your backend:

```html Browser
<div id="payment-form"></div>
<script src="https://sdk-web.y.uno/v2.1.2/main.js"></script>
<script>
  async function startYuno() {
    const sdkPayments = await SdkPayments.initialize("your-public-api-key");
    const transaction = sdkPayments.transaction({
      checkoutSession: "checkout-session-from-your-server",
      countryCode: "US",
      elementSelector: "#payment-form",
      createPayment: async (token) => {
        await fetch("/api/pay", {
          method: "POST",
          headers: { "content-type": "application/json" },
          body: JSON.stringify({
            token: token.token,
            checkout_session: token.checkout_session,
          }),
        });
      },
      onStatus: (result) => console.log("Final status:", result.status),
    });
    await transaction.start({ paymentMethod: { type: "CARD" } });
  }

  if (window.SdkPayments) {
    startYuno();
  } else {
    window.addEventListener("sdk-payments-ready", startYuno);
  }
</script>
```

Settle the promise on every path, including a network failure, or the transaction stays in progress. See [`createPayment`](/docs/yuno-sdk/controllers/create-payment).

**On your server again**, your `/api/pay` handler creates the payment with `POST /v1/payments`. Send the token in `payment_method.token` and the session in `checkout.session`:

```javascript Node.js
// token and checkoutSession come from the browser request body
async function createPayment({ token, checkoutSession }) {
  const res = await fetch("https://api-sandbox.y.uno/v1/payments", {
    method: "POST",
    headers: {
      "public-api-key": process.env.YUNO_PUBLIC_API_KEY,
      "private-secret-key": process.env.YUNO_PRIVATE_SECRET_KEY,
      "X-Idempotency-Key": crypto.randomUUID(),
      "content-type": "application/json",
    },
    body: JSON.stringify({
      account_id: process.env.YUNO_ACCOUNT_ID,
      merchant_order_id: "order-0001",
      description: "First test payment",
      country: "US",
      amount: { currency: "USD", value: 25 },
      customer_payer: { id: process.env.YUNO_CUSTOMER_ID },
      payment_method: { token },
      checkout: { session: checkoutSession },
    }),
  });
  return res.json();
}
```

Enter the test card **4507 9900 0000 0002**, expiry **11/28**, CVV **123**, name **John Doe**, then click Pay. The response has the same shape as the `DIRECT` response above.

## Troubleshooting

<AccordionGroup>
<Accordion title="The API returns 401">
The `public-api-key` or `private-secret-key` header is missing or wrong. Sandbox and production use different keys, so check that you copied the sandbox keys from the dashboard in Test Mode. See [Authentication](/reference/getting-started/authentication).
</Accordion>
<Accordion title="The payment ends in INTERNAL_ERROR">
The `workflow` does not match your integration. Use `DIRECT` when your server sends the card, and `SDK_SEAMLESS` on the checkout session when the Web SDK creates the payment.
</Accordion>
<Accordion title="No provider processes the payment">
Card has no published route. Open [Routing](https://dashboard.y.uno/routing) and check that the Card route with the Yuno Test Payment Gateway is under the **Published** tab, and that Card is turned on in the [Checkout builder](https://dashboard.y.uno/checkout-builder).
</Accordion>
<Accordion title="The card is declined">
Test cards are specific to a provider. The cards in this Quickstart only work when your sandbox routes Card to the Yuno Test Payment Gateway. Other results are listed on the [Yuno Test Payment Gateway](/docs/direct-integration-use-cases/yuno-testing-gateway) page.
</Accordion>
</AccordionGroup>
