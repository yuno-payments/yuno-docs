The Yuno iOS SDK stays small on purpose: every third-party native SDK ships as a **separate, optional module**. You add only the modules your integration needs, and the Yuno SDK picks them up automatically when a checkout uses the matching provider. Your payment and enrollment code does not change.

<Note>
  Installing a module does not make the SDK use it: a module runs only when the provider is enabled for your Yuno account and the backend requests it for the current transaction.
</Note>

## Available modules

| Module | What it adds | Minimum iOS |
|---|---|---|
| ClearSale antifraud | Collects the ClearSale device fingerprint and attaches it to the payment | 14.0 |
| Koin antifraud | Collects the Koin device fingerprint and attaches it to the payment | 14.0 |
| Riskified antifraud | Starts the Riskified beacon with the checkout session and attaches that session to the payment | 14.0 |
| [Signifyd antifraud](/docs/sdks/external-native-modules/signifyd-ios) | Profiles the device with Signifyd's Profiling SDK and attaches the session ID to the payment | 14.0 |
| [Netcetera 3DS](/docs/sdks/external-native-modules/netcetera-3ds-ios) | Runs 3D Secure challenges natively in your app, for payments and enrollment | 14.0 |
| Revolut Pay | Native Revolut Pay checkout on top of Revolut's official SDK | 15.0 |

Package names:

| Module | Swift Package Manager product | Supported from |
|---|---|---|
| ClearSale antifraud | `YunoAntifraudClearsale` | 2.25.0 |
| Koin antifraud | `YunoAntifraudKoin` | 2.25.0 |
| Riskified antifraud | `YunoAntifraudRiskified` | 2.29.0 |
| Signifyd antifraud | `YunoAntifraudSignifyd` (separate package) | 2.30.0 |
| Netcetera 3DS | `Yuno3DSNetcetera` | 2.25.0 |
| Revolut Pay | CocoaPods pod `YunoRevolutPay`, see [Revolut Pay (CocoaPods only)](#revolut-pay-cocoapods-only) | 2.25.0 to 2.30.0 |

From YunoSDK 2.31.0 the modules are distributed only through Swift Package Manager and work with either `YunoSDK` or `YunoSDK-Static`.

Netcetera has extra setup steps (sandbox certificate), covered in [Netcetera 3DS (iOS)](/docs/sdks/external-native-modules/netcetera-3ds-ios). Signifyd ships in its own package and needs a Signifyd token, covered in [Signifyd antifraud (iOS)](/docs/sdks/external-native-modules/signifyd-ios).

## Installation

Every module lives in the same package as the Yuno SDK, so there is a single URL to add. In Xcode go to **File > Add Package Dependencies...**, add:

```
https://github.com/yuno-payments/yuno-sdk-ios
```

choose the **Up to Next Major Version** rule starting at `2.31.0`, and in the product list tick `YunoSDK` (dynamic) or `YunoSDK-Static` (static), never both, plus the modules you need (`YunoAntifraudClearsale`, `YunoAntifraudKoin`, `YunoAntifraudRiskified`, `Yuno3DSNetcetera`). Nothing else is required: each product brings its own vendor binary.

<Note>
  Signifyd is not in this package: it ships in `yuno-sdk-ios-signifyd` and needs your Signifyd token to download Signifyd's SDK. See [Signifyd antifraud (iOS)](/docs/sdks/external-native-modules/signifyd-ios).
</Note>

### Revolut Pay (CocoaPods only)

`YunoRevolutPay` is available only as a CocoaPods pod, and works with `YunoSDK` up to 2.30.0, the last version published on CocoaPods. Add it next to `YunoSDK` in your Podfile:

```ruby
platform :ios, '15.0'

target 'YourApp' do
  use_frameworks!

  pod 'YunoSDK', '~> 2.25'
  pod 'YunoRevolutPay', '~> 1.0'
end

# Revolut's dependencies declare an old deployment target that
# Xcode 14.3 or later cannot build as-is.
post_install do |installer|
  installer.pods_project.targets.each do |target|
    target.build_configurations.each do |config|
      config.build_settings['IPHONEOS_DEPLOYMENT_TARGET'] = '15.0'
    end
  end
end
```

Then run:

```bash
pod install
```

<Note>
  Revolut Pay installs `lottie-ios` as a dependency, in the 4.4.1 to 4.5.x range.
</Note>

<Note>
  `YunoRevolutPay` pins `RevolutPayments/RevolutPay` to `~> 3.16.0`, because the prebuilt binary is tied to that API. If your Podfile already declares `RevolutPayments`, align it to that range.
</Note>

<Note>
  Revolut Pay returns to your app through a deeplink: forward it to `Yuno.receiveDeeplink(url)` as described in [Handle external browser return](/docs/sdks/full-checkout/ios-payments#step-10-handle-external-browser-return-optional).
</Note>

## Activating a module

Modules **register themselves** when the app launches, with either `YunoSDK` or `YunoSDK-Static`. No code is required beyond adding the product to your target.

Revolut Pay is the exception: call `YunoRevolutPay.register()` **once**, before `Yuno.initialize(...)`, for example in `application(_:didFinishLaunchingWithOptions:)`:

```swift
import YunoSDK
import YunoRevolutPay

YunoRevolutPay.register()

Yuno.initialize(apiKey: "YOUR_API_KEY", config: YunoConfig())
```

<Tip>
  Once a module is registered the Yuno SDK uses it automatically. You do not need to change any payment, enrollment or 3DS code.
</Tip>

## Troubleshooting

<AccordionGroup>
  <Accordion title="Revolut Pay is installed but nothing changes">
    Make sure you call `YunoRevolutPay.register()` before `Yuno.initialize(...)`.
  </Accordion>
  <Accordion title="pod install: required a higher minimum deployment target">
    The `platform` line in your Podfile is below the module's minimum. Use `platform :ios, '15.0'` for `YunoRevolutPay`.
  </Accordion>
  <Accordion title="pod install: CocoaPods could not find compatible versions for pod YunoSDK">
    `YunoRevolutPay` depends on `YunoSDK ~> 2.25`, and the last `YunoSDK` on CocoaPods is 2.30.0. If your Podfile pins an older SDK (for example `'2.24.1'`), relax it to that range.
  </Accordion>
  <Accordion title="pod install: CocoaPods could not find compatible versions for pod RevolutPayments">
    `YunoRevolutPay` requires `RevolutPayments/RevolutPay ~> 3.16.0`. If your Podfile pins another version of `RevolutPayments`, align it to `'~> 3.16.0'` or remove the pin and let `YunoRevolutPay` bring it.
  </Accordion>
  <Accordion title="pod install: SDK does not contain 'libarclite' (YunoRevolutPay)">
    Add the `post_install` hook shown in [Revolut Pay (CocoaPods only)](#revolut-pay-cocoapods-only) so every pod target builds for iOS 15.0.
  </Accordion>
  <Accordion title="Swift Package Manager: duplicate RiskifiedBeacon framework">
    The `YunoAntifraudRiskified` product already brings Riskified's `RiskifiedBeacon` 1.6.4. If your app also adds Riskified's own package, remove it and keep only the Yuno product.
  </Accordion>
  <Accordion title="Revolut Pay never completes after coming back to the app">
    The return deeplink is not reaching the Yuno SDK. Make sure your app declares a URL scheme, that incoming URLs are forwarded to `Yuno.receiveDeeplink(url)`, and that a `guard` on the scheme is not dropping the Revolut Pay return URL (`yourscheme://revolut-pay`).
  </Accordion>
  <Accordion title="Swift Package Manager: no such module 'CSBehavior' when importing YunoAntifraudClearsale">
    Affects `YunoAntifraudClearsale` 1.0.0 only. The module registers itself, so you do not need to import it from Swift: remove the `import YunoAntifraudClearsale` line and the project builds.
  </Accordion>
</AccordionGroup>
