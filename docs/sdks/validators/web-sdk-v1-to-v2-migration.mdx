Drop this file in the root of your project and ask your coding agent:

> List what I must change to move my Yuno Web SDK integration to v2, following this file.

It works as `CLAUDE.md`, `AGENTS.md` or a pasted prompt, with Claude Code, Cursor, Codex or Copilot. It is
read-only: it scans your code and reports, and it changes nothing unless you ask.

**The target.** v2 is the sdk-web 2.x line ("Yuno SDK 2.x", the unified Transaction API). The latest release is
version 2.2.0 (2026-10-27). It is served at
`https://sdk-web.y.uno/v2.2.0/main.js`, and `v2.0.0`, `v2.1.0`, `v2.1.2` are also live. There is no rolling
folder: `/v2/`, `/v2.0/` and `/v2.2/` return 404, so you pin a full version and bump it by hand. The EU host
`sdk-web.prod.eu.y.uno` serves up to `v2.1.2` and returns 404 for `v2.2.0` (at the time of writing). The SRI path is
`https://prod.y.uno/sdk-static-bundles-ms/sdk-web/v2.2.0/main.js`. Public docs: the "SDK" tab
(`docs/yuno-sdk/*`, migration series in `docs/yuno-sdk/migration/web/*`). The "SDKs" tab is the 1.x line.
v1.x stays supported side by side until 2027.

**The source.** v1.11 (`window.Yuno`, rolling `/v1.11/main.js`), the current 1.x line.

```
v1.11                                              v2
<script .../v1.11/main.js>                         <script .../v2.2.0/main.js>
yuno = await Yuno.initialize(key)                  sdk = await SdkPayments.initialize(key)
yuno.startCheckout(cfg)        (or Seamless)       tx = sdk.transaction(cfg)   (session, country, onStatus,
yuno.mountCheckoutLite({...})                           createPayment present = manual, absent = managed)
yuno.mountCheckout()                               tx.start({ paymentMethod })          form or headless
yunoCreatePayment(ott, info, cs)                   tx.getPaymentMethodsViews({...}).paymentMethodList.mount()
yuno.continuePayment()                             createPayment(token)  -> SDK continues by itself
yunoPaymentResult(status) / yunoError(...)         onStatus({ status, substatus, message })
yuno.unmountSdk()                                  await tx.unmount()
```

## What v2 keeps (do not report these as blocking)

- **v2 keeps no v1 alias.** It sets only `window.SdkPayments` and dispatches only `sdk-payments-ready`. It does
  not set `window.Yuno` and never fires `yuno-sdk-ready`. Every `window.Yuno` and `yuno-sdk-ready` use must change.
- **v1.11 already exposes the v2 names.** It sets both globals and fires both events. So
  `window.SdkPayments` and `sdk-payments-ready` in a v1.11 repo are already correct. That rename can ship on 1.11
  first, before the script switch.
- **Unchanged on v2:** the `sdk-payments-*` CSS prefix; the `initialize` options keys (`cookies`, `sdkType`,
  `apiUrl`, `assetUrl`, `plugin`); `clearApiCache()` and `setCanaryMode()` on the instance; `onChange(state)`;
  the options `onPromotionQuoteUpdated`, `externalButtons`, `texts`, `issuersFormEnable`, `showPayButton`,
  `deviceFingerprints`, `paymentListConfig`, `savePaymentMethodEnabled`; the `card` keys `styles`, `type`
  (except `'step'`), `vaultOnSuccess`, `texts`, `documentEnable`, `isCreditCardProcessingOnly`, `fonts`,
  `onChange`, `onGetInstallments`, `onInstallmentSelected`.
- **Silent keys.** v2 forwards unknown or v1-only config keys without any error. Most are never read: the
  feature they controlled just disappears. Mark those rows SILENT. Three v1 keys are still read on 2.2.0:
  `onLoading` is still called when no `showLoading` function is set; `paymentMethodSelected` and
  `yunoPaymentMethodSelected` still fire on every list selection, so keeping one next to `onPaymentSelected`
  gives two calls per selection; `yunoCreatePayment` is merged into `createPayment` in state. Rename them anyway.
- **CSS.** v2 renders `yuno-container-spinner-content` and `yuno-container-spinner-ring` (the loading spinner
  of every mount) and sets `data-yuno-placeholder`. These are v2 names: never report selectors on them.

## How to use

1. **Find the v1 surface.** Run over source, server templates, tag-manager snippets and `package.json`:

```
grep -rnE "window\.Yuno\b|\bYuno\.initialize|yuno-sdk-ready|YunoSDK|sdk-web\.[a-z.]*y\.uno/v[0-9.]+/main\.js|sdk-static-bundles-ms/sdk-web/|loadScript\(|@yuno-payments/sdk-web(-types)?" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
grep -rnE "\.(startCheckout|startSeamlessCheckout|mountCheckout|mountCheckoutLite|mountSeamlessCheckout|mountSeamlessCheckoutLite|mountSeamlessExternalButtons|mountExternalButtons|unmountExternalButton|unmountAllExternalButtons|unmountSeamlessExternalButtons?|mountEnrollmentLite|mountFraud|mountStatusPayment|startPayment|continuePayment|submitOneTimeTokenForm|unmountSdk|showLoader|hideLoader|notifyError|apiClientPayment|apiClientEnroll|continueEnrollment|clickToPay|executeFraudCheck|generateToken\w*|getThreeDSecureChallenge|getContinuePaymentAction|isPaymentMethodAvailable|updateCheckoutSession|refreshPromotionQuote)\(" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
grep -rnE "yunoPaymentResult|paymentResult|yunoError|yunoEnrollmentStatus|enrollmentStatus|yunoCreatePayment|createPayment|yunoPaymentMethodSelected|paymentMethodSelected|onLoading|showLoading|showPaymentStatus|renderMode|viewContainer|onlyExpressPaymentMethods|stickyPayButton|__internal|cardSaveEnable|requiredFieldsOrderedEnabled|topLevelDomain|isRetrying|newCheckoutSession|payment_method\.card\.detail|holder_name|enableV2|enableMultiplesCard|\.render\(" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
grep -rnE "'(FAIL|REJECT|PROCESSING|READY)'|\"(FAIL|REJECT|PROCESSING|READY)\"|type:\s*['\"]step['\"]|checkout/sessions|workflow" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
```

2. **Find any v2 surface already present:** `grep -rnE "SdkPayments\.initialize|\.transaction\(|\.start\(\{|getPaymentMethodsViews|transactionStatus|\.antifraud\(|onStatus|saveCardEnabled|showStatusScreen|sdk-web\.[a-z.]*y\.uno/v2"`.
   A repo with both is mid-migration: report the v1 leftovers on every page that loads the v2 script. At
   runtime, `typeof sdk.transaction === 'function'` means v2; a v1 instance has `startCheckout` and no `transaction`.
3. **Classify each flow** (Lite, Full, Seamless, Seamless Lite, external buttons, headless, Secure Fields,
   enrollment, fraud, status screen) as manual (merchant creates the payment) or managed (SDK creates it).
4. **Map every hit** with the table below, run checks M1 to M25, and write the report.

## Mapping

Sections follow the research table 3.A to 3.H. Kind: KEEP, RENAME, MOVE, BEHAVIOUR, NEW REQUIRED,
REMOVED (no replacement), SILENT (v2 accepts and ignores the old key), BLOCKED (parity gap: report "blocked: parity gap, do not migrate this flow yet", not as a change).

## Checks

Report each as PASS / FAIL / N/A with file:line, and quote the line. Each title ends with the research check id
and a severity: B blocking (no payment or no result), H high (feature silently lost or wrong outcome), M medium
(degraded UX), L low (hygiene), P parity gap (report as blocked, never as a change to make).

### 1. Global and ready event (M1, B)

Look: `window.Yuno`, `Yuno.initialize`, `yuno-sdk-ready`. Still v1: any hit. Change: `window.SdkPayments`, `sdk-payments-ready`, check the global before listening. Symptom: `Yuno is not defined`, init never runs.

### 2. Script URL and loader (M2, B)

Look: script tags, `loadScript`, `sdk-static-bundles-ms`. Still v1: `/v1.11/`, `loadScript()` without `baseUrl`, `sri: true`; also wrong: `/v2/`, `/v2.2/`. Change: full `v2.x.y` URL; EU pages check the EU host has the version. A `v2.0.0` pin that matches the public docs sample is valid, not a finding. Symptom: `sdk.transaction is not a function`, or 404.

### 3. v1 entry points (M3, B)

Look: the second grep. Still v1: any call. Change: per Mapping; REMOVED rows say "no replacement". Symptom: `yuno.startCheckout is not a function`.

### 4. Mode and session workflow (M4, B)

Look: v1 mode (Seamless = managed; `startCheckout` with `yunoCreatePayment` = manual) and the backend `POST /v1/checkout/sessions` body. Change: managed has no `createPayment` and uses `workflow: "SDK_SEAMLESS"`; manual has `createPayment` and the default workflow. Symptom: `onStatus` `INTERNAL_ERROR`.

### 5. `createPayment` signature (M5, B)

Look: `(yuno)?[cC]reatePayment`, `continuePayment`. Still v1: two or three parameters, the first used as a string, the config session used, `continuePayment()`, `notifyError()`. Change: one `token`; send `token.token` and `token.checkout_session`; return a Promise that settles on every path; reject on failure. Rename `yunoCreatePayment`: the 2.2.0 code keeps an alias, but mode selection reads only `createPayment` (verify at runtime). Symptom: Create Payment 4xx, stale-session payment, form stuck.

### 6. Result callbacks and statuses (M6, B)

Look: `yunoPaymentResult`, `paymentResult`, `yunoError`, `enrollmentStatus`, the v1 status strings. Change: one `onStatus(result)` on backend statuses plus `INTERNAL_ERROR` and `USER_CANCEL`; SDK error codes (`FORM_INVALID`, `MERCHANT_CREATE_PAYMENT_FAILED`, `ELEMENT_NOT_FOUND`) are in `message.code` and `substatus` is `null`, so never branch on `substatus` for them; `FORM_INVALID` and retryable declines are not final. Symptom: no result handled, console warns `...created without an onStatus function...`.

### 7. Rendering model (M7, H)

Look: `renderMode`, `viewContainer`, overlay CSS. Change: a sized container and `elementSelector` on `transaction()`. Symptom: form inline instead of modal; `Wrong element selector`. Blocked if the merchant requires a modal.

### 8. Status screen option (M8, H)

Look: `showPaymentStatus`. Change: `showStatusScreen`. Symptom: the SDK result screen shows anyway and `onStatus` waits for the shopper to dismiss it. The public v2.1.0 changelog still says `showPaymentStatus` (doc drift).

### 9. Loading (M9, M)

Look: `onLoading`, `showLoading`, `showLoader`, `hideLoader`. Change: `showLoading: (isLoading) => void`, drop `type`; a boolean must go. Symptom: a kept `onLoading` still runs, so nothing breaks until both are set; `showLoading: true` throws a minified TypeError; `showLoading: false` silently shows the SDK loader. Blocked where the loader is driven by hand with `showLoader`/`hideLoader`.

### 10. List selection and Pay (M10, B)

Look: `paymentMethodSelected`, `startPayment`, `mountCheckout`. Change: `getPaymentMethodsViews`, store `onPaymentSelected`, Pay calls `start({paymentMethod: selected})`, ignore `selectionSource: 'auto'`. Symptom: the list shows and nothing pays.

### 11. External buttons (M11, H)

Look: `mount(Seamless)?ExternalButtons`, `unmount*ExternalButton*`. Change: one view `mount` per wallet, awaited or caught. Symptom: wallet missing, unhandled rejection. The non-seamless family is blocked.

### 12. `card` keys (M12, H)

Look: `cardSaveEnable`, `requiredFieldsOrderedEnabled`, `type: 'step'`. Change: `saveCardEnabled`; drop the other. Symptom: save-card checkbox silently gone. `'step'` is blocked.

### 13. Removed options (M13, H)

Look: `onlyExpressPaymentMethods`, `stickyPayButton`, `__internal`, `renderMode`. Change: report each; decide with the merchant. Symptom: behaviour silently missing. `onLoading` is not in this list: it is still called (M9). The parity-gap items are blocked.

### 14. Secure Fields (M14, B)

Look: `secureFields(`, `.render(`, `generateToken*`, `enableV2`, `enableMultiplesCard`. Change: `tx.secureFields()`, `.mount`, pay with `start` and only non-PCI keys in `data.card` (`holderName`, `type`, `installment`, `customer`, `vaultOnSuccess`); gate Pay on `!error && isDirty`. Symptom: `render is not a function`, PCI-keys error.

### 15. Headless (M15, B)

Look: `apiClientPayment`, `generateToken`, `getThreeDSecureChallenge`, `payment_method.card.detail`, `holder_name`. Change: camelCase `data.card` plus `createPayment`; delete 3DS code; one headless `start()` per transaction. Symptom: tokenization error, empty fields.

### 16. Enrollment (M16, B)
