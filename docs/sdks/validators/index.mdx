A validator is a Markdown checklist written for an AI coding agent. You give it to the agent that works in your repository, and the agent reads your code against every check in the list. For each check it reports PASS, FAIL or N/A, quotes the file and line that proves the result, and explains what breaks and how to fix it.

Validators are read-only. The agent searches and reads your code and changes nothing unless you ask it to.

## Choose a validator

| Your integration | Validator |
| --- | --- |
| Web SDK v1 (1.11) with Yuno's UI: Full checkout, Lite, Seamless, external wallet buttons, Enrollment Lite, status screens | [Web SDK v1: checkout flows](/docs/sdks/validators/web-sdk-v1-checkout-flows) |
| Web SDK v1 (1.11) without Yuno's UI: headless payment and enrollment, two-card split, Secure Fields | [Web SDK v1: headless and Secure Fields](/docs/sdks/validators/web-sdk-v1-headless-secure-fields) |
| Web SDK v2 (`window.SdkPayments` and `sdk.transaction`) | [Web SDK v2](/docs/sdks/validators/web-sdk-v2) |
| Web SDK v1 (1.11) that you plan to move to v2 | [Web SDK v1 to v2 migration](/docs/sdks/validators/web-sdk-v1-to-v2-migration) |
| VTEX headless storefronts and apps | [VTEX validators](/docs/plugins/vtex/validators/index) |

If your repository uses both Yuno's UI and Secure Fields, run both v1 validators.

## Get the raw file

Every validator page is also served as plain Markdown. Add `.md` to the page URL to get the file the agent needs:

```text
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-checkout-flows.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-headless-secure-fields.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v2.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-to-v2-migration.md
```

## Run it with Claude Code

<Steps>
  <Step title="Save the validator in your repository root">
    ```bash
    curl -o CLAUDE.md https://docs.y.uno/docs/sdks/validators/web-sdk-v1-checkout-flows.md
    ```
  </Step>
  <Step title="Ask Claude Code to validate">
    ```text
    Validate my Yuno Web SDK integration following CLAUDE.md
    ```
  </Step>
  <Step title="Read the report">
    Claude Code answers with one line per check and a list of failures ordered by impact, each with a one-line fix.
  </Step>
</Steps>

<Warning>
If your repository already has a `CLAUDE.md` or `AGENTS.md`, do not overwrite it. Save the validator under another name, such as `yuno-validator.md`, and ask the agent to validate your integration following that file.
</Warning>

## Run it with Cursor, Codex or Copilot

Save the validator as `AGENTS.md` in the repository root and ask the agent to validate your Yuno integration following `AGENTS.md`. You can also paste the whole file into the chat as the prompt.

## When a check fails

Fix the failures in the order the report lists them: blocked payments first, then lost or wrong results, then degraded experience. If you need help from Yuno support, send:

- The full validator report.
- The diagnostics listed in the "Diagnostics to capture" section of the validator you ran. They include the SDK version, the checkout session ID, the UTC time of the attempt and the console and network errors.

Remove API keys, card data and personal data before you send anything.

## How the checks were built

The checks were derived from the Web SDK source code and from real support tickets. Where a validator says the public docs and the code disagree, follow the code. Yuno is fixing those docs pages.
