## v2.1.2
*October 20, 2026*

**Transaction**

- <ChangelogBadge type="added" /> **Check whether a payment method will render before listing it**  
  New [`transaction.isPaymentMethodAvailable({ paymentMethodType })`](/docs/yuno-sdk/reference/objects-you-receive#checking-payment-method-availability-web) resolves to `true` or `false` for any payment method type, with the same decision the SDK takes before it shows that method for the checkout session. Merchants that draw their own payment method list can call it and hide the methods that would not render.

**Checkout**

- <ChangelogBadge type="fixed" /> **Payment method names keep the checkout font**  
  On host pages that set fonts on every element with a `*` rule, the payment method name and its Checkout Builder description in the radio list use the checkout font, weight and spacing.

- <ChangelogBadge type="fixed" /> **Checkbox texts keep the checkout font**  
  On host pages that set fonts on every element with a `*` rule, the text of every checkbox (save card, save on success, billing same as shipping, mandate consent, Click to Pay sign-up and remember me) and of the Click to Pay radio options uses the checkout font, weight and spacing, like the payment method names (sdk-web-core 9.4.1).

## v2.1.1
*October 19, 2026*

**Card Payments**

- <ChangelogBadge type="fixed" /> **Card CVC Length Follows The Card Service**  
  The CVC field now enforces the `security_code_length` the card service returns for the card's brand, for a new card and for a saved card. A 4-digit CVC typed on a 3-digit brand (Elo, Alelo, Edenred, Sodexo, VR) shows "Invalid security code" instead of being sent, which Adyen refused with code 103 "CVC is not the right length". Amex keeps 4 digits, and brands with no length from the card service keep the previous 3-or-4 rule. Also picks up sdk-web-card 1.91.1: a card frame served from y.uno ignores an `apiUrl` or `assetUrl` outside the Yuno domain (sdk-web-card 1.92.0).

## v2.1.0
*October 17, 2026*

**Universal Web SDK**

- <ChangelogBadge type="added" /> **Czech Checkout Language**  
  Adds Czech (cs, cs-CZ) localization to the Universal Web SDK checkout, with the same copy as the Web SDK 1.11 release.

- <ChangelogBadge type="added" /> **Payment method description from the Checkout Builder**  
  In the payment method list, the description the merchant sets for a payment method in the Checkout Builder (`custom_description`) shows as a grey second line under its name. The text is shown complete, wraps to as many lines as it needs and keeps its line breaks. Methods without a description, and saved cards or accounts, render as before. Same behavior as the Web SDK 1.11 release.

- <ChangelogBadge type="fixed" /> **Fixed Loader After 3DS Setup**  
  When a payment ends at the 3DS setup step and the merchant handles the payment status (`showStatusScreen: false`), the SDK now hides its loader as soon as it delivers the result. Before, the loader stayed on screen for about a minute and then showed a "Transaction failed" error, even though the result had already reached the merchant. This affected 3DS-only authentications and card payments declined during 3DS authentication. Same behavior as the Web SDK 1.11 release.

- <ChangelogBadge type="fixed" /> **EBANX Fingerprint No Longer Throws "invalid country"**  
  When EBANX device fingerprinting is configured and the `countryCode` passed to the SDK is a country EBANX does not support (for example `US`), the SDK no longer surfaces an uncaught `invalid country` error on every load. The error is now caught and logged, and the EBANX fingerprint is skipped for that load. Payments were not affected before or after this change.

## v2.0.0
*October 16, 2026*

- <ChangelogBadge type="breaking" /> **A new Yuno SDK**  
  Version 2.0.0 is the new Yuno SDK: one integration for payments and enrollment, with the same API on Web, iOS and Android. Load it from the CDN, create a transaction, and get the result in `onStatus`. It replaces the Full, Lite, Seamless, Render, Headless and Secure Fields integrations and isn't compatible with 1.x.  
  [Migration guide →](/docs/yuno-sdk/migration/overview)
  *See also: [Yuno SDK documentation](/docs/yuno-sdk/introduction) · [Get started](/docs/yuno-sdk/get-started)*

- <ChangelogBadge type="breaking" /> **New global: SdkPayments**  
  The SDK is exposed as `window.SdkPayments` and initialized with `SdkPayments.initialize` (previously `window.Yuno`).
  *See also: [Get started](/docs/yuno-sdk/get-started)*

- <ChangelogBadge type="deprecated" /> **Previous SDK supported until 2027**  
  The 1.x SDK (Full, Lite, Seamless, Render, Headless and Secure Fields) stays supported side by side with the new Yuno SDK during the transition. Its deprecation is scheduled for 2027. Contact your Account Manager to plan the migration.
