## v3.3.0
*November 27, 2026*

- <ChangelogBadge type="changed" /> **Icons Display Improvement**  
  Icons such as payment method and card brand logos now appear immediately when their view is displayed, without showing an empty frame or spinner first.

- <ChangelogBadge type="added" /> **Privacy Manifest**  
  A privacy manifest has been added to declare the data collected by the SDK and the APIs it uses.

- <ChangelogBadge type="changed" /> **Two-Card Payment 3DS Behavior**  
  During a two-card payment with a 3DS challenge on each card, the SDK now shows a loader and waits for the result of the first card before starting the second, instead of calling status updates between challenges.

- <ChangelogBadge type="changed" /> **Card Brand Limitation Message**  
  When merchants limit the accepted card brands, the card form now displays a message under the card number indicating the accepted brands and shows the logos of these brands.

- <ChangelogBadge type="changed" /> **Antifraud Fingerprint Collection**  
  In a two-card payment, the antifraud device fingerprint is now collected once and sent with every card, whether new or saved.

- <ChangelogBadge type="changed" /> **Offline Bank Indicator**  
  Banks that are temporarily offline are now marked as offline in the bank list and cannot be selected.

- <ChangelogBadge type="fixed" /> **Bug Fixes and Stability**  
  Various bug fixes and stability improvements.

## v3.2.0
*November 17, 2026*

- <ChangelogBadge type="fixed" /> **3DS Challenge Status Reporting**  
  The `onStatus` function now correctly reports `PENDING` when a 3DS challenge shown in a web view closes, aligning with other 3DS challenges.

- <ChangelogBadge type="changed" /> **Co-Badged Card Brand Selector**  
  The brand selector is shown for every co-badged card, with the default network preselected, and the selected network is sent in the payment token.

- <ChangelogBadge type="added" /> **Device Fingerprint Collection**  
  A device fingerprint is collected from each antifraud provider configured for the checkout session.

- <ChangelogBadge type="added" /> **Signifyd Antifraud Fingerprinting**  
  The native Signifyd module is used for antifraud fingerprinting when its package is added.

- <ChangelogBadge type="changed" /> **Card Brand Logo Display**  
  The card brand logo is now displayed in the card number field from the first digits entered.

- <ChangelogBadge type="fixed" /> **Payment Status Handling**  
  `onStatus` now returns `REFUNDED` and `VERIFIED` payment statuses as sent by the backend, instead of incorrectly reporting `INTERNAL_ERROR`.

## v3.1.0
*November 6, 2026*

- <ChangelogBadge type="added" /> **Two Cards Without the SDK UI**  
  You can now split one payment across two cards without the SDK UI.

- <ChangelogBadge type="added" /> **Card Information While Typing**  
  The card brand, type, issuer and country are delivered to the merchant while the shopper types the card number.

- <ChangelogBadge type="added" /> **Backend-Driven Form Copy**  
  Field labels, placeholders and texts in the forms can now come from the backend.

- <ChangelogBadge type="changed" /> **Card Brand Icons**  
  Card brand icons in payment and enrollment forms now come from the backend brand catalog, with fallback to bundled icons.

- <ChangelogBadge type="changed" /> **Payment Method Descriptions**  
  The payment method description set in the Checkout Builder is now displayed under its name in the full payment methods list.

- <ChangelogBadge type="changed" /> **Form Field Colors**  
  Form fields now follow the field color set in the Checkout Builder.

- <ChangelogBadge type="fixed" /> **Card Brand Loading Spinner**  
  The loading spinner now stays aligned with the brand icon while the card number is validated.

- <ChangelogBadge type="fixed" /> **Cybersource 3DS Device Data Collection**  
  Device data collection now falls back to cancel when messages arrive from an unexpected origin.

## v3.0.0
*October 16, 2026*

- <ChangelogBadge type="breaking" /> **A new Yuno SDK**  
  Version 3.0.0 is the new Yuno SDK: one integration for payments and enrollment, with the same API on iOS, Android and Web. Create a `Transaction`, start it, and get the result in `onStatus`. It replaces the Full, Lite, Seamless, Render and Headless integrations and isn't compatible with 2.x.  
  [Migration guide →](/docs/yuno-sdk/migration/overview)  
  *See also: [Yuno SDK documentation](/docs/yuno-sdk/introduction) · [Get started](/docs/yuno-sdk/get-started)*

- <ChangelogBadge type="breaking" /> **Module renamed to SdkPayments**  
  The pod, the Swift Package product and the module are now named `SdkPayments` (previously `YunoSDK`). Update your Podfile or package dependency and replace `import YunoSDK` with `import SdkPayments`.  
  *See also: [Get started](/docs/yuno-sdk/get-started)*

- <ChangelogBadge type="deprecated" /> **Previous SDK supported until 2027**  
  The 2.x SDK (Full, Lite, Seamless, Render and Headless) stays supported side by side with the new Yuno SDK during the transition. Its deprecation is scheduled for 2027. Contact your Account Manager to plan the migration.
