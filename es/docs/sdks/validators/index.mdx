Un validador es una lista de verificación en Markdown escrita para un agente de programación con IA. Se la entregas al agente que trabaja en tu repositorio y este lee tu código contra cada verificación de la lista. Por cada verificación informa PASS, FAIL o N/A, cita el archivo y la línea que demuestran el resultado, y explica qué falla y cómo corregirlo.

Los validadores son de solo lectura. El agente busca y lee tu código, y no cambia nada a menos que se lo pidas.

## Elige un validador {#choose-a-validator}

| Tu integración | Validador |
| --- | --- |
| Web SDK v1 (1.11) con la interfaz de Yuno: Full checkout, Lite, Seamless, botones de billeteras externas, Enrollment Lite, pantallas de estado | [Web SDK v1: flujos de checkout](/es/docs/sdks/validators/web-sdk-v1-checkout-flows) |
| Web SDK v1 (1.11) sin la interfaz de Yuno: pago e inscripción headless, división en dos tarjetas, Secure Fields | [Web SDK v1: headless y Secure Fields](/es/docs/sdks/validators/web-sdk-v1-headless-secure-fields) |
| Web SDK v2 (`window.SdkPayments` y `sdk.transaction`) | [Web SDK v2](/es/docs/sdks/validators/web-sdk-v2) |
| Web SDK v1 (1.11) que planeas migrar a v2 | [Migración del Web SDK v1 a v2](/es/docs/sdks/validators/web-sdk-v1-to-v2-migration) |
| Storefronts y apps headless de VTEX | [Validadores de VTEX](/es/docs/plugins/vtex/validators/index) |

Si tu repositorio usa tanto la interfaz de Yuno como Secure Fields, ejecuta ambos validadores de v1.

## Obtén el archivo sin formato {#get-the-raw-file}

Cada página de validador también se sirve como Markdown simple. Agrega `.md` a la URL de la página para obtener el archivo que necesita el agente:

```text
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-checkout-flows.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-headless-secure-fields.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v2.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-to-v2-migration.md
```

## Ejecútalo con Claude Code {#run-it-with-claude-code}

<Steps>
  <Step title="Guarda el validador en la raíz de tu repositorio">
    ```bash
    curl -o CLAUDE.md https://docs.y.uno/docs/sdks/validators/web-sdk-v1-checkout-flows.md
    ```
  </Step>
  <Step title="Pídele a Claude Code que valide">
    ```text
    Validate my Yuno Web SDK integration following CLAUDE.md
    ```
  </Step>
  <Step title="Lee el informe">
    Claude Code responde con una línea por verificación y una lista de fallos ordenados por impacto, cada uno con una corrección de una línea.
  </Step>
</Steps>

<Warning>
Si tu repositorio ya tiene un `CLAUDE.md` o un `AGENTS.md`, no lo sobrescribas. Guarda el validador con otro nombre, como `yuno-validator.md`, y pídele al agente que valide tu integración siguiendo ese archivo.
</Warning>

## Ejecútalo con Cursor, Codex o Copilot {#run-it-with-cursor-codex-or-copilot}

Guarda el validador como `AGENTS.md` en la raíz del repositorio y pídele al agente que valide tu integración de Yuno siguiendo `AGENTS.md`. También puedes pegar el archivo completo en el chat como prompt.

## Cuando una verificación falla {#when-a-check-fails}

Corrige los fallos en el orden en que los lista el informe: primero los pagos bloqueados, luego los resultados perdidos o incorrectos y por último la experiencia degradada. Si necesitas ayuda del soporte de Yuno, envía:

- El informe completo del validador.
- Los diagnósticos que se listan en la sección "Diagnostics to capture" del validador que ejecutaste. Incluyen la versión del SDK, el ID de la sesión de checkout, la hora UTC del intento y los errores de consola y de red.

Elimina las claves de API, los datos de tarjetas y los datos personales antes de enviar cualquier cosa.

## Cómo se crearon las verificaciones {#how-the-checks-were-built}

Las verificaciones se derivaron del código fuente del Web SDK y de tickets de soporte reales. Cuando un validador indica que la documentación pública y el código no coinciden, sigue el código. Yuno está corrigiendo esas páginas de la documentación.
