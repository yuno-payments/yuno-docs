En esta página encontrarás todos los pasos para agregar, configurar y usar el Seamless SDK de iOS para realizar pagos en tu proyecto de iOS.

<Tip>
**SDK recomendado**

Yuno recomienda usar el **Seamless SDK de iOS** para una integración fluida. Esta opción ofrece una solución de pago flexible con componentes de interfaz prediseñados y opciones de personalización.
</Tip>

## Paso 1: incluye la biblioteca en tu proyecto {#step-1-include-the-library-in-your-project}

Agregas la biblioteca con Swift Package Manager. YunoSDK ya no se publica en CocoaPods; la última versión en CocoaPods es la 2.30.0.

### Swift Package Manager {#swift-package-manager}

Agrega el Yuno SDK como dependencia con [Swift Package Manager](https://www.swift.org/package-manager/), como se muestra en el siguiente bloque de código:

```swift
dependencies: [
    .package(url: "https://github.com/yuno-payments/yuno-sdk-ios.git", .upToNextMajor(from: "2.31.0"))
]
```

Agrega `YunoSDK` (dinámico) o `YunoSDK-Static` (estático, lo que distribuía CocoaPods) al target de tu app, nunca ambos.

## Paso 2: inicializa el SDK con la clave pública {#step-2-initialize-sdk-with-the-public-key}

Para empezar a ejecutar el checkout Seamless de Yuno para iOS, primero debes obtener tu ID de app de Yuno y tu clave de API pública. Luego, importa e inicializa Yuno como se muestra en el siguiente fragmento de código:

```swift
import YunoSDK

Yuno.initialize(
    apiKey: "PUBLIC_API_KEY",
    config: YunoConfig(),
    callback: { print("Yuno SDK initialized") }
)
```

<Warning>
**UISceneDelegate**

Si tu app usa un `UISceneDelegate`, asegúrate de colocar el código de inicialización de Yuno dentro de tu `SceneDelegate`.
</Warning>

El checkout Seamless te permite configurar la apariencia del SDK. Es un paso opcional que configuras mediante la clase `YunoConfig`. Para definir las configuraciones, usa el siguiente bloque de código para configurar los elementos disponibles:

```swift
final class YunoConfig {
    let appearance: Yuno.Appearance,
    let saveCardEnabled: Bool
}
```

Configura el SDK con las siguientes opciones:

| Parámetro | Descripción |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `appearance` | Este campo opcional define la apariencia del checkout. De forma predeterminada, usa los estilos de Yuno. Consulta [Personalizaciones del SDK](/es/docs/sdks/customization/ios) para obtener más información. |
| `saveCardEnabled` | Este campo opcional te permite elegir si la casilla **Save Card** se muestra en los flujos de tarjeta. De forma predeterminada es false. |

<Note>
**Acceso a tu clave de API**

Puedes obtener tu clave de API en la [sección Developers](/es/docs/using-yuno/settings/developers-credentials) del Yuno Dashboard.
</Note>

### Crea una sesión de checkout {#create-a-checkout-session}

Antes de iniciar el proceso de pago, debes crear una `checkout_session` con el endpoint [Crear sesión de checkout](/es/reference/checkout-sessions/create-checkout-session). Esta sesión inicializa el flujo de pago y se usará en el siguiente paso.

<Info>
  Controla la autorización frente a la captura enviando `payment_method.detail.card.capture` en la sesión de checkout: `false` = solo autorizar, `true` = capturar de inmediato.
</Info>

#### Parámetros clave {#key-parameters}

| Parámetro | Obligatorio | Descripción |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `amount` | Sí | El objeto del monto principal de la transacción, que contiene `currency` (código ISO 4217) y `value` (monto numérico en esa moneda). |
| `workflow` | Sí | Define el valor como `SDK_SEAMLESS` para que el SDK pueda completar correctamente el flujo de pago. |
| `alternative_amount` | No | Una representación del monto de la transacción en otra moneda, con la misma estructura que `amount` (`currency` y `value`). Es útil en escenarios multimoneda. Por ejemplo, puedes mostrar los precios a los clientes en su moneda preferida (por ejemplo, USD) mientras procesas el pago en la moneda local (por ejemplo, COP). |

## Paso 3: inicia el checkout y el proceso de pago {#step-3-start-the-checkout-and-payment-process}

El checkout seamless y el proceso de pago se inician con un único método, `startPaymentSeamlessLite`. En el `ViewController`, donde se mostrará Yuno, llama al método `Yuno.startPaymentSeamlessLite()`. Puedes usar el método con async/await o con callbacks:

```swift Swift (async/await)
func startPaymentSeamlessLite(
    with params: SeamlessParams,
    paymentSelected: PaymentMethodSelected,
    showPaymentStatus: Bool = true
) async -> Result
```
```swift Swift (with callbacks)
func startPaymentSeamlessLite(
    with params: SeamlessParams,
    paymentSelected: PaymentMethodSelected,
    showPaymentStatus: Bool = true,
    callback: @escaping ((Result) -> Void)
)
```

La versión seamless requiere parámetros adicionales. Estos incluyen:

* `PaymentMethodSelected`: el token almacenado y/o el método de pago que el cliente usará para realizar el pago.

```swift
protocol PaymentMethodSelected {
    var vaultedToken: String? { get }
    var paymentMethodType: String { get }
}
```

* `SeamlessParams`

```swift
class SeamlessParams {
    var checkoutSession: String
    var countryCode: String
    var language: String?
    var viewController: UIViewController?
}
```

Parámetros

La siguiente tabla describe cada parámetro de `SeamlessParams`:

| Parámetro | Descripción |
| ----------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkoutSession` | Hace referencia a la sesión de checkout del pago actual. |
| `countryCode` | Este parámetro determina el país para el que se configura el proceso de pago. Consulta la página [Cobertura por país](/es/docs/sdks/resources/country-coverage) para ver la lista completa de países compatibles y sus códigos. |
| `language` | Define el idioma que se usará en los formularios de pago. Consulta [Idiomas compatibles](/es/docs/sdks/resources/languages-supported) para ver las opciones. |
| `viewController` | Esta propiedad representa el `UIViewController` que se usa para presentar el flujo de pago. La propiedad sigue siendo opcional por compatibilidad con versiones anteriores. Aun así, debes proporcionar un controlador visible para que el SDK pueda presentar su interfaz correctamente. |

<Info>
**Requisitos de concurrencia de Swift 6**

Si usas Swift 6, deberás implementar el protocolo `YunoPaymentDelegate` con consideraciones específicas de concurrencia. Consulta la guía de [Concurrencia en Swift 6](/es/docs/sdks/resources/swift-6-concurrency) para conocer las opciones de implementación y las mejores prácticas.
</Info>

## Paso 4: gestiona el estado del pago (opcional) {#step-4-handle-payment-status-optional}

<Danger>
**Deep links y Mercado Pago Checkout Pro**

Este paso solo es necesario si usas un método de pago que depende de deep links o de Mercado Pago Checkout Pro. Si tus métodos de pago no usan deep links, puedes omitir este paso.
</Danger>

Algunos métodos de pago sacan a los usuarios de tu app para completar la transacción. Una vez finalizado el pago, el usuario regresa a tu app mediante un deep link. El SDK usa este deep link para determinar qué ocurrió (si el pago fue exitoso, falló o se canceló) y puede mostrar una pantalla de estado al usuario.

Para gestionarlo, debes actualizar tu `AppDelegate` para pasar la URL entrante de vuelta al Yuno SDK. Así, el SDK puede leer el resultado y, opcionalmente, mostrar el estado del pago. El siguiente fragmento de código muestra cómo agregarlo a tu app:

```swift
func application(_ app: UIApplication,
                 open url: URL,
                 options: [UIApplication.OpenURLOptionsKey : Any] = [:]) -> Bool {

  guard url.scheme == "yunoexample" else { return false }

  return Yuno.receiveDeeplink(url)
}
```

Este código escucha los deep links que abren tu app. Cuando se recibe una URL, verifica si el esquema coincide con el que usaste en el `callback_url` al configurar la sesión de checkout. Si coincide, la URL se pasa al Yuno SDK mediante `Yuno.receiveDeeplink(_:)`, que lee el resultado del pago.

Asegúrate de que el `url.scheme` de este código coincida con el `callback_url` que indicaste al crear la `checkout_session`.

## Estado de la transacción {#transaction-state}

Una vez completado el pago, el SDK puede devolver distintos estados de la transacción. La lista de todos los estados posibles y sus descripciones se presenta en la siguiente tabla:

| Estado de la transacción | Descripción |
| ----------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `succeeded` | Indica que la transacción o el proceso de pago se completó correctamente. |
| `fail` | Este estado indica que la transacción o el proceso de pago falló. Significa que hubo un error o un problema durante el proceso de pago que impidió completarlo correctamente. |
| `processing` | Indica que la transacción o el proceso de pago se está procesando actualmente. Se usa normalmente cuando hay un retraso en el procesamiento del pago, por ejemplo, al esperar la aprobación de un servicio de terceros o de una institución financiera. |
| `reject` | Este estado indica que la transacción fue rechazada. El rechazo puede ocurrir por varios motivos, como fondos insuficientes, actividad fraudulenta o solicitudes que infringen reglas o políticas específicas. |
| `internalError` | Significa que ocurrió un error inesperado en el sistema o en la infraestructura que gestiona el proceso de pago. Este estado sugiere un problema del lado del servidor o del backend y no un problema con los datos o la solicitud del usuario. |
| `userCancelled` | Este estado indica que el usuario canceló o abortó voluntariamente la transacción o el proceso de pago. Se usa normalmente cuando el usuario tiene la opción de cancelar o abandonar el proceso de pago. |

### Validación del estado del pago {#payment-status-validation}

Esta sección explica cómo gestiona el SDK el estado del pago cuando los usuarios cancelan o abandonan los flujos de pago, y cómo se relaciona el estado del SDK con el estado del pago en el backend en estos escenarios.

#### Métodos de pago síncronos (Apple Pay) {#sync-payment-methods-apple-pay}

En los métodos de pago síncronos como Apple Pay, cuando un usuario cancela o cierra la interfaz de la billetera antes de recibir la respuesta de un proveedor de servicios de pago (PSP):

* **Estado del SDK**: devuelve `userCancelled` (CANCELLED_BY_USER)
* **Estado del pago en el backend**: permanece en `PENDING` hasta que se agote el tiempo del PSP o el comercio cancele el pago
* **Importante**: el SDK no devolverá `reject` ni `processing` en este escenario

Esto garantiza que el pago en el backend permanezca en estado pendiente y que el sistema del comercio pueda gestionarlo correctamente.

#### Métodos de pago asíncronos (PIX y métodos basados en QR) {#async-payment-methods-pix-and-qr-based-methods}

En los métodos de pago asíncronos, cuando un usuario cierra la ventana de pago antes de completar el pago:

* **Estado del SDK**: devuelve `userCancelled`\*.
* **Estado del pago en el backend**: permanece en `PENDING` y el código de pago sigue siendo válido hasta que expire.
* **Reutilización de la sesión de checkout**: al reabrir la misma sesión de checkout se puede mostrar el mismo código de pago válido.
* **Sin cancelación automática**: el pago no se cancela automáticamente en el backend cuando el usuario cierra la ventana.
* **Confirmación del estado**: `userCancelled` significa que el comprador salió de la pantalla, y no implica que el pago haya fallado. Confirma el estado final mediante webhook o `GET /v1/payments/{payment_id}` antes de mostrar una cancelación.

<Note>
\* Los métodos de pago que muestran un código de pago o un comprobante (código QR de PIX, boleto, OXXO y similares), y Pix Parcelado, devuelven `processing` con el subestado `CLOSED_BY_USER` en lugar de `userCancelled` cuando el usuario cierra la pantalla. El pago permanece en `PENDING` en el backend y aún se puede completar.
</Note>

#### Pagos asíncronos vencidos {#expired-async-payments}

Si un código QR de PIX vence de forma natural:

* **Estado en el backend**: se actualiza a `EXPIRED`
* **Estado del SDK**: los callbacks del SDK y los endpoints de sondeo devuelven `EXPIRED` de forma consistente

Esto garantiza que los comercios reciban información de estado precisa cuando un método de pago ha vencido.

El estado de la transacción se puede gestionar de dos maneras al usar el método `startPaymentSeamlessLite`:

* **Async/Await**: usa el enfoque async/await para un flujo más simplificado. Este método devuelve un Result de forma asíncrona, lo que hace que el código sea más fácil de leer y mantener.
* **Callback**: puedes gestionar el estado de la transacción mediante una función callback, lo que permite una ejecución inmediata en cuanto el resultado está disponible.

Ambas opciones ofrecen flexibilidad según tu enfoque preferido para el código asíncrono.

```swift
class Result {
    var status: Status

    enum Status {
        case reject, succeeded, fail, processing, internalError, userCancelled
    }
}
```

Evalúa `result.status` con switch, no `result` directamente.

## Manejo de errores {#error-handling}

Gestiona en tu app los errores que devuelve el SDK, como los pagos fallidos y los errores de validación. Para conocer los códigos de estado HTTP y de respuesta, consulta [Códigos de estado y de respuesta](/es/reference/payments/status-and-response-codes/payment) en la referencia de la API.
