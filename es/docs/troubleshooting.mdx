## Maneja una solicitud con resultado incierto {#handle-an-uncertain-request-outcome}

Si una solicitud supera el tiempo de espera, pierde la conexión, devuelve un `500` o devuelve una respuesta que no puedes interpretar, reinténtala con el mismo `X-Idempotency-Key`. Un reintento con una clave nueva crea una operación duplicada si la primera solicitud fue exitosa.

El reintento devuelve uno de estos resultados:

* **El pago original.** La primera solicitud creó un pago, así que maneja el estado actual de ese pago. Yuno ignora el cuerpo del reintento.
* **`400 REQUEST_IN_PROCESS`.** La primera solicitud todavía se está procesando. Reintenta con la misma clave después de unos segundos.
* **`400 IDEMPOTENCY_DUPLICATED`.** La primera solicitud falló antes de crear un pago. No existe ningún pago para esta clave y no puedes reutilizarla. Corrige la solicitud y envíala con una clave nueva.
* **Procesamiento normal.** La primera solicitud fue rechazada antes de empezar a procesarse, así que la clave no se usó y el reintento se ejecuta como una solicitud nueva.

Las reglas completas están en [Idempotencia](/reference/getting-started/authentication#idempotency). Para cada estado HTTP y código de error, consulta [Códigos de respuesta](/reference/getting-started/response-codes).

## Verifica el entorno correcto {#check-the-right-environment}

Sandbox y producción tienen claves distintas. Antes de comparar registros, verifica tres valores:

* **Host de la API.** Sandbox y producción usan URLs base distintas. Consulta [Developers](/docs/developers).
* **Modo del dashboard.** El indicador de contexto en la barra superior muestra **Test** o **Live**.
* **Claves.** Cada cuenta tiene un conjunto de claves distinto para cada modo.

Consulta [Entornos](/docs/using-yuno/environments) y [Credenciales de Developers](/docs/using-yuno/settings/developers-credentials).

## Pide ayuda con información útil {#ask-for-help-with-useful-evidence}

Escribe a [support@y.uno](mailto:support@y.uno) e incluye:

* El entorno, y la hora de la solicitud con su zona horaria.
* El endpoint, el método HTTP, el estado HTTP y el `code` del error.
* El ID del pago o de la sesión de checkout, y tu referencia del pedido.
* La plataforma y la versión del SDK, lo que esperabas y lo que pasó.
* Los pasos para reproducirlo, con los campos de la solicitud y de la respuesta que importan.

Quita las claves privadas, las credenciales, los números de tarjeta sin procesar y los datos personales que no necesitas enviar. Consulta el [estado del servicio](https://status.y.uno) para ver incidentes en curso, y [Developers](/docs/developers) para las versiones y los changelogs de los SDKs.
