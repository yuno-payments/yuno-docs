---
title: "Glosario"
description: "Definiciones de los términos principales que se usan en la plataforma de orquestación de pagos de Yuno, con enlaces a las páginas que explican cada uno."
---

Este glosario define los términos que encuentras en la documentación de Yuno, desde sesiones y tokens hasta enrutamiento y payouts. Cada entrada enlaza a la página que explica el concepto por completo.

### 3DS (3D Secure) {#3ds-3d-secure}

3D Secure (3DS) es un protocolo de seguridad que añade un paso de verificación a las transacciones sin tarjeta presente para autenticar al cliente y reducir el fraude. Yuno registra una verificación 3DS como una transacción secundaria del pago y admite 3DS2 y 3DS Standalone. Consulta [3DS](/docs/basic-concepts/3ds-1).

### Cuenta {#account}

Una cuenta es una unidad dentro de tu organización que puede representar un país, una franquicia o una unidad de negocio, con sus propios usuarios, conexiones y claves. Cada cuenta tiene Account IDs únicos para Live Mode y Test Mode. Consulta [Cuentas](/es/docs/using-yuno/organization/accounts).

### Autorizar {#authorize}

Autorizar es un tipo de transacción primaria que reserva un monto de pago en una tarjeta para que puedas capturarlo después. Para autorizar sin cobrar al cliente, envía `capture` como `false` al crear el pago. Consulta [Transacciones](/es/docs/basic-concepts/transactions).

### Cancelar {#cancel}

Cancelar es una transacción secundaria que anula una autorización inicial y libera los fondos retenidos. Solo se pueden cancelar los pagos con estado `PENDING`. Consulta [Cancelar pagos](/es/docs/direct-integration-use-cases/cancel-payments).

### Captura {#capture}

La captura es una transacción secundaria que cobra los fondos de una autorización inicial, de forma total o parcial. Solo se pueden capturar los pagos con estado `PENDING`. Consulta [Capturar pagos](/es/docs/direct-integration-use-cases/capture-payments).

### Contracargo {#chargeback}

Un contracargo es una reclamación que un cliente presenta a través de su banco emisor para impugnar una transacción. En Yuno, un contracargo y una disputa son el mismo objeto: el contracargo pasa a ser una disputa activa cuando envías evidencia. Consulta [Gestión de contracargos](/es/docs/payouts-and-disputes/chargeback-management).

### Checkout Builder {#checkout-builder}

El Checkout Builder es una herramienta del dashboard sin código que habilita los métodos de pago con una ruta publicada, define sus condiciones de visualización y los campos requeridos, y da estilo al checkout. Los cambios se aplican después de hacer clic en **Publish settings**. Consulta [Checkout Builder](/es/docs/using-yuno/dashboard-overview/checkout-builder).

### Sesión de checkout {#checkout-session}

Una sesión de checkout inicia el flujo de pago de un cliente y da acceso a todos los métodos de pago disponibles para ese cliente. Creas una nueva sesión de checkout para cada pago cuando usas los SDK de Yuno. Consulta [Sesiones](/es/docs/basic-concepts/sessions).

### Conexión {#connection}

Una conexión vincula tu cuenta de Yuno con un proveedor, como un método de pago, un procesador o una solución antifraude, mediante las credenciales del proveedor. Agregas conexiones en el dashboard y luego las asignas a rutas. Consulta [Conexiones](/es/docs/using-yuno/dashboard-overview/connections).

### Cliente {#customer}

Un cliente es una persona de la red de pagos de un comercio que puede realizar pagos y almacenar métodos de pago en Yuno. Cada pago se vincula a un cliente, identificado por el `customer_id` que genera Yuno. Consulta [Clientes](/es/docs/basic-concepts/customers).

### Sesión de cliente {#customer-session}

Una sesión de cliente te permite inscribir y almacenar los métodos de pago de un cliente para uso futuro. Creas una nueva sesión de cliente cada vez que registras un método de pago para un cliente específico. Consulta [Sesiones](/es/docs/basic-concepts/sessions).

### Transacción iniciada por el cliente (CIT) {#customer-initiated-transaction-cit}

Una transacción iniciada por el cliente (CIT) es un pago que el cliente inicia activamente, como una compra en línea o en una tienda. Normalmente requiere la autenticación del titular de la tarjeta. Consulta [Credenciales almacenadas](/es/docs/payment-features/stored-credentials).

### Inscripción {#enrollment}

La inscripción almacena el método de pago de un cliente en el vault de Yuno para uso futuro y devuelve un `vaulted_token`. Los métodos de pago inscritos permiten pagos recurrentes, suscripciones y reintentos entre proveedores. Consulta [Inscribir métodos de pago](/es/docs/payment-features/enrollment/enroll-payment-methods).

### Verificación de fraude {#fraud-screening}

La verificación de fraude es la comprobación previa o posterior a la autorización que ejecuta un proveedor externo de detección de fraude sobre un pago. Cuando una ruta incluye verificación de fraude, Yuno agrega una transacción `FRAUD_SCREENING` al pago. Consulta [Prevención de fraude](/docs/basic-concepts/fraud).

### Clave de idempotencia {#idempotency-key}

Una clave de idempotencia es un UUID único que se envía en el encabezado `X-Idempotency-Key` para que puedas reintentar con seguridad una solicitud con un resultado incierto. Reutilizar la clave devuelve el pago original en lugar de crear un duplicado. Consulta [Autenticación](/es/reference/getting-started/authentication).

### Cuotas {#installments}

Las cuotas permiten a un cliente repartir el costo de una compra con tarjeta en varios pagos. Yuno admite cuotas del comercio, definidas por tus propios acuerdos, y cuotas del proveedor, definidas por el procesador de pagos. Consulta [Cuotas](/es/docs/payment-features/installments/index).

### Lite SDK {#lite-sdk}

El Lite SDK es una integración ligera que te da control total sobre cómo y dónde se muestra cada método de pago. Tú implementas la selección del método de pago. Consulta [Elegir integración](/es/docs/sdks/overview/choose-integration).

### Transacción iniciada por el comercio (MIT) {#merchant-initiated-transaction-mit}

Una transacción iniciada por el comercio (MIT) es un pago que el comercio envía sin la participación activa del cliente, como un cobro recurrente o la renovación de una suscripción. Se apoya en una autenticación inicial del cliente durante la configuración. Consulta [Credenciales almacenadas](/es/docs/payment-features/stored-credentials).

### Monitors {#monitors}

Monitors detecta caídas en la tasa de aprobación de una ruta, te alerta por los canales que configuraste y redirige automáticamente el tráfico a proveedores de respaldo. El tráfico vuelve a la ruta original cuando la tasa de aprobación se recupera. Consulta [Monitors](/es/docs/using-yuno/dashboard-overview/monitors).

### Token de red {#network-token}

Un token de red es una representación digitalizada del número de cuenta principal (PAN) de una tarjeta, emitida por redes de tarjetas como Visa, Mastercard o American Express. Cuando está habilitado, Yuno aprovisiona tokens de red para todas las tarjetas inscritas, y la red de tarjetas los actualiza automáticamente. Consulta [Tokens de red](/es/docs/security-and-compliance/network-tokens).

### Token de un solo uso {#one-time-token}

Un token de un solo uso contiene la información de pago que recopila el Yuno SDK para una única sesión de checkout. Lo usas una vez al crear el pago y no se puede reutilizar. Consulta [Tokens](/es/docs/basic-concepts/tokens).

### Organización {#organization}

Una organización es la entidad de nivel superior que agrupa tus cuentas y usuarios de Yuno. Las claves de organización dan acceso a todas las cuentas de la organización, y los roles a nivel de organización se aplican a todas las cuentas. Consulta [Developers (Credenciales)](/es/docs/using-yuno/settings/developers-credentials).

### Pago {#payment}

Un pago representa la transacción de un usuario, sin importar los procesadores o métodos de pago utilizados, y reúne los detalles del pedido, como cliente, monto y moneda. Un pago consta de una o más transacciones que determinan su resultado final. Consulta [Pagos](/es/docs/basic-concepts/payments-1).

### Enlace de pago {#payment-link}

Un enlace de pago es una URL que creas en el dashboard para cobrar un pago sin escribir código. Defines el país, la moneda, el monto, los métodos de pago y las fechas opcionales de inicio y vencimiento. Consulta [Enlaces de pago](/es/docs/using-yuno/dashboard-overview/payment-links).

### Método de pago {#payment-method}

Un método de pago es una forma de recopilar la información de pago del cliente y enviarla a un procesador, como tarjetas, billeteras digitales, transferencias bancarias o servicios de compra ahora, paga después. Los métodos de pago se diferencian por la compatibilidad con la inscripción y por el procesamiento síncrono o asíncrono. Consulta [Métodos de pago](/es/docs/basic-concepts/payment-methods).

### Estado del pago {#payment-status}

El `status` y el `sub_status` del pago describen el estado actual de un pago y siguen un ciclo de vida estandarizado en todos los métodos de pago. Yuno recomienda usarlos como referencia principal del estado del pago, sin importar cuántas transacciones tenga. Consulta [Estados del pago y códigos de respuesta](/reference/payments/status-and-response-codes/payment).

### Payout {#payout}

Un payout envía fondos de ti a un beneficiario mediante un método de retiro bancario, con tarjeta o con billetera. Un payout comienza como `CREATED`, pasa a `PENDING` y termina como `SUCCEEDED`, `REJECTED` o `DECLINED`. Consulta [Payouts](/es/docs/payouts-and-disputes/payouts).

### Plan {#plan}

Un plan es una definición de precio reutilizable con un nombre, un precio (opcionalmente por país), una frecuencia de facturación y una fase de prueba opcional. Suscribes a los clientes a un plan con `plan_id` en lugar de enviar `amount` y `frequency` en cada suscripción. Consulta [Planes](/es/docs/payment-features/subscriptions/plans).

### Clave secreta privada {#private-secret-key}

La `private-secret-key` es la credencial que tu servidor envía, junto con la `public-api-key`, para autenticar cada solicitud a la API de Yuno. No la compartas en lugares públicos como GitHub o Bitbucket. Consulta [Autenticación](/es/reference/getting-started/authentication).

### Proveedor {#provider}

Un proveedor es un tercero que conectas a Yuno, incluidos métodos de pago, procesadores de pago y soluciones antifraude. El enrutamiento decide qué proveedor procesa cada pago. Consulta [Conexiones](/es/docs/using-yuno/dashboard-overview/connections).

### Clave de API pública {#public-api-key}

La `public-api-key` es la credencial que envías en cada solicitud a la API de Yuno y que usas para la inicialización del SDK del lado del cliente. La encuentras en la sección Developers del dashboard. Consulta [Autenticación](/es/reference/getting-started/authentication).

### Conciliación {#reconciliation}

La conciliación compara las transacciones procesadas a través de Yuno con los archivos de liquidación de cada proveedor de pagos para encontrar discrepancias y confirmar la liquidación. El dashboard muestra la tasa de conciliación por proveedor, cuenta y moneda. Consulta [Conciliaciones](/es/docs/using-yuno/dashboard-overview/reconciliations).

### Reembolso {#refund}

Un reembolso devuelve fondos al cliente por un pago capturado, de forma total o parcial, y agrega una transacción `REFUND` al pago. Yuno admite reembolsos referenciados a través de la API, reembolsos por lotes mediante la carga de un CSV en el dashboard y reembolsos no referenciados que no hacen referencia a un pago de Yuno. Consulta [Reembolsos](/es/docs/direct-integration-use-cases/unreferenced-refunds-overview).

### Condiciones de riesgo {#risk-conditions}

Las condiciones de riesgo son las reglas de prevención de fraude, listas de bloqueo y listas de permitidos propias de Yuno que agregas a una ruta para controlar qué transacciones se verifican. Reducen las solicitudes innecesarias a los proveedores de prevención de fraude. Consulta [Condiciones de riesgo](/es/docs/using-yuno/dashboard-overview/risk-conditions).

### Enrutamiento {#routing}

El enrutamiento dirige cada pago a un proveedor según las reglas que configuras en el dashboard, como tipo de tarjeta, monto de la transacción, moneda y origen del pago. Una ruta pertenece a un método de pago y debe estar publicada antes de procesar transacciones. Consulta [Enrutamiento](/es/docs/using-yuno/dashboard-overview/routing).

### Seamless SDK {#seamless-sdk}

El Seamless SDK es la integración recomendada de Yuno: ofrece componentes de interfaz prediseñados, te da control sobre la experiencia de pago y te permite agregar métodos de pago desde el dashboard sin código. Consulta [Seamless SDK](/es/docs/sdks/seamless-sdk/index).

### Secure Fields {#secure-fields}

Secure Fields son campos de entrada prediseñados que incrustas en tu propio formulario de pago Web para que los datos de tarjeta en bruto nunca pasen por tus servidores. Mantienen una interfaz de checkout personalizada en cumplimiento con PCI. Consulta [Descripción general de Secure Fields](/docs/sdks/customization/secure-fields/index).

### Vendedor (franquicia) {#seller-franchise}

Un vendedor es la identidad de una tienda franquiciada que un comercio registra con credenciales por proveedor, de modo que Yuno resuelve el `merchant_id` correcto al momento del pago cuando el pago hace referencia al vendedor en `additional_data.seller_details`. Los vendedores no son los destinatarios (submerchants) que se usan en los [pagos divididos](#split-payments). Consulta [Vendedores (franquicia)](/es/reference/sellers/manage-sellers).

### Smart Routing {#smart-routing}

Smart Routing optimiza el rendimiento de los pagos eligiendo entre dos o más conexiones de una ruta según la variable que selecciones: tasa de conversión y latencia, o tasa de conversión y costos. Lo activas con un interruptor al definir las condiciones de la ruta. Consulta [Enrutamiento](/es/docs/using-yuno/dashboard-overview/routing).

### Pagos divididos {#split-payments}

Los pagos divididos reparten un pago de marketplace entre varios destinatarios, los submerchants que incorporas en Yuno, con montos, comisiones y cargos. El proveedor de pagos seleccionado debe admitir pagos divididos, porque Yuno orquesta la división pero no la procesa. Consulta [Pagos divididos de marketplace](/es/docs/payment-features/split-payments-marketplace).

### Suscripción {#subscription}

Una suscripción es un pago recurrente que el motor de recurrencia de Yuno crea y envía en tu nombre con la frecuencia que defines. Su estado pasa de `CREATED` a `ACTIVE` o `TRIALING`, y puede convertirse en `PAUSED`, `PAST_DUE`, `COMPLETED` o `CANCELED`. Consulta [Suscripciones](/es/docs/payment-features/subscriptions/index).

### Test Mode y Live Mode {#test-mode-and-live-mode}

Test Mode (Sandbox) te permite explorar el dashboard y hacer pruebas sin transacciones reales. Live Mode (Producción) procesa transacciones reales de clientes y requiere una solicitud de activación, y un interruptor del dashboard cambia entre ambos. Consulta [Entornos](/es/docs/using-yuno/environments).

### Transacción {#transaction}

Una transacción es una operación dentro de un pago, procesada a través de una conexión. Las transacciones primarias (compra, autorización, verificación) inician un pago, y las transacciones secundarias (reembolso, cancelación, captura, contracargo, 3DS, verificación de fraude) cambian su resultado. Consulta [Transacciones](/es/docs/basic-concepts/transactions).

### Token almacenado {#vaulted-token}

Un token almacenado se crea cuando un método de pago se inscribe y se guarda en el vault centralizado de Yuno junto con la información del cliente. Funciona con todos los procesadores conectados a tu cuenta y persiste hasta que el cliente cancela la inscripción del método de pago. Consulta [Tokens](/es/docs/basic-concepts/tokens).

### Webhook {#webhook}

Un webhook es una notificación HTTP POST que Yuno envía a tu API REST pública cada vez que ocurre un evento en el flujo de pago. Los webhooks mantienen tu sistema actualizado sobre los cambios de estado del pago sin solicitudes repetidas a Yuno. Consulta [Webhooks](/es/docs/basic-concepts/webhooks-1).

### Workflow {#workflow}

El atributo `workflow` de un pago le indica a Yuno qué integración usas: `SDK_CHECKOUT` cuando el Yuno SDK recopila los datos de pago, `DIRECT` cuando los envías de servidor a servidor y recibes la respuesta en bruto del proveedor, y `REDIRECT` cuando Yuno también proporciona una URL de redirección y gestiona la experiencia de pago de ese pago. Consulta [Integración de flujo directo](/es/docs/direct-integration-use-cases/direct-flow).
