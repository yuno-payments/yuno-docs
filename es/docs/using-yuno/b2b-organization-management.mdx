Yuno ofrece un conjunto de APIs de gestión de organizaciones B2B diseñadas para plataformas y socios white-label que necesitan gestionar varias suborganizaciones y sus usuarios. Estas APIs te permiten automatizar el onboarding de tus comercios mediante la creación de una estructura jerárquica de grupos de cuentas, cuentas y usuarios.

<Note>
  **Requisitos previos**
  Para usar estas APIs, tu organización debe tener la propiedad **whitelabel** habilitada en el Dashboard de Yuno. Contacta a tu gerente de cuenta de Yuno para habilitar esta función.
</Note>

## Flujo principal de gestión {#core-management-flow}

Sigue estos pasos para configurar un nuevo entorno de comercio.

<Steps>
  <Step title="Crea un grupo de cuentas">
    El grupo de cuentas actúa como la entidad principal de tu comercio y centraliza la gestión de las cuentas relacionadas. Usa el endpoint [Create Account Group](/es/reference/organizations/create-account-group) para inicializar este grupo.

    ```bash
    curl --request POST \
      --url https://api-sandbox.y.uno/v1/organizations/account-groups \
      --header 'PRIVATE-SECRET-KEY: <YOUR_PRIVATE_SECRET_KEY>' \
      --header 'PUBLIC-API-KEY: <YOUR_PUBLIC_API_KEY>' \
      --header 'Content-Type: application/json' \
      --data '{
        "name": "Acme Payments",
        "merchant_id": "acme_001"
      }'
    ```

    **Salida y siguientes pasos**: La respuesta incluirá un `id` único para el grupo de cuentas. Guarda este ID, ya que lo necesitarás para crear cuentas de comercio específicas en el siguiente paso.
  </Step>

  <Step title="Crea una cuenta">
    Dentro del grupo de cuentas recién creado, puedes crear una o más cuentas. Esta estructura te permite separar la lógica de negocio, las regiones o las líneas de negocio de un mismo comercio. Usa el endpoint [Create Account](/es/reference/organizations/create-account).

    ```bash
    curl --request POST \
      --url https://api-sandbox.y.uno/v1/organizations/account-groups/{account_group_id}/accounts \
      --header 'PRIVATE-SECRET-KEY: <YOUR_PRIVATE_SECRET_KEY>' \
      --header 'PUBLIC-API-KEY: <YOUR_PUBLIC_API_KEY>' \
      --header 'Content-Type: application/json' \
      --data '{
        "name": "Acme Production"
      }'
    ```

    **Salida y siguientes pasos**: Recibirás un `id` para la cuenta de comercio. Este ID se usa para acotar pagos, sesiones y configuraciones específicamente a este entorno de comercio.
  </Step>

  <Step title="Crea un usuario y asigna permisos">
    Por último, crea un usuario real y otórgale acceso a la cuenta o a todo el grupo de cuentas. Asignar roles (como `merchant-admin`) garantiza que el usuario tenga los permisos necesarios para gestionar el Dashboard del comercio. Usa el endpoint [Create User](/es/reference/organizations/create-user).

    ```bash
    curl --request POST \
      --url https://api-sandbox.y.uno/v1/organizations/users \
      --header 'PRIVATE-SECRET-KEY: <YOUR_PRIVATE_SECRET_KEY>' \
      --header 'PUBLIC-API-KEY: <YOUR_PUBLIC_API_KEY>' \
      --header 'Content-Type: application/json' \
      --data '{
        "email": "admin@acmepay.com",
        "first_name": "John",
        "last_name": "Doe",
        "account_group_permissions": [
          {
            "account_group_id": "{account_group_id}",
            "role_id": "merchant-admin"
          }
        ]
      }'
    ```

    **Salida y siguientes pasos**: El usuario se creará en el sistema. Para permitirle iniciar sesión en tu portal whitelabel, usa el endpoint [Authenticate Whitelabel User](/es/reference/organizations/authenticate-whitelabel-user) para generar un token de acceso seguro.
  </Step>
</Steps>

## Anidar grupos de cuentas {#nest-account-groups}

Los grupos de cuentas se pueden anidar para reflejar cómo está estructurada tu organización: un grupo puede contener cuentas y subgrupos, y un subgrupo puede contener grupos propios. Cada grupo tiene como máximo un padre, y un grupo no puede anidarse dentro de su propio subárbol.

Un grupo siempre se crea como raíz. Para anidarlo, define `parent_code` en [Update Account Group](/es/reference/organizations/update-account-group); envía `parent_code: null` para desvincularlo y volver a convertirlo en raíz. Cada respuesta de grupo de cuentas informa el padre en `parent_code` (`null` para una raíz).

```bash
curl --request PATCH \
  --url https://api-sandbox.y.uno/v1/organizations/account-groups/{account_group_id} \
  --header 'PRIVATE-SECRET-KEY: <YOUR_PRIVATE_SECRET_KEY>' \
  --header 'PUBLIC-API-KEY: <YOUR_PUBLIC_API_KEY>' \
  --header 'Content-Type: application/json' \
  --data '{
    "parent_code": "{parent_account_group_id}"
  }'
```

El anidamiento es solo estructural: mover un grupo no concede ni revoca nada, por lo que los permisos de usuario existentes no cambian. Un grupo que aún tiene subgrupos o cuentas no se puede eliminar: muévelos o [quítalos](/es/reference/organizations/remove-account-from-group) primero.

## Gestionar proveedores mediante la API {#manage-providers-through-the-api}

Una vez que tus comercios pueden iniciar sesión, la pestaña **Providers** de tu Dashboard white-label decide a qué proveedores de pago pueden conectarse y qué leen tus usuarios mientras lo hacen. Esa capa se puede configurar mediante la API: qué proveedores ofreces, y el nombre, las instrucciones de conexión, el enlace de documentación y el logotipo que se muestran para cada uno.

Consulta la [Descripción general de proveedores white-label](/es/reference/organizations/whitelabel/overview) para ver el contrato común y los endpoints.

## Disponibilidad por entorno {#environment-availability}

Las APIs de gestión de organizaciones B2B están disponibles en los entornos **Sandbox** y **Producción**. Para más información sobre cómo gestionar tus claves de API y URL base, visita la página de [Entornos](/es/docs/using-yuno/environments).
