Yuno ejecuta las reglas operativas que la mayoría de los equipos de pagos programan a mano. Esta página relaciona la tarea que necesitas con la función que la realiza, para que encuentres el ajuste correcto sin leer cada página. Algunas se configuran en el Dashboard y otras en la propia solicitud de la API; la última columna te indica cuál.

## Qué se ejecuta automáticamente {#what-runs-automatically}

| Cuando necesitas | Yuno lo hace con | Configúralo en |
| :--- | :--- | :--- |
| Conmutar por error cuando cae la tasa de aprobación de un proveedor | [Monitors](/es/docs/using-yuno/dashboard-overview/monitors): alerta por email u Opsgenie, redirige el tráfico a tus proveedores de respaldo, mantiene una pequeña parte en el proveedor original para detectar la recuperación y devuelve el tráfico cuando la tasa se recupera | Routing, en el conjunto de condiciones de cada ruta |
| Reintentar la renovación rechazada de una suscripción en el momento adecuado | [Smart Retries](/es/docs/payment-features/subscriptions/retries): hasta seis intentos con un calendario predeterminado, inteligente o personalizado, una detención ante rechazos definitivos y una cancelación opcional cuando se agotan los reintentos | El objeto `retries` de la suscripción |
| Reintentar una renovación bajo demanda | Endpoint [Retry Subscription](/reference/subscriptions/retry-subscription) | API |
| Reintentar una captura o un reembolso que el proveedor no pudo procesar | [Transaction Retries](/es/docs/payment-features/transaction-retries): hasta siete intentos en un calendario fijo, con subestados que puedes seguir | `simplified_mode: true` en la solicitud de captura o reembolso |
| Capturar o liberar una autorización después de un tiempo definido | [Captura diferida y cancelación diferida](/es/docs/payment-features/Cancel-and-capture-flow): Yuno captura después de `delayed_capture_settings.delay` o cancela después de `delayed_cancel_settings.delay` | La solicitud de pago |
| Rechazar, permitir o retener un pago según quién paga | [Risk Conditions](/es/docs/using-yuno/dashboard-overview/risk-conditions): reglas con resultados de permitir, bloquear, revisar o probar, además de listas de bloqueo, listas de permitidos y listas de revisión | Risk Conditions, asociadas a tus rutas |
| Omitir la revisión antifraude o 3DS para clientes de confianza | [Listas de permitidos](/es/docs/using-yuno/dashboard-overview/risk-conditions#allowlists) con el resultado que elijas | Risk Conditions |
| Enviar un pago a otro proveedor según monto, BIN, marca, país, moneda, cuotas, tipo de transacción o metadatos | [Routing](/es/docs/using-yuno/dashboard-overview/routing) y [condiciones de enrutamiento](/reference/organizations/routing/routing-conditions), con Smart Routing para el resto | Routing |
| Actuar sobre un contracargo o una consulta en tus propios sistemas | El [webhook](/docs/webhooks/index) `payment.chargeback`, con el `status` y el `sub_status` de la disputa, y la vista de [gestión de contracargos](/es/docs/payouts-and-disputes/chargeback-management) | Developers, Webhooks |
| Reaccionar a cualquier cambio en un pago, reembolso, captura, cancelación, inscripción o suscripción | [Webhooks](/es/docs/webhooks/configure-webhooks) para cada objeto, firmados con HMAC | Developers, Webhooks |

## Combínalas {#combine-them}

Las funciones se complementan. Una configuración típica para un negocio de suscripciones:

1. Una ruta con un proveedor principal y uno de respaldo, y un Monitor sobre ella, para que una caída en la tasa de aprobación mueva el tráfico sin que nadie mire un gráfico.
2. Smart Retries en cada suscripción, para que una renovación rechazada se reintente en el mejor momento con el proveedor que seleccione la ruta.
3. Risk Conditions en la misma ruta, para que las tarjetas o los clientes en los que ya no confías se bloqueen o se retengan antes de llamar al proveedor.
4. Un endpoint de webhook que consuma `payment.purchase`, `payment.refund`, `payment.chargeback` y `subscription.*`, para que tu sistema de facturación se mantenga sincronizado sin sondeo.

## Lo que Yuno no hace {#what-yuno-does-not-do}

Yuno no ofrece un generador libre de disparadores y acciones. No hay forma de definir "cuando ocurra este evento, llama a esta URL o envía este email" desde el Dashboard. Si necesitas una regla que la tabla anterior no cubre, el patrón es consumir el webhook del evento y llamar al endpoint de [captura](/es/reference/payments/capture-authorization), [cancelación](/es/reference/payments/cancel-payment) o [reembolso](/es/reference/payments/refund-payment) desde tu propio sistema. Cuéntale también a tu equipo de cuenta sobre la regla; la mayoría de las solicitudes de este tipo corresponden a una función de la hoja de ruta.
