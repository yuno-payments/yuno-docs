Un **rol** es un conjunto de permisos. La pestaña **Roles** muestra lo que puede hacer cada rol y es donde creas los tuyos.

Ábrela desde **Organization → Roles**.

## Roles predeterminados {#default-roles}

Yuno incluye seis roles predeterminados:

| Rol       | Descripción                                                                        |
| :-------- | :--------------------------------------------------------------------------------- |
| Admin     | Acceso a todas las funciones del Dashboard.                                        |
| Agent     | Ver y realizar acciones sobre los pagos.                                           |
| Developer | Ver y realizar acciones sobre las integraciones y los webhooks.                    |
| Read only | Ver todas las funciones del Dashboard.                                             |
| Custodian | Asigna este rol cuando invites a expertos del equipo de Yuno a unirse a tu equipo. |
| IAM Admin | Administrar el acceso y la configuración de seguridad, como SSO y los roles.       |

## Alcance del rol: cuenta u organización {#role-scope-account-or-organization}

El mismo rol se comporta de forma distinta según el nivel en el que se otorga:

* **Cuenta**: el rol se aplica solo en las cuentas a las que se asigna a la persona. Invítala por separado a cada cuenta que necesite.
* **Organización**: el rol se aplica a todas las cuentas de la organización, incluidas las que se creen más adelante. Esto funciona con cualquier rol, no solo con Admin. Un "analista de pagos" a nivel de organización ve los pagos en todas partes sin que lo inviten cuenta por cuenta.

<Note>
**Los permisos de seguridad son solo a nivel de organización**

Los permisos de **Security**, como configurar SSO, solo se pueden otorgar mediante un rol a nivel de organización. No se pueden asignar en una sola cuenta.
</Note>

## Crear un rol personalizado {#creating-a-custom-role}

Selecciona **Create role** y luego define un nombre, una descripción y los permisos que debe incluir el rol.

### Permisos por entorno {#per-environment-permissions}

Cada permiso se configura de forma independiente para:

* **Sandbox**: pruebas y desarrollo.
* **Producción**: operaciones reales y datos sensibles.

Así, un rol puede tener acceso completo en Sandbox para hacer pruebas y a la vez estar restringido en producción.

### Permisos disponibles {#available-permissions}

* **Insights**: acceso a información útil sobre los pagos
* **Payments**: ver y operar pagos, administrar enlaces de pago
* **Payouts**: ver payouts y detalles de las transacciones
* **Reconciliation**: ver reportes de liquidación
* **Connections**: ver y administrar conexiones de pago
* **Routing**: ver y administrar rutas de procesamiento
* **Checkout builder**: ver y crear configuraciones de checkout
* **Developers**: ver y administrar las claves de la cuenta
* **Webhooks**: ver y administrar webhooks
* **Accounts**: administrar la configuración de las cuentas
* **Team and roles**: ver y administrar miembros del equipo y roles
* **Risk conditions**: ver y administrar reglas y listas
* **Audit logs**: ver los logs del Dashboard, de la API y de los monitores
