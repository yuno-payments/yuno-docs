Un validador es una lista de verificación en Markdown escrita para un agente de programación con IA. Se la entregas al agente que trabaja en tu repositorio y el agente lee tu código según cada verificación de la lista. Por cada verificación informa PASS, FAIL o N/A, cita el archivo y la línea que demuestran el resultado, y explica qué se rompe y cómo solucionarlo.

Los validadores son de solo lectura. El agente busca y lee tu código y no cambia nada a menos que se lo pidas.

Estos validadores son para integraciones headless, en las que tu propio front end o tu app se comunica con Yuno. Las tiendas con el flujo estándar del plugin descrito en [Configura Yuno en VTEX](/es/docs/plugins/vtex/set-up-yuno-on-vtex) no los necesitan. Toda tienda con CSS o JS personalizado en el checkout debería ejecutar la verificación de actualización.

## Qué ejecutar {#what-to-run}

| Tu integración | Ejecuta | Archivo sin formato |
| --- | --- | --- |
| Storefront headless o página WebView que monta Yuno SDK Web para VTEX | [Headless Web](/es/docs/plugins/vtex/validators/headless-web) | `https://docs.y.uno/docs/plugins/vtex/validators/headless-web.md` |
| App Flutter con Google Pay, Apple Pay o Click to Pay mediante el flujo preflight | [Wallets headless (Flutter)](/es/docs/plugins/vtex/validators/headless-wallets-flutter) | `https://docs.y.uno/docs/plugins/vtex/validators/headless-wallets-flutter.md` |
| App React Native con Google Pay, Apple Pay o Click to Pay mediante el flujo preflight | [Wallets headless (React Native)](/es/docs/plugins/vtex/validators/headless-wallets-react-native) | `https://docs.y.uno/docs/plugins/vtex/validators/headless-wallets-react-native.md` |
| Servicio backend que llama a las rutas preflight del conector para wallets en nombre de una app o un sitio web | [Wallets headless (backend)](/es/docs/plugins/vtex/validators/headless-wallets-backend) | `https://docs.y.uno/docs/plugins/vtex/validators/headless-wallets-backend.md` |
| Cualquier tienda con CSS o JS personalizado en el checkout (`checkout6-custom.css`, `checkout6-custom.js`, código de tema o de app) | [Verificación de actualización a Web SDK 1.11](/es/docs/plugins/vtex/validators/upgrade-check-1-6-to-1-11) | Fragmento de consola y escáner en esa página |

## Quién ejecuta qué {#who-runs-what}

- **Los desarrolladores del comercio** ejecutan el validador que corresponde a su storefront, app o backend en su propio repositorio, y el escáner de la verificación de actualización sobre sus archivos de checkout personalizados.
- **Los gerentes técnicos de cuenta** ejecutan el fragmento de consola de la verificación de actualización en el checkout en vivo de una tienda, ejecutan el escáner sobre los archivos que comparte el comercio y ejecutan un validador cuando revisan con él el repositorio de un comercio.

## Ejecuta un validador con Claude Code {#run-a-validator-with-claude-code}

<Steps>
  <Step title="Guarda el validador en la raíz de tu repositorio">
    ```bash
    curl -o CLAUDE.md https://docs.y.uno/docs/plugins/vtex/validators/headless-web.md
    ```
  </Step>
  <Step title="Pide a Claude Code que valide">
    ```text
    Validate my Yuno VTEX headless integration following CLAUDE.md
    ```
  </Step>
  <Step title="Lee el informe">
    Claude Code responde con una línea por verificación y una lista de fallas ordenadas por impacto, cada una con una solución de una línea.
  </Step>
</Steps>

<Warning>
Si tu repositorio ya tiene un `CLAUDE.md` o un `AGENTS.md`, no lo sobrescribas. Guarda el validador con otro nombre, como `yuno-validator.md`, y pide al agente que valide tu integración siguiendo ese archivo.
</Warning>

## Ejecuta un validador con Cursor, Codex o Copilot {#run-a-validator-with-cursor-codex-or-copilot}

Guarda el validador como `AGENTS.md` en la raíz del repositorio y pide al agente que valide tu integración con Yuno siguiendo `AGENTS.md`. También puedes pegar el archivo completo en el chat como prompt.

## Cuando falla una verificación {#when-a-check-fails}

Corrige las fallas en el orden en que las enumera el informe. Si necesitas ayuda del soporte de Yuno o de tu gerente técnico de cuenta, envía:

- El informe completo del validador.
- Los diagnósticos enumerados en la sección "Diagnostics to capture" del validador que ejecutaste. Incluyen el ID de pedido o el grupo de pedidos de VTEX, la hora UTC del intento y los errores de red y de consola.

Elimina las claves de API, los datos de tarjetas y los datos personales antes de enviar cualquier cosa.

## Cómo se crearon las verificaciones {#how-the-checks-were-built}

Las verificaciones se derivaron del código fuente del SDK y de tickets de soporte reales. Cuando un validador y la documentación pública no coinciden, sigue el validador. Yuno está corrigiendo esas páginas de la documentación.
