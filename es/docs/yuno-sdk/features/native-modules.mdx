title: "Módulos nativos"
sidebarTitle: "Agregar módulos nativos"
description: "Agrega un SDK nativo de terceros, antifraude o 3DS, al Yuno SDK como módulo opcional, sin cambiar tu código de transacción."
---

El Yuno SDK se mantiene pequeño a propósito: cada SDK nativo de terceros se distribuye como un módulo independiente y opcional. Agregas solo los módulos que usa tu cuenta, el SDK los detecta cuando la app inicia y tu código de `Transaction` no cambia.

<Note>
Los módulos nativos aplican solo a iOS y Android. Una app de React Native los agrega a su proyecto nativo de Android (`android/`) exactamente como una app nativa, y su código JavaScript no cambia. Los módulos de iOS aún no están disponibles para React Native. En Web no hay nada que instalar. El SDK carga en tiempo de ejecución los scripts de los proveedores de antifraude habilitados para tu cuenta y recopila los fingerprints durante la transacción. Para recopilarlos antes de la transacción, llama a `sdkPayments.antifraud()`.
</Note>

<Note>
Instalar un módulo no hace que el SDK lo use. Un módulo se ejecuta solo cuando el proveedor está habilitado para tu cuenta de Yuno y el backend lo solicita para la transacción en curso.
</Note>

## Cómo funciona {#how-it-works}

1. Agregas el módulo a tu app junto al SDK, como producto de paquete o dependencia de Gradle.
2. Cuando la app inicia, el módulo se registra en el SDK.
3. Durante una transacción, el SDK consulta a Yuno qué proveedores aplican y usa el módulo correspondiente: recopila una huella digital del dispositivo y la adjunta al pago o ejecuta el desafío 3DS de forma nativa en lugar de en un WebView.

## Módulos disponibles {#available-modules}

| Módulo | Qué agrega | iOS | Android |
|---|---|---|---|
| Antifraude de ClearSale | Recopila el fingerprint del dispositivo de ClearSale y lo adjunta al pago | `SdkAntifraudClearsale` | `yuno-sdk-antifraud-clearsale` |
| Antifraude de Koin | Recopila el fingerprint del dispositivo de Koin y lo adjunta al pago | `SdkAntifraudKoin` | `yuno-sdk-antifraud-koin` |
| Antifraude de Riskified | Inicia el beacon de Riskified con la sesión de checkout y adjunta esa sesión al pago | `SdkAntifraudRiskified` | `yuno-sdk-antifraud-riskified` |
| Antifraude de Signifyd | Ejecuta el perfilado de dispositivo de Signifyd y adjunta la sesión de Signifyd al pago | `SdkAntifraudSignifyd` (paquete aparte) | `yuno-sdk-antifraud-signifyd` |
| Netcetera 3DS | Ejecuta los desafíos de 3D Secure de forma nativa en tu app, para pagos e inscripción | `SdkPaymentsNetcetera` | `yuno-sdk-3ds-netcetera` |

Plataforma mínima: iOS 14.0, Android 6.0 (API 23). Cada módulo requiere la misma versión del SDK que instalas desde [Get Started](/es/docs/yuno-sdk/get-started#install). En iOS los módulos están soportados desde SdkPayments 3.2.0, solo mediante Swift Package Manager, con `SdkPayments` o `SdkPayments-Static`.

## Instalación {#install}

<Tabs>
  <Tab title="iOS">

Agrega los módulos que necesites a tu app junto al SDK. En Xcode, ve a **File > Add Package Dependencies**, selecciona el paquete de tu proyecto y agrega los productos de módulos desde `https://github.com/yuno-payments/yuno-sdk-ios.git`. O agrégalos directamente en tu `Package.swift`:

```swift
dependencies: [
    .package(url: "https://github.com/yuno-payments/yuno-sdk-ios.git", .upToNextMajor(from: "3.2.0"))
],
targets: [
    .target(
        name: "YourApp",
        dependencies: [
            .product(name: "SdkPayments", package: "yuno-sdk-ios"),
            // Agrega solo los módulos que usa tu cuenta
            .product(name: "SdkAntifraudClearsale", package: "yuno-sdk-ios"),
            .product(name: "SdkAntifraudKoin", package: "yuno-sdk-ios"),
            .product(name: "SdkAntifraudRiskified", package: "yuno-sdk-ios"),
            .product(name: "SdkPaymentsNetcetera", package: "yuno-sdk-ios"),
        ]
    )
]
```

Cada módulo trae su SDK del proveedor y se registra solo cuando la app inicia. El binario del módulo se descarga desde la URL de release del proveedor.

Agrega `SdkPayments` (dinámico) o `SdkPayments-Static` (estático, lo que distribuía CocoaPods) al target de tu app, nunca ambos. Los módulos funcionan con cualquiera de los dos.

Signifyd se distribuye en su propio paquete (`SdkAntifraudSignifyd`, desde `2.0.0`) y necesita tu token de Signifyd: sigue [Signifyd antifraud (iOS)](/es/docs/yuno-sdk/features/signifyd-ios).

Los módulos del Legacy SDK (2.x) documentados en [iOS Overview](/es/docs/sdks/external-native-modules/ios-overview) son solo para el Legacy SDK y no se pueden usar con el Yuno SDK (3.x).

  </Tab>
  <Tab title="Android">

Agrega los módulos que necesites al archivo de compilación del módulo de tu app, junto al SDK. Cada módulo trae su SDK del proveedor y sus propias dependencias.

```kotlin
repositories {
    maven { url = uri("https://yunopayments.jfrog.io/artifactory/snapshots-libs-release") }
}

dependencies {
    implementation("com.yuno.payments:android-sdk:3.0.0")
    // Add only the modules your account uses
    implementation("com.yuno.payments:yuno-sdk-antifraud-clearsale:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-antifraud-koin:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-antifraud-riskified:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-antifraud-signifyd:1.0.0")
    implementation("com.yuno.payments:yuno-sdk-3ds-netcetera:1.0.1")
}
```

<Note>
El módulo de Netcetera también necesita que declares el repositorio Maven de Netcetera en tu proyecto, porque su SDK de 3DS no está en Maven Central. Consulta [Netcetera 3DS on Android](/es/docs/sdks/external-native-modules/netcetera-3ds-android#step-1-declare-the-netcetera-maven-repository).

El módulo de Signifyd necesita el registro privado de Signifyd y un token de descarga que proporciona Signifyd. Consulta [Signifyd antifraud (Android)](/es/docs/sdks/external-native-modules/signifyd-android).
</Note>

  </Tab>
  <Tab title="React Native">

Agrega los módulos de Android a `android/app/build.gradle` como muestra la pestaña de Android.

Los módulos de iOS aún no están disponibles para React Native.

  </Tab>
</Tabs>

## Activación {#activate}

<Tabs>
  <Tab title="iOS">

Cada módulo se registra solo cuando la app inicia, con `SdkPayments` o con `SdkPayments-Static`. Mantén tu inicialización habitual:

```swift
import SdkPayments

SdkPayments.initialize(apiKey: "your-public-api-key")
```

  </Tab>
  <Tab title="Android">

Cada módulo se registra solo cuando inicia el proceso de tu app, mediante [Jetpack App Startup](https://developer.android.com/topic/libraries/app-startup). Mantén tu inicialización habitual:

```kotlin
import com.yuno.payments.sdk.api.SdkPayments

class MyApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        SdkPayments.initialize(this, apiKey = "your-public-api-key")
    }
}
```

Para confirmar que un módulo se cargó, filtra Logcat por su etiqueta justo después de que la app inicie: `adb logcat -s ClearSaleAntifraud`, `adb logcat -s KoinAntifraud`, `adb logcat -s SignifydAntifraud`.

<Accordion title="Si tu app desactiva App Startup">

Algunas apps eliminan el content provider de App Startup de su manifiesto para controlar por sí mismas el trabajo de arranque. En ese caso, ejecuta tú mismo los inicializadores, antes de cualquier transacción:

```kotlin
import androidx.startup.AppInitializer
import com.yuno.antifraud.clearsale.ClearSaleAntifraudInitializer
import com.yuno.antifraud.koin.KoinAntifraudInitializer
import com.yuno.antifraud.signifyd.SignifydAntifraudInitializer
import com.yuno.threedsecure.netcetera.Netcetera3DSInitializer

val initializer = AppInitializer.getInstance(applicationContext)
initializer.initializeComponent(ClearSaleAntifraudInitializer::class.java)
initializer.initializeComponent(KoinAntifraudInitializer::class.java)
initializer.initializeComponent(SignifydAntifraudInitializer::class.java)
initializer.initializeComponent(Netcetera3DSInitializer::class.java)
```

</Accordion>

  </Tab>
  <Tab title="React Native">

En Android los módulos se registran solos mediante App Startup, como en la pestaña de Android. Los módulos de iOS aún no están disponibles para React Native.

  </Tab>
</Tabs>

<Tip>
Una vez que un módulo está registrado, el SDK lo usa automáticamente. No cambias ningún código de pago, inscripción ni 3DS.
</Tip>

## Qué necesita cada módulo de tu app {#what-each-module-needs-from-your-app}

### Módulos de antifraude {#antifraud-modules}

- No cambia nada en los datos que envías.
- La recopilación se ejecuta cuando el comprador confirma el pago, y el comprador espera a que termine. En Android la recopilación está limitada por el `timeout` configurado para el proveedor en tu cuenta de Yuno (5 segundos por defecto). Mantenlo corto.
- Ninguno solicita la ubicación. En Android, no agregues `play-services-location` versión 21 o superior junto al módulo de ClearSale: esas versiones son incompatibles con el SDK de ClearSale incluido.
- Signifyd en iOS: el módulo usa la clave del SDK de Signifyd que Yuno entrega para tu cuenta, por lo que no configuras ninguna clave en tu app. El SDK de Signifyd viene del repositorio privado de Signifyd, y tu compilación lo descarga con tu propio token. La configuración del token está en [Signifyd antifraud (iOS)](/es/docs/yuno-sdk/features/signifyd-ios).
- Signifyd en Android: el módulo usa la clave del SDK de Signifyd que Yuno entrega para tu cuenta, por lo que no configuras ninguna clave en tu app. El SDK de Signifyd viene del registro privado de Signifyd, y tu compilación lo descarga con tu propio token. El fragmento del registro, la configuración del token y los permisos están en [Signifyd antifraud (Android)](/es/docs/sdks/external-native-modules/signifyd-android).

### Netcetera 3DS {#netcetera-3ds}

**iOS:**
- Agrega el producto `SdkPaymentsNetcetera`. Ejecuta el desafío de 3D Secure dentro de tu app, para pagos e inscripción, en lugar del desafío en WebView.
- Solo en sandbox: `SdkPaymentsNetcetera` necesita el certificado raíz de prueba de Visa (`acq-root-certeq-prev-environment.crt`) en el bundle principal de tu app, igual que en Android. Pídelo a tu TAM de Yuno. Las compilaciones de producción no lo usan.

**Android:**
- Ejecuta el desafío de 3D Secure dentro de tu app, para pagos e inscripción, en lugar del desafío en WebView. Si personalizas los estilos del SDK, se propagan a la pantalla del desafío.
- El SDK sigue presentando el desafío a pantalla completa: no pasa por `showView`.
- Solo en sandbox: el SDK de Netcetera necesita un certificado raíz de prueba de Visa (`acq-root-certeq-prev-environment.crt`) en el paquete de tu app. Pídelo a tu TAM de Yuno, no se distribuye públicamente. Las compilaciones de producción no lo usan.

## Solución de problemas {#troubleshooting}

<AccordionGroup>
  <Accordion title="El módulo está instalado pero nada cambia (Android)">
    Revisa, en este orden: que el proveedor esté habilitado para tu cuenta de Yuno (consulta a tu TAM); que la línea del módulo aparezca en Logcat al iniciar; y que tu app no esté eliminando el proveedor de App Startup del manifiesto.
  </Accordion>
  <Accordion title="Android: NoClassDefFoundError que menciona LocationServices en cada recopilación">
    Es lo esperado con el módulo de ClearSale: la biblioteca de ubicación está ausente a propósito. El SDK captura el error internamente y la recopilación se completa igualmente.
  </Accordion>
</AccordionGroup>
