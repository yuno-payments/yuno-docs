<div className="ysdk-qs-intro-text">

Los SDK de Yuno exponen una sola clase `Transaction`. Lo que cambia entre las 
integraciones es **qué parámetros pasas** y **qué controladores 
sobrescribes**. Cada decisión es independiente. Combínalas libremente.

Esta página recorre las decisiones que tomarás y te lleva a la 
documentación relevante para cada una.

Activa el interruptor en cada paso y el código de la derecha se arma solo para tu plataforma. Cada bloque que usa el código también está escrito debajo de su paso, así que puedes componerlo a mano: parte de la base y luego agrega el bloque de cada paso en el que elegiste la respuesta distinta de la predeterminada. Un bloque de configuración reemplaza el `TransactionConfig`, un bloque de método de pago reemplaza el `PaymentMethodSelected`, una línea de indicador va dentro de `TransactionConfig`, y un bloque de controlador va dentro de tu clase de controlador, o dentro de las opciones de la transacción en Web.

## Base {#base}

El SDK hace todo: muestra el formulario, crea el pago, gestiona 3DS e informa el resultado a `onStatus`. Crea la sesión de checkout con `workflow: "SDK_SEAMLESS"` para esta base.

## 1. ¿Estás procesando un pago o guardando un método de pago? {#1-are-you-processing-a-payment-or-saving-a-payment-method}

<div data-toggle="enrollment"></div>

Esta decisión afecta qué tipo de sesión creas en tu backend y 
pasas al SDK.

- **Para procesar un pago**, crea una sesión de checkout y pásala a 
  `TransactionConfig` como `checkoutSession`. Usa esto cuando quieras 
  cobrarle al cliente.
- **Para guardar un método de pago sin cobrar**, crea una sesión de 
  cliente y pásala como `customerSession`. Usa esto cuando quieras 
  inscribir una tarjeta u otro método para uso futuro.
- **Para pagar e inscribir al mismo tiempo**, pasa solo `checkoutSession`:
  - **Tarjetas.** Activa el indicador "guardar tarjeta al pagar" en tu 
    Checkout Builder. El SDK cobra al cliente y guarda la 
    tarjeta para uso futuro.
  - **Otros métodos de pago.** Asegúrate de que la variante inscribible del 
    método esté agregada en tus conexiones. Cuando lo está, el SDK 
    gestiona el pago y la inscripción juntos a partir de la sesión de 
    checkout únicamente. En Web, pasa también `savePaymentMethodEnabled: true` 
    en `TransactionConfig` y crea la sesión de checkout con un 
    `customer_id`. Entonces el SDK agrega una opción de guardado al formulario.

No puedes pasar `checkoutSession` y `customerSession` al mismo 
tiempo.

Consulta [Sesiones](/es/docs/basic-concepts/sessions) e 
[Inscripción](/es/docs/yuno-sdk/features/enrollment).

## 2. ¿Quién crea el pago? {#2-who-creates-the-payment}

<div data-toggle="create-payment"></div>

Esta decisión afecta si sobrescribes `createPayment`.

- **Predeterminado. El SDK crea el pago.** Después de la tokenización, el 
  SDK llama a Yuno para crear el pago, gestiona 3DS si es necesario y 
  emite el estado final a `onStatus`. No sobrescribes nada. 
  Crea la sesión de checkout con `workflow: "SDK_SEAMLESS"` para que el 
  SDK pueda gestionar la creación del pago de principio a fin. Consulta el 
  [campo `workflow`](https://docs.y.uno/reference/checkout-sessions/create-checkout-session#body-workflow).
- **Tú creas el pago.** Sobrescribe `createPayment` para recibir el 
  token. Envíalo a tu backend, crea el pago llamando a 
  [`POST /v1/payments`](https://docs.y.uno/reference/payments/create-payment) y resuelve la 
  Promise/Task. Entonces el SDK consulta el estado y continúa el flujo.

<Warning>
  `workflow` es un campo del cuerpo de la solicitud 
  `POST /v1/checkout/sessions`. **No** forma parte de `TransactionConfig` y no se puede definir 
  desde el SDK. Debe coincidir con esta decisión:

  - El SDK crea el pago (sin sobrescribir) → crea la sesión con 
    `workflow: "SDK_SEAMLESS"`.
  - Tú creas el pago (sobrescribes `createPayment`) → usa el 
    workflow predeterminado (`SDK_CHECKOUT`).

  Con el `SDK_CHECKOUT` predeterminado y **sin** sobrescribir `createPayment`, 
  el backend rechaza la creación del pago por parte del SDK y la transacción 
  termina en `INTERNAL_ERROR` con `message.source: "backend"`, por lo que el 
  flujo no puede completarse.
</Warning>

<Note>
  En un flujo de **inscripción** (cuando pasas `customerSession`), 
  `createPayment` no se invoca con datos de pago. No hay 
  ningún pago que crear. Sobrescribir este controlador no tiene efecto en 
  la inscripción.
</Note>

Consulta [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment).

## 3. ¿Quién recopila los datos de pago? {#3-who-collects-the-payment-data}

<div data-toggle="transaction-data"></div>

Esta decisión afecta si pasas `transactionData` en 
`PaymentMethodSelected`.

- **Predeterminado. El SDK muestra los formularios.** El SDK presenta el 
  formulario adecuado (formulario de tarjeta, formulario de datos de APM, etc.) y recopila los datos que ingresa el 
  usuario.
- **Tú proporcionas los datos.** Pasa `transactionData` (`data` en Web) en 
  `PaymentMethodSelected` con los valores ya recopilados (por 
  ejemplo, datos de tarjeta capturados por tu propia interfaz). El SDK omite los 
  formularios y tokeniza directamente.

Consulta [`PaymentMethodSelected`](/es/docs/yuno-sdk/reference/objects-you-pass#payment-method-selected) 
y [`TransactionData`](/es/docs/yuno-sdk/reference/objects-you-pass#transaction-data).

## 4. ¿Quién controla la interfaz del formulario? (iOS, Android, React Native) {#4-who-controls-the-forms-ui-ios-android-react-native}

<div data-toggle="show-view"></div>

Esta decisión afecta si sobrescribes `showView`.

- **Predeterminado. El SDK presenta el formulario a pantalla completa.** El SDK muestra 
  el formulario con su propio encabezado y su propio botón de envío.
- **Tú incrustas el formulario.** Sobrescribe `showView` para recibir la vista del formulario 
  y un control `TransactionProcess`. Coloca la vista en tu propio 
  diseño y llama a `process.onSubmit()` para controlar el envío.

Este controlador solo está disponible en iOS, Android y React Native.

### En Web: tu propio botón de pago en lugar de `showView` {#on-web-your-own-pay-button-instead-of-showview}

En Web el SDK renderiza el formulario dentro del elemento que pasas como `elementSelector`, por lo que el formulario ya está en tu diseño. Para usar tu propio botón de envío, define `showPayButton: false` en `TransactionConfig` y llama a `transaction.submit()` desde tu botón después de que `start()` se haya resuelto. Si el formulario está incompleto, `submit()` informa `INTERNAL_ERROR` con el código `FORM_INVALID` a través de `onStatus` y mantiene el formulario montado. `submit()` no está disponible para las transacciones de inscripción.

Consulta [`showView`](/es/docs/yuno-sdk/controllers/show-view).

## Implementa siempre `onStatus` {#always-implement-onstatus}

Sin importar las decisiones que tomes arriba, siempre debes 
implementar `onStatus`. Es la única forma de saber cómo terminó la 
transacción. Consulta [`onStatus`](/es/docs/yuno-sdk/controllers/on-status) para saber cuándo 
se ejecuta y qué estados informa en cada plataforma, y 
[`Status`](/es/docs/yuno-sdk/reference/objects-you-receive#status) para ver el 
objeto que recibes.

## Referencia rápida {#quick-reference}

| Decisión | Valor predeterminado | Para cambiarlo | Lee |
|---|---|---|---|
| Tipo de sesión |  | Pasa `checkoutSession` o `customerSession` | [Inscripción](/es/docs/yuno-sdk/features/enrollment) |
| Quién crea el pago | SDK | Sobrescribe `createPayment` | [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment) |
| Quién recopila los datos | El SDK muestra los formularios | Pasa `transactionData` | [`TransactionData`](/es/docs/yuno-sdk/reference/objects-you-pass#transaction-data) |
| Pagar con dos tarjetas | Un método de pago | Pasa un arreglo de dos elementos a `start()`, cada uno con su `amount` (Web, iOS, Android, React Native) | [Pago dividido](/es/docs/yuno-sdk/features/split-payment) |
| Quién renderiza la interfaz del formulario (iOS, Android, React Native) | El SDK la presenta a pantalla completa | Sobrescribe `showView` | [`showView`](/es/docs/yuno-sdk/controllers/show-view) |
| Quién muestra el indicador de carga | El SDK muestra el suyo | Sobrescribe `showLoading` | [`showLoading`](/es/docs/yuno-sdk/controllers/show-loading) |
| ¿Mostrar la pantalla de resultado del SDK? | No (Web: Sí) | Define `showStatusScreen: true` en `TransactionConfig` (Web: `showStatusScreen: false` para ocultarla) | [`TransactionConfig`](/es/docs/yuno-sdk/reference/objects-you-pass#transaction-config) |
