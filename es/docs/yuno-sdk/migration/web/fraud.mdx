---
title: "Fraude"
description: "Migra las integraciones de fraude de Web (yuno.mountFraud + yuno.executeFraudCheck) al SDK unificado."
---

La evaluación de fraude tenía dos puntos de entrada heredados en Web:

- `yuno.mountFraud(...)`: modo UI. Mostraba un widget de fraude Y creaba el pago mediante su propio `yunoCreatePayment`.
- `yuno.executeFraudCheck(...)`: modo headless. Devolvía identificadores de huella digital del dispositivo; sin UI.

En la API unificada, la evaluación de fraude se ejecuta **automáticamente dentro de `Transaction`** durante la tokenización (no necesitas conectar nada). La verificación headless independiente pasa a un método de nivel superior en `SdkPayments` (no en `Transaction`, porque es una consulta, no una transacción). La variante UI se elimina: sus responsabilidades las absorbe `Transaction`.

## Antes de empezar {#before-you-start}

- Carga el bundle del SDK unificado en lugar del heredado e inicialízalo como muestra la comparación lado a lado: `window.Yuno.initialize(...)` pasa a ser `SdkPayments.initialize(...)`. Tu clave de API pública y las sesiones de checkout que crea tu backend no cambian ([Antes de comenzar](/es/docs/yuno-sdk/get-started#before-you-begin)).
- Si reemplazas `mountFraud` por un `Transaction`, decide quién crea el pago. El `workflow` de la sesión de checkout debe coincidir con esa decisión:

| Quién crea el pago | En Fraud UI tenías | En la API unificada | `workflow` de la sesión |
|---|---|---|---|
| Tu backend | `yunoCreatePayment` en `mountFraud` | Sobrescribe `createPayment` | Predeterminado (`SDK_CHECKOUT`) |
| El SDK | Sin equivalente: `mountFraud` creaba el pago mediante `yunoCreatePayment` | Sin sobrescritura | `SDK_SEAMLESS` |

<Warning>
Una sesión con el workflow predeterminado y sin sobrescritura de `createPayment` termina en `INTERNAL_ERROR`: el backend rechaza la creación del pago desde el SDK. Consulta [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Comparación lado a lado {#side-by-side}

### Verificación de fraude headless {#headless-fraud-check}

<CodeGroup>

```typescript Before. executeFraudCheck
const yuno = await window.Yuno.initialize('your-public-api-key')

const result = await yuno.executeFraudCheck({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    paymentType: 'CARD',
    deviceFingerprints: [],
})

if (result.status === 'success') {
    console.log('fingerprints:', result.deviceFingerprints)
} else {
    console.error('fraud check failed:', result.error)
}
```

```typescript After. sdkPayments.antifraud
const sdkPayments = await SdkPayments.initialize('your-public-api-key')

const result = await sdkPayments.antifraud({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    paymentType: 'CARD',
})

if (result.status === 'success') {
    for (const fp of result.deviceFingerprints) {
        console.log('fingerprint:', fp.providerId, fp.sessionId)
    }
} else {
    console.error('fraud check failed:', result.error)
}
```

</CodeGroup>

### UI de fraude {#fraud-ui}

<CodeGroup>

```typescript Before. mountFraud (UI)
await yuno.mountFraud({
    checkoutSession: 'session-from-backend',
    language: 'en',
    deviceFingerprints: [],
    type: 'CARD',
    yunoCreatePayment: async (oneTimeToken, info) => {
        await myBackend.pay(oneTimeToken)
        yuno.continuePayment()
    },
    yunoError: (msg) => console.error(msg),
})
```

```typescript After. Normal Transaction, fraud is automatic
const transaction = sdkPayments.transaction({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    elementSelector: '#root',
    deviceFingerprints: [],            // optional: inject your own
    createPayment: async (token) => {
        await myBackend.pay(token.token)
    },
    showLoading: (isLoading) => mySpinner.toggle(isLoading),
    onStatus: (result) => console.log('done:', result.status),
})

await transaction.start({ paymentMethod: { type: 'CARD' } })
```

</CodeGroup>

## Qué cambia {#what-changes}

Agrupado en el orden en que editas el código. **Renombrado**: mismo rol, nombre nuevo. **Movido**: mismo valor, nuevo responsable. **Eliminado**: nada que llamar. **Nuevo**: sin equivalente heredado. La última columna es lo único que tienes que hacer además del cambio de nombre.

### Inicialización y configuración {#initialization-and-config}

| Fraude | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `window.Yuno.initialize(publicApiKey)` | `SdkPayments.initialize(publicApiKey)` | Renombrado | El global es `window.SdkPayments`. Como antes, usa `await`: se resuelve con la instancia de `SdkPayments`. |
| Argumentos `checkoutSession`, `countryCode` de `executeFraudCheck` | Los mismos argumentos de `sdkPayments.antifraud` | Movido | |
| `executeFraudCheck.paymentType` (internamente tenía `CARD` por defecto) | `antifraud.paymentType?` | Movido | Mismo valor por defecto. |
| `executeFraudCheck.deviceFingerprints?` | `antifraud.deviceFingerprints?` | Movido | Misma forma (`ExternalProviderId[]`). |
| `deviceFingerprints?: ExternalProviderId[]` pasado a `mountFraud` junto con los datos del pago | `deviceFingerprints?: ExternalProviderId[]` en `TransactionConfig` | Movido | Opcional: inyecta los tuyos. |
| `checkoutSession`, `language`, `type` en `mountFraud` | `checkoutSession`, `language` en la configuración de la transacción; `type` pasa a ser `paymentMethod.type` en `start()` | Movido | |

### Callbacks {#callbacks}

| Fraude | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `yunoCreatePayment(oneTimeToken, info)` en `mountFraud` | `createPayment(token)` en la configuración de la transacción | Renombrado | La creación del pago ya no va unida al fraude: es `createPayment` (o la gestiona el SDK, consulta Antes de empezar). Basado en Promise, con un solo argumento. Crea el pago y resuelve: resolver equivale a lo que antes era `yuno.continuePayment()`. Consulta [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment). |
| `yunoError(msg)` en `mountFraud` | *(eliminado)* | Eliminado | La transacción informa su resultado mediante `onStatus`. |
| *(ninguno)* | `showLoading(isLoading)` | Nuevo | Opcional. Úsalo si necesitas retroalimentación personalizada en la UI ahora que el widget de fraude ya no existe. Consulta [`showLoading`](/es/docs/yuno-sdk/controllers/show-loading). |
| *(ninguno)* | `onStatus(result)` | Nuevo | La transacción informa aquí su estado final. Consulta [`Status`](/es/docs/yuno-sdk/reference/objects-you-receive#status). |

### Puntos de entrada {#entry-points}

| Fraude | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `yuno.executeFraudCheck({...})` | `sdkPayments.antifraud({...})` | Renombrado | Método de nivel superior en `SdkPayments`, no en `Transaction`: una consulta independiente, no parte del ciclo de vida de una transacción. Úsalo si necesitas una evaluación previa antes de crear una sesión de checkout. |
| `ExecuteFraudCheckReturn` (`status`, `deviceFingerprints`, `error`) | Unión discriminada `FraudResult` | Renombrado | La Promise nunca se rechaza. `status: 'success'` → `deviceFingerprints` presente (`{ providerId: string; sessionId: string }[]`); `status: 'error'` → `error: Error` presente. En comparación con v1, donde `error` siempre era opcional junto a `deviceFingerprints`, la nueva forma te obliga a revisar `status` antes de leer cualquiera de los dos campos (TS lo acota): ya no hay campos opcionales. |
| `yuno.mountFraud({...})` | *(eliminado)* | Eliminado | Sin reemplazo directo: lo sustituye un `sdkPayments.transaction(config).start({ paymentMethod })` normal. Las responsabilidades del widget ahora son parte de `Transaction`: las señales de fraude se recopilan automáticamente durante la tokenización en los flujos normales, y la creación del pago pasa a `createPayment` (consulta Callbacks). |
| `yuno.continuePayment()` dentro de `yunoCreatePayment` | *(eliminado)* | Eliminado | Elimina la llamada: resolver `createPayment` continúa el flujo. |
