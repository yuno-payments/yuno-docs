---
title: "Modo Lite"
description: "Migra las integraciones Lite de React Native (YunoSdk.startPaymentLite) a la API unificada Transaction."
---

El modo Lite preseleccionaba el método de pago de tu lado y delegaba en el SDK el renderizado del formulario y la tokenización. En React Native 1.x el SDK emitía entonces el token de un solo uso mediante `onOneTimeToken`, tu backend creaba el pago y `continuePayment` reanudaba el flujo. En la API unificada esto es `Transaction.start(paymentSelected)` con un controlador `createPayment`: el SDK espera a tu backend y continúa por sí solo.

## Antes de empezar {#before-you-start}

- Actualiza `@yuno-payments/yuno-sdk-react-native` a la versión 2.0.0 y ejecuta `pod install`. Tu clave de API pública y las sesiones de checkout que crea tu backend no cambian ([Antes de comenzar](/es/docs/yuno-sdk/get-started#before-you-begin)).
- En Android, `minSdkVersion` ahora es 23. Si tu `android/build.gradle` aplica el plugin del compilador de Compose al módulo de Yuno (una solución alternativa de 1.x), elimina ese bloque: con 2.0.0 la compilación falla con "The Compose Compiler requires the Compose Runtime to be on the class path".
- Decide quién crea el pago. El `workflow` de la sesión de checkout debe coincidir con esa decisión:

| Quién crea el pago | En Lite tenías | En la API unificada | `workflow` de la sesión |
|---|---|---|---|
| Tu backend | `onOneTimeToken`, tu llamada al backend y luego `continuePayment` | Implementa `createPayment` | Predeterminado (`SDK_CHECKOUT`) |
| El SDK | `startPaymentSeamlessLite` (consulta [Seamless Lite](/es/docs/yuno-sdk/migration/react-native/payment/seamless-lite)) | No implementes `createPayment` | `SDK_SEAMLESS` |

<Warning>
Una sesión con el workflow predeterminado y sin `createPayment` en el controlador termina en `INTERNAL_ERROR`: el backend rechaza la creación del pago por parte del SDK. Consulta [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Comparación lado a lado {#side-by-side}

<CodeGroup>

```tsx Before. Lite mode
import { YunoSdk, YunoStatus } from '@yuno-payments/yuno-sdk-react-native';

// 1. Initialize once at app startup
await YunoSdk.initialize({
  apiKey: 'your-public-api-key',
  countryCode: 'CO',
  yunoConfig: { language: 'en', saveCardEnabled: true },
});

// 2. Subscribe to the token and the result
const tokenSubscription = YunoSdk.onOneTimeToken(async (token) => {
  await myBackend.createPayment(token);
  await YunoSdk.continuePayment(checkoutSession, 'CO', true);
});
const statusSubscription = YunoSdk.onPaymentStatus((state) => {
  switch (state.status) {
    case YunoStatus.SUCCEEDED: console.log('Success'); break;
    case YunoStatus.REJECTED: console.log('Rejected'); break;
    case YunoStatus.FAILED: console.log('Failed'); break;
    case YunoStatus.PROCESSING: console.log('Processing'); break;
    case YunoStatus.CANCELLED_BY_USER: console.log('User cancelled'); break;
  }
});

// 3. Trigger the payment with a pre-selected method
await YunoSdk.startPaymentLite({
  checkoutSession,
  methodSelected: { paymentMethodType: 'CARD', vaultedToken: savedToken },
  showPaymentStatus: true,
});

// 4. Remove the subscriptions when the screen goes away
tokenSubscription.remove();
statusSubscription.remove();
```

```tsx After. Unified Transaction
import { SdkPayments, Transaction } from '@yuno-payments/yuno-sdk-react-native';

// 1. Initialize once at app startup
await SdkPayments.initialize('your-public-api-key');

// 2. Build the transaction with its controller
const transaction = new Transaction({
  checkoutSession,
  countryCode: 'CO',
  language: 'en',
  saveCardEnabled: true,
  showStatusScreen: true,
  controller: {
    createPayment: async (token) => {
      await myBackend.createPayment(token);
    },
    onStatus: (status) => {
      switch (status.status) {
        case 'SUCCEEDED': console.log('Success'); break;
        case 'DECLINED': console.log('Declined'); break;
        case 'REJECTED': console.log('Rejected'); break;
        case 'ERROR': console.log('Error'); break;
        case 'PENDING': console.log('Pending'); break;
        case 'INTERNAL_ERROR': console.log('Internal error'); break;
        case 'USER_CANCEL': console.log('User cancelled'); break;
      }
    },
  },
});

// 3. Trigger the payment with a pre-selected method
await transaction.start({ type: 'CARD', vaultedToken: savedToken });

// 4. Release it when the screen goes away
transaction.dispose();
```

</CodeGroup>

## Qué cambia {#what-changes}

Agrupado en el orden en que editas el código. **Renombrado**: mismo rol, nombre nuevo. **Movido**: mismo valor, nuevo responsable. **Eliminado**: no hay nada que llamar. **Nuevo**: sin equivalente anterior. La última columna es lo único que tienes que hacer además del cambio de nombre.

### Inicialización y configuración {#initialization-and-config}

| Lite | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `YunoSdk` | `SdkPayments` y `Transaction` | Renombrado | `SdkPayments` conserva las llamadas globales; todo lo relativo a un pago vive en una `Transaction`. |
| `YunoSdk.initialize({ apiKey, countryCode, yunoConfig, iosConfig, androidConfig })` | `SdkPayments.initialize(apiKey)` | Renombrado | Ahora solo recibe la clave. Los demás argumentos pasan a `TransactionConfig` o desaparecen (filas siguientes). |
| `countryCode` de `initialize` y el argumento opcional `countryCode` de cada llamada | `TransactionConfig.countryCode` | Movido | Pásalo una vez por transacción. |
| `yunoConfig.language` | `TransactionConfig.language` | Movido | Pásalo por transacción en lugar de una sola vez al iniciar. |
| `yunoConfig.saveCardEnabled` | `TransactionConfig.saveCardEnabled` | Movido | Pásalo por transacción en lugar de una sola vez al iniciar. |
| `yunoConfig.keepLoader` | *(eliminado)* | Eliminado | El SDK conserva su indicador de carga. Implementa `showLoading` solo si quieres uno propio (consulta Controlador). |
| `yunoConfig.isDynamicViewEnabled`, `cardFormDeployed`, el enum `CardFlow` | *(eliminado)* | Eliminado | Elimínalos: el SDK tiene un solo formulario de tarjeta, y la lista desplegada de métodos de pago se configura en el Checkout Builder de tu Dashboard. |
| `iosConfig`, `androidConfig` | *(eliminado)* | Eliminado | Elimínalos. |
| `checkoutSession` de `startPaymentLite` | `TransactionConfig.checkoutSession` | Movido | El argumento de la llamada se convierte en un campo de configuración. |
| `showPaymentStatus` de `startPaymentLite` | `TransactionConfig.showStatusScreen` | Movido | Consulta la nota siguiente. |
| *(ninguno)* | `TransactionConfig.appearance` | Nuevo | Opcional. Colores y fuente de las vistas del SDK, por transacción. Consulta [Estilos](/es/docs/yuno-sdk/features/styling). |

<Note>
**La pantalla de resultado del SDK ahora está desactivada de forma predeterminada.** Establece `showStatusScreen: true` para conservarla.
</Note>

### Controlador {#controller}

| Lite | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| Suscripciones a eventos (`onPaymentStatus`, `onOneTimeToken`) | `TransactionConfig.controller` | Renombrado | Los listeners se convierten en un único objeto simple con métodos, que se pasa en la configuración. No hay suscripciones que eliminar: llama a `transaction.dispose()` cuando la pantalla desaparezca. |
| `YunoSdk.onPaymentStatus((state) => …)` | `onStatus(status)` | Renombrado | Sigue siendo el único callback de resultado, una vez por transacción con el estado final, también cuando el SDK muestra su pantalla de resultado. `state.status` pasa a ser `status.status`, y `status.substatus` y `status.message` son nuevos. `status` y `substatus` provienen del backend, tal como los devuelve: los valores `FAILED` y `PROCESSING` de 1.x ya no se emiten, así que maneja `DECLINED`, `REJECTED`, `ERROR` y `PENDING` en su lugar. `CANCELLED_BY_USER` ahora es `USER_CANCEL`. El propio SDK solo emite `INTERNAL_ERROR` y `USER_CANCEL`. Consulta [`Status`](/es/docs/yuno-sdk/reference/objects-you-receive#status). |
| `YunoSdk.onOneTimeToken(listener)` / `onOneTimeTokenInfo(listener)` + tu llamada al backend + `YunoSdk.continuePayment(checkoutSession, countryCode, showPaymentStatus)` | `createPayment(token)` | Renombrado | Los tres pasos se convierten en un solo método. `token` es el objeto completo del token de un solo uso, no solo la cadena del token: envía `token.token` a tu backend. Crea el pago y resuelve la Promise devuelta; el SDK entonces consulta el estado, ejecuta 3DS si es necesario y llama a `onStatus`. Si la Promise se rechaza, el flujo se detiene: en Android `onStatus` recibe `INTERNAL_ERROR` con `message.code` `MERCHANT_CREATE_PAYMENT_FAILED`; en iOS el flujo se cierra sin un estado. Consulta [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment). |
| `getLastOneTimeToken`, `getLastOneTimeTokenInfo`, `clearLastOneTimeToken`, `clearLastPaymentStatus` | *(eliminado)* | Eliminado | El token llega en `createPayment` y el resultado en `onStatus`: no hay nada en caché que leer ni limpiar. |
| `YunoSdk.hideLoader()` | `showLoading(isLoading)` | Renombrado | Opcional. Impleméntalo y el SDK oculta su propio indicador de carga y te informa del estado de carga. Consulta [`showLoading`](/es/docs/yuno-sdk/controllers/show-loading). |
| *(ninguno)* | `showView(view, process, step)` | Nuevo | Opcional. Incrusta el formulario del SDK en tu propia pantalla con `<YunoView>`. Consulta [`showView`](/es/docs/yuno-sdk/controllers/show-view). |

### Puntos de entrada {#entry-points}

| Lite | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `YunoSdk.startPaymentLite({ checkoutSession, methodSelected, showPaymentStatus }, countryCode)` | `new Transaction(config).start(paymentSelected)` | Renombrado | Crea la configuración y luego llama a `start`. Sigues eligiendo el método y pasándolo. `checkoutSession` y `showPaymentStatus` pasaron a la configuración (consulta Inicialización y configuración). |
| `methodSelected: { paymentMethodType, vaultedToken }` | `PaymentMethodSelected`: `{ type, vaultedToken }` | Renombrado | `paymentMethodType` ahora es `type`. Consulta [`PaymentMethodSelected`](/es/docs/yuno-sdk/reference/objects-you-pass#payment-method-selected). |
| `YunoSdk.receiveDeeplink(url)` | `transaction.handleDeeplink(url)` | Renombrado | Reenvía a la transacción las URL que recibe tu app. Consulta [Manejo de deeplinks](/es/docs/yuno-sdk/features/handle-deeplinks). |
