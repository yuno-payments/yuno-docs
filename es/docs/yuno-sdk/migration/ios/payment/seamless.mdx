---
title: "Modo Seamless"
description: "Migra las integraciones iOS Seamless (Yuno.startPaymentSeamlessLite) a la API unificada Transaction."
---

Seamless era el punto de entrada anterior más simple: una sola llamada `await` que devolvía el resultado final. Sin delegate ni callbacks. Entregabas un `SeamlessParams` y un `PaymentMethodSelected`; el SDK renderizaba el formulario, tokenizaba, creaba el pago, ejecutaba 3DS y devolvía un `Yuno.Result`.

En la API unificada el mismo flujo es el **comportamiento por defecto** de `Transaction.start(paymentSelected:)`. No necesitas sobrescribir ningún controlador aparte de `onStatus`. El único cambio estructural es el modelo de entrega del resultado: antes se devolvía de forma asíncrona, ahora llega mediante un callback en `onStatus`.

## Antes de comenzar {#before-you-start}

- Reemplaza `import YunoSDK` por `import SdkPayments`. Tu clave de API pública y las sesiones de checkout que crea tu backend no cambian ([Before you begin](/es/docs/yuno-sdk/get-started#before-you-begin)).
- Decide quién crea el pago. El `workflow` de la sesión de checkout debe coincidir con esa decisión:

| Quién crea el pago | En Seamless tenías | En la API unificada | `workflow` de la sesión |
|---|---|---|---|
| Tu backend | Sin equivalente: Seamless nunca permitía crearlo | Sobrescribe `createPayment` | Por defecto (`SDK_CHECKOUT`) |
| El SDK | Siempre | Sin sobrescritura | `SDK_SEAMLESS` |

<Warning>
Una sesión con el workflow por defecto y sin sobrescritura de `createPayment` termina en `INTERNAL_ERROR`: el backend rechaza la creación del pago por parte del SDK. Consulta [`createPayment`](/es/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Comparación lado a lado {#side-by-side}

<CodeGroup>

```swift Before. Seamless mode
import YunoSDK

// 1. Initialize once at app startup
Yuno.initialize(apiKey: "your-public-api-key")

// 2. Trigger the payment from a single async call
func pay(paymentSelected: PaymentMethodSelected) async {
    let params = SeamlessParams(
        checkoutSession: "session-from-backend",
        countryCode: "CO",
        language: "en",
        viewController: nil
    )

    let result = await Yuno.startPaymentSeamlessLite(
        with: params,
        paymentSelected: paymentSelected,
        showPaymentStatus: true
    )

    switch result.status {
    case .succeeded:      print("Success")
    case .reject:         print("Rejected")
    case .fail:           print("Failed")
    case .processing:     print("Processing")
    case .internalError:  print("Internal error")
    case .userCancelled:  print("User cancelled")
    @unknown default:     break
    }
}
```

```swift After. Unified Transaction
import SdkPayments

// 1. Initialize once at app startup
SdkPayments.initialize(apiKey: "your-public-api-key")

// 2. Implement a minimal controller
final class Checkout: SdkPayments.TransactionController {

    func onStatus(status: SdkPayments.TransactionStatus) {
        switch status.status {
        case "INTERNAL_ERROR":  print("Internal error")
        case "USER_CANCEL":     print("User cancelled")
        // Handle other backend statuses (e.g. SUCCEEDED, DECLINED, PENDING) as needed.
        default:                break
        }
    }

    // 3. Trigger the payment
    func pay(paymentSelected: SdkPayments.PaymentMethodSelected) {
        let config = SdkPayments.TransactionConfig(
            checkoutSession: "session-from-backend",
            countryCode: "CO",
            language: "en",
            controller: self,
            showStatusScreen: true,
            viewController: nil
        )

        SdkPayments.Transaction(config: config)
            .start(paymentSelected: paymentSelected)
    }
}
```

</CodeGroup>

## Qué cambia {#what-changes}

Agrupado en el orden en que editas el código. **Renombrado**: mismo rol, nuevo nombre. **Movido**: mismo valor, nuevo propietario. **Eliminado**: no hay nada que llamar. **Nuevo**: sin contraparte anterior. La última columna es lo único que debes hacer además del cambio de nombre.

### Inicialización y configuración {#initialization-and-config}

| Seamless | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `import YunoSDK` | `import SdkPayments` | Renombrado | |
| `Yuno.initialize(apiKey:)` | `SdkPayments.initialize(apiKey:)` | Renombrado | El parámetro `callback:` ya no existe; usa la sobrecarga `async` si necesitas esperar. |
| `Yuno.Appearance` pasado en `YunoConfig.appearance` | `SdkPayments.Appearance` en `SdkPayments.TransactionConfig.appearance` | Renombrado | Mismo inicializador; elimina el prefijo `Yuno.` y pásalo en cada transacción en lugar de una sola vez al inicio. |
| `SeamlessParams.checkoutSession`, `.countryCode`, `.language`, `.viewController` | Los mismos campos en `SdkPayments.TransactionConfig` | Movido | Mismos valores; `viewController` sigue siendo exclusivo de iOS y opcional en SwiftUI. La configuración también recibe el `controller` (consulta Controlador). |
| Argumento `showPaymentStatus:` de `startPaymentSeamlessLite` | `SdkPayments.TransactionConfig.showStatusScreen` | Movido | Consulta la nota siguiente. |

<Note>
**La pantalla de resultado del SDK ahora está desactivada por defecto.** Define `showStatusScreen: true` para mantenerla.
</Note>

### Controlador {#controller}

| Seamless | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| *(sin delegate)* | `SdkPayments.TransactionController` | Nuevo | Incluso el caso más simple necesita una instancia de controlador: haz que una clase implemente solo `onStatus` y pásala como `TransactionConfig.controller`. El SDK no la retiene: mantenla viva durante toda la transacción. |
| `Yuno.Result` devuelto por `await` | `onStatus(status:)` con `SdkPayments.TransactionStatus` | Movido | El resultado ahora se entrega mediante callback: no puedes usar `await` en línea, así que si tu código encadenaba lógica sobre el valor devuelto o lo devolvía al llamador, refactorízalo para reaccionar dentro de `onStatus`. Sigue siendo el único callback de resultado, una vez por transacción, también cuando el SDK muestra su pantalla de resultado. `status` y `substatus` provienen del backend; el SDK solo emite `INTERNAL_ERROR` y `USER_CANCEL`. Consulta [`Status`](/es/docs/yuno-sdk/reference/objects-you-receive#status). |
| `Yuno.Result.message` | `SdkPayments.TransactionStatus.message` | Renombrado | Mismo rol. `source` ahora es un enum (`.sdk` / `.backend`) y `code` ya no es opcional. |

### Puntos de entrada {#entry-points}

| Seamless | Unificado | Cambio | Qué hacer |
|---|---|---|---|
| `Yuno.startPaymentSeamlessLite(with:paymentSelected:showPaymentStatus:)`, tanto la sobrecarga `async` como la de `callback:` | `SdkPayments.Transaction(config:).start(paymentSelected:)` | Renombrado | Crea la configuración y luego llama a `start`. No hay nada que esperar con `await` ni callback que pasar: el resultado llega en `onStatus`. Sigues eligiendo el método y pasándolo. |
| `Yuno.receiveDeeplink(_:)` | `SdkPayments.handleDeeplink(_:)` | Renombrado | Mismo rol: reenvía la URL que recibe tu app después de una redirección externa. Consulta [Handle deeplinks](/es/docs/yuno-sdk/features/handle-deeplinks). |
| `Yuno.hideLoader()` | *(eliminado)* | Eliminado | Elimina la llamada: el SDK cierra su propio indicador de carga. Con una sobrescritura de `showLoading` recibes `isLoading: false` en su lugar. |
