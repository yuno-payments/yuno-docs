Aunque Yuno ofrece opciones de pago muy diversas, el proceso básico de pago siempre sigue la misma secuencia. Esta guía desglosa paso a paso el proceso y los elementos clave involucrados, y aclara cómo fluyen los pagos cuando usas los SDKs o la API de Yuno.

## El proceso de pago de Yuno {#the-yuno-payment-process}

El proceso de pago consta de los siguientes pasos:

<Steps>
  <Step title="Crea un cliente">
    En Yuno, los pagos normalmente se vinculan a un [cliente](/es/docs/basic-concepts/customers). El sistema guarda datos del cliente como el nombre, la dirección y el número de teléfono. Yuno usa esta información para procesar pagos con distintos [métodos de pago](/docs/basic-concepts/payment-methods) y procesadores.
    Cuando creas un cliente, Yuno genera un identificador único que se usa en los pasos siguientes.
    <Note>
      Se puede crear un pago sin un cliente. Si creas la sesión de checkout con un `customer_id`, envía el mismo cliente en `customer_payer.id` cuando crees el pago.
    </Note>
  </Step>
  <Step title="Crea una sesión de checkout">
    Para procesar un pago con el Yuno SDK o el Checkout, crea una [sesión de checkout](/es/docs/basic-concepts/sessions#checkout-session). Esta sesión conecta al cliente con el pago y guarda los datos clave de la transacción. Yuno carga todos los [métodos de pago](/docs/basic-concepts/payment-methods) disponibles vinculados a tu cuenta.
    <Note>
      Las integraciones directas (servidor a servidor) omiten este paso y envían los datos de la transacción directamente al crear el pago. Define `workflow` como `DIRECT` (o `REDIRECT`) en la solicitud de pago. Sin ese valor, la API pide el objeto `checkout`.
    </Note>

  </Step>
  <Step title="Recopila los datos de pago">
    Para procesar un pago, necesitas recopilar la información de pago del cliente.
    * **Integración con SDK**: los SDKs de Yuno capturan los datos sensibles de forma segura y generan un token de un solo uso (OTT).
    * **Integración directa**: recopilas los datos de pago directamente en tus servidores (lo que requiere cumplimiento PCI) y los envías al endpoint de pagos.
    <Note>
      Un OTT es un código temporal de un solo uso que los SDKs de Yuno usan para reforzar la seguridad de los comercios.
    </Note>
  </Step>

  <Step title="Crea el pago">
    Un [pago](/es/docs/basic-concepts/payments-1) representa la transacción final. Usa los datos recopilados en los pasos anteriores (el ID del cliente y la información de pago) para procesar la transacción final.

    <Note>
      Algunos campos son opcionales, pero pueden mejorar la experiencia del usuario. Ten en cuenta los campos obligatorios si decides incluir esta información.
    </Note>
    <Note>
      La solicitud de creación de pago requiere el encabezado `X-Idempotency-Key`. Envía un valor único (por ejemplo, un UUID) para poder reintentar la solicitud de forma segura. Consulta [Idempotencia](/reference/getting-started/authentication#idempotency).
    </Note>
  </Step>
</Steps>

Después de crear el pago, Yuno te mantiene al tanto de las actualizaciones mediante [webhooks](/es/docs/basic-concepts/webhooks-1). Además, Yuno ofrece soluciones de [prevención de fraude](/docs/basic-concepts/fraud) que puedes integrar en el proceso de pago.
