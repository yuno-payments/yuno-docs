## Qué expone el servidor {#what-the-server-exposes}

Tres herramientas, todas de solo lectura. Tu agente las llama por sí solo una vez que el servidor está conectado.

<div className="yd-mcp-tools">
  <div className="yd-mcp-tool"><code>search_yuno_api_documentation</code><p>Busca en la documentación guías, ejemplos de código y referencias de la API que coincidan con una pregunta.</p></div>
  <div className="yd-mcp-tool"><code>query_docs_filesystem_yuno_api_documentation</code><p>Ejecuta consultas de solo lectura al estilo shell, como <code>rg</code> o <code>cat</code>, sobre la documentación como si fuera un sistema de archivos virtual.</p></div>
  <div className="yd-mcp-tool"><code>submit_feedback</code><p>Reporta al equipo de documentación una página incorrecta o faltante, con la ruta de la página y qué está mal.</p></div>
</div>

## Agrega el servidor {#add-the-server}

<Steps>
  <Step title="Elige tu herramienta y agrega la URL">
    <Tabs>
      <Tab title="Cursor">
        1. Abre **Cursor Settings** (`Cmd+Shift+P` o `Ctrl+Shift+P`, luego "Open MCP Settings").
        2. Haz clic en **+ Add New MCP Server**.
        3. Completa los detalles:
           - **Name**: Yuno Docs
           - **Type**: `http`
           - **URL**: `https://docs.y.uno/mcp`
        4. Haz clic en **Save**.
      </Tab>
      <Tab title="Claude Code">
        ```bash
        claude mcp add --transport http yuno-docs https://docs.y.uno/mcp
        ```

        Agrega `--scope project` para compartir el servidor con tu equipo mediante `.mcp.json`.
      </Tab>
      <Tab title="Claude Desktop">
        1. Abre el archivo de configuración de Claude Desktop (`~/Library/Application Support/Claude/claude_desktop_config.json` en macOS, `%APPDATA%\Claude\claude_desktop_config.json` en Windows).
        2. Agrega el servidor a `mcpServers`:

        ```json
        {
          "mcpServers": {
            "yuno-docs": {
              "url": "https://docs.y.uno/mcp"
            }
          }
        }
        ```
      </Tab>
      <Tab title="Codex">
        ```bash
        codex mcp add yuno-docs --url https://docs.y.uno/mcp
        ```
      </Tab>
      <Tab title="VS Code">
        Crea `.vscode/mcp.json` en tu proyecto:

        ```json
        {
          "servers": {
            "yuno-docs": {
              "type": "http",
              "url": "https://docs.y.uno/mcp"
            }
          }
        }
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step title="Verifica la conexión">
    Hazle a tu agente una pregunta que solo responda la documentación:

    ```text
    Which two headers authenticate a Yuno API call?
    ```

    Un agente conectado responde `public-api-key` y `private-secret-key`, y cita una página de docs.y.uno. Si adivina o nombra otro encabezado, el servidor aún no está conectado: reinicia la herramienta y revisa la URL.
  </Step>
  <Step title="Pide un primer pago">
    El servidor funciona mejor con una tarea concreta. Por ejemplo:

    ```text
    Using the Yuno docs, write a Node script that
    creates a checkout session and a sandbox payment
    with the test card from the Quickstart.
    ```

    El agente lee el [Quickstart](/es/docs/quickstart) y la referencia de la API a través del servidor, de modo que la URL base, los encabezados y los campos obligatorios provienen de la documentación actual.
  </Step>
</Steps>

## ¿Qué MCP de Yuno necesitas? {#which-yuno-mcp-do-you-need}

| Servidor | Qué hace | Credenciales |
|---|---|---|
| **MCP de documentación** (esta página) | Busca y lee la documentación de Yuno. No puede actuar sobre tu cuenta. | Ninguna |
| [MCP de acciones local](/es/docs/ai-capabilities/building-ai-integrations-with-yunos-llms-and-mcp) | Se ejecuta desde tu máquina con `npx`. Crea y gestiona pagos, clientes y suscripciones. | Tus API keys |
| [MCP de acciones remoto](/es/docs/ai-capabilities/remote-yuno-mcp-server) | Endpoint alojado con las mismas acciones, además de límites de tasa, vinculación de IP y vencimiento de sesión aplicados por Yuno. | Tus API keys |
