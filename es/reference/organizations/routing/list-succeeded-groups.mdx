---
title: "Listar grupos de exitosos"
description: "Lista los grupos de exitosos de una cuenta, para referenciarlos por group_id desde las salidas SUCCEEDED_GROUP del enrutamiento."
openapi: "/openapi/es/organizations/routing/list-succeeded-groups.json GET /routing/succeeded-groups"
---

Lista los grupos de exitosos guardados en una cuenta: grupos de subestados de éxito que referencias con `status: "SUCCEEDED_GROUP"` en una salida de enrutamiento, para reaccionar de forma distinta ante una autorización que el proveedor retiene para revisión (`PENDING_IN_REVIEW`) que ante una aprobación simple. Usa el `id` de un grupo como `group_id`: consulta [Grupos de resultados](/es/reference/organizations/routing/routing-resource-shape#outcome-groups).

El endpoint es de solo lectura. Los grupos de exitosos se crean en el dashboard.

### Parámetros de consulta {#query-parameters}

<ParamField query="account_id" type="string" required>
  La cuenta para la que se listan los grupos. Debe pertenecer a la organización a la que están asociadas tus credenciales de API.
</ParamField>

### Respuesta {#response}

Un arreglo con los grupos de la cuenta, o un arreglo vacío si no tiene ninguno. Cada grupo contiene:

<ResponseField name="id" type="integer">
  El valor que se envía como `group_id`.
</ResponseField>
<ResponseField name="name" type="string">
  El nombre del grupo, tal como se muestra en el dashboard y se devuelve como `group_name` en las salidas de enrutamiento.
</ResponseField>
<ResponseField name="type" type="enum">
  Siempre `SUCCEEDED_GROUP`, el `status` de salida con el que se usa el grupo.
</ResponseField>
<ResponseField name="succeeded_types" type="string[]">
  Los miembros del grupo. Hoy el único subestado de éxito que se puede agrupar es `PENDING_IN_REVIEW`. Consulta [Códigos de transacción](/es/reference/payments/status-and-response-codes/transaction#succeeded-status).
</ResponseField>

<CodeGroup>
```bash cURL
curl -X GET 'https://api.y.uno/v1/routing/succeeded-groups?account_id=7825fc5e-e50a-4248-9ae8-5d3786afb0be' \
  -H 'public-api-key: <YOUR_PUBLIC_KEY>' \
  -H 'private-secret-key: <YOUR_SECRET_KEY>'
```

```json 200 OK
[
  {
    "id": 430,
    "name": "Pending review",
    "type": "SUCCEEDED_GROUP",
    "succeeded_types": ["PENDING_IN_REVIEW"]
  }
]
```

```json 400 Bad Request — Missing account_id
{
  "code": "ROUTING_VALIDATION_FAILED",
  "messages": ["account_id is required."]
}
```
</CodeGroup>

### Errores {#errors}

<div className="code-nowrap-table dense-table">

| HTTP | `code` | Cuándo |
|---|---|---|
| `400` | `ROUTING_VALIDATION_FAILED` | Falta el parámetro de consulta `account_id`. |
| `400` | `INVALID_ACCOUNT_ID` | `account_id` pertenece a una organización que tu clave de API no posee. |
| `401` | `NOT_AUTHENTICATED` | Falta el encabezado `public-api-key` o `private-secret-key`. |
| `401` | `INVALID_CREDENTIALS` | Par de claves incorrecto, o se usó una **clave de API personalizada** del Dashboard. Usa una clave de cuenta o de organización en su lugar. |
| `502` | `ROUTING_UPSTREAM_ERROR` | No se pudo establecer conexión con el servicio de enrutamiento. Reintenta la solicitud. |

</div>
