---
title: "Consultar un reembolso sin referencia por ID"
description: "Consulta los detalles de un reembolso sin referencia existente mediante el id proporcionado en la ruta de la solicitud."
api: "GET /v1/unreferenced-refunds/{unreferenced_refund_id}"
---

Esta solicitud te permite consultar los detalles de un reembolso sin referencia a partir de su `id`, que debe proporcionarse en la ruta de la solicitud.

<Info>
**Datos del proveedor en la respuesta**

La respuesta siempre incluye un objeto `provider_data` con el resultado del proveedor que procesó el reembolso. Los payloads de webhook contienen el mismo objeto.

| Campo | Contenido |
| --- | --- |
| `id` | Proveedor que procesó el reembolso, por ejemplo `STRIPE`. |
| `type` | Tipo de proveedor, por ejemplo `PSP`. |
| `connection_id` | Conexión que procesó el reembolso (UUID). |
| `transaction_id` | El identificador del reembolso en el proveedor. |
| `category` | Categoría del resultado del proveedor, por ejemplo `APPROVED`. |
| `response_code` | Código de respuesta que devolvió el proveedor. |
| `response_message` | Mensaje de respuesta que devolvió el proveedor. |

Los siguientes campos contienen el intercambio sin modificar con el proveedor. Su estructura la define el proveedor, no Yuno, por lo que varía según el proveedor y la operación. Cada uno se controla por separado:

| Campo | Contenido | Cómo obtenerlo |
| --- | --- | --- |
| `raw_request` | El payload exacto que Yuno envió al proveedor. | Requiere que tu cuenta esté habilitada para los datos sin procesar del proveedor. Contacta a tu gerente de cuenta de Yuno para solicitar acceso. No se ve afectado por `include_raw_responses`. |
| `raw_request_details` | Detalles de la solicitud que Yuno envió al proveedor, como el método HTTP, la URL y los encabezados, con las credenciales ocultas. | Igual que `raw_request`. |
| `raw_response` | El payload completo que devolvió el proveedor. | Envía `include_raw_responses=true` en esta solicitud. |
| `raw_response_details` | Detalles de la respuesta del proveedor, como el código de estado HTTP. | Igual que `raw_response`. |

`response_code` y `response_message` son resúmenes de la respuesta del proveedor y siempre se devuelven, independientemente de los campos sin procesar anteriores.
</Info>

<ParamField header="public-api-key" type="string" required>
La clave de API pública única de tu cuenta.
</ParamField>

<ParamField header="private-secret-key" type="string" required>
La clave secreta privada única de tu cuenta.
</ParamField>

<ParamField path="unreferenced_refund_id" type="string" required>
Identificador único del reembolso sin referencia generado por Yuno.
</ParamField>

<ParamField query="include_raw_responses" type="boolean" default="false">
Cuando es `true`, el objeto `provider_data` en el payload de la respuesta incluirá `raw_response`, el payload completo que devolvió el proveedor, y `raw_response_details`. Los campos de resumen `response_code` y `response_message` siempre se devuelven, sin importar este parámetro.
</ParamField>

<ParamField query="include_transaction_responses" type="boolean" default="false">
Cuando es `true`, devuelve la lista completa de intentos y respuestas intermedias de la red si el reembolso desencadenó varios reintentos internos.
</ParamField>

<RequestExample>
```bash Example request
curl --request GET \
  --url 'https://api.y.uno/v1/unreferenced-refunds/d290f1ee-6c54-4b01-90e6-d701748f0851?include_raw_responses=true' \
  --header 'public-api-key: YOUR_PUBLIC_API_KEY' \
  --header 'private-secret-key: YOUR_PRIVATE_SECRET_KEY' \
  --header 'Accept: application/json'
```
</RequestExample>
