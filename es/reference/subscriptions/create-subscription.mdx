<Note>
**Crear la suscripción junto con su primer pago**

Este endpoint inicia una suscripción a partir de un `vaulted_token` que ya tienes. Si el cliente se registra y paga al mismo tiempo, puedes enviar un bloque `subscription` en [Crear pago](/es/reference/payments/create-payment): una sola llamada cobra la tarjeta y crea la suscripción a partir de ese mismo cobro. Esa ruta está documentada solo para pagos con tarjeta sin fricción. Consulta [Inicia una suscripción con el primer pago](/es/docs/payment-features/subscriptions/start-with-payment).
</Note>

<Note>
**Aplicar una promoción al crear la suscripción**

Envía `promotion` con un `id` o un `code` para aplicar una promoción asociada al plan. El primer cobro lleva el descuento. La suscripción debe estar en un plan que tenga la promoción asociada. La suscripción almacena su propia copia de la promoción, que no se edita después. Consulta [Promociones en planes de suscripción](/es/docs/payment-features/subscriptions/promotions).

```json
{ "promotion": { "id": "8f2d6c1e-3b7a-4c55-9a1e-2f4d8b7c6a10" } }
```

Una promoción `AUTOMATIC` asociada al plan se aplica por sí sola cuando la suscripción se crea en ese plan. Si la solicitud también envía una `promotion`, gana el descuento mayor; los dos no se acumulan.
</Note>

<Warning>
**Finalización de la suscripción**

Los campos `billing_cycles` y `availability.finish_at` se afectan entre sí. Si ambos se completan al crear la suscripción, esta pasará al estado `COMPLETED` al llegar al evento más cercano definido en esos campos, ya sea el ciclo de facturación o el `finish_at` correspondiente.
</Warning>

<Warning>
**Uso de credenciales para un CIT previo**

Si creas un pago CIT (por ejemplo, Apple Pay o tarjeta) *antes* de crear la suscripción y pasas el vaulted token resultante a la suscripción, **debes** incluir `payment_method.card.usage` para indicar si es el primer uso o uno posterior. Sin esto, los cobros recurrentes se tratarán como CIT y el proveedor los rechazará.

El payload requerido para suscripciones nuevas es:

```json
{
  "payment_method": {
    "type": "CARD",
    "vaulted_token": "{{vaulted_token}}",
    "card": {
      "usage": "USED"
    }
  }
}
```
</Warning>

## Errores de promoción {#promotion-errors}

Crear una suscripción con `promotion` puede fallar con los códigos de abajo. En cada caso, no se crea nada.

| HTTP | `code` | Cuándo |
| :--- | :----- | :--- |
| `404` | `PROMOTION_NOT_FOUND` | El ID o código de `promotion` es desconocido o pertenece a otra cuenta. |
| `422` | `PROMOTION_NOT_ATTACHED_TO_PLAN` | La promoción no está asociada al plan. |
| `422` | `PROMOTION_NOT_APPLICABLE` | La promoción no se puede aplicar. El `reason` dice por qué, por ejemplo `USAGE_LIMIT_REACHED`, `EXPIRED` o `PROMOTIONS_NOT_ENABLED` cuando las promociones no están activadas para tu organización. |
| `503` | `PROMOTION_ENGINE_UNAVAILABLE` | El servicio de promociones no respondió. Reintenta la solicitud. |
| `504` | `PROMOTION_ENGINE_TIMEOUT` | El servicio de promociones no respondió a tiempo. Reintenta la solicitud. |

Una promoción `AUTOMATIC` asociada al plan se maneja de forma distinta. Si no se puede aplicar, porque está deshabilitada, venció o no tiene usos restantes, la suscripción se crea sin ella y la solicitud igualmente tiene éxito. Lo mismo ocurre cuando el servicio de promociones no encuentra la promoción asociada. Solo un `503` o `504` detiene la creación.

Consulta la sección [Códigos de respuesta HTTP](/es/reference/getting-started/response-codes) para ver los detalles de los posibles resultados de error.

## Configurar una regla de reembolso {#setting-a-refund-rule}

`refund_rule` se puede definir al crear la suscripción para configurar cómo se calcula un reembolso `CUSTOM` cuando una solicitud de cancelación posterior no incluye su propio `refund_amount`:

<CodeGroup>
```json A share of the charged amount
{ "refund_rule": { "type": "PERCENT", "percent": 50 } }
```

```json A flat amount
{ "refund_rule": { "type": "FIXED", "amount": { "value": 8000, "currency": "COP" } } }
```
</CodeGroup>

`PERCENT` y `FIXED` son excluyentes: una regla `PERCENT` solo lleva `percent` (0–100) y una regla `FIXED` solo lleva `amount`. El `amount.currency` de una regla `FIXED` debe ser igual a la moneda de la propia suscripción.

Se puede cambiar o eliminar más adelante en [Actualizar suscripción](/es/reference/subscriptions/update-subscription#setting-a-refund-rule) y se describe en [el objeto Subscription](/es/reference/subscriptions/the-subscription-object). Consulta [Cancelar suscripción](/es/reference/subscriptions/cancel-subscription#custom) para ver cómo se usa. Está disponible para las organizaciones habilitadas; contacta a Yuno. Para las demás, enviar `refund_rule` se ignora en silencio y no se almacena nada.
