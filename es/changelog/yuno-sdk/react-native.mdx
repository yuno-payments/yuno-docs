## v2.1.0 {#v210}
*November 9, 2026*

**Payments**

- <ChangelogBadge type="added" /> **Divide pagos entre dos tarjetas en headless**  
  `transaction.start([...])` cobra una orden con dos tarjetas en Android y iOS. Cada elemento es una tarjeta nueva o un `vaultedToken` y define el nuevo `transactionData.amount` (`{ currency, value }`). El orden de la lista es el orden de los pagos. El SDK crea un token compuesto, se lo entrega a `createPayment`, ejecuta 3DS tarjeta por tarjeta e informa el estado general del pago en `onStatus`. Con `autoContinuePayment: false` se detiene después de `createPayment`. `transaction.start(paymentSelected)` no cambia.
  *Consulta también: [Pagos divididos](/es/docs/yuno-sdk/features/split-payment)*

- <ChangelogBadge type="changed" /> **Basado en el Yuno SDK 3.1.0**  
  El wrapper ahora se ejecuta sobre el Yuno SDK nativo 3.1.0 en ambas plataformas (Android `com.yuno.payments:android-sdk:3.1.0`, iOS `SdkPayments` 3.1.0).

## v2.0.0 {#v200}
*November 2, 2026*

- <ChangelogBadge type="breaking" /> **El Yuno SDK para React Native**  
  La versión 2.0.0 se ejecuta sobre el Yuno SDK nativo 3.0.0 en Android y iOS y lleva la misma integración a React Native: inicializa con `SdkPayments.initialize`, crea una `Transaction`, inícialo y obtén el resultado en `onStatus`. Reemplaza la API 1.x (`YunoSdk.startPayment`, `startPaymentLite`, `continuePayment`, el componente `YunoPaymentMethods` y los listeners de estado y token) y no es compatible con 1.x.  
  [Guía de migración →](/es/docs/yuno-sdk/migration/overview)  
  *Consulta también: [Documentación del Yuno SDK](/docs/yuno-sdk/introduction) · [Primeros pasos](/es/docs/yuno-sdk/get-started)*

- <ChangelogBadge type="added" /> **Vistas integradas con `YunoView`**  
  Implementa `showView` en el controlador para colocar el formulario de tarjeta, los formularios de APM y el formulario de inscripción en tu propia pantalla: renderiza la vista con `<YunoView view={view} />` y envíala desde tu propio botón con `process.onSubmit()`. Sin `showView`, el SDK muestra sus propias pantallas.  
  *Consulta también: [showView](/es/docs/yuno-sdk/controllers/show-view)*

- <ChangelogBadge type="added" /> **Lista de métodos de pago y botones de billetera**  
  `transaction.getPaymentMethodsViews` devuelve la lista de métodos de pago y el botón de Google Pay (Android) o Apple Pay (iOS) para renderizar con `<YunoView>`, con callbacks de selección, altura y baja de inscripción.  
  *Consulta también: [Lista de métodos de pago](/es/docs/yuno-sdk/features/payment-methods-list)*

- <ChangelogBadge type="added" /> **Crea el pago en tu backend**  
  Implementa `createPayment(token)` y el SDK espera la Promise que devuelve antes de continuar con 3DS y el resultado.  
  *Consulta también: [createPayment](/es/docs/yuno-sdk/controllers/create-payment)*

- <ChangelogBadge type="added" /> **Devuelve un paso al SDK**  
  `SdkPayments.defaultShowView`, `SdkPayments.defaultShowLoading` y `SdkPayments.defaultCreatePayment` permiten que el SDK maneje una sola llamada de tu controlador, por ejemplo para integrar solo el formulario de tarjeta o para que el SDK cree el pago en algunos métodos.  
  *Consulta también: [Toma el control del SDK](/docs/yuno-sdk/controllers/take-over-the-sdk)*

- <ChangelogBadge type="changed" /> **Versiones mínimas**  
  React Native 0.73 o superior, con la arquitectura nueva o la anterior. En Android, `minSdkVersion` 23 y el repositorio Maven de Yuno en tus repositorios de Gradle; en iOS, 14.0.  
  *Consulta también: [Primeros pasos](/es/docs/yuno-sdk/get-started)*
