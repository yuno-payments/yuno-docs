O checkout da Yuno dentro da VTEX passa do Web SDK 1.6 para o Web SDK 1.11. Desde o Web SDK 1.9, toda classe e todo id que o SDK renderiza se chama `sdk-payments-*` em vez de `yuno-*` ou `Yuno-*`. Por exemplo, `Yuno-accordion__heading` passa a ser `sdk-payments-accordion__heading`.

Nenhum erro aparece depois do upgrade. O CSS e o JS personalizados que usam um nome antigo simplesmente deixam de ser aplicados: um elemento oculto volta a aparecer, um botão com estilo personalizado volta ao estilo padrão, um script que lê um elemento não encontra nada.

Estes nomes continuam funcionando:

- `window.Yuno` e o evento `yuno-sdk-ready`, que permanecem como aliases.
- Os nomes que pertencem à camada da VTEX, como `yuno-checkout-root`, `yuno-form-root`, `yuno-external-button-root`, `yuno-sdk-web-vtex-app` e as classes dos botões expressos (`yuno-google-pay-button`, `yuno-samsung-pay-button` e os grupos deles).

Use uma das três verificações abaixo antes que o upgrade chegue à sua loja.

## Opção 1: snippet de console no checkout em produção {#option-1-console-snippet-on-the-live-checkout}

Use esta opção para verificar o que a loja em produção carrega, incluindo o CSS do seu tema e dos seus apps.

<Steps>
  <Step title="Abra o checkout na etapa de pagamento">
    Abra o checkout da sua loja no Chrome, vá até a etapa de pagamento e confira se o formulário da Yuno está visível.
  </Step>
  <Step title="Cole o snippet no console do DevTools">
    Abra o DevTools, vá até a aba **Console**, cole o snippet e pressione Enter.
  </Step>
  <Step title="Leia a tabela">
    O snippet mostra o bundle do SDK presente na página, uma tabela com cada regra de CSS e cada script inline que usa um nome `yuno-*`, e a contagem de seletores que quebram na 1.11. A coluna `on_1_11` mostra `BREAKS -> <new name>` para um seletor renomeado, `BREAKS (removed)` para um nome sem equivalente, e `ok` ou `not an SDK name` nos demais casos.
  </Step>
</Steps>

```js yuno-upgrade-check.browser.js
/* Paste in the DevTools console of the live checkout page (payment step open). Reports the SDK
   version on the page and every same-origin CSS rule / inline script that targets a yuno-* name. */
(async () => {
  const MAP_URL = 'https://docs.y.uno/files/validators/web-sdk-1.11-upgrade-check/rename-map.json';
  let map = null;
  try { const r = await fetch(MAP_URL); if (r.ok) map = await r.json(); } catch {}
  if (!map || !map.names) { console.error('[yuno-check] could not load the rename map from', MAP_URL, ': no verdicts given. Check the network tab (CSP, offline) and run again.'); return; }
  const src = [...document.scripts].map(s => s.src).find(s => /sdk-web[^/]*\.y\.uno\/v\d/.test(s)) || '';
  console.log('[yuno-check] SDK bundle on page:', src || 'none found', '| window.Yuno:', !!window.Yuno, '| SdkPayments:', !!window.SdkPayments);
  const hits = [];
  for (const ss of document.styleSheets) { let rules; try { rules = ss.cssRules; } catch { console.warn('[yuno-check] cannot read (cross-origin), check by hand:', ss.href); continue; }
    for (const r of rules) { const t = r.selectorText || r.cssText; for (const m of (t || '').matchAll(/\b[yY]uno-[A-Za-z0-9_-]+/g)) hits.push({ where: ss.href || 'inline <style>', name: m[0], rule: r.selectorText }); } }
  for (const s of document.scripts) if (!s.src) for (const m of s.textContent.matchAll(/\b[yY]uno-[A-Za-z0-9_-]+/g)) hits.push({ where: 'inline <script>', name: m[0] });
  const names = Object.keys(map.names);
  const verdict = n => { const base = map.names[n] ? n : names.filter(k => n.startsWith(k) && /^(__|--)/.test(n.slice(k.length))).sort((a, b) => b.length - a.length)[0]; const e = base && map.names[base]; return !e ? 'not an SDK name' : e.status === 'renamed' ? 'BREAKS -> ' + n.replace(base, e.to) : e.status === 'removed' ? 'BREAKS (removed)' : 'ok'; };
  console.table(hits.map(h => ({ ...h, on_1_11: verdict(h.name) })));
  console.log('[yuno-check]', hits.filter(h => verdict(h.name).startsWith('BREAKS')).length, 'selectors break on SDK 1.11', '(', hits.length, 'yuno-looking names found )');
})();
```

O snippet busca o mapa de renomeação em docs.y.uno, então o console precisa de acesso de rede a esse host. Se o mapa não puder ser carregado, ele para com um erro em vez de informar um resultado limpo.

O snippet não consegue ler folhas de estilo servidas a partir de outra origem. Ele lista cada uma delas como um aviso, então verifique esses arquivos manualmente ou com o scanner abaixo.

## Opção 2: scanner nos seus arquivos {#option-2-scanner-on-your-files}

Use esta opção nos arquivos que você edita: `checkout6-custom.css`, `checkout6-custom.js`, uma pasta de tema ou um app VTEX IO. Ela exige Node.js 18 ou posterior.

<Steps>
  <Step title="Salve o scanner em um arquivo">
    Copie o script abaixo para um arquivo chamado `yuno-upgrade-check.mjs`. Ele carrega sozinho o mapa de renomeação de docs.y.uno; para executá-lo offline, baixe o [mapa de renomeação](/files/validators/web-sdk-1.11-upgrade-check/rename-map.json) para a mesma pasta ou aponte `YUNO_RENAME_MAP` para o arquivo.

    ```js yuno-upgrade-check.mjs
    #!/usr/bin/env node
    // Yuno Web SDK 1.6 -> 1.11 pre-upgrade check for merchant custom CSS/JS.
    // Usage: node yuno-upgrade-check.mjs <file-or-dir> [...more]
    // Scans .css .scss .less .js .mjs .ts .jsx .tsx .html .vue .liquid .hbs for yuno-* / Yuno-* names and
    // reports, per hit, what happens to that name on SDK 1.11. Exit code 1 when something breaks.
    // The rename map is read from ./rename-map.json next to this script when present, or from
    // YUNO_RENAME_MAP, or fetched from docs.y.uno.
    import fs from 'node:fs'; import path from 'node:path';
    const MAP_URL = 'https://docs.y.uno/files/validators/web-sdk-1.11-upgrade-check/rename-map.json';
    async function loadMap() {
      const local = process.env.YUNO_RENAME_MAP || new URL('./rename-map.json', import.meta.url);
      try { return JSON.parse(fs.readFileSync(local, 'utf8')); } catch {}
      const res = await fetch(MAP_URL);
      if (!res.ok) throw new Error(`cannot load the rename map (${res.status}) from ${MAP_URL}; download it next to this script`);
      return res.json();
    }
    const MAP = await loadMap();
    const EXT = new Set(['.css','.scss','.less','.js','.mjs','.ts','.jsx','.tsx','.html','.vue','.liquid','.hbs']);
    const SKIP_DIRS = new Set(['node_modules', '.git', 'dist', 'build']);
    const files = [];
    const walk = (p) => {
      const st = fs.statSync(p);
      if (st.isDirectory()) {
        for (const f of fs.readdirSync(p)) {
          if (SKIP_DIRS.has(f)) continue; // skip only folders inside the argument, never the argument itself
          walk(path.join(p, f));
        }
      } else if (EXT.has(path.extname(p))) files.push(p);
    };
    process.argv.slice(2).forEach(a => walk(a));
    const NAMES = Object.keys(MAP.names);
    const lookup = name => {
      if (MAP.names[name]) return [name, MAP.names[name]];
      // BEM modifier or element of a known block: yuno-status__title--small -> yuno-status__title
      const base = NAMES.filter(k => name.startsWith(k) && /^(__|--)/.test(name.slice(k.length))).sort((a, b) => b.length - a.length)[0];
      return base ? [base, MAP.names[base]] : [null, null];
    };
    const rows = []; const seen = new Set();
    for (const f of files) {
      fs.readFileSync(f, 'utf8').split('\n').forEach((line, i) => {
        for (const m of line.matchAll(/\b[yY]uno-[A-Za-z0-9_-]+/g)) {
          const name = m[0]; const [base, entry] = lookup(name);
          let status, action;
          if (!entry) { status = 'not-sdk'; action = 'not a Yuno SDK 1.6 name: likely your own id/class, no change'; }
          else if (entry.status === 'renamed') { status = 'BREAKS'; action = `rename to ${name.replace(base, entry.to)}`; }
          else if (entry.status === 'removed') { status = 'BREAKS'; action = 'element no longer exists under this name in 1.11: re-check the selector on the 1.11 DOM'; }
          else if (entry.status === 'vtex-layer') { status = 'ok'; action = 'VTEX layer name, unchanged'; }
          else { status = 'ok'; action = 'unchanged (alias kept)'; }
          if (entry?.note && status === 'BREAKS') action += ` (${entry.note})`;
          const key = `${f}:${i + 1}:${name}`; if (seen.has(key)) continue; seen.add(key);
          rows.push({ file: f, line: i + 1, name, status, action });
        }
      });
    }
    const breaks = rows.filter(r => r.status === 'BREAKS');
    for (const r of rows) console.log(`${r.status.padEnd(7)} ${r.file}:${r.line}  ${r.name}  ->  ${r.action}`);
    console.log(`\n${files.length} files scanned, ${rows.length} Yuno-looking names, ${breaks.length} break on 1.11.`);
    console.log(breaks.length ? 'Fix the BREAKS lines before the upgrade, then test on sandbox (SDK 1.11).' : 'Nothing here depends on the old names.');
    process.exit(breaks.length ? 1 : 0);
    ```
  </Step>
  <Step title="Execute-o nos seus arquivos ou pastas">
    ```bash
    node yuno-upgrade-check.mjs checkout6-custom.css checkout6-custom.js my-theme
    ```
    Ele analisa arquivos `.css`, `.scss`, `.less`, `.js`, `.mjs`, `.ts`, `.jsx`, `.tsx`, `.html`, `.vue`, `.liquid` e `.hbs` e ignora as pastas `node_modules`, `dist` e `build` encontradas dentro dos caminhos que você passa (um caminho passado explicitamente é sempre analisado). Um nome do lojista que apenas começa como um nome do SDK, como `yuno-checkout-banner`, é informado como `not-sdk`.
  </Step>
  <Step title="Leia o resultado">
    Cada linha mostra o status, o arquivo e a linha, o nome e o que fazer. O código de saída é `1` quando pelo menos um nome quebra na 1.11 e `0` caso contrário, então você pode executá-lo no CI.
  </Step>
</Steps>

Exemplo de saída:

```text

BREAKS  store/checkout6-custom.css:2  Yuno-accordion__heading  ->  rename to sdk-payments-accordion__heading
BREAKS  store/checkout6-custom.css:3  Yuno-apple-pay__button  ->  element no longer exists under this name in 1.11: re-check the selector on the 1.11 DOM
not-sdk store/checkout6-custom.css:4  yuno-my-banner  ->  not a Yuno SDK 1.6 name: likely your own id/class, no change

1 files scanned, 4 Yuno-looking names, 2 break on 1.11.

```

## Opção 3: o mapa de renomeação {#option-3-the-rename-map}

O [mapa de renomeação](/files/validators/web-sdk-1.11-upgrade-check/rename-map.json) é o arquivo JSON que as duas ferramentas leem. Use-o para consultar um nome manualmente ou para criar a sua própria verificação. Ele lista os 222 nomes de classe e id encontrados no bundle do Web SDK 1.6, além dos nomes da camada da VTEX que não mudam:

| Status | Quantidade | Significado |
| --- | --- | --- |
| `renamed` | 192 | O nome existe na 1.11 como `sdk-payments-*`. O campo `to` informa o novo nome. |
| `removed` | 23 | Nenhum elemento com um equivalente de mesmo nome existe na 1.11. |
| `unchanged` | 7 | O nome ainda existe na 1.11. |
| `vtex-layer` | 45 | Pertence à camada da VTEX. Não muda. |

Um nome que não está no mapa não é um nome do SDK 1.6. Muito provavelmente é um id ou uma classe sua e não precisa de alteração.

## O que fazer com uma ocorrência {#what-to-do-with-a-hit}

1. **Renamed**: substitua o nome antigo pelo novo no seu CSS ou JS. Um seletor que precisa funcionar antes e depois do upgrade pode listar os dois nomes, por exemplo `.Yuno-accordion__heading, .sdk-payments-accordion__heading`.
2. **Removed**: abra o checkout no Web SDK 1.11 em sandbox, encontre o elemento ao qual a sua regra se destinava e escreva o seletor com base no DOM da 1.11. O elemento pode ter uma estrutura diferente ou pode não existir mais.
3. **Teste antes da produção**: peça ao seu gerente técnico de conta um teste em sandbox do seu checkout no Web SDK 1.11 com os seus arquivos personalizados aplicados.

<Note>
As mesmas renomeações valem para qualquer lojista no Web SDK 1.6, 1.7 ou 1.8 que passe para a 1.9 ou posterior, dentro ou fora da VTEX. O scanner e o mapa de renomeação funcionam da mesma forma para essas integrações.
</Note>
