---
title: "Glossário"
description: "Definições dos principais termos usados na plataforma de orquestração de pagamentos da Yuno, com links para as páginas que explicam cada um."
---

Este glossário define os termos que você encontra na documentação da Yuno, de sessões e tokens a roteamento e payouts. Cada entrada leva à página que explica o conceito por completo.

### 3DS (3D Secure) {#3ds-3d-secure}

3D Secure (3DS) é um protocolo de segurança que adiciona uma etapa de verificação às transações com cartão não presente para autenticar o cliente e reduzir a fraude. A Yuno registra uma verificação 3DS como uma transação secundária no pagamento e oferece suporte a 3DS2 e 3DS Standalone. Veja [3DS](/docs/basic-concepts/3ds-1).

### Conta {#account}

Uma conta é uma unidade dentro da sua organização que pode representar um país, uma franquia ou uma unidade de negócio, com seus próprios usuários, conexões e chaves. Cada conta tem Account IDs exclusivos para o Live Mode e o Test Mode. Veja [Contas](/pt-br/docs/using-yuno/organization/accounts).

### Autorizar {#authorize}

Autorizar é um tipo de transação primária que reserva o valor de um pagamento em um cartão para que você possa capturá-lo depois. Para autorizar sem cobrar o cliente, envie `capture` como `false` ao criar o pagamento. Veja [Transações](/pt-br/docs/basic-concepts/transactions).

### Cancelar {#cancel}

Cancelar é uma transação secundária que anula uma autorização inicial e libera os fundos retidos. Só pagamentos com status `PENDING` podem ser cancelados. Veja [Cancelar pagamentos](/pt-br/docs/direct-integration-use-cases/cancel-payments).

### Captura {#capture}

A captura é uma transação secundária que coleta os fundos de uma autorização inicial, de forma total ou parcial. Só pagamentos com status `PENDING` podem ser capturados. Veja [Capturar pagamentos](/pt-br/docs/direct-integration-use-cases/capture-payments).

### Chargeback {#chargeback}

Um chargeback é uma reclamação que um cliente abre no banco emissor para contestar uma transação. Na Yuno, um chargeback e uma disputa são o mesmo objeto: o chargeback se torna uma disputa ativa quando você envia evidências. Veja [Gestão de chargebacks](/pt-br/docs/payouts-and-disputes/chargeback-management).

### Checkout Builder {#checkout-builder}

O Checkout Builder é uma ferramenta no-code do dashboard que habilita meios de pagamento com uma rota publicada, define suas condições de exibição e campos obrigatórios e personaliza o estilo do checkout. As alterações são aplicadas depois que você clica em **Publish settings**. Veja [Checkout Builder](/pt-br/docs/using-yuno/dashboard-overview/checkout-builder).

### Sessão de checkout {#checkout-session}

Uma sessão de checkout inicia o fluxo de pagamento para um cliente e dá acesso a todos os meios de pagamento disponíveis para esse cliente. Você cria uma nova sessão de checkout para cada pagamento quando usa os SDKs da Yuno. Veja [Sessões](/pt-br/docs/basic-concepts/sessions).

### Conexão {#connection}

Uma conexão vincula sua conta da Yuno a um provedor, como um meio de pagamento, um processador ou uma solução antifraude, usando as credenciais do provedor. Você adiciona conexões no dashboard e depois as atribui às rotas. Veja [Conexões](/pt-br/docs/using-yuno/dashboard-overview/connections).

### Cliente {#customer}

Um cliente é uma pessoa na rede de pagamentos de um lojista que pode fazer pagamentos e armazenar meios de pagamento na Yuno. Todo pagamento está vinculado a um cliente, identificado pelo `customer_id` que a Yuno gera. Veja [Clientes](/pt-br/docs/basic-concepts/customers).

### Sessão de cliente {#customer-session}

Uma sessão de cliente permite cadastrar e armazenar os meios de pagamento de um cliente para uso futuro. Você cria uma nova sessão de cliente sempre que registra um meio de pagamento para um cliente específico. Veja [Sessões](/pt-br/docs/basic-concepts/sessions).

### Transação iniciada pelo cliente (CIT) {#customer-initiated-transaction-cit}

Uma transação iniciada pelo cliente (CIT) é um pagamento que o próprio cliente inicia, como uma compra online ou em loja física. Normalmente exige a autenticação do titular do cartão. Veja [Credenciais armazenadas](/pt-br/docs/payment-features/stored-credentials).

### Cadastro {#enrollment}

O cadastro armazena o meio de pagamento de um cliente no vault da Yuno para uso futuro e retorna um `vaulted_token`. Os meios de pagamento cadastrados permitem pagamentos recorrentes, assinaturas e novas tentativas entre provedores. Veja [Cadastrar meios de pagamento](/pt-br/docs/payment-features/enrollment/enroll-payment-methods).

### Análise de fraude {#fraud-screening}

A análise de fraude é a verificação antes ou depois da autorização que um provedor externo de detecção de fraude executa em um pagamento. Quando uma rota inclui verificação de fraude, a Yuno adiciona uma transação `FRAUD_SCREENING` ao pagamento. Veja [Prevenção de fraude](/docs/basic-concepts/fraud).

### Chave de idempotência {#idempotency-key}

Uma chave de idempotência é um UUID único enviado no cabeçalho `X-Idempotency-Key` para que você possa repetir com segurança uma requisição de resultado incerto. Reutilizar a chave retorna o pagamento original em vez de criar um duplicado. Veja [Autenticação](/reference/getting-started/authentication).

### Parcelas {#installments}

As parcelas permitem que um cliente divida o valor de uma compra com cartão em vários pagamentos. A Yuno oferece suporte a parcelas do lojista, definidas pelos seus próprios acordos, e parcelas do provedor, definidas pelo processador de pagamento. Veja [Parcelas](/pt-br/docs/payment-features/installments/index).

### Lite SDK {#lite-sdk}

O Lite SDK é uma integração leve que dá a você controle total sobre como e onde cada meio de pagamento é exibido. Você mesmo implementa a seleção do meio de pagamento. Veja [Escolher a integração](/docs/sdks/overview/choose-integration).

### Transação iniciada pelo lojista (MIT) {#merchant-initiated-transaction-mit}

Uma transação iniciada pelo lojista (MIT) é um pagamento que o lojista envia sem a participação ativa do cliente, como uma cobrança recorrente ou a renovação de uma assinatura. Ela depende de uma autenticação inicial do cliente na configuração. Veja [Credenciais armazenadas](/pt-br/docs/payment-features/stored-credentials).

### Monitors {#monitors}

Os Monitors detectam quedas na taxa de aprovação de uma rota, alertam você pelos canais configurados e redirecionam automaticamente o tráfego para provedores de fallback. O tráfego volta para a rota original quando a taxa de aprovação se recupera. Veja [Monitors](/pt-br/docs/using-yuno/dashboard-overview/monitors).

### Network token {#network-token}

Um network token é uma representação digitalizada do Primary Account Number (PAN) de um cartão, emitida por bandeiras de cartão como Visa, Mastercard ou American Express. Quando habilitado, a Yuno provisiona network tokens para todos os cartões cadastrados, e a bandeira do cartão os atualiza automaticamente. Veja [Network Tokens](/pt-br/docs/security-and-compliance/network-tokens).

### Token de uso único {#one-time-token}

Um token de uso único guarda as informações de pagamento que o Yuno SDK coleta para uma única sessão de checkout. Você o usa uma vez ao criar o pagamento, e ele não pode ser reutilizado. Veja [Tokens](/pt-br/docs/basic-concepts/tokens).

### Organização {#organization}

Uma organização é a entidade de nível mais alto que agrupa suas contas e usuários da Yuno. As chaves da organização dão acesso a todas as contas da organização, e as funções no nível da organização valem para todas as contas. Veja [Developers (Credenciais)](/pt-br/docs/using-yuno/settings/developers-credentials).

### Pagamento {#payment}

Um pagamento representa a transação de um usuário, independentemente dos processadores ou meios de pagamento usados, e reúne os detalhes do pedido, como cliente, valor e moeda. Um pagamento é composto por uma ou mais transações que determinam seu resultado final. Veja [Pagamentos](/pt-br/docs/basic-concepts/payments-1).

### Link de pagamento {#payment-link}

Um link de pagamento é uma URL que você cria no dashboard para receber um pagamento sem escrever código. Você define o país, a moeda, o valor, os meios de pagamento e datas opcionais de início e de expiração. Veja [Links de pagamento](/pt-br/docs/using-yuno/dashboard-overview/payment-links).

### Meio de pagamento {#payment-method}

Um meio de pagamento é uma forma de coletar as informações de pagamento do cliente e enviá-las a um processador, como cartões, carteiras digitais, transferências bancárias ou serviços de compre agora, pague depois. Os meios de pagamento diferem quanto ao suporte a cadastro e ao processamento síncrono ou assíncrono. Veja [Meios de pagamento](/pt-br/docs/basic-concepts/payment-methods).

### Status do pagamento {#payment-status}

O `status` e o `sub_status` do pagamento descrevem o estado atual de um pagamento e seguem um ciclo de vida padronizado em todos os meios de pagamento. A Yuno recomenda usá-los como a principal referência do estado do pagamento, independentemente de quantas transações ele tenha. Veja [Status do pagamento e códigos de resposta](/reference/payments/status-and-response-codes/payment).

### Payout {#payout}

Um payout envia fundos de você para um beneficiário por meio de um método de saque bancário, em cartão ou em carteira. Um payout começa como `CREATED`, passa para `PENDING` e termina como `SUCCEEDED`, `REJECTED` ou `DECLINED`. Veja [Payouts](/pt-br/docs/payouts-and-disputes/payouts).

### Plano {#plan}

Um plano é uma definição de preço reutilizável com um nome, um preço (opcionalmente por país), uma frequência de cobrança e uma fase de teste opcional. Você inscreve clientes em um plano com `plan_id` em vez de enviar `amount` e `frequency` em cada assinatura. Veja [Planos](/pt-br/docs/payment-features/subscriptions/plans).

### Chave secreta privada {#private-secret-key}

A `private-secret-key` é a credencial que seu servidor envia, junto com a `public-api-key`, para autenticar cada requisição à API da Yuno. Não a compartilhe em locais públicos, como GitHub ou Bitbucket. Veja [Autenticação](/reference/getting-started/authentication).

### Provedor {#provider}

Um provedor é um terceiro que você conecta à Yuno, incluindo meios de pagamento, processadores de pagamento e soluções antifraude. O roteamento decide qual provedor processa cada pagamento. Veja [Conexões](/pt-br/docs/using-yuno/dashboard-overview/connections).

### Chave de API pública {#public-api-key}

A `public-api-key` é a credencial que você envia em cada requisição à API da Yuno e usa para inicializar o SDK no lado do cliente. Você a encontra na seção Developers do dashboard. Veja [Autenticação](/reference/getting-started/authentication).

### Conciliação {#reconciliation}

A conciliação compara as transações processadas pela Yuno com os arquivos de liquidação de cada provedor de pagamento para encontrar divergências e confirmar a liquidação. O dashboard mostra a taxa de conciliação por provedor, conta e moeda. Veja [Conciliações](/pt-br/docs/using-yuno/dashboard-overview/reconciliations).

### Reembolso {#refund}

Um reembolso devolve fundos ao cliente por um pagamento capturado, de forma total ou parcial, e adiciona uma transação `REFUND` ao pagamento. A Yuno oferece suporte a reembolsos referenciados pela API, reembolsos em lote por upload de CSV no dashboard e reembolsos não referenciados, que não fazem referência a um pagamento da Yuno. Veja [Reembolsos](/pt-br/docs/direct-integration-use-cases/unreferenced-refunds-overview).

### Condições de risco {#risk-conditions}

As condições de risco são as regras próprias de prevenção de fraude da Yuno, listas de bloqueio e listas de permissão que você adiciona a uma rota para controlar quais transações passam por análise. Elas reduzem requisições desnecessárias aos provedores de prevenção de fraude. Veja [Condições de risco](/pt-br/docs/using-yuno/dashboard-overview/risk-conditions).

### Roteamento {#routing}

O roteamento direciona cada pagamento a um provedor com base em regras que você configura no dashboard, como tipo de cartão, valor da transação, moeda e origem do pagamento. Uma rota pertence a um meio de pagamento e precisa ser publicada antes de processar transações. Veja [Roteamento](/pt-br/docs/using-yuno/dashboard-overview/routing).

### Seamless SDK {#seamless-sdk}

O Seamless SDK é a integração recomendada pela Yuno: ele oferece componentes de UI prontos, dá a você controle sobre a experiência de pagamento e permite adicionar meios de pagamento pelo dashboard sem código. Veja [Seamless SDK](/docs/sdks/seamless-sdk/index).

### Secure Fields {#secure-fields}

Os Secure Fields são campos de entrada prontos que você incorpora no seu próprio formulário de pagamento Web para que os dados brutos do cartão nunca passem pelos seus servidores. Eles mantêm uma UI de checkout personalizada em conformidade com o PCI. Veja [Visão geral dos Secure Fields](/docs/sdks/customization/secure-fields/index).

### Seller (franquia) {#seller-franchise}

Um seller é a identidade de uma loja franqueada que um lojista registra com credenciais por provedor, para que a Yuno resolva o `merchant_id` correto no momento do pagamento quando o pagamento faz referência ao seller em `additional_data.seller_details`. Os sellers não são os recebedores (submerchants) usados em [split de pagamento](#split-payments). Veja [Sellers (franquia)](/reference/sellers/manage-sellers).

### Smart Routing {#smart-routing}

O Smart Routing otimiza o desempenho dos pagamentos escolhendo entre duas ou mais conexões em uma rota de acordo com a variável que você seleciona: taxa de conversão e latência, ou taxa de conversão e custos. Você o ativa com um toggle ao definir as condições da rota. Veja [Roteamento](/pt-br/docs/using-yuno/dashboard-overview/routing).

### Split de pagamento {#split-payments}

O split de pagamento divide um pagamento de marketplace entre vários recebedores, os submerchants que você cadastra na Yuno, com valores, tarifas e comissões. O provedor de pagamento selecionado precisa oferecer suporte a split de pagamento, porque a Yuno orquestra o split, mas não o processa. Veja [Split de pagamento para marketplace](/pt-br/docs/payment-features/split-payments-marketplace).

### Assinatura {#subscription}

Uma assinatura é um pagamento recorrente que o motor de recorrência da Yuno cria e envia em seu nome na frequência que você define. Seu status passa de `CREATED` para `ACTIVE` ou `TRIALING` e pode se tornar `PAUSED`, `PAST_DUE`, `COMPLETED` ou `CANCELED`. Veja [Assinaturas](/pt-br/docs/payment-features/subscriptions/index).

### Test Mode e Live Mode {#test-mode-and-live-mode}

O Test Mode (Sandbox) permite explorar o dashboard e executar testes sem transações reais. O Live Mode (produção) processa transações reais de clientes e exige uma requisição de ativação, e um toggle no dashboard alterna entre os dois. Veja [Ambientes](/pt-br/docs/using-yuno/environments).

### Transação {#transaction}

Uma transação é uma operação dentro de um pagamento, processada por meio de uma conexão. As transações primárias (compra, autorização, verificação) iniciam um pagamento, e as transações secundárias (reembolso, cancelamento, captura, chargeback, 3DS, análise de fraude) alteram seu resultado. Veja [Transações](/pt-br/docs/basic-concepts/transactions).

### Vaulted token {#vaulted-token}

Um vaulted token é criado quando um meio de pagamento é cadastrado e armazenado no vault centralizado da Yuno com as informações do cliente. Ele funciona em todos os processadores conectados à sua conta e permanece até que o cliente remova o cadastro do meio de pagamento. Veja [Tokens](/pt-br/docs/basic-concepts/tokens).

### Webhook {#webhook}

Um webhook é uma notificação HTTP POST que a Yuno envia para a sua API REST pública sempre que ocorre um evento no fluxo de pagamento. Os webhooks mantêm seu sistema atualizado sobre mudanças de status do pagamento sem requisições repetidas à Yuno. Veja [Webhooks](/pt-br/docs/basic-concepts/webhooks-1).

### Workflow {#workflow}

O atributo `workflow` de um pagamento informa à Yuno qual integração você usa: `SDK_CHECKOUT` quando o Yuno SDK coleta os dados do pagamento, `DIRECT` quando você os envia de servidor para servidor e recebe a resposta bruta do provedor, e `REDIRECT` quando a Yuno também fornece uma URL de redirecionamento e cuida da experiência de pagamento desse pagamento. Veja [Integração Direct Flow](/pt-br/docs/direct-integration-use-cases/direct-flow).
