Esta página apresenta um guia do Yuno Headless Android SDK para pagamentos.

Este SDK é ideal para lojistas que:

* Precisam de controle total sobre a UI de pagamento e a experiência do usuário
* Querem criar fluxos de pagamento personalizados
* Precisam de recursos avançados de integração

O Headless SDK inclui recursos principais como:

* Acesso direto à API para processamento de pagamentos
* Geração de tokens para meios de pagamento
* Tratamento da autenticação 3DS
* Coleta de dados para prevenção de fraude

Para lojistas que preferem uma solução de UI pronta, considere usar o [Full Checkout SDK](/docs/sdks/full-checkout/android-payments) ou o [Lite SDK](/pt-br/docs/sdks/lite-android/checkout) da Yuno.

## Requisitos {#requirements}

Antes de iniciar a integração do Yuno Android SDK, verifique se o seu projeto atende aos requisitos técnicos. Verifique também se os seguintes pré-requisitos estão atendidos:

* **Versão mínima do SDK**: `minSdkVersion` 23 ou superior (Android 6.0). Obrigatório desde o Yuno Android SDK 2.24.0
* **Java**: Java 8 habilitado
* **AndroidX**: use AndroidX em vez das bibliotecas de suporte antigas
* **Android Gradle Plugin**: 4.0.0 ou superior
* **ProGuard**: 6.2.2 ou superior
* **Kotlin Gradle Plugin**: 1.4.0 ou superior
* **Suporte a ELF Page Size**: compatível com os requisitos de alinhamento de página ELF de 16 KB do Google (pronto para Android 15 / ARMv9)

### Configuração do ProGuard / R8 {#proguard--r8-configuration}

Se o seu projeto tem `minifyEnabled = true`, adicione estas regras ao seu arquivo `proguard-rules.pro` para garantir que o SDK funcione corretamente, principalmente com o **R8 full mode do AGP 8.x+**.

<Accordion title="Regras oficiais de ProGuard / R8 da Yuno">
  ```proguard
  # Preserve generic type signatures and annotations
  -keepattributes Signature
  -keepattributes *Annotation*

  # Yuno SDK
  -keep class com.yuno.** { *; }
  -dontwarn com.yuno.**

  # Gson — R8 full mode compatibility
  -keep class com.google.gson.** { *; }
  -keep,allowobfuscation,allowshrinking,allowoptimization class * extends com.google.gson.reflect.TypeToken
  -dontwarn com.google.gson.**

  # Retrofit — R8 full mode compatibility
  -keep,allowobfuscation,allowshrinking interface retrofit2.Call
  -keep,allowobfuscation,allowshrinking class retrofit2.Response
  -keep,allowobfuscation,allowshrinking class kotlin.coroutines.Continuation
  -dontwarn retrofit2.**

  # OkHttp + Okio — Suppress warnings
  -dontwarn okhttp3.**
  -dontwarn okio.**
  ```

  ### Por que essas regras são necessárias?

  O AGP 8.x+ habilita o **R8 full mode** por padrão, que remove agressivamente as assinaturas de tipos genéricos. Sem `-keepattributes Signature`, o `TypeToken<T>` do Gson pode falhar em tempo de execução com `java.lang.Class cannot be cast to java.lang.reflect.ParameterizedType`.
</Accordion>

## Passo 1: Crie um cliente {#step-1-create-a-customer}

Crie um cliente usando o [endpoint Create customer](/reference/customers/create-customer) antes de iniciar pagamentos. Este passo é necessário para:

* Identificar a pessoa que faz o pagamento
* Habilitar a funcionalidade de meios de pagamento salvos (se habilitada)
* Acompanhar o histórico de pagamentos

O ID do cliente retornado por este endpoint será usado ao criar a `checkout_session`.

## Passo 2: Crie uma sessão de checkout {#step-2-create-a-checkout-session}

Crie uma nova `checkout_session` usando o endpoint [Create checkout session](/reference/checkout-sessions/create-checkout-session) para inicializar o fluxo de pagamento. Lembre-se de:

* Incluir o ID do cliente obtido no passo anterior
* Armazenar o ID da `checkout_session` retornada para usar nos passos seguintes

A `checkout_session` é única para cada tentativa de pagamento e não pode ser reutilizada.

## Passo 3: Inclua a biblioteca no seu projeto {#step-3-include-the-library-in-your-project}

Inclua o Yuno SDK no seu projeto via Gradle. Adicione a origem do repositório:

```kotlin
maven { url "https://yunopayments.jfrog.io/artifactory/snapshots-libs-release" }
```

Adicione a dependência do Yuno SDK ao seu aplicativo no arquivo `build.gradle`:

```kotlin
dependencies {
    implementation 'com.yuno.payments:android-sdk:2.27.0'
}
```

O Yuno SDK inclui, por padrão, a permissão `INTERNET`, necessária para fazer requisições de rede.

`<uses-permission android:name="android.permission.INTERNET" />`

## Passo 4: Inicialize o Headless SDK com a chave pública {#step-4-initialize-headless-sdk-with-the-public-key}

Importe a Yuno e informe uma **PUBLIC_API_KEY** válida para inicializar o Headless SDK. Se você não tem suas credenciais de API, consulte a página [Developers (Credentials)](/pt-br/docs/using-yuno/settings/developers-credentials) para ver como obtê-las no Dashboard.

Crie uma aplicação personalizada, se ainda não tiver uma. No método `onCreate()` da sua classe de aplicação, inicialize o SDK chamando a função `Yuno.initialize()`:

```kotlin
class CustomApplication : Application() {
  override fun onCreate() {
    super.onCreate()
    Yuno.initialize(
      this,
      PUBLIC_API_KEY,
      config = YunoConfig(
        keepLoader = true,
      ),
    )
  }
}
```

<Info>
  Para uma explicação detalhada do parâmetro `keepLoader` e do tratamento obrigatório de erros, consulte o [Guia de referência do Android](/pt-br/docs/sdks/resources/references/android#keeploader-parameter).
</Info>

## Passo 5: Inicie o processo de checkout {#step-5-start-the-checkout-process}

Chame a função `apiClientPayment` depois que o seu cliente selecionar um meio de pagamento para iniciar o processo de checkout. Essa função exige parâmetros de configuração e inicia a coleta das informações necessárias para a autenticação 3DS e para as ferramentas de prevenção de fraude configuradas no seu roteamento.

A tabela a seguir descreve os parâmetros obrigatórios:

| Parâmetro | Descrição |
| --- | --- |
| `country_code` | Este parâmetro define o país para o qual o processo de pagamento está sendo configurado. A lista completa de países compatíveis e seus `country_code` está disponível na página [Cobertura por país](/pt-br/docs/sdks/resources/country-coverage). |
| `checkout_session` | Refere-se à sessão de checkout do pagamento atual, criada usando o endpoint [Create Checkout Session](/reference/checkout-sessions/create-checkout-session). Exemplo: `'438413b7-4921-41e4-b8f3-28a5a0141638'` |

O bloco de código a seguir mostra um exemplo da configuração dos parâmetros:

```kotlin
 val apiClientPayment = Yuno.apiClientPayment(
   countryCode = "US",
   checkoutSession = "74bf4b96-6b35-42a6-8c73-2fe094c34ca9",
   context = this
)

```

## Passo 6: Gere o token {#step-6-generate-token}

Depois de coletar as informações do usuário, crie um token de uso único (OTT) usando a função `apiClientPayment.generateToken`. Como essa é uma função assíncrona, use um bloco `try/catch` para tratar os erros que possam ocorrer. Os exemplos a seguir mostram dois cenários diferentes para criar um token de uso único:

1. **Exemplo 1**: crie um token de uso único usando um cartão como meio de pagamento e incluindo todas as informações obrigatórias do cartão.
2. **Exemplo 2**: crie um token de uso único usando as informações do `vaulted_token`.

### Benefícios de usar um vaulted token {#benefits-of-using-a-vaulted-token}

Quando você usa um vaulted token com o SDK, todas as informações de fraude dos provedores configurados no seu roteamento de cartões são coletadas. Essas informações são anexadas ao token de uso único. Você também pode adicionar informações de parcelamento e um código de segurança, se o provedor exigir.

Os dois exemplos chamam `generateToken`, que é declarada no companion object de `ApiClientPayment`. Adicione `import com.yuno.sdk.ApiClientPayment.Companion.generateToken` ao seu arquivo.

## Passo 7: Crie o pagamento {#step-7-create-the-payment}

Depois de gerar o token de uso único, crie o pagamento chamando o [endpoint Create Payment](/reference/payments/create-payment). Inclua o token de uso único obtido no Passo 6 no parâmetro `payment_method.token` da sua requisição. O bloco de código a seguir mostra um exemplo de requisição de criação de pagamento:

```json
{
  "merchant_order_id": "0000022",
  "country": "US",
  "account_id": "<Your account_id>",
  "description": "Test",
  "amount": {
    "currency": "USD",
    "value": 500
  },
  "customer_payer": {
    "id": "cfae0941-7234-427a-a739-ef4fce966c79"
  },
  "checkout": {
    "session": "<checkout session>"
  },
  "workflow": "SDK_CHECKOUT",
  "payment_method": {
    "type":"CARD",
    "token": "2cd31999-e44e-4de3-bbe4-179981ff4295"
  }
}
```

A resposta do endpoint inclui o parâmetro `sdk_action_required`, que indica se ações adicionais são necessárias para concluir o pagamento:

* Para meios de pagamento síncronos, o pagamento é concluído instantaneamente. Nesse caso, `sdk_action_required` será `false` na resposta da API e o processo de pagamento termina
* Para fluxos de pagamento que exigem interação adicional com o SDK, `sdk_action_required` será `true`. Quando isso acontecer, siga para o Passo 8 para os próximos passos

## Passo 8: Continue o pagamento (se necessário) {#step-8-continue-the-payment-if-required}

Quando um pagamento criado pelo seu backend exige um passo adicional, como um desafio 3DS, a resposta do endpoint Create Payment inclui:

* Status `PENDING` e sub-status `WAITING_ADDITIONAL_STEP`
* `sdk_action_required = true`

Chame `continueCardPayment` para que o SDK retome o pagamento. O SDK executa internamente a ação pendente, incluindo a renderização do desafio 3DS, aguarda o resultado e entrega o estado final do pagamento ao seu callback.

### Assinatura da função {#function-signature}

```kotlin
fun ApiClientPayment.continueCardPayment(
    activity: ComponentActivity,
    showPaymentStatus: Boolean = true,
    callbackPaymentState: ((String?, String?, StatusMessage?) -> Unit)? = null,
)
```

### Parâmetros {#parameters}

| Parâmetro | Tipo | Descrição |
| :--- | :--- | :--- |
| `activity` | `ComponentActivity` | A activity que o SDK usa para apresentar a ação pendente. |
| `showPaymentStatus` | `Boolean` | Se `true`, o SDK exibe a tela de status do pagamento quando o fluxo termina. Defina como `false` para usar apenas o callback. |
| `callbackPaymentState` | `((String?, String?, StatusMessage?) -> Unit)?` | Chamado na thread principal com o estado final do pagamento, seu sub-status e, em desfechos com erro, um [`StatusMessage?`](/pt-br/docs/sdks/resources/references/android#statusmessage-error-details). Terceiro parâmetro adicionado no SDK `2.22.0`. |

### Uso {#usage}

```kotlin
Yuno.apiClientPayment(
    checkoutSession = checkoutSession,
    countryCode = countryCode,
    context = this,
).continueCardPayment(
    activity = this,
    showPaymentStatus = false,
) { paymentState, paymentSubState, message ->
    when (paymentState) {
        "SUCCEEDED" -> { }
        "PROCESSING" -> { }
        "REJECT", "FAIL" -> {
            // message is present when the backend returned a response_code
            val declineCode = message?.code
        }
        "CANCELED_BY_USER" -> { }
        "INTERNAL_ERROR" -> {
            // message is always present: source "sdk" or "backend", code, reason, context
            val failure = message
        }
        else -> { }
    }
}
```

### Estados do pagamento {#payment-states}

| Estado | Significado |
| :--- | :--- |
| `SUCCEEDED` | O pagamento foi concluído com sucesso. |
| `PROCESSING` | O pagamento ainda está sendo processado. |
| `REJECT` | O pagamento foi rejeitado pelo provedor. |
| `FAIL` | O pagamento falhou. |
| `CANCELED_BY_USER` | O cliente abandonou o passo adicional. |
| `INTERNAL_ERROR` | Ocorreu um erro inesperado ao retomar o pagamento. |

`continueCardPayment` é compatível apenas com pagamentos `CARD`.

## Passo 9: Continue o pagamento (não suportado) {#step-9-continue-payment-not-supported}

<Warning>
**Sem suporte para mobile**

O método `getContinuePaymentAction` e as configurações de "Continue Payment" (necessárias para recursos como Passkey SCOF) atualmente **não são suportados** no Headless Android SDK.

Se a sua integração exige esses recursos, considere usar o [Full Checkout SDK](/docs/sdks/full-checkout/android-payments) ou o [Web Headless SDK](/pt-br/docs/sdks/headless-web/payment) como alternativa.
</Warning>

## Tratamento de erros {#error-handling}

Trate no seu app os erros retornados pelo SDK, como pagamentos com falha ou erros de validação. Para status HTTP e códigos de resposta, consulte [Status e códigos de resposta](/reference/payments/status-and-response-codes/payment) na referência da API.
