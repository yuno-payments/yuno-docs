Esta página traz um guia do Yuno Headless SDK para cadastro no Android.

O Yuno Headless SDK para Android oferece uma solução flexível e sem UI para cadastrar meios de pagamento e tokenizar cartões.

Este SDK oferece controle total sobre o processo de cadastro de meios de pagamento, o que o torna ideal para lojistas que:

* Precisam de controle total sobre a UI e a experiência do usuário
* Querem implementar fluxos de cadastro personalizados
* Exigem recursos avançados de integração

O Headless SDK inclui recursos principais como:

* Tokenização de cartões
* Cadastro seguro de meios de pagamento
* Acesso direto à API
* Tratamento de erros personalizado

Para lojistas que precisam de uma solução com UI pronta ou de uma integração mais simples, considere usar as outras implementações de SDK da Yuno:

* [Full Checkout SDK](/docs/sdks/full-checkout/android-payments)
* [Lite SDK](/pt-br/docs/sdks/lite-android/enrollment)

## Requisitos {#requirements}

Antes de começar a integração do Yuno Android SDK, garanta que seu projeto atenda aos requisitos técnicos:

* **Versão mínima do SDK**: `minSdkVersion` 23 ou superior (Android 6.0). Obrigatória desde o Yuno Android SDK 2.24.0
* **Java**: Java 8 habilitado
* **AndroidX**: use o AndroidX em vez das bibliotecas de suporte antigas
* **Android Gradle Plugin**: 4.0.0 ou superior
* **ProGuard**: 6.2.2 ou superior
* **Kotlin Gradle Plugin**: 1.4.0 ou superior
* **Suporte a tamanho de página ELF**: compatível com os requisitos de alinhamento de página ELF de 16 KB do Google (pronto para Android 15 / ARMv9)

### Configuração do ProGuard / R8 {#proguard--r8-configuration}

Se o seu projeto tiver `minifyEnabled = true`, adicione estas regras ao seu arquivo `proguard-rules.pro` para garantir que o SDK funcione corretamente, principalmente com o **modo completo do R8 no AGP 8.x+**.

<Accordion title="Regras oficiais de ProGuard / R8 da Yuno">
  ```proguard
  # Preserve generic type signatures and annotations
  -keepattributes Signature
  -keepattributes *Annotation*

  # Yuno SDK
  -keep class com.yuno.** { *; }
  -dontwarn com.yuno.**

  # Gson — R8 full mode compatibility
  -keep class com.google.gson.** { *; }
  -keep,allowobfuscation,allowshrinking,allowoptimization class * extends com.google.gson.reflect.TypeToken
  -dontwarn com.google.gson.**

  # Retrofit — R8 full mode compatibility
  -keep,allowobfuscation,allowshrinking interface retrofit2.Call
  -keep,allowobfuscation,allowshrinking class retrofit2.Response
  -keep,allowobfuscation,allowshrinking class kotlin.coroutines.Continuation
  -dontwarn retrofit2.**

  # OkHttp + Okio — Suppress warnings
  -dontwarn okhttp3.**
  -dontwarn okio.**
  ```

  ### Por que essas regras são necessárias?

  O AGP 8.x+ habilita o **modo completo do R8** por padrão, que remove de forma agressiva as assinaturas de tipos genéricos. Sem `-keepattributes Signature`, o `TypeToken<T>` do Gson pode falhar em tempo de execução com `java.lang.Class cannot be cast to java.lang.reflect.ParameterizedType`.
</Accordion>

## Passo 1: Criar um cliente {#step-1-create-a-customer}

Crie um cliente usando o endpoint [Create Customer](/pt-br/reference/customers/create-customer) antes de cadastrar meios de pagamento.

## Passo 2: Criar uma sessão de cliente {#step-2-create-a-customer-session}

Crie um novo `customer_session` usando o endpoint [Create Customer Session](/pt-br/reference/customer-sessions-enrollment/create-customer-session):

* Inclua o ID do cliente na requisição
* Armazene o ID `customer_session` retornado
* Gere um novo `customer_session` para cada cadastro de meio de pagamento.

## Passo 3: Adicionar o SDK ao seu projeto {#step-3-add-the-sdk-to-your-project}

1. Adicione a origem do repositório:

```kotlin
maven { url "https://yunopayments.jfrog.io/artifactory/snapshots-libs-release" }
```

2. Adicione a dependência do SDK:

```kotlin
dependencies {
    implementation 'com.yuno.payments:android-sdk:2.27.0'
}
```

<Info>
**Permissão de internet obrigatória**

O Yuno SDK inclui automaticamente a permissão `INTERNET`, necessária para requisições de rede. Garanta que seu AndroidManifest.xml contenha:

`<uses-permission android:name="android.permission.INTERNET" />`
</Info>

## Passo 4: Inicializar o Headless SDK com a chave pública {#step-4-initialize-headless-sdk-with-the-public-key}

Obtenha suas chaves de API públicas no [Dashboard da Yuno](https://dashboard.y.uno/).

Se você ainda não implementou uma aplicação personalizada, crie uma. No método `onCreate()` da sua classe de aplicação, chame a função de inicialização (`Yuno.initialize`):

```kotlin
class CustomApplication : Application() {
  override fun onCreate() {
    super.onCreate()
    Yuno.initialize(
      this,
      PUBLIC_API_KEY,
      config = YunoConfig(),
    )
  }
}
```

## Passo 5: Criar um objeto de meio de pagamento para cadastro {#step-5-create-an-enrollment-payment-method-object}

Crie um objeto de meio de pagamento para cadastro usando o endpoint [Enroll Payment Method](/pt-br/reference/payment-methods-checkout/enroll-payment-method-checkout) para configurar a integração do Headless SDK para cadastro. Ao criar esse objeto, especifique em qual tipo de meio de pagamento seu cliente pode se cadastrar. No momento, o Headless SDK só é compatível com o tipo de meio de pagamento CARD.

<Info>
**Verificação de cartão**

Para verificar cartões (autorização de valor zero) antes do cadastro, inclua o objeto `verify` ao criar o objeto de meio de pagamento para a sessão do cliente.
</Info>

## Passo 6: Iniciar o processo de cadastro {#step-6-start-the-enrollment-process}

Use a função `apiClientEnroll` para iniciar o processo de cadastro. Essa função exige parâmetros de configuração que definem como o cadastro será processado. A tabela a seguir descreve os parâmetros obrigatórios:

| Parâmetro | Descrição |
| --- | --- |
| `country_code` | Esse parâmetro determina o país para o qual o processo de pagamento está sendo configurado. A lista completa de países compatíveis e seus `country_code` está disponível na página [Cobertura por país](/pt-br/docs/sdks/resources/country-coverage). |
| `customer_session` | Refere-se à sessão do cliente do cadastro atual, recebida como resposta do endpoint [Create Customer Session](/pt-br/reference/customer-sessions-enrollment/create-customer-session). Exemplo: `438413b7-4921-41e4-b8f3-28a5a0141638` |

O bloco de código a seguir mostra um exemplo da configuração de parâmetros:

```kotlin
override fun onCreate(savedInstanceState: Bundle?) {
	val apiClientEnroll = Yuno.apiClientEnroll(
    countryCode = "CO",
    customerSession = "eec6578e-ac2f-40a0-8065-25b5957f6dd3",
    context = this 
  )
 }
```


## Passo 7: Gerar um token armazenado {#step-7-generate-a-vaulted-token}

Depois de coletar todas as informações necessárias do cliente, crie um `vaulted_token` usando a função `apiClientEnroll.continueEnrollment`. Como essa é uma função assíncrona, use um bloco `try/catch` para tratar os erros que possam ocorrer. O exemplo a seguir mostra como criar um `vaulted_token`:

```kotlin
apiClientEnroll.continueEnrollment( 
 collectedData = EnrollmentCollectedData(
    customerSession = "customer_session",
    paymentMethod = EnrollmentMethod(
           type = "CARD",
           card = CardData(
               save = true,
               detail = Detail(
                   expirationMonth = 11,
                   expirationYear = 55,
                   number = "4111111111111111",
                   securityCode = "123",
                   holderName = "Firstname Lastname",
                   type = CardType.CREDIT
               ),
           ),
           customer = Customer(
               id = "id",
               merchantCustomerId = "merchant_customer_id",
               firstName = "firstName",
               email = "email@email.com",
               country = "CO",
               document = Document(
                   documentType = "PAS",
                   documentNumber = "PAS12312"
               ),
             phone = Phone(
                   number = "321123321123",
                   countryCode = "57"
               )
            )
      )
  ),
  context = this
 )

```

`type` em `Detail` é opcional. Se você não o enviar, a Yuno detecta o tipo do cartão pelo número do cartão. Se você o enviar, ele é salvo com o cartão e usado em pagamentos posteriores, então um tipo errado pode causar recusas.

A função `apiClientEnroll.continueEnrollment` é uma função `suspend`. Chame-a a partir de uma coroutine (por exemplo, `lifecycleScope.launch`). Ela retorna um `Map<String, Any?>` com a resposta completa. Veja abaixo um exemplo de resposta da chamada a `apiClientEnroll.continueEnrollment`:

```json
{
  "vaulted_token": "9104911d-5df9-429e-8488-ad41abea1a4b",
  "status": "SUCCEEDED",
  "customer": {
    "session": "eec6578e-ac2f-40a0-8065-25b5957f6dd3"
  }
}
```

O bloco de código a seguir mostra um exemplo de leitura da resposta. `continueEnrollment` é declarada no companion object `ApiClientEnroll`, então importe-a explicitamente:

```kotlin
import com.yuno.sdk.ApiClientEnroll.Companion.continueEnrollment

lifecycleScope.launch {
   val response = apiClientEnroll.continueEnrollment(data, context)
   val status = response["status"] as String?
   val vaultedToken = response["vaulted_token"] as String?
}
```

### Estados do fluxo de cadastro {#enrollment-flow-states}

A função `apiClientEnroll.continueEnrollment` retorna uma resposta que inclui um campo `status` indicando o estado atual do processo de cadastro. Estes são os estados possíveis:

```kotlin
const val ENROLLMENT_STATE_SUCCEEDED = "SUCCEEDED"
const val ENROLLMENT_STATE_FAIL = "FAIL"
const val ENROLLMENT_STATE_PROCESSING = "PROCESSING"
const val ENROLLMENT_STATE_REJECT = "REJECT"
const val ENROLLMENT_STATE_INTERNAL_ERROR = "INTERNAL_ERROR"
const val ENROLLMENT_STATE_CANCELED_BY_USER = "CANCELED"
```

A tabela a seguir traz informações adicionais sobre os estados possíveis:

| Estado | Descrição | Ação adicional necessária |
| --- | --- | --- |
| `SUCCEEDED` | O processo de cadastro foi concluído com sucesso, sem erros. | Não. |
| `FAIL` | A tentativa de cadastro falhou por erros como problemas de validação de dados, falhas de conexão com o servidor ou problemas técnicos. | Sim. Investigue a causa da falha (validação, rede, servidor) e tome medidas corretivas. |
| `PROCESSING` | O cadastro está em andamento, aguardando aprovação ou verificação. | Não. |
| `REJECT` | O cadastro foi rejeitado por motivos como requisitos ausentes ou inconsistências detectadas. | Sim. Informe o usuário sobre a rejeição, explique o motivo se possível e sugira os próximos passos. |
| `INTERNAL_ERROR` | Ocorreu um erro interno inesperado no sistema que processa o cadastro. | Sim. Exige intervenção técnica para revisar o sistema, corrigir os problemas internos e tentar de novo ou informar o usuário. |
| `CANCELED` | O usuário cancelou voluntariamente o processo de cadastro ou saiu antes de concluí-lo. | Não. |

<Info>
**Acompanhamento de status por webhook**

Considere usar o status do cadastro recebido via [Webhooks](/docs/webhooks/index). A Yuno recomenda basear sempre as decisões de negócio da sua plataforma nesse status.
</Info>

## Tratamento de erros {#error-handling}

Trate no seu app os erros retornados pelo SDK, como pagamentos com falha ou erros de validação. Para status HTTP e códigos de resposta, veja [Status e códigos de resposta](/reference/payments/status-and-response-codes/payment) na referência da API.
