Coloque este arquivo na raiz do seu projeto e peça ao seu agente de programação:

> Liste o que preciso mudar para passar minha integração com o Yuno Web SDK para a v2, seguindo este arquivo.

Ele funciona como `CLAUDE.md`, `AGENTS.md` ou como um prompt colado, com Claude Code, Cursor, Codex ou Copilot. Ele é
somente leitura: analisa o seu código e gera um relatório, e não altera nada a menos que você peça.

**O destino.** A v2 é a linha sdk-web 2.x ("Yuno SDK 2.x", a API unificada de Transaction). Consulte o
[changelog do Web SDK](https://docs.y.uno/changelog/yuno-sdk/web) para ver a versão atual. Cada versão é servida em uma URL com a versão completa, por exemplo
`https://sdk-web.y.uno/v2.5.1/main.js`, e `v2.0.0`, `v2.1.0`, `v2.1.2`, `v2.2.0` também estão no ar. Não existe pasta
móvel: `/v2/`, `/v2.0/` e `/v2.2/` retornam 404, então você fixa uma versão completa e a atualiza manualmente. O caminho SRI é
`https://prod.y.uno/sdk-static-bundles-ms/sdk-web/v2.5.1/main.js`. Documentação pública: a aba "SDK"
(`docs/yuno-sdk/*`, série de migração em `docs/yuno-sdk/migration/web/*`). A aba "SDKs" é a linha 1.x.
A v1.x continua com suporte em paralelo até 2027.

**A origem.** v1.11 (`window.Yuno`, `/v1.11/main.js` móvel), a linha 1.x atual.

```
v1.11                                              v2
<script .../v1.11/main.js>                         <script .../v2.5.1/main.js>
yuno = await Yuno.initialize(key)                  sdk = await SdkPayments.initialize(key)
yuno.startCheckout(cfg)        (or Seamless)       tx = sdk.transaction(cfg)   (session, country, onStatus,
yuno.mountCheckoutLite({...})                           createPayment present = manual, absent = managed)
yuno.mountCheckout()                               tx.start({ paymentMethod })          form or headless
yunoCreatePayment(ott, info, cs)                   tx.getPaymentMethodsViews({...}).paymentMethodList.mount()
yuno.continuePayment()                             createPayment(token)  -> SDK continues by itself
yunoPaymentResult(status) / yunoError(...)         onStatus({ status, substatus, message })
yuno.unmountSdk()                                  await tx.unmount()
```

## O que a v2 mantém (não reporte isto como bloqueante) {#what-v2-keeps-do-not-report-these-as-blocking}

- **A v2 não mantém nenhum alias da v1.** Ela define apenas `window.SdkPayments` e dispara apenas `sdk-payments-ready`. Ela
  não define `window.Yuno` e nunca dispara `yuno-sdk-ready`. Todo uso de `window.Yuno` e `yuno-sdk-ready` precisa mudar.
- **A v1.11 já expõe os nomes da v2.** Ela define os dois globais e dispara os dois eventos. Por isso,
  `window.SdkPayments` e `sdk-payments-ready` em um repositório v1.11 já estão corretos. Essa renomeação pode ir para produção na 1.11
  primeiro, antes da troca do script.
- **Sem mudança na v2:** o prefixo CSS `sdk-payments-*`; as chaves de opções de `initialize` (`cookies`, `sdkType`,
  `apiUrl`, `assetUrl`, `plugin`); `clearApiCache()` e `setCanaryMode()` na instância; `onChange(state)`;
  as opções `onPromotionQuoteUpdated`, `externalButtons`, `texts`, `issuersFormEnable`, `showPayButton`,
  `deviceFingerprints`, `paymentListConfig`, `savePaymentMethodEnabled`; as chaves de `card` `styles`, `type`
  (exceto `'step'`), `vaultOnSuccess`, `texts`, `documentEnable`, `isCreditCardProcessingOnly`, `fonts`,
  `onChange`, `onGetInstallments`, `onInstallmentSelected`.
- **Chaves silenciosas.** A v2 repassa chaves de configuração desconhecidas ou exclusivas da v1 sem nenhum erro. A maioria nunca é lida: o
  recurso que elas controlavam simplesmente desaparece. Marque essas linhas como SILENT. Três chaves da v1 ainda são lidas na 2.2.0:
  `onLoading` ainda é chamada quando nenhuma função `showLoading` está definida; `paymentMethodSelected` e
  `yunoPaymentMethodSelected` ainda disparam a cada seleção na lista, então manter uma delas junto com `onPaymentSelected`
  gera duas chamadas por seleção; `yunoCreatePayment` é mesclada em `createPayment` no estado. Renomeie-as mesmo assim.
- **CSS.** A v2 renderiza `yuno-container-spinner-content` e `yuno-container-spinner-ring` (o spinner de carregamento
  de toda montagem) e define `data-yuno-placeholder`. Esses são nomes da v2: nunca reporte seletores sobre eles.

## Como usar {#how-to-use}

1. **Encontre a superfície da v1.** Execute sobre o código-fonte, templates de servidor, snippets de tag manager e `package.json`:

```
grep -rnE "window\.Yuno\b|\bYuno\.initialize|yuno-sdk-ready|YunoSDK|sdk-web\.[a-z.]*y\.uno/v[0-9.]+/main\.js|sdk-static-bundles-ms/sdk-web/|loadScript\(|@yuno-payments/sdk-web(-types)?" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
grep -rnE "\.(startCheckout|startSeamlessCheckout|mountCheckout|mountCheckoutLite|mountSeamlessCheckout|mountSeamlessCheckoutLite|mountSeamlessExternalButtons|mountExternalButtons|unmountExternalButton|unmountAllExternalButtons|unmountSeamlessExternalButtons?|mountEnrollmentLite|mountFraud|mountStatusPayment|startPayment|continuePayment|submitOneTimeTokenForm|unmountSdk|showLoader|hideLoader|notifyError|apiClientPayment|apiClientEnroll|continueEnrollment|clickToPay|executeFraudCheck|generateToken\w*|getThreeDSecureChallenge|getContinuePaymentAction|isPaymentMethodAvailable|updateCheckoutSession|refreshPromotionQuote)\(" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
grep -rnE "yunoPaymentResult|paymentResult|yunoError|yunoEnrollmentStatus|enrollmentStatus|yunoCreatePayment|createPayment|yunoPaymentMethodSelected|paymentMethodSelected|onLoading|showLoading|showPaymentStatus|renderMode|viewContainer|onlyExpressPaymentMethods|stickyPayButton|__internal|cardSaveEnable|requiredFieldsOrderedEnabled|topLevelDomain|isRetrying|newCheckoutSession|payment_method\.card\.detail|holder_name|enableV2|enableMultiplesCard|\.render\(" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
grep -rnE "'(FAIL|REJECT|PROCESSING|READY)'|\"(FAIL|REJECT|PROCESSING|READY)\"|type:\s*['\"]step['\"]|checkout/sessions|workflow" --exclude-dir=node_modules --exclude-dir=.git --exclude-dir=dist --exclude-dir=build .
```

2. **Encontre qualquer superfície da v2 já presente:** `grep -rnE "SdkPayments\.initialize|\.transaction\(|\.start\(\{|getPaymentMethodsViews|transactionStatus|\.antifraud\(|onStatus|saveCardEnabled|showStatusScreen|sdk-web\.[a-z.]*y\.uno/v2"`.
   Um repositório com as duas está no meio da migração: reporte as sobras da v1 em toda página que carrega o script da v2. Em
   tempo de execução, `typeof sdk.transaction === 'function'` significa v2; uma instância v1 tem `startCheckout` e não tem `transaction`.
3. **Classifique cada fluxo** (Lite, Full, Seamless, Seamless Lite, botões externos, headless, Secure Fields,
   cadastro, fraude, tela de status) como manual (o lojista cria o pagamento) ou gerenciado (o SDK cria o pagamento).
4. **Mapeie cada ocorrência** com a tabela abaixo, execute as verificações M1 a M25 e escreva o relatório.

## Mapeamento {#mapping}

As seções seguem a tabela de pesquisa 3.A a 3.H. Tipo: KEEP, RENAME, MOVE, BEHAVIOUR, NEW REQUIRED,
REMOVED (sem substituto), SILENT (a v2 aceita e ignora a chave antiga), BLOCKED (lacuna de paridade: reporte "blocked: parity gap, do not migrate this flow yet", não como uma mudança).

### 3.A Inicialização e globais {#3a-bootstrap-and-globals}

| v1.11 | v2 | Tipo | O que fazer | Evidência |
|---|---|---|---|---|
| `window.Yuno`, `new Yuno`, `YunoSDK` | `window.SdkPayments` | RENAME | Substitua todas as referências | `src/main.ts` na 1.11 vs 2.2.0 |
| Evento `yuno-sdk-ready` | `sdk-payments-ready` | RENAME | Escute o novo evento; verifique também `window.SdkPayments` antes | igual |
| `<script .../v1.11/main.js>` | `<script .../v2.x.y/main.js>` | BEHAVIOUR | Fixe uma versão completa; não há pasta móvel | Testes na CDN na data em que isto foi escrito |

| `@yuno-payments/sdk-web-types` | nenhum publicado | REMOVED | Escreva uma declaração local a partir das páginas públicas de migração para a v2 | `@yuno-payments/sdk-web-types` declara `startCheckout`, sem `transaction` |

## Verificações {#checks}

Reporte cada uma como PASS / FAIL / N/A com arquivo:linha e cite a linha. Cada título termina com o id da verificação na pesquisa
e uma severidade: B bloqueante (sem pagamento ou sem resultado), H alta (recurso perdido silenciosamente ou resultado errado), M média
(UX degradada), L baixa (higiene), P lacuna de paridade (reporte como bloqueado, nunca como uma mudança a fazer).

### 1. Global e evento de pronto (M1, B) {#1-global-and-ready-event-m1-b}

Procure: `window.Yuno`, `Yuno.initialize`, `yuno-sdk-ready`. Ainda v1: qualquer ocorrência. Mude: `window.SdkPayments`, `sdk-payments-ready`, verifique o global antes de escutar. Sintoma: `Yuno is not defined`, a inicialização nunca roda.

### 2. URL do script e loader (M2, B) {#2-script-url-and-loader-m2-b}

Procure: tags de script, `loadScript`, `sdk-static-bundles-ms`. Ainda v1: `/v1.11/`, `loadScript()` sem `baseUrl`, `sri: true`; também errado: `/v2/`, `/v2.2/`. Mude: URL `v2.x.y` completa; em páginas da UE, verifique se o host da UE tem a versão. Fixações v2 mais antigas, como `v2.0.0`, são válidas se a integração foi testada com essa versão. ### 3. Pontos de entrada da v1 (M3, B) {#3-v1-entry-points-m3-b}

Mude: o modo gerenciado não tem `createPayment` e usa `workflow: "SDK_SEAMLESS"`; o manual tem `createPayment` e o workflow padrão. Sintoma: `onStatus` `INTERNAL_ERROR`.

### 5. Assinatura de `createPayment` (M5, B) {#5-createpayment-signature-m5-b}

Procure: `(yuno)?[cC]reatePayment`, `continuePayment`. Ainda v1: dois ou três parâmetros, o primeiro usado como string, a sessão da configuração usada, `continuePayment()`, `notifyError()`. Mude: um único `token`; envie `token.token` e `token.checkout_session`; retorne uma Promise que se resolva em todos os caminhos; rejeite em caso de falha. Procure: `yunoPaymentResult`, `paymentResult`, `yunoError`, `enrollmentStatus`, as strings de status da v1. ### 17. Fraude e tela de status (M17, H) {#17-fraud-and-status-screen-m17-h}

Procure: `executeFraudCheck`, `mountFraud`, `mountStatusPayment`. ## Formato do relatório {#report-format}

```
PART 1  Migration list (B first, then H, M, L)
B  M5   src/checkout/pay.ts:41    yunoCreatePayment(ott, info, cs) -> createPayment(token), send token.token
B  M6   src/checkout/pay.ts:58    yunoPaymentResult -> onStatus; 'FAIL' -> DECLINED/REJECTED/INTERNAL_ERROR
H  M12  src/checkout/config.ts:9  card.cardSaveEnable -> card.saveCardEnabled
KEEP    src/index.html:12         window.SdkPayments / sdk-payments-ready already v2-compatible

PART 2  Parity gaps (flows that cannot migrate yet)
P  M11  src/wallets.ts:20  mountExternalButtons (non-seamless wallets): blocked: parity gap, do not migrate this flow yet
P  M13  src/cart.ts:77     stickyPayButton: blocked: parity gap, do not migrate this flow yet
```

Uma linha por achado: severidade, verificação, arquivo:linha, a mudança em uma linha. Termine com as versões dos scripts v1 e v2
encontradas e se o repositório é somente v1 ou misto.

## Diagnósticos a coletar {#diagnostics-to-capture}

1. A URL do script efetivamente carregada (aba Network) e o valor de `typeof sdk.transaction` (`function` apenas na v2).
2. O id da sessão de checkout, o seu `workflow` e o horário UTC da tentativa.
3. Todo payload de `onStatus` recebido (`status`, `substatus`, `message.code`, `message.reason`).
4. Linhas do console que começam com `SdkPayments` e qualquer mensagem lançada por `transaction()`, `start()` ou `mount()`.
5. A requisição `createPayment` que o seu backend enviou (campo do token e sessão, sem dados pessoais).

## Verifique em tempo de execução {#verify-at-runtime}

Estes pontos não puderam ser confirmados lendo o código; teste-os antes de confiar neles:
o que um `yunoCreatePayment` isolado (assinatura da v1) faz depois de mesclado em `createPayment`; o que
`card.type: 'step'` renderiza; `transaction.unmount()` em uma remontagem do React StrictMode; a lista completa de classes CSS;
a disponibilidade da `v2.2.0` na UE. Parte disto foi lida em código da v2 ainda não lançado, então alguns comportamentos
podem ainda não estar no bundle da 2.2.0.
