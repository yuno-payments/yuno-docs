Um validador é um checklist em Markdown escrito para um agente de programação com IA. Você o entrega ao agente que trabalha no seu repositório, e o agente lê o seu código comparando-o com cada verificação da lista. Para cada verificação, ele informa PASS, FAIL ou N/A, cita o arquivo e a linha que comprovam o resultado e explica o que quebra e como corrigir.

Os validadores são somente leitura. O agente pesquisa e lê o seu código e não altera nada, a menos que você peça.

## Escolha um validador {#choose-a-validator}

| Sua integração | Validador |
| --- | --- |
| Web SDK v1 (1.11) com a UI da Yuno: Full checkout, Lite, Seamless, botões de carteiras externas, Enrollment Lite, telas de status | [Web SDK v1: fluxos de checkout](/pt-br/docs/sdks/validators/web-sdk-v1-checkout-flows) |
| Web SDK v1 (1.11) sem a UI da Yuno: pagamento e cadastro headless, split em dois cartões, Secure Fields | [Web SDK v1: headless e Secure Fields](/pt-br/docs/sdks/validators/web-sdk-v1-headless-secure-fields) |
| Web SDK v2 (`window.SdkPayments` e `sdk.transaction`) | [Web SDK v2](/pt-br/docs/sdks/validators/web-sdk-v2) |
| Web SDK v1 (1.11) que você planeja migrar para a v2 | [Migração do Web SDK v1 para a v2](/pt-br/docs/sdks/validators/web-sdk-v1-to-v2-migration) |
| Lojas e apps headless da VTEX | [Validadores da VTEX](/pt-br/docs/plugins/vtex/validators/index) |

Se o seu repositório usa tanto a UI da Yuno quanto os Secure Fields, execute os dois validadores da v1.

## Obtenha o arquivo bruto {#get-the-raw-file}

Toda página de validador também é servida como Markdown puro. Adicione `.md` à URL da página para obter o arquivo de que o agente precisa:

```text
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-checkout-flows.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-headless-secure-fields.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v2.md
https://docs.y.uno/docs/sdks/validators/web-sdk-v1-to-v2-migration.md
```

## Execute com o Claude Code {#run-it-with-claude-code}

<Steps>
  <Step title="Salve o validador na raiz do seu repositório">
    ```bash
    curl -o CLAUDE.md https://docs.y.uno/docs/sdks/validators/web-sdk-v1-checkout-flows.md
    ```
  </Step>
  <Step title="Peça ao Claude Code para validar">
    ```text
    Validate my Yuno Web SDK integration following CLAUDE.md
    ```
  </Step>
  <Step title="Leia o relatório">
    O Claude Code responde com uma linha por verificação e uma lista de falhas ordenadas por impacto, cada uma com uma correção de uma linha.
  </Step>
</Steps>

<Warning>
Se o seu repositório já tem um `CLAUDE.md` ou `AGENTS.md`, não o sobrescreva. Salve o validador com outro nome, como `yuno-validator.md`, e peça ao agente para validar sua integração seguindo esse arquivo.
</Warning>

## Execute com Cursor, Codex ou Copilot {#run-it-with-cursor-codex-or-copilot}

Salve o validador como `AGENTS.md` na raiz do repositório e peça ao agente para validar sua integração com a Yuno seguindo o `AGENTS.md`. Você também pode colar o arquivo inteiro no chat como prompt.

## Quando uma verificação falha {#when-a-check-fails}

Corrija as falhas na ordem em que o relatório as lista: primeiro os pagamentos bloqueados, depois os resultados perdidos ou errados e, por fim, a experiência degradada. Se precisar de ajuda do suporte da Yuno, envie:

- O relatório completo do validador.
- Os diagnósticos listados na seção "Diagnostics to capture" do validador que você executou. Eles incluem a versão do SDK, o ID da sessão de checkout, o horário UTC da tentativa e os erros de console e de rede.

Remova chaves de API, dados de cartão e dados pessoais antes de enviar qualquer coisa.

## Como as verificações foram criadas {#how-the-checks-were-built}

As verificações foram derivadas do código-fonte do Web SDK e de tickets reais de suporte. Quando um validador indicar que a documentação pública e o código divergem, siga o código. A Yuno está corrigindo essas páginas da documentação.
