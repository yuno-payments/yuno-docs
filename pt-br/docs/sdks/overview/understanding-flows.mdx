Nos SDKs da Yuno, os **fluxos de pagamento** e os **fluxos de cadastro** são separados. O pagamento é o processo de concluir uma transação. O cadastro é o processo de salvar um meio de pagamento (por exemplo, um cartão) na conta de um cliente para uso futuro. Esta página explica os dois fluxos em alto nível, com diagramas e sequências de passos. Use o [Guia de início rápido](/pt-br/docs/sdks/overview/quickstart) e as páginas de fluxo de cada plataforma ([Web](/docs/sdks/full-checkout/web-payments), [iOS](/docs/sdks/full-checkout/ios-payments), [Android](/docs/sdks/full-checkout/android-payments)) para ver os detalhes de implementação.

### Passos do fluxo de pagamento {#payment-flow-steps}

1. Servidor do lojista: `Create Customer` → Servidor da Yuno: `Creates Customer`
2. Cliente do lojista: `Initiate Checkout` → Servidor do lojista: `Create Checkout session`
3. Servidor do lojista: `Create Checkout session` → Servidor da Yuno: `Creates Checkout session`
4. Cliente do lojista: `Initiate Checkout` → `Initiate SDK` para continuar o fluxo de pagamento
5. Cliente do lojista: `Initiate SDK` para continuar o fluxo de pagamento → Yuno SDK: `Receive checkout session`
6. Yuno SDK: `Receive checkout session` → `List payment methods`
7. Yuno SDK: `List payment methods` → O usuário seleciona os meios de pagamento
8. Yuno SDK: O usuário seleciona os meios de pagamento → Callback com o `one-time token`
9. Yuno SDK: Callback com o `one-time token` → Cliente do lojista: Recebe o `one-time token` (uso único)
10. Cliente do lojista: Recebe o `one-time token` (uso único) → `Initiate payment`
11. Cliente do lojista: `Initiate payment` → `Initiate SDK` para continuar o fluxo de pagamento
12. Cliente do lojista: `Initiate SDK` para continuar o fluxo de pagamento → Yuno SDK: `Continue with the payment flow`
13. Yuno SDK: `Continue with the payment flow` → Mostra a tela para o usuário concluir o pagamento
14. Yuno SDK: Mostra a tela para o usuário concluir o pagamento → Exibe o `payment result` (opcional)
15. Cliente do lojista: `Initiate payment` → Servidor do lojista: `Create payment`
16. Servidor do lojista: `Create payment` → Servidor da Yuno: `Creates payment` no provedor de pagamento

#### Passos do fluxo com token armazenado {#vaulted-token-flow-steps}

1. Cliente do lojista: `Initiate checkout` → Servidor do lojista: `Create Customer`
2. Servidor do lojista: `Create Customer` → Servidor da Yuno: `Create Customer`
3. Cliente do lojista: `Initiate SDK` com a `checkout session` → Yuno SDK: `Receive checkout session`
4. Yuno SDK: `Receive checkout session` → `List payment methods`
5. Yuno SDK: `List payment methods` → O usuário seleciona os meios de pagamento
6. Yuno SDK: O usuário seleciona o meio de pagamento → Callback com o `one-time token`
7. Yuno SDK: Callback com o `one-time token` → Cliente do lojista: `Initiate payment`
8. Cliente do lojista: `Initiate payment` → Servidor do lojista: `Create payment`
9. Servidor do lojista: `Create payment` → Servidor da Yuno: `Creates payment` no provedor de pagamento
10. Cliente do lojista: Mostra o `payment result` → Servidor do lojista: `Receive payment result`
11. Servidor do lojista: `Receive payment result` → Servidor da Yuno: Fornece o `payment result`

## Fluxo de cadastro {#enrollment-flow}

O **cadastro** é o processo de salvar um meio de pagamento (por exemplo, um cartão) na conta de um cliente para que ele possa ser usado depois (por exemplo, com um token armazenado). O full-checkout oferece suporte ao cadastro; o diagrama abaixo descreve o fluxo de cadastro.

### Passos do fluxo de cadastro {#enrollment-flow-steps}

1. Servidor do lojista: `Create Customer` → Servidor da Yuno: `Creates Customer`
2. Cliente do lojista: `Add payment method` → Servidor do lojista: `Create customer session`
3. Servidor do lojista: `Create customer session` → Servidor da Yuno: `Creates customer session`
4. Cliente do lojista: `Display payment methods to enroll` → Servidor do lojista: `Request available payment methods to enroll`
5. Servidor do lojista: `Request available payment methods to enroll` → Servidor da Yuno: `Returns available payment method`
6. Cliente do lojista: `Display payment methods to enroll` → Cliente do lojista: O usuário seleciona o meio de pagamento a cadastrar
7. Cliente do lojista: O usuário seleciona o meio de pagamento a cadastrar → Cliente do lojista: `Initiate enrollment`
8. Cliente do lojista: `Initiate enrollment` → Cliente do lojista: `Initiate SDK` para continuar o cadastro
9. Cliente do lojista: `Initiate SDK` para continuar o cadastro → Yuno SDK: `Continue enrollment flow`
10. Yuno SDK: `Continue enrollment flow` → Yuno SDK: Mostra as telas para o usuário concluir o cadastro
11. Servidor do lojista: Recebe o `enrollment result` via webhook → Servidor da Yuno: Recebe os `enrollment results` do provedor de pagamento
12. Servidor da Yuno: Recebe os `enrollment results` do provedor de pagamento → Yuno SDK: Exibe o `enrollment result` (opcional)

## Fluxo do Headless SDK {#headless-sdk-flow}

O **Headless SDK** oferece o máximo de flexibilidade, permitindo que você gerencie toda a interface do usuário enquanto a Yuno cuida da lógica complexa de pagamento e da segurança (como o 3DS).

### Passos do fluxo headless {#headless-flow-steps}

1. Servidor do lojista: `Create Customer` → Servidor da Yuno: `Creates Customer`
2. Cliente do lojista: `Initiate Checkout` → Servidor do lojista: `Create Checkout session`
3. Cliente do lojista: `Collect Information` → O usuário informa os dados do cartão/pagamento na sua interface personalizada.
4. Cliente do lojista: `Generate Token` → Yuno SDK: Chame `generateToken(details)` para receber um `one-time token`.
5. Cliente do lojista: `Process Payment` → Servidor do lojista: Envie o `one-time token` para o seu backend.
6. Servidor do lojista: `Create Payment` → Servidor da Yuno: Chame a API [Create Payment](/reference/payments/create-payment).
7. Cliente do lojista: `Handle Actions` → Se a resposta da API retornar `sdk_action_required: true`, use o SDK para tratar o 3DS ou outras [Ações de pagamento](/pt-br/docs/sdks/headless-web/payment#step-7-get-payment-actions).
