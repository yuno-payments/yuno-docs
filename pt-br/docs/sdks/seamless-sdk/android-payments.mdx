Esta página traz um guia do Yuno Seamless SDK para pagamentos no Android.

<Tip>
**SDK recomendado**

A Yuno recomenda usar o **Android Seamless SDK** para uma experiência de integração tranquila. Essa opção oferece uma solução de pagamento flexível, com componentes de UI prontos e opções de personalização.
</Tip>

Este SDK é ideal para lojistas que:

* Querem controle sobre o fluxo de pagamento enquanto aproveitam componentes de UI prontos
* Precisam personalizar a experiência de pagamento mantendo a conformidade com o PCI
* Buscam um equilíbrio entre velocidade de implementação e personalização

O Seamless SDK inclui recursos como:

* Componentes de UI de pagamento prontos, com opções de personalização
* Suporte a vários meios de pagamento
* Tratamento avançado do status do pagamento
* Gerenciamento completo de erros

Para lojistas que precisam de controle total da UI ou de recursos mais avançados, considere usar o [Full SDK](/docs/sdks/full-checkout/android-payments) da Yuno.

## Requisitos {#requirements}

Antes de iniciar a integração do Yuno Android SDK, confirme que seu projeto atende aos requisitos técnicos. Confirme também que os seguintes pré-requisitos estão atendidos:

* **Versão mínima do SDK**: `minSdkVersion` 23 ou superior (Android 6.0). Obrigatória desde o Yuno Android SDK 2.24.0
* **Java**: Java 8 habilitado
* **AndroidX**: use AndroidX em vez das bibliotecas de suporte antigas
* **Android Gradle Plugin**: 4.0.0 ou superior
* **Kotlin Gradle Plugin**: 1.4.0 ou superior
* **ProGuard**: 6.2.2 ou superior

### Configuração do ProGuard / R8 {#proguard--r8-configuration}

Se o seu projeto tiver `minifyEnabled = true`, adicione estas regras ao seu arquivo `proguard-rules.pro` para garantir que o SDK funcione corretamente, principalmente com o **modo completo do R8 no AGP 8.x+**.

<Accordion title="Regras oficiais de ProGuard / R8 da Yuno">
  ```proguard
  # Preserve generic type signatures and annotations
  -keepattributes Signature
  -keepattributes *Annotation*

  # Yuno SDK
  -keep class com.yuno.** { *; }
  -dontwarn com.yuno.**

  # Gson — R8 full mode compatibility
  -keep class com.google.gson.** { *; }
  -keep,allowobfuscation,allowshrinking,allowoptimization class * extends com.google.gson.reflect.TypeToken
  -dontwarn com.google.gson.**

  # Retrofit — R8 full mode compatibility
  -keep,allowobfuscation,allowshrinking interface retrofit2.Call
  -keep,allowobfuscation,allowshrinking class retrofit2.Response
  -keep,allowobfuscation,allowshrinking class kotlin.coroutines.Continuation
  -dontwarn retrofit2.**

  # OkHttp + Okio — Suppress warnings
  -dontwarn okhttp3.**
  -dontwarn okio.**
  ```

  ### Por que essas regras são necessárias?

  O AGP 8.x+ habilita o **modo completo do R8** por padrão, que remove de forma agressiva as assinaturas de tipos genéricos. Sem `-keepattributes Signature`, o `TypeToken<T>` do Gson pode falhar em tempo de execução com `java.lang.Class cannot be cast to java.lang.reflect.ParameterizedType`.
</Accordion>

<Info>
**Verifique a versão do SDK**

Consulte as [Notas de versão](/changelog/android) ou o [repositório do Yuno Android SDK](https://github.com/yuno-payments/yuno-sdk-android) para verificar a versão atual disponível do SDK.
</Info>

## Passo 1: Crie um cliente {#step-1-create-a-customer}

Crie um cliente usando o [endpoint Create customer](/reference/customers/create-customer) antes de iniciar pagamentos. Este passo é necessário para:

* Identificar a pessoa que faz o pagamento
* Habilitar a funcionalidade de cartão salvo (se estiver habilitada)
* Acompanhar o histórico de pagamentos

O ID do cliente retornado por esse endpoint será usado ao criar a `checkout_session`.

## Passo 2: Crie uma sessão de checkout {#step-2-create-a-checkout-session}

Crie uma nova `checkout_session` usando o endpoint [Create checkout session](/reference/checkout-sessions/create-checkout-session) para inicializar o fluxo de pagamento. Lembre-se de:

* Incluir o ID do cliente obtido no passo anterior
* Armazenar o ID da `checkout_session` retornado para usar no Passo 6 da integração

<Info>
  Controle a autorização ou a captura enviando `payment_method.detail.card.capture` na sessão de checkout: `false` = apenas autorizar, `true` = capturar imediatamente.
</Info>

### Parâmetros principais {#key-parameters}

| Parâmetro            | Obrigatório | Descrição |
| -------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `amount`             | Sim      | O objeto do valor principal da transação, que contém `currency` (código ISO 4217) e `value` (valor numérico nessa moeda). |
| `alternative_amount` | Não       | Uma representação do valor da transação em moeda alternativa, com a mesma estrutura de `amount` (`currency` e `value`). Útil em cenários com várias moedas, como mostrar preços aos clientes na moeda de preferência deles (por exemplo, USD) enquanto o pagamento é processado na moeda local (por exemplo, COP). |

<Warning>
**Uso da sessão de checkout**

A `checkout_session` é única para cada tentativa de pagamento e não pode ser reutilizada.
</Warning>

## Passo 3: Adicione o SDK ao seu projeto {#step-3-add-sdk-to-your-project}

Adicione a origem do repositório:

```groovy
maven { url "https://yunopayments.jfrog.io/artifactory/snapshots-libs-release" }
```

Inclua o código a seguir no arquivo `build.gradle` para adicionar a dependência do Yuno SDK ao aplicativo:

```kotlin
dependencies {
    implementation 'com.yuno.payments:android-sdk:2.27.0'
}
```

## Passo 4: Configure as permissões {#step-4-configure-permissions}

O Yuno SDK precisa de permissões de rede. Confirme que a permissão `INTERNET` está incluída no seu `AndroidManifest.xml`:

```xml
<uses-permission android:name="android.permission.INTERNET" />
```

## Passo 5: Inicialize o SDK {#step-5-initialize-sdk}

Obtenha suas chaves de API públicas no [Dashboard da Yuno](https://dashboard.y.uno/).

Se você ainda não implementou uma aplicação personalizada, crie uma. No método `onCreate()` da sua classe de aplicação, chame a função de inicialização (`Yuno.initialize`):

```kotlin
class CustomApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        Yuno.initialize(
            this,
            PUBLIC_API_KEY,
            config = YunoConfig()
        )
    }
}
```

Use a data class `YunoConfig` para definir configurações adicionais do SDK. A tabela a seguir lista e descreve as opções de personalização:

| Opção                    | Descrição |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **saveCardEnabled**       | Habilita a caixa de seleção para salvar o cartão nos fluxos de cartão. Consulte a seção [Salvar cartão](#save-card-for-future-payments) para mais informações. |
| **language**              | Define o idioma usado nos formulários de pagamento. Consulte [Idiomas compatíveis](/pt-br/docs/sdks/resources/languages-supported) para ver as opções. |
| **styles**                | Habilita a personalização da UI em todo o SDK. Use para definir estilos visuais globais, como família de fonte e aparência dos botões, por meio de um objeto `YunoStyles`. Para mais informações, consulte a seção [styles](/pt-br/docs/sdks/resources/references/android#styles). |

O bloco de código a seguir mostra um exemplo de `YunoConfig`:

```kotlin
data class YunoConfig(
    val saveCardEnabled: Boolean = false,
    val keepLoader: Boolean = false, // Not applicable to Seamless SDK
    val language: YunoLanguage? = null,
  	val styles: YunoStyles? = null,
)
```

## Passo 6: Inicie o checkout {#step-6-start-checkout}

Chame o método `startCheckout` na função `onCreate()` da activity que integra o SDK para iniciar um novo processo de pagamento com o Seamless SDK:

```kotlin
startCheckout(
  checkoutSession: "checkout_session",
  countryCode: "US",
  callbackPaymentState: ((String?, String?, StatusMessage?) -> Unit)? = null,
  merchantSessionId: String? = null
)
```

| Parâmetro              | Descrição |
| :--------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `checkoutSession`      | A `checkout_session` relacionada ao pagamento. |
| `countryCode`          | Código do país em que o pagamento é realizado. Consulte [Cobertura de países](/pt-br/docs/sdks/resources/country-coverage) para ver a lista completa de países compatíveis e seus códigos. |
| `callbackPaymentState` | Callback opcional `(state, subState, message)` com o estado do pagamento, seu subestado e, nos resultados de erro, um [`StatusMessage?`](/pt-br/docs/sdks/resources/references/android#statusmessage-error-details). O terceiro parâmetro foi adicionado no SDK `2.22.0`. |
| `merchantSessionId`    | Identificador opcional para acompanhar a sessão do lojista. O padrão é null. |

Os estados de pagamento possíveis retornados por `callbackPaymentState` são:

```kotlin
const val PAYMENT_STATE_SUCCEEDED = "SUCCEEDED"
const val PAYMENT_STATE_FAIL = "FAIL"
const val PAYMENT_STATE_PROCESSING = "PROCESSING"
const val PAYMENT_STATE_REJECT = "REJECT"
const val PAYMENT_STATE_INTERNAL_ERROR = "INTERNAL_ERROR"
const val PAYMENT_STATE_STATE_CANCELED_BY_USER = "CANCELED_BY_USER"
```

A tabela a seguir traz mais informações sobre os estados possíveis:

| **Estado**          | **Descrição** | **Ação adicional necessária** |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `SUCCEEDED`        | A transação ou o processo de pagamento foi concluído com sucesso, sem erros. | Não. |
| `FAIL`             | A transação falhou por erros como problemas de validação de dados, falhas de conexão com o servidor ou problemas técnicos ou de rede. | Sim. Investigue a causa da falha (validação, rede, servidor) e tome medidas corretivas. |
| `PROCESSING`       | A transação está em andamento, aguardando aprovação ou verificação. | Não. |
| `REJECT`           | A transação foi rejeitada por motivos como saldo insuficiente ou suspeita de atividade fraudulenta. | Sim. Informe o usuário sobre a rejeição, informe o motivo se possível e sugira ações. |
| `INTERNAL_ERROR`   | Ocorreu um erro interno inesperado no sistema que processa o pagamento. | Sim. Exige intervenção técnica para revisar o sistema, corrigir os problemas internos e tentar novamente ou informar o usuário. |
| `CANCELED_BY_USER` | O usuário cancelou a transação voluntariamente ou abandonou o processo de pagamento. | Não. |

### Validação do status do pagamento {#payment-status-validation}

Esta seção explica como o SDK trata o status do pagamento quando os usuários cancelam ou saem dos fluxos de pagamento, e como o status do SDK se relaciona com o status do pagamento no backend nesses cenários.

#### Meios de pagamento síncronos (Google Pay) {#sync-payment-methods-google-pay}

Para meios de pagamento síncronos, como o Google Pay, quando o usuário cancela ou fecha a UI da carteira antes de receber a resposta do provedor de serviços de pagamento (PSP):

* **Status do SDK**: retorna `CANCELED_BY_USER`
* **Status do pagamento no backend**: continua `PENDING` até o timeout do PSP ou o cancelamento pelo lojista
* **Importante**: o SDK não retorna `REJECT` nem `PROCESSING` nesse cenário

Isso garante que o pagamento no backend continue em estado pendente e possa ser tratado corretamente pelo sistema do lojista.

#### Meios de pagamento assíncronos (PIX e métodos baseados em QR) {#async-payment-methods-pix-and-qr-based-methods}

Para meios de pagamento assíncronos, quando o usuário fecha a janela de pagamento antes de concluir o pagamento:

* **Status do SDK**: retorna `CANCELED_BY_USER`\*.
* **Status do pagamento no backend**: continua `PENDING`, e o código de pagamento continua válido até expirar.
* **Reutilização da sessão de checkout**: reabrir a mesma sessão de checkout pode exibir o mesmo código de pagamento válido.
* **Sem cancelamento automático**: o pagamento não é cancelado automaticamente no backend quando o usuário fecha a janela.
* **Confirmação do status**: `CANCELED_BY_USER` significa que o comprador saiu da tela, não que o pagamento falhou. Confirme o estado final por webhook ou por `GET /v1/payments/{payment_id}` antes de mostrar um cancelamento.

<Note>
\* Meios de pagamento que mostram um código de pagamento ou voucher (QR code PIX, boleto, OXXO e similares) e o Pix Parcelado retornam `PROCESSING` com o subestado `CLOSED_BY_USER` em vez de `CANCELED_BY_USER` quando o usuário fecha a tela. O pagamento continua `PENDING` no backend e ainda pode ser concluído.
</Note>

#### Pagamentos assíncronos expirados {#expired-async-payments}

Se um QR code PIX expirar naturalmente:

* **Status no backend**: atualizado para `EXPIRED`
* **Status do SDK**: os callbacks do SDK e os endpoints de polling retornam `EXPIRED` de forma consistente

Isso garante que os lojistas recebam informações de status precisas quando um meio de pagamento expira.

## Passo 7: Obtenha o token de uso único (OTT) do pagamento {#step-7-get-payment-one-time-token-ott}

Chame o método `startPaymentSeamlessLite` para iniciar um processo de pagamento:

```kotlin
startPaymentSeamlessLite(
    paymentSelected: PaymentSelected,
    showPaymentStatus: Boolean = true,
    callbackPaymentState: ((String?, String?, StatusMessage?) -> Unit)? = null,
)
```

A tabela a seguir descreve os parâmetros para iniciar o pagamento:

| Parâmetro              | Descrição |
| :--------------------- | :--------------------------------------------------------------------------------------- |
| `paymentSelected`      | Especifica o meio de pagamento, por meio de um token armazenado ou de um tipo de pagamento selecionado. |
| `callbackPaymentState` | Callback opcional `(state, subState, message)`; `message` é um [`StatusMessage?`](/pt-br/docs/sdks/resources/references/android#statusmessage-error-details) nos resultados de erro. |
| `showPaymentStatus`    | Parâmetro opcional. Quando `true`, exibe a tela de resultado padrão do SDK. |

Você receberá o status do pagamento por meio de `callbackPaymentState`, que indica se o pagamento foi bem-sucedido ou se ocorreu algum problema.

## Passo 8: Crie o pagamento {#step-8-create-payment}

Chame o método `startPaymentSeamlessLite` com o meio de pagamento selecionado para concluir o processo de pagamento:

```kotlin
startPaymentSeamlessLite(
    paymentSelected: PaymentSelected,
    showPaymentStatus: Boolean = true,
    callbackPaymentState: ((String?, String?, StatusMessage?) -> Unit)? = null,
)
```

## Recursos complementares {#complementary-features}

O Yuno Android SDK oferece serviços e configurações adicionais que você pode usar para melhorar a experiência dos clientes. Use a [personalização do SDK](/pt-br/docs/sdks/customization/android) para alterar a aparência do SDK de acordo com a sua marca ou para configurar o loader.

### `styles` {#styles}

Com a opção de personalização `styles`, você pode definir estilos visuais globais por meio de um objeto `YunoStyles`. Ela permite aplicar uma identidade visual consistente em todo o SDK, personalizando a aparência dos botões e a tipografia.

```kotlin
data class YunoStyles(
    val buttonStyles: YunoButtonStyles? = null,
    val fontFamily: FontFamily? = null
)
```

| Parâmetro      | Descrição |
| :------------- | :------------------------------------------------------ |
| `buttonStyles` | Personaliza os botões principais exibidos no SDK. |
| `fontFamily`   | Define a família de fonte usada em todos os elementos de texto do SDK. |

O objeto `YunoButtonStyles` permite definir configurações específicas para a aparência dos botões:

```kotlin
data class YunoButtonStyles(
    val backgroundColor: Color? = null,
    val contentColor: Color? = null,
    val cornerRadius: Dp? = null,
    val elevation: Dp? = null,
    val padding: Dp? = null,
    val fontFamily: FontFamily? = null,
    val fontSize: TextUnit? = null,
    val fontStyle: FontStyle? = null
)
```

Use a data class `YunoConfig`, descrita no Passo 5, para usar a opção de personalização `styles`.

### Loader {#loader}

A funcionalidade do loader é controlada pelo parâmetro `keepLoader` na data class `YunoConfig`, documentado diretamente na seção anterior de configuração do SDK.

### Preenchimento automático do Google {#google-autofill}

Desde a versão 2.16.0 do Android SDK, os campos de número do cartão, nome do titular do cartão, data de validade e CVV podem usar o preenchimento automático do Google (Google Autofill). Quando o cliente foca em qualquer um desses campos, a UI de preenchimento automático do Android pode sugerir um cartão salvo na conta Google dele, e ao selecioná-lo o formulário é preenchido automaticamente.

<Note>
  Isso vale para qualquer usuário de Android que paga com cartão. Não está vinculado ao meio de pagamento Google Pay. Não é necessária nenhuma feature flag nem configuração extra; o recurso fica ativo automaticamente quando você atualiza para a versão 2.16.0 ou posterior.
</Note>

## Tratamento de erros {#error-handling}

Trate no seu app os erros retornados pelo SDK, incluindo pagamentos com falha e erros de validação. Para os códigos de status HTTP e de resposta, consulte [Códigos de status e de resposta](/reference/payments/status-and-response-codes/payment) na referência da API.
