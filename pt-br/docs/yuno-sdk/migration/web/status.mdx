---
title: "Status do pagamento"
description: "Migre a tela de status independente da Web (yuno.mountStatusPayment) para o SDK unificado."
---

`yuno.mountStatusPayment(...)` renderizava uma tela independente de resultado do pagamento para uma sessão de checkout, normalmente exibida depois que o comprador voltava de um redirecionamento externo. Na API unificada, isso passa a ser um método de nível superior em `SdkPayments`: `sdkPayments.transactionStatus(...)`.

Ele não faz parte de uma `Transaction`. Assim como `antifraud`, é uma operação independente, por isso fica diretamente na instância de `SdkPayments`.

## Antes de começar {#before-you-start}

- Carregue o bundle do SDK unificado em vez do legado e inicialize-o como mostra o lado a lado: `window.Yuno.initialize(...)` passa a ser `SdkPayments.initialize(...)`. A sua chave de API pública e as sessões de checkout que o seu backend cria não mudam ([Antes de começar](/pt-br/docs/yuno-sdk/get-started#before-you-begin)).

## Lado a lado {#side-by-side}

<CodeGroup>

```typescript Before. mountStatusPayment
const yuno = await window.Yuno.initialize('your-public-api-key')

yuno.mountStatusPayment({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    language: 'en',
    paymentResult(data) {
        console.log('paymentResult', data)
    },
})
```

```typescript After. sdkPayments.transactionStatus
const sdkPayments = await SdkPayments.initialize('your-public-api-key')

await sdkPayments.transactionStatus({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',           // optional
    language: 'en',              // optional
    elementSelector: '#status',  // required
})
```

</CodeGroup>

## O que muda {#what-changes}

Agrupado na ordem em que você edita o código. **Renomeado**: mesma função, novo nome. **Movido**: mesmo valor, novo dono. **Removido**: nada a chamar. **Novo**: sem equivalente legado. A última coluna é a única coisa que você precisa fazer além da renomeação.

### Inicialização e config {#initialization-and-config}

| Status | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `window.Yuno.initialize(publicApiKey)` | `SdkPayments.initialize(publicApiKey)` | Renomeado | O global é `window.SdkPayments`. Como antes, use `await`: ele resolve para a instância de `SdkPayments`. |
| `checkoutSession` | `checkoutSession` | Movido | Igual. Obrigatório. |
| `countryCode` | `countryCode?` | Movido | Agora é opcional. |
| `language` | `language?` | Movido | Agora é opcional. |
| *(container padrão)* | `elementSelector` | Novo | Agora é obrigatório: você passa o seletor CSS do elemento onde a tela será renderizada, em vez de depender do container padrão do SDK. |

### Callbacks {#callbacks}

| Status | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `paymentResult(data)` | *(removido)* | Removido | A tela renderiza o resultado e serve apenas para exibição. Confirme o resultado no servidor por meio de [webhooks](/docs/webhooks) ou da API de pagamentos, como fonte da verdade para atender o pedido; dentro de uma `Transaction`, o status final chega em [`onStatus`](/pt-br/docs/yuno-sdk/controllers/on-status). |

### Pontos de entrada {#entry-points}

| Status | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `yuno.mountStatusPayment({...})` | `sdkPayments.transactionStatus({...})` | Renomeado | Método de nível superior em `SdkPayments`, não em `Transaction`: uma operação independente, que não faz parte do ciclo de vida de uma transação. Retorna uma `Promise<void>`. |
