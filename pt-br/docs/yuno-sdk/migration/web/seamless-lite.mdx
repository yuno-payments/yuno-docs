---
title: "Modo Seamless Lite"
description: "Migre integrações Seamless Lite na Web (yuno.startSeamlessCheckout + yuno.mountSeamlessCheckoutLite) para a API unificada de Transaction."
---

O Seamless Lite combinava duas características legadas: **Seamless** (o SDK criava o pagamento internamente, sem expor o callback `yunoCreatePayment`) e **Lite** (o meio de pagamento era pré-selecionado pelo lojista; o SDK só renderizava o formulário desse único meio).

Na API unificada, `transaction.start({ paymentMethod })` monta o formulário do meio pré-selecionado e `transaction.submit()` paga a partir do seu botão. Sem `createPayment` na configuração (o Seamless sempre foi gerenciado).

## Antes de começar {#before-you-start}

- Carregue o bundle do SDK unificado em vez do legado e inicialize-o como mostra o lado a lado: `window.Yuno.initialize(...)` passa a ser `SdkPayments.initialize(...)`. A sua chave de API pública e as sessões de checkout que o seu backend cria não mudam ([Antes de começar](/pt-br/docs/yuno-sdk/get-started#before-you-begin)).
- Decida quem cria o pagamento. O `workflow` da sessão de checkout precisa corresponder a essa decisão:

| Quem cria o pagamento | No Seamless Lite você tinha | Na API unificada | `workflow` da sessão |
|---|---|---|---|
| O seu backend | Sem equivalente: o Seamless nunca deixava você criá-lo | Sobrescreva `createPayment` | Padrão (`SDK_CHECKOUT`) |
| O SDK | Sempre | Sem sobrescrita | `SDK_SEAMLESS` |

<Warning>
Uma sessão com o workflow padrão e sem sobrescrita de `createPayment` termina em `INTERNAL_ERROR`: o backend rejeita a criação do pagamento pelo SDK. Consulte [`createPayment`](/pt-br/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Lado a lado {#side-by-side}

<CodeGroup>

```typescript Before. Seamless Lite
const yuno = await window.Yuno.initialize('your-public-api-key')

await yuno.startSeamlessCheckout({
    checkoutSession: 'session-from-backend',
    elementSelector: '#root',
    countryCode: 'CO',
    language: 'en',
    yunoPaymentResult: (status) => console.log('done:', status),
})

await yuno.mountSeamlessCheckoutLite({
    paymentMethodType: 'PIX',
    vaultedToken: null,
})

// Merchant's pay button triggers. SDK does everything else
document.getElementById('pay').addEventListener('click', () => {
    yuno.startPayment()
})
```

```typescript After. Unified Transaction (managed + pre-selected)
const sdkPayments = await SdkPayments.initialize('your-public-api-key')

const transaction = sdkPayments.transaction({
    checkoutSession: 'session-from-backend',
    countryCode: 'CO',
    language: 'en',
    elementSelector: '#root',
    showPayButton: false,
    // managed mode: no createPayment wired
    onStatus: (result) => console.log('done:', result.status),
})

// Mount the form for the pre-selected method
await transaction.start({
    paymentMethod: { type: 'PIX' },
})

// Merchant's pay button submits it. SDK does everything else
document.getElementById('pay').addEventListener('click', () => {
    transaction.submit()
})
```

</CodeGroup>

## O que muda {#what-changes}

Agrupado na ordem em que você edita o código. **Renomeado**: mesma função, novo nome. **Movido**: mesmo valor, novo dono. **Removido**: nada para chamar. **Novo**: sem equivalente legado. A última coluna é a única coisa que você precisa fazer além da renomeação.

### Inicialização e configuração {#initialization-and-config}

| Seamless Lite | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `window.Yuno.initialize(publicApiKey)` | `SdkPayments.initialize(publicApiKey)` | Renomeado | O global é `window.SdkPayments`. Como antes, use `await` nele: ele resolve para a instância de `SdkPayments` a partir da qual você cria as transações. |
| `checkoutSession`, `countryCode`, `language` na configuração de `startSeamlessCheckout` | Os mesmos campos na configuração da transação | Movido | Mesmos valores, uma única factory. |
| `elementSelector` na configuração de `startSeamlessCheckout` | `elementSelector` na configuração da transação | Movido | Obrigatório. `start({ paymentMethod })` renderiza o formulário dentro desse elemento e lança um erro sem ele. Os fluxos headless o ignoram. |
| `showPayButton` na configuração de `startSeamlessCheckout` | `showPayButton` na configuração da transação | Movido | Mesmo significado. Somente fluxos de pagamento. |

### Callbacks {#callbacks}

| Seamless Lite | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `yunoPaymentResult(status, subStatus?)` | `onStatus(result)` | Renomeado | Continua sendo o único callback de resultado, agora um campo na configuração da transação. Ele recebe um objeto `TransactionStatus` (`status`, `substatus`, `message`). Consulte [`Status`](/pt-br/docs/yuno-sdk/reference/objects-you-receive#status). |
| `yunoError(message, data?)` | *(removido)* | Removido | Os erros chegam por `onStatus` ou por uma Promise de `start()` rejeitada. |
| `onLoading({ isLoading, type })` | `showLoading(isLoading)` | Renomeado | Opcional. Apenas um sinal Boolean. Consulte [`showLoading`](/pt-br/docs/yuno-sdk/controllers/show-loading). |
| *(nenhum: a criação do pagamento sempre foi gerenciada)* | `createPayment` | Novo | Não o conecte. A ausência dele mantém o SDK no modo gerenciado, o mesmo modelo que o Seamless tinha. |

### Pontos de entrada {#entry-points}

| Seamless Lite | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `yuno.startSeamlessCheckout(config)` | `sdkPayments.transaction(config)` | Renomeado | A factory `Seamless` deixou de existir: use a factory normal, sem `createPayment` (consulte Callbacks). |
| `yuno.mountSeamlessCheckoutLite({ paymentMethodType, vaultedToken })` + `yuno.startPayment()` (gatilho do lojista) | `transaction.start({ paymentMethod: { type, vaultedToken } })` + `transaction.submit()` | Renomeado | Os mesmos dois passos. `start()` monta o formulário dentro do `elementSelector` definido na configuração da transação, e a pré-seleção vira o argumento `paymentMethod` dele. `submit()` é o seu gatilho de pagamento. Defina `showPayButton: false` para ocultar o botão do SDK. `Lite` vs `Full` deixou de existir como divisão de métodos: agora depende de você passar `paymentMethod` diretamente para `start()` (pré-selecionado) ou obtê-lo de `onPaymentSelected` dentro de `getPaymentMethodsViews` (o usuário escolhe na lista). |
| `yuno.submitOneTimeTokenForm()` | `transaction.submit()` | Renomeado | Envia o formulário que `start()` montou, a partir do seu próprio botão. Use-o com `showPayButton: false`. Consulte [Web: enviar a partir do seu próprio botão](/pt-br/docs/yuno-sdk/controllers/show-view#web-submit-from-your-own-button). |
