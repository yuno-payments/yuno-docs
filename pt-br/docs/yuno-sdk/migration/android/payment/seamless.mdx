---
title: "Modo Seamless"
description: "Migre integrações Seamless no Android (Activity.startPaymentSeamlessLite) para a API unificada de Transaction."
---

O Seamless era o ponto de entrada legado mais simples no Android: depois de configurar o launcher com `startCheckout(…)`, uma única chamada `startPaymentSeamlessLite(paymentSelected, …)` entregava tudo ao SDK: ele renderizava o formulário, tokenizava, criava o pagamento, executava o 3DS e informava o resultado por uma lambda `callbackPaymentState`.

Na API unificada, o mesmo fluxo é o **comportamento padrão** de `Transaction.start(activity, paymentSelected)`. Nenhuma sobrescrita de controller além de `onStatus`. A mudança estrutural está no modelo de entrega do resultado: antes era uma lambda passada para a chamada de início, agora é um callback por `onStatus` em um `TransactionController`.

## Antes de começar {#before-you-start}

- Substitua os imports `com.yuno.sdk.*` e `com.yuno.presentation.*` pelos equivalentes em `com.yuno.payments.sdk.api.*` (o lado a lado os lista). A sua chave de API pública e as sessões de checkout que o seu backend cria não mudam ([Antes de começar](/pt-br/docs/yuno-sdk/get-started#before-you-begin)).
- Decida quem cria o pagamento. O `workflow` da sessão de checkout precisa corresponder a essa decisão:

| Quem cria o pagamento | No Seamless você tinha | Na API unificada | `workflow` da sessão |
|---|---|---|---|
| O seu backend | Sem equivalente: o Seamless nunca deixava você criá-lo | Sobrescreva `createPayment` | Padrão (`SDK_CHECKOUT`) |
| O SDK | Sempre | Sem sobrescrita | `SDK_SEAMLESS` |

<Warning>
Uma sessão com o workflow padrão e sem sobrescrita de `createPayment` termina em `INTERNAL_ERROR`: o backend rejeita a criação do pagamento pelo SDK. Consulte [`createPayment`](/pt-br/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Lado a lado {#side-by-side}

<CodeGroup>

```kotlin Before. Seamless mode
import com.yuno.sdk.Yuno
import com.yuno.sdk.payments.startCheckout
import com.yuno.sdk.payments.startPaymentSeamlessLite
import com.yuno.presentation.core.components.PaymentSelected

class CheckoutActivity : ComponentActivity() {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 1. Initialize once at app startup
        Yuno.initialize(applicationContext, apiKey = "your-public-api-key")

        // 2. Wire up the checkout launcher
        startCheckout(
            checkoutSession = "session-from-backend",
            countryCode = "CO",
        )
    }

    // 3. Trigger the payment with a single call; result arrives in the lambda
    fun pay(paymentSelected: PaymentSelected) {
        startPaymentSeamlessLite(
            paymentSelected = paymentSelected,
            showPaymentStatus = true,
            callbackPaymentState = { state, subState ->
                when (state) {
                    "SUCCEEDED"         -> println("Success")
                    "REJECT"            -> println("Rejected")
                    "FAIL"              -> println("Failed")
                    "PROCESSING"        -> println("Processing")
                    "INTERNAL_ERROR"    -> println("Internal error")
                    "CANCELED_BY_USER"  -> println("User cancelled")
                }
            },
        )
    }
}
```

```kotlin After. Unified Transaction
import com.yuno.payments.sdk.api.SdkPayments
import com.yuno.payments.sdk.api.Transaction
import com.yuno.payments.sdk.api.TransactionConfig
import com.yuno.payments.sdk.api.TransactionController
import com.yuno.payments.sdk.api.models.PaymentMethodSelected
import com.yuno.payments.sdk.api.models.TransactionStatus

class CheckoutActivity : ComponentActivity(), TransactionController {

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        // 1. Initialize once at app startup
        SdkPayments.initialize(applicationContext, apiKey = "your-public-api-key")
    }

    // 2. Implement a minimal controller
    override fun onStatus(status: TransactionStatus) {
        when (status.status) {
            "SUCCEEDED"      -> println("Success")
            "DECLINED"       -> println("Declined")
            "REJECTED"       -> println("Rejected")
            "ERROR"          -> println("Error")
            "PENDING"        -> println("Pending")
            "INTERNAL_ERROR" -> println("Internal error")
            "USER_CANCEL"    -> println("User cancelled")
        }
    }

    // 3. Trigger the payment
    fun pay(paymentSelected: PaymentMethodSelected) {
        val config = TransactionConfig(
            checkoutSession = "session-from-backend",
            countryCode = "CO",
            language = "en",
            controller = this,
            showStatusScreen = true,
        )

        Transaction(config = config)
            .start(activity = this, paymentSelected = paymentSelected)
    }
}
```

</CodeGroup>

## O que muda {#what-changes}

Agrupado na ordem em que você edita o código. **Renomeado**: mesma função, novo nome. **Movido**: mesmo valor, novo dono. **Removido**: nada para chamar. **Novo**: sem equivalente legado. A última coluna é a única coisa que você precisa fazer além da renomeação.

### Inicialização e configuração {#initialization-and-config}

| Seamless | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `import com.yuno.sdk.*` | `import com.yuno.payments.sdk.api.*` | Renomeado | |
| `Yuno.initialize(context, apiKey)` | `SdkPayments.initialize(context, apiKey)` | Renomeado | |
| Argumentos `checkoutSession` e `countryCode` de `startCheckout` | Os mesmos campos em `TransactionConfig` | Movido | Mesmos valores; a configuração também recebe o `controller` (consulte Controller). |
| Argumento `showPaymentStatus` de `startPaymentSeamlessLite` | `TransactionConfig.showStatusScreen` | Movido | Consulte a observação abaixo. |

<Note>
**A tela de resultado do SDK agora vem desativada por padrão.** Defina `showStatusScreen = true` para mantê-la.
</Note>

### Controller {#controller}

| Seamless | Unificada | Mudança | O que fazer |
|---|---|---|---|
| *(sem controller: uma lambda passada para a chamada de início)* | `TransactionController` | Novo | Até o caso mais simples precisa de uma instância de controller: implemente `TransactionController` apenas com `onStatus` e passe-a como `TransactionConfig.controller`. O SDK não a retém: mantenha-a viva durante toda a transação. |
| `callbackPaymentState: (state, subState) -> Unit` | `onStatus(status: TransactionStatus)` | Movido | O resultado chega pelo controller em vez de uma lambda passada para a chamada de início. Continua sendo o único callback de resultado, uma vez por transação, também quando o SDK exibe a sua tela de resultado. O par bruto `(state, subState)` vira um objeto `TransactionStatus`: `status` e `substatus` vêm do backend, como o backend os retorna. As strings legadas `REJECT`, `FAIL` e `PROCESSING` não são mais emitidas: trate `DECLINED`, `REJECTED`, `ERROR` e `PENDING` no lugar delas. `CANCELED_BY_USER` agora é `USER_CANCEL`. O próprio SDK só emite `INTERNAL_ERROR` e `USER_CANCEL`. Consulte [`Status`](/pt-br/docs/yuno-sdk/reference/objects-you-receive#status). |

### Pontos de entrada {#entry-points}

| Seamless | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `startCheckout(…)` + `startPaymentSeamlessLite(paymentSelected, showPaymentStatus, callbackPaymentState)` | `Transaction(config).start(activity, paymentSelected)` | Renomeado | Monte a configuração e depois chame `start`: ponto de entrada único, e o resultado chega em `onStatus`. Você ainda escolhe o meio e o passa. As funções de extensão de `Activity` viram uma única chamada em uma instância comum de `Transaction`, que não precisa de uma `Activity` para ser construída. |
| `PaymentSelected` | `PaymentMethodSelected` | Renomeado | Mesma função: o valor que você passa para `start`. |
