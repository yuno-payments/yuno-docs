---
title: "Modo Lite"
description: "Migre integrações Lite do iOS (Yuno.startPaymentLite) para a API unificada de Transaction."
---

O modo Lite pré-selecionava o meio de pagamento no lado do lojista e depois passava o controle para o SDK renderizar o formulário, tokenizar, criar o pagamento, tratar o 3DS e informar o resultado. Na API unificada, esse é o **comportamento padrão** de `Transaction.start(paymentSelected:)`. Nenhuma sobrescrita de controller é necessária.

## Antes de começar {#before-you-start}

- Substitua `import YunoSDK` por `import SdkPayments`. A sua chave de API pública e as sessões de checkout que o seu backend cria não mudam ([Antes de começar](/pt-br/docs/yuno-sdk/get-started#before-you-begin)).
- Decida quem cria o pagamento. O `workflow` da sessão de checkout precisa corresponder a essa decisão:

| Quem cria o pagamento | No Lite você tinha | Na API unificada | `workflow` da sessão |
|---|---|---|---|
| O seu backend | `yunoCreatePayment` implementado | Sobrescreva `createPayment` | Padrão (`SDK_CHECKOUT`) |
| O SDK | Sem equivalente: só o Seamless deixava o SDK criar o pagamento | Sem sobrescrita | `SDK_SEAMLESS` |

<Warning>
Uma sessão com o workflow padrão e sem sobrescrita de `createPayment` termina em `INTERNAL_ERROR`: o backend rejeita a criação do pagamento pelo SDK. Consulte [`createPayment`](/pt-br/docs/yuno-sdk/controllers/create-payment).
</Warning>

## Lado a lado {#side-by-side}

<CodeGroup>

```swift Before. Lite mode
import YunoSDK

// 1. Initialize once at app startup
Yuno.initialize(
    apiKey: "your-public-api-key",
    config: YunoConfig(
        appearance: customAppearance,
        saveCardEnabled: true,
        keepLoader: false
    )
)

// 2. Implement the delegate
final class Checkout: YunoPaymentDelegate {
    var checkoutSession: String = "session-from-backend"
    var countryCode: String = "CO"
    var language: String? = "en"
    var viewController: UIViewController?

    func yunoPaymentResult(_ result: Yuno.Result) {
        switch result.status {
        case .succeeded:      print("Success")
        case .reject:         print("Rejected")
        case .fail:           print("Failed")
        case .processing:     print("Processing")
        case .internalError:  print("Internal error")
        case .userCancelled:  print("User cancelled")
        @unknown default:     break
        }
    }

    // 3. Start the payment
    func pay(paymentSelected: PaymentMethodSelected) {
        Yuno.startPaymentLite(
            with: self,
            paymentSelected: paymentSelected,
            showPaymentStatus: true
        )
    }
}
```

```swift After. Unified Transaction
import SdkPayments

// 1. Initialize once at app startup
SdkPayments.initialize(apiKey: "your-public-api-key")

// 2. Implement the controller
final class Checkout: SdkPayments.TransactionController {

    func onStatus(status: SdkPayments.TransactionStatus) {
        switch status.status {
        case "INTERNAL_ERROR":  print("Internal error")
        case "USER_CANCEL":     print("User cancelled")
        // Handle other backend statuses (e.g. SUCCEEDED, DECLINED, PENDING) as needed.
        default:                break
        }
    }

    // 3. Start the payment
    func pay(paymentSelected: SdkPayments.PaymentMethodSelected) {
        let config = SdkPayments.TransactionConfig(
            checkoutSession: "session-from-backend",
            countryCode: "CO",
            language: "en",
            appearance: customAppearance,    // optional
            controller: self,
            showStatusScreen: true,
            saveCardEnabled: true
        )

        SdkPayments.Transaction(config: config)
            .start(paymentSelected: paymentSelected)
    }
}
```

</CodeGroup>

## O que muda {#what-changes}

Agrupado na ordem em que você edita o código. **Renomeado**: mesma função, novo nome. **Movido**: mesmo valor, novo dono. **Removido**: nada a chamar. A última coluna é a única coisa que você precisa fazer além da renomeação.

### Inicialização e configuração {#initialization-and-config}

| Lite | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `import YunoSDK` | `import SdkPayments` | Renomeado | |
| `Yuno.initialize(apiKey:config:)` | `SdkPayments.initialize(apiKey:)` | Renomeado | `YunoConfig` deixou de existir: os campos dele passam para `SdkPayments.TransactionConfig` (próximas linhas). O parâmetro `callback:` também deixou de existir; use a sobrecarga `async` se você precisar esperar. |
| `YunoConfig.appearance` | `SdkPayments.TransactionConfig.appearance` | Movido | Passe-o por transação em vez de uma única vez na inicialização. |
| `Yuno.Appearance` | `SdkPayments.Appearance` | Renomeado | Mesmo inicializador; remova o prefixo `Yuno.`. |
| `YunoConfig.saveCardEnabled` | `SdkPayments.TransactionConfig.saveCardEnabled` | Movido | O padrão é `false`. Com `true`, o formulário de cartão exibe a caixa de seleção para salvar o cartão (somente pagamentos), desmarcada. |
| `YunoConfig.keepLoader` | *(removido)* | Removido | O SDK mantém o seu loader. Sobrescreva `showLoading` somente se você quiser um loader próprio (consulte Controller). |
| `YunoPaymentDelegate.checkoutSession`, `.countryCode`, `.language`, `.viewController` | Os mesmos campos em `SdkPayments.TransactionConfig` | Movido | As propriedades do delegate viram campos de configuração. `viewController` continua exclusivo do iOS e opcional no SwiftUI. |
| Argumento `showPaymentStatus:` de `startPaymentLite` | `SdkPayments.TransactionConfig.showStatusScreen` | Movido | Consulte a observação abaixo. |

<Note>
**A tela de resultado do SDK agora vem desativada por padrão.** Defina `showStatusScreen: true` para mantê-la.
</Note>

### Controller {#controller}

| Lite | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `YunoPaymentDelegate` | `SdkPayments.TransactionController` | Renomeado | Faça a mesma classe conformar com o protocolo e passe-a como `TransactionConfig.controller`. Como antes, o SDK não a retém: mantenha-a viva durante toda a transação. |
| `yunoPaymentResult(_:)` | `onStatus(status:)` | Renomeado | Continua sendo o único callback de resultado, uma vez por transação, inclusive quando o SDK mostra a sua tela de resultado. `status` e `substatus` vêm do backend; o próprio SDK emite apenas `INTERNAL_ERROR` e `USER_CANCEL`. Consulte [`Status`](/pt-br/docs/yuno-sdk/reference/objects-you-receive#status). |
| `Yuno.Result.message` | `SdkPayments.TransactionStatus.message` | Renomeado | Mesma função. `source` agora é um enum (`.sdk` / `.backend`) e `code` não é opcional. |
| `yunoCreatePayment(with:)` / `(with:information:)` | `createPayment(token:)` | Renomeado | Opcional. Um único handler substitui as duas variantes; `token` é o Token de uso único completo como dicionário. Crie o pagamento e retorne: retornar é o que antes era `continuePayment()`. Se o handler lançar um erro, o fluxo para e `onStatus` não é chamado, então mostre o erro você mesmo. Consulte [`createPayment`](/pt-br/docs/yuno-sdk/controllers/create-payment). |
| `YunoLoaderDelegate.onLoading(isLoading:)` | `showLoading(isLoading:)` | Renomeado | Opcional. O Lite nunca o invocava. Se você o sobrescrever agora, o SDK oculta o próprio loader e informa o estado a você. Consulte [`showLoading`](/pt-br/docs/yuno-sdk/controllers/show-loading). |
| `onInstallmentSelected(_:)` com `YunoInstallmentSelected` | `onInstallmentSelected(_:)` com `SdkPayments.InstallmentSelected` | Renomeado | Opcional. Mesmo gatilho e mesmos campos; só o tipo do payload muda. Consulte [`onInstallmentSelected`](/pt-br/docs/yuno-sdk/controllers/on-installment-selected). |
| `YunoShippingDelegate.onShippingAddressChanged(_:shippingInfo:)` | `onShippingAddressChanged(_:shippingInfo:)` via `SdkPayments.ShippingAddressHandling` | Movido | Opcional. Faça o controller conformar com o protocolo; os tipos perdem o prefixo `Yuno` e a variante baseada em completion deixou de existir. Consulte [`onShippingAddressChanged`](/pt-br/docs/yuno-sdk/controllers/on-shipping-address-changed). |

### Pontos de entrada {#entry-points}

| Lite | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `Yuno.startPaymentLite(with:paymentSelected:showPaymentStatus:)` | `SdkPayments.Transaction(config:).start(paymentSelected:)` | Renomeado | Monte a configuração e depois chame `start`. Você continua escolhendo o meio e passando-o. |
| `Yuno.continuePayment()` | *(removido)* | Removido | Apague a chamada: retornar de `createPayment` retoma o fluxo. Defina [`autoContinuePayment`](/pt-br/docs/yuno-sdk/reference/objects-you-pass#autocontinuepayment) como `false` somente se você precisar que o SDK pare logo depois que o pagamento for criado. |
| `Yuno.receiveDeeplink(_:)` | `SdkPayments.handleDeeplink(_:)` | Renomeado | Mesma função: encaminhe a URL que o seu app recebe após um redirecionamento externo. Consulte [Tratar deeplinks](/pt-br/docs/yuno-sdk/features/handle-deeplinks). |
| `Yuno.hideLoader()` | *(removido)* | Removido | Apague a chamada: o SDK fecha o próprio loader. Com uma sobrescrita de `showLoading`, você recebe `isLoading: false` em vez disso. |
