---
title: "Cadastro Headless"
description: "Migre o cadastro Headless do iOS (Yuno.apiClientEnroll) para a Transaction API unificada."
---

O cadastro Headless era uma API de tokenização pura: você coletava os dados na sua própria UI, chamava `continueEnrollment(data:)` e recebia de volta um dicionário com `vaultedToken`, `customerSession` e `status`.

Na API unificada, o cadastro headless deixa de ser um client separado. É o mesmo `Transaction.start(paymentSelected:)` com `transactionData` definido no `PaymentMethodSelected`. O SDK executa o cadastro internamente e informa a conclusão por meio de `onStatus`.

## Antes de começar {#before-you-start}

- Substitua `import YunoSDK` por `import SdkPayments`. A sua chave de API pública e as sessões de cliente que o seu backend cria não mudam ([Antes de começar](/pt-br/docs/yuno-sdk/get-started#before-you-begin)).
- Não há pagamento a criar: `createPayment` não é chamado durante o cadastro, então sobrescrevê-lo não tem efeito.

## Lado a lado {#side-by-side}

<CodeGroup>

```swift Before. Headless enrollment
import YunoSDK

Yuno.initialize(apiKey: "your-public-api-key")

let enrollHeadless = try Yuno.apiClientEnroll(
    countryCode: "CO",
    customerSession: "session-from-backend"
)

// Card fields come from your own form
let data = EnrollmentCollectedData(
    customerSession: "session-from-backend",
    paymentMethod: CollectedData(
        type: "CARD",
        vaultedToken: nil,
        card: CardData(
            detail: CardData.Detail(
                number: cardNumber,
                expirationMonth: expMonth,
                expirationYear: expYear,
                securityCode: cvv,
                holderName: holder
            )
        ),
        customer: nil
    )
)

let result = try await enrollHeadless.continueEnrollment(data: data)
let vaultedToken = result["vaultedToken"]
let status = result["status"]
```

```swift After. Unified Transaction
import SdkPayments

SdkPayments.initialize(apiKey: "your-public-api-key")

final class EnrollmentModel: SdkPayments.TransactionController {

    func onStatus(status: SdkPayments.TransactionStatus) {
        // On a successful status, retrieve the vaulted token from your
        // backend's "list customer payment methods" endpoint.
    }

    func enroll(card: SdkPayments.CardTransactionData) {
        let paymentSelected = SdkPayments.PaymentMethodSelected(
            paymentMethodType: "CARD",
            transactionData: SdkPayments.TransactionData(card: card)
        )

        let config = SdkPayments.TransactionConfig(
            customerSession: "session-from-backend",
            countryCode: "CO",
            controller: self
        )

        SdkPayments.Transaction(config: config)
            .start(paymentSelected: paymentSelected)
    }
}
```

</CodeGroup>

## O que muda {#what-changes}

Agrupado na ordem em que você edita o código. **Renomeado**: mesma função, novo nome. **Movido**: mesmo valor, novo dono. **Removido**: nada a chamar. **Novo**: sem equivalente legado. A última coluna é a única coisa que você precisa fazer além da renomeação.

### Inicialização e config {#initialization-and-config}

| Headless | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `import YunoSDK` | `import SdkPayments` | Renomeado | |
| `Yuno.initialize(apiKey:)` | `SdkPayments.initialize(apiKey:)` | Renomeado | O parâmetro `callback:` deixou de existir; use a sobrecarga `async` se precisar aguardar. |
| `Yuno.Appearance` passado em `YunoConfig.appearance` | `SdkPayments.Appearance` em `SdkPayments.TransactionConfig.appearance` | Renomeado | Mesmo inicializador; remova o prefixo `Yuno.` e passe-o por transação, em vez de uma vez na inicialização. |
| `EnrollmentCollectedData` / `CollectedData` | `SdkPayments.PaymentMethodSelected` + `SdkPayments.TransactionData` | Renomeado | O wrapper se divide em dois: o tipo do meio vai em `PaymentMethodSelected` (a sessão determina o meio efetivamente cadastrado), e os dados coletados ficam sob o seu `transactionData` (próximas linhas). |
| `EnrollmentCollectedData.customerSession` e o argumento `customerSession:` de `apiClientEnroll` | `SdkPayments.TransactionConfig.customerSession` | Movido | Passa para a config; informe-o uma vez. |
| Argumento `countryCode:` de `apiClientEnroll` | `SdkPayments.TransactionConfig.countryCode` | Movido | |
| `CollectedData.type` | `SdkPayments.PaymentMethodSelected.paymentMethodType` | Movido | Passa para o objeto pai. |
| `CollectedData.card.detail` (`CardData.Detail`) | `SdkPayments.TransactionData.card` (`SdkPayments.CardTransactionData`) | Movido | Mesmos campos, agrupados sob `transactionData`. `CardData.save` e `CardData.installment` não tinham função no cadastro e continuam sem ter. Veja [`TransactionData`](/pt-br/docs/yuno-sdk/reference/objects-you-pass#transaction-data). |
| `CollectedData.customer` | `SdkPayments.TransactionData.customer` | Movido | Passa para dentro de `transactionData`. |
| `CollectedData.vaultedToken` | `SdkPayments.PaymentMethodSelected.vaultedToken` | Movido | Nada obrigatório. Ele é ignorado durante o cadastro: o cadastro existe para gerar um vaulted token, então ainda não há nada vinculado para referenciar. |

### Controller {#controller}

| Headless | Unificada | Mudança | O que fazer |
|---|---|---|---|
| *(nenhum)* | `SdkPayments.TransactionController` | Novo | Faça uma classe conformar ao protocolo e passe-a como `TransactionConfig.controller`. O SDK não a retém: mantenha-a viva durante toda a transação. |
| Resultado `[String: String]` de `continueEnrollment` (`vaultedToken`, `customerSession`, `status`) | `onStatus(status:)` | Movido | Agora é o único callback de resultado, uma vez por transação. `status` e `substatus` vêm do backend; o próprio SDK só emite `INTERNAL_ERROR` e `USER_CANCEL`. **O vaulted token não é mais retornado ao client**: busque-o no endpoint list-customer-payment-methods do seu backend depois que o status de sucesso chegar. Veja [`Status`](/pt-br/docs/yuno-sdk/reference/objects-you-receive#status). |
| `YunoEnrollHeadlessError` lançado por `apiClientEnroll` e `continueEnrollment` | `onStatus` com `status == "INTERNAL_ERROR"` e `message` | Movido | Nada lança erro: trate `INTERNAL_ERROR` em `onStatus`. |

### Pontos de entrada {#entry-points}

| Headless | Unificada | Mudança | O que fazer |
|---|---|---|---|
| `Yuno.apiClientEnroll(countryCode:customerSession:)` | `SdkPayments.Transaction(config:)` | Renomeado | O objeto de transação substitui o client headless. Crie a config e depois a transação. |
| `continueEnrollment(data:)` | `start(paymentSelected:)` | Renomeado | Passe os dados coletados como `transactionData` em `PaymentMethodSelected`. A chamada não retorna mais um resultado: o SDK executa o cadastro internamente e informa a conclusão por meio de `onStatus`. |
| `Yuno.receiveDeeplink(_:)` | `SdkPayments.handleDeeplink(_:)` | Renomeado | Mesma função: encaminhe a URL que o seu app recebe após um redirecionamento externo. Veja [Tratar deeplinks](/pt-br/docs/yuno-sdk/features/handle-deeplinks). |
