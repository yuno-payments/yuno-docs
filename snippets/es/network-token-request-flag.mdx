El booleano opcional `payment_method.network_token` te permite decidir, por tarjeta, si Yuno usa un token de red. Envíalo al [crear un pago](/es/reference/payments/create-payment) y al inscribir una tarjeta ([flujo Checkout](/es/reference/payment-methods-checkout/enroll-payment-method-checkout) y [API directa](/es/reference/payment-methods-direct-workflow/enroll-payment-method-api)).

| `payment_method.network_token` | Pago | Inscripción de tarjeta |
| --- | --- | --- |
| `false` | Yuno nunca solicita ni reutiliza un token de red: el PAN va al proveedor, incluso cuando la ruta tiene activado el token de red. Un token ya almacenado para la tarjeta se conserva, no se elimina. | Yuno no aprovisiona un token de red para la tarjeta, incluida la ruta de migración para tarjetas inscritas sin CVV. |
| `true` | En una tarjeta guardada en el vault (`vaulted_token` o `vault_on_success: true`), Yuno usa el token de red de la tarjeta, o aprovisiona uno, incluso cuando la ruta tiene desactivado el token de red. | Yuno aprovisiona un token de red para la tarjeta, como lo hace hoy. |
| Omitido | La ruta decide, como hoy: el token de red se usa solo cuando la ruta lo tiene activado. | Yuno aprovisiona un token de red como lo hace hoy. |

El campo depende del onboarding de tokens de red: `true` solo tiene efecto cuando tu organización tiene el onboarding de tokens de red para la red de la tarjeta y el proveedor los admite. Cuando no es así, la solicitud no falla; el pago se envía con el PAN.

El campo no tiene efecto en:

- Tarjetas de invitado (sin guardar en el vault), que nunca obtienen un token de red.
- Pagos con wallets (Apple Pay, Google Pay, Samsung Pay).
- Tokens de red que envías tú mismo con su criptograma (tokens de red externos del comercio).
