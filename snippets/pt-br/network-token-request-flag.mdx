O booleano opcional `payment_method.network_token` permite decidir, por cartão, se a Yuno usa um network token. Envie-o em [Create Payment](/reference/payments/create-payment) e no cadastro de cartão ([fluxo de Checkout](/reference/payment-methods-checkout/enroll-payment-method-checkout) e [API direta](/reference/payment-methods-direct-workflow/enroll-payment-method-api)).

| `payment_method.network_token` | Pagamento | Cadastro de cartão |
| --- | --- | --- |
| `false` | A Yuno nunca solicita nem reutiliza um network token: o PAN vai para o provedor, mesmo quando a rota está com a opção de network token ativada. Um token já armazenado para o cartão é mantido, não excluído. | A Yuno não provisiona um network token para o cartão, incluindo o caminho de migração para cartões cadastrados sem CVV. |
| `true` | Em um cartão salvo no vault (`vaulted_token`, ou `vault_on_success: true`), a Yuno usa o network token do cartão, ou provisiona um, mesmo quando a rota está com a opção de network token desativada. | A Yuno provisiona um network token para o cartão, como já faz hoje. |
| Omitido | A rota decide, como hoje: o network token é usado apenas quando a rota está com a opção ativada. | A Yuno provisiona um network token como hoje. |

O campo depende do onboarding de network tokens: `true` só tem efeito quando sua organização tem onboarding de network tokens para a bandeira do cartão e o provedor oferece suporte a eles. Caso contrário, a requisição não falha; o pagamento segue com o PAN.

O campo não tem efeito sobre:

- Cartões de convidado (não salvos no vault), que nunca recebem um network token.
- Pagamentos com carteira digital (Apple Pay, Google Pay, Samsung Pay).
- Network tokens que você mesmo envia com o criptograma (network tokens externos do lojista).
