## What the server exposes

Three tools, all read-only. Your agent calls them on its own once the server is connected.

<div className="yd-mcp-tools">
  <div className="yd-mcp-tool"><code>search_yuno_api_documentation</code><p>Searches the docs for guides, code examples and API references that match a question.</p></div>
  <div className="yd-mcp-tool"><code>query_docs_filesystem_yuno_api_documentation</code><p>Runs read-only shell-style queries, such as <code>rg</code> or <code>cat</code>, against the docs as a virtual filesystem.</p></div>
  <div className="yd-mcp-tool"><code>submit_feedback</code><p>Reports an incorrect or missing page to the docs team, with the page path and what is wrong.</p></div>
</div>

## Add the server

<Steps>
  <Step title="Pick your tool and add the URL">
    <Tabs>
      <Tab title="Cursor">
        1. Open **Cursor Settings** (`Cmd+Shift+P` or `Ctrl+Shift+P`, then "Open MCP Settings").
        2. Click **+ Add New MCP Server**.
        3. Fill in the details:
           - **Name**: Yuno Docs
           - **Type**: `http`
           - **URL**: `https://docs.y.uno/mcp`
        4. Click **Save**.
      </Tab>
      <Tab title="Claude Code">
        ```bash
        claude mcp add --transport http yuno-docs https://docs.y.uno/mcp
        ```

        Add `--scope project` to share the server with your team through `.mcp.json`.
      </Tab>
      <Tab title="Claude Desktop">
        1. Open the Claude Desktop configuration file (`~/Library/Application Support/Claude/claude_desktop_config.json` on macOS, `%APPDATA%\Claude\claude_desktop_config.json` on Windows).
        2. Add the server to `mcpServers`:

        ```json
        {
          "mcpServers": {
            "yuno-docs": {
              "url": "https://docs.y.uno/mcp"
            }
          }
        }
        ```
      </Tab>
      <Tab title="Codex">
        ```bash
        codex mcp add yuno-docs --url https://docs.y.uno/mcp
        ```
      </Tab>
      <Tab title="VS Code">
        Create `.vscode/mcp.json` in your project:

        ```json
        {
          "servers": {
            "yuno-docs": {
              "type": "http",
              "url": "https://docs.y.uno/mcp"
            }
          }
        }
        ```
      </Tab>
    </Tabs>
  </Step>
  <Step title="Check the connection">
    Ask your agent a question only the docs answer:

    ```text
    Which two headers authenticate a Yuno API call?
    ```

    A connected agent answers `public-api-key` and `private-secret-key`, and cites a docs.y.uno page. If it guesses or names another header, the server is not connected yet: restart the tool and check the URL.
  </Step>
  <Step title="Ask for a first payment">
    The server works best with a concrete task. For example:

    ```text
    Using the Yuno docs, write a Node script that
    creates a checkout session and a sandbox payment
    with the test card from the Quickstart.
    ```

    The agent reads the [Quickstart](/docs/quickstart) and the API reference through the server, so the base URL, headers and required fields come from the current docs.
  </Step>
</Steps>

## Which Yuno MCP do you need?

| Server | What it does | Credentials |
|---|---|---|
| **Documentation MCP** (this page) | Searches and reads the Yuno docs. Cannot act on your account. | None |
| [Local Action MCP](/docs/ai-capabilities/building-ai-integrations-with-yunos-llms-and-mcp) | Runs from your machine with `npx`. Creates and manages payments, customers and subscriptions. | Your API keys |
| [Remote Action MCP](/docs/ai-capabilities/remote-yuno-mcp-server) | Hosted endpoint with the same actions, plus rate limits, IP binding and session expiry enforced by Yuno. | Your API keys |
